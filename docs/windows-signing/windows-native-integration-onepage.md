# Integration supplement — smallest functional patch (design only)

**Evidence:** hosted run [34853134630](https://github.com/Hiper-nexus/nexus-ide/actions/runs/34853134630), commit `037dc0c4`, passed all six standalone cases. This proves system ConPTY + atomic job-list creation/owned-handle cleanup in the fixture. It does **not** prove N-API lifetime, upstream named-pipe integration, vendored ConPTY DLL, packaged Electron, signing or installed updates.

**Choice:** patch the exact upstream Windows implementation, not a new PTY addon. A new addon must recreate argv, sockets, draining, resize and loading. The patch changes three upstream files plus one native context helper; it is still a lifecycle refactor.

| Owner/file | Minimum functional change |
|---|---|
| Pinned upstream `src/win/conpty.cc` + new `owned_job_context.h` | JOB_LIST + CREATE_SUSPENDED, membership verification before resume; preserve upstream null standard-handle policy. Replace raw baton lifetime with one shared context; registry mutation only on owner thread. Retain job after root exit. One finalizer orders cancellation, job stop/zero proof, console drain and disposal. |
| Pinned `lib/windowsPtyAgent.js` | Retain opaque native capability immediately at start; explicit creation-ready promise; timeout cancels pending creation instead of force-connecting. Job termination bypasses console-PID helper and uses `useConptyDll=true`. |
| Pinned `lib/windowsTerminal.js` | Immediate kill/cancel bypasses deferred queue; do not use output readiness for creation. Root exit, job-zero and socket/drain completion remain separate; no socket-close success receipt. |
| New `src/main/pty/windows-pty-job.ts`; `pty-host-entry.ts` + focused tests | Native API/version guard; bind capability to exact host epoch/session generation. Keep entry until native completion/error; map positive job receipt only after observed zero. Existing host-down stays fail-closed. Leave Windows POSIX/CIM inventory unsupported. |

**API:** `startProcess` returns existing pipes/ID plus an opaque N-API ObjectWrap capability. Private native methods `connectOwned(capability, argv/env/cwd, deadline) → Promise<{pid, creationReady}>`, `terminateOwned(capability, deadline) → Promise<{rootExited, jobZero, consoleClosed, error?}>`, and a completion notification retain a shared context. PID is diagnostic only. No raw HANDLE or arbitrary-ID termination surface. Repeated stop is single-flight; cancellation blocks later resume. Query zero before closing the job handle.

**Real transport constraint:** upstream passes synchronous named-pipe handles directly to ConPTY; `FILE_FLAG_OVERLAPPED` is explicitly disabled. [Microsoft restricts these handles to synchronous I/O](https://learn.microsoft.com/en-us/windows/console/createpseudoconsole). Do not merely enable overlapped on them. Smallest candidate is a dedicated native connect worker using synchronous ConnectNamedPipe plus CancelSynchronousIo, a cancellation gate and bounded settlement. Never block the N-API thread or start I/O after cancellation. This cancellation race remains to be proved. The spike used a separate overlapped control pipe and synchronous anonymous ConPTY pipes, so does not cover this seam.

**Build/loading:** retain exact npm tar SRI from the main design; stage source + checked patch privately, build conpty.node against pinned Electron/N-API/MSVC/SDK, and preserve exact 1.25.260303002 conpty.dll/OpenConsole.exe pair. Proposed *smaller* staging target is the existing platform package `node_modules/@lydell/node-pty-win32-x64/`: patched JS under `lib/`, generated addon under `prebuilds/win32-x64/conpty.node`, DLL pair adjacent under `conpty/`. Existing Forge unpackDir then supplies the matching `app.asar.unpacked/node_modules/@lydell/node-pty-win32-x64/` path. This supersedes the earlier separate resources-package suggestion. Record SRI, patch/toolchain/output digests and variant identity; reject unknown/stale inputs. Do not silently alter trust roots or label generated bytes as original prebuilds. Wire the script before the success exit in `rebuild-electron-natives.mjs`; verify staged capability/manifest during packaging. Keep MIT notices.

**Remaining gates:** cancellation/finalizer review; actual synchronous-connect cancellation under the pinned DLL; output/exit ordering and capability-generation tests; clean native rebuild and staged-loader proof; all six lifecycle scenarios repeated inside the real packaged Electron utilityProcess with RunAsNode=false. No integration code started. Signing and signed N→N+1 remain separate prerequisites.
