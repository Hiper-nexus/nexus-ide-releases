# Overclock 1.0.4 vs NexusIDE 0.6.5 — pareamento e plano de integração

Data: 2026-07-06. Terceira auditoria da série. As duas anteriores (`2026-07-05-*`) compararam o
Overclock **1.0.0**; esta confronta o **1.0.4** instalado (`/Applications/Overclock.app`, Tauri +
sidecar Node) contra o **working tree atual** do Nexus (0.6.5, `main`, árvore limpa). Ambos os lados
foram mapeados a fundo (bundle/sidecar compilado do Overclock; `src/` inteiro do Nexus). Leitura
estática, zero alteração de código. Nenhum segredo/token foi copiado.

Foco pedido pelo usuário: **Jarvis, Harness, Mídia** e o **modo Agêntico** — cada um tratado abaixo
com o fato do Overclock, o que o Nexus já tem, o gap exato e como **superar** (não só parear).

---

## 1. Veredito executivo

**O Nexus não está atrás como as telas sugerem.** Entre 05/07 e hoje o working tree absorveu quase
todo o roadmap das duas auditorias anteriores: telemetria real de tokens (watchers Claude+Codex,
SQLite, `--session-id` ditado), sessões duráveis por session-id + `--resume`, `stall-watchdog` +
status `stalled`, `--disallowedTools Task`, Jarvis com memória/echo/fast-path/narrator + máquina de
estado Live + seleção de brain provider, confirmação de voz em `run_command`, browser pane + preview
server + screenshots, remote bridge endurecido, SSH/tmux, `catalog-overlay` + recipe-lint +
`agent-spec-writer`, hibernate/wake, perf snapshot, onboarding com vitórias, e **multi-conta com
failover** (troca de credencial no Keychain — algo que o Overclock não tem).

Sobrou uma lista **curta e cirúrgica** de vantagens reais do Overclock 1.0.4 — nenhuma delas é
estrutural (nenhuma exige trocar a base Electron/xterm/canvas):

1. **Geração de mídia — o único "whitespace" limpo.** Imagem/vídeo/áudio como MCP tools. O Nexus
   tem **zero**. Trava 2–3 dos playbooks de fábrica deles (absurd-landing, cinema, cinema-site).
2. **Voz realtime de verdade** — um subsistema (áudio full-duplex WSS), não o pacote todo. O resto do
   Jarvis deles o Nexus já replicou.
3. **Harness auto-organizável** — o "Enriquecer (F5)": uma passada de LLM que anota tier + propósito
   por item e **persiste** para o orquestrador consumir na hora da missão; + faixas MÍDIA e LLMS·CLIS
   no arsenal. O Nexus tem overlay + recipe-lint, falta a passada de enriquecimento e as faixas.
4. **Modo Agêntico** — 3º modo de missão (descreve → IA monta o time → entrega). Motor existe no
   Nexus (`squad-architect`), falta entrada por intenção + card + auto-launch.
5. **Cron / squads agendados** — ausente no Nexus.
6. **Injeção real de MCP nos CLIs não-Claude** — o Overclock escreve config MCP em Codex/Gemini/
   Antigravity; o Nexus só passa env var (Claude é o único com `--mcp-config`). Gap de profundidade
   multi-CLI.

**Em uma frase:** o Overclock 1.0.4 ganha em **alcance de capacidade** (mídia, voz realtime,
multi-CLI wired, cron); o Nexus ganha em **fundação** (isolamento de processo, segredos, failover
multi-conta, roteamento por custo, voz offline). Fechar os seis itens acima sobre a nossa fundação
coloca o Nexus acima no uso real — e a ordem certa começa por Mídia, que é o maior ganho pelo menor
esforço porque cai em cima de infra que já existe (preview server, browser pane, secrets safeStorage).

## 3. Os quatro focos

### 3.1 Mídia — o gap prioritário (whitespace real)

**Overclock (fatos):** três MCP tools resolvem provider/modelo contra o allowlist do squad e chamam
`@overclock-app/core/mediaGeneration.js`. As keys são resolvidas no processo principal a partir do
`ServiceKeysStore` (Settings → API Keys) e **o agente nunca vê a key** — recebe só o caminho do
arquivo gerado, salvo no workspace.

| Tool | Provider padrão | Modelo padrão | Detalhe |
|---|---|---|---|
| `overclock_image_generate` | google-image | `gemini-3.1-flash-image-preview` ("nano-banana") | alt: openai `gpt-image-2`; i2i via inlineData |
| `overclock_video_generate` | replicate-video | `bytedance/seedance-2.0` | alt: kling v3/v2.5 (2 keyframes), hailuo; poll 4s/6min→mp4; recovery de job em `video-jobs.json` |
| `overclock_audio_generate` | elevenlabs | voz Rachel, `eleven_multilingual_v2` | TTS |
| `overclock_media_providers` | — | — | reporta quais têm key |

`mediaAllowlist.resolveMediaModel` aplica whitelist de modelo por provider (sem fallback silencioso).
Isso é o motor de **absurd-landing** (passo 6: `overclock_image_generate` por slot), **cinema** (DP
gera clipe Seedance, sound gera locução ElevenLabs) e **cinema-site** (Kling 2-keyframe). Sem mídia,
o Nexus não roda nenhum desses.

**Nexus hoje:** ausente por completo — nenhuma tool, nenhum provider, nenhum `kind:'media'`, nenhum
store de key de mídia. O único adjacente é STT/TTS de voz e `nexus_browser_screenshot`.

**Como superar (não só parear):**
- Criar `src/main/media/media-generation.ts` + `media-keys-store.ts` (reusar `secrets-store.ts`/
  safeStorage — **nossa vantagem**: keys nunca em plaintext, ao contrário do provider store deles).
- Expor `nexus_image_generate`, `nexus_video_generate`, `nexus_audio_generate`, `nexus_media_providers`
  no MCP server, com allowlist por squad (o modelo de allowlist já existe em `tools-panes`/gate).
- Providers iniciais: imagem Gemini `nano-banana` + OpenAI `gpt-image`; vídeo Replicate (Seedance +
  Kling); áudio ElevenLabs. Output no workspace via um `resolveOutPath` equivalente.
- Wire no `preview-server` + `browser` (já existem) para exibir o entregável — fecha o loop que o
  Overclock tem.
- **Superar:** (a) key nunca em plaintext (eles admitiram plaintext); (b) roteamento por custo
  também para mídia (escolher o provider mais barato que atende o pedido, reusando a filosofia do
  `task-router`); (c) telemetria real de custo de mídia na mesma tabela `token_usage`/nova
  `media_usage` (eles não somam custo de mídia ao painel).
- **Esforço:** médio, mas **contido** — cai sobre infra existente (secrets, preview, browser,
  allowlist). É o maior ganho competitivo por unidade de esforço.
- **Win-condition:** rodar o playbook `absurd-landing` (ou equivalente) ponta a ponta no Nexus,
  gerando arte real no workspace, com key protegida no Keychain.

### 3.2 Jarvis — uma diferença, não o pacote todo

**Overclock (fatos):** `GeminiLiveSession` fala `gemini-3.1-flash-live-preview` (áudio nativo) por
WSS BidiGenerateContent — mic in `pcm 16kHz`, TTS out `pcm 24kHz`, VAD server-side, barge-in por
`serverContent.interrupted`. **Tela = TEXTO** (300 chars sanitizados, debounce 1,5s — nunca pixels).
**8 tools de voz**, das quais só `delegar` cai num brain Claude Haiku (`claude-haiku-4-5`) — as outras
7 (`consultar/ler/navegar/comandar/perguntar/restaurar/encerrar`) respondem direto do estado =
latência percebida baixíssima. Wake local FSM (sem Porcupine), `JarvisWakeLock` (mutex de mic
anti-"2 vozes"), `JarvisMemory` (slug, supersede, bloco de 4000 chars injetado na voz E no brain),
persona (`assistantName/userName/customPrompt/greetOnConnect`), 11 "leis" (incl. "NUNCA PENSAR PELO
TRABALHO" — até "1+1" vai pra um pane via `perguntar`), `voiceSafeText`, `contextWindowCompression:
slidingWindow` (cortou 12,9M tok/noite), `sessionResumption`, singleton.

**Nexus hoje:** wake ONNX local keyless (UX de mãos-livres melhor), STT Groq→OpenAI→whisper.cpp, TTS
OpenAI→Piper→`say` (funciona com **zero key**), brain Gemini 3.5-flash→gpt-4o-mini→llama-3.3-70b,
ações (open_squad/workspace/design_squad/new_mission/`run_command` **com confirmação obrigatória**/
send_to_pane/none + remember/forget), `jarvis-memory` (slug, supersede, soft-delete, 200 fatos),
`jarvis-fastpath` (queries de estado ~0ms), `jarvis-narrator` (handoff proativo), `echo-suppress`
(match por transcript), `speakable` (código nunca falado), e `jarvis-live` = **máquina de estado
sobre o pipeline batch** (listening/thinking/speaking/interrupted/dormant, grace 90s, dormant 5min) —
**não** é áudio full-duplex WSS.

**O gap real é UM subsistema:** o transporte de áudio realtime. Todo o resto (memória, echo,
fast-path, narração, safe text, persona, disjuntores) o Nexus já tem. É por isso que a conversa
contínua deles "parece melhor" — é o protocolo, não a inteligência.

**Como superar:**
- Adicionar um transporte **Live real** opcional dentro de `jarvis-live.ts`: Gemini Live (mesma API)
  **ou** OpenAI Realtime — escolher por custo/idioma. Manter o pipeline Classic como fallback
  keyless (nossa identidade).
- Portar as alavancas de custo como **requisito de lançamento**, não polish: `slidingWindow`,
  dormant, grace reuse, `pendingMic`, singleton (a evidência deles é 12,9M tok/noite sem isso).
- Tela-como-texto (já temos o context block em `jarvis-brain`), debounced.
- **Superar:** manter fallback offline + `run_command` confirmado ON (eles têm OFF/UI removida) →
  Nexus fica com voz melhor E mais segura E que não morre sem nuvem.
- Persona: garantir os campos `assistantName/userName/customInstructions/wakeWord` no
  `voice-config-store` (a tela deles tem SEU NOME / NOME DO ASSISTENTE / INSTRUÇÕES / WAKE WORD).
- **Esforço:** médio-alto (o transporte é o custo). **Win-condition:** 1ª resposta audível <800ms
  com sessão quente; barge-in <200ms; cai para Classic sem perder a intenção.

### 3.3 Harness / Arsenal — falta a passada de enriquecimento e duas faixas

**Overclock (fatos):** o "Enriquecer (F5)" é o `harnessAssistant` — **duas passadas de LLM**
(`claude-sonnet-5`, effort low, maxTurns 4, sem tools, 60s, JSON-only, arsenal chunked 40 /
concorrência 4):
1. `enrichCatalog` → classifica cada agent/skill em tier (**scout/builder/reviewer**) + blurb ~120
   chars; tier determinístico vence o LLM para os `oc-chef-*` e workers first-party. **Persiste** em
   `harness-enriched-catalog.json`.
2. `proposeRecipes` → lê a "despensa" habilitada (agents/skills/**modelos de mídia**/**LLMs**) e
   propõe 2–4 planos executáveis com estrutura fixa de 3 chefes + activations, marcando `gap` quando
   um item pedido está fora do catálogo.

O MCP lê o catálogo enriquecido **na criação da missão**, então o orquestrador escolhe a skill certa
por tier em runtime. O catálogo modela tipos `agent|skill|mcp|tool|plugin|hook|rule|squad` + rank
(chefe/worker por convenção de nome) + tier + origem (overclock/terceiro, built-in vence duplicata),
e sintetiza `catalog_stacks` (bundles).

**Nexus hoje:** catálogo aitmpl + Marketplace, `catalog-overlay` (stacks/disabled/tombstones/
categoria por workspace), `recipe-overlay` + **recipe-lint** com `gap` explícito, `nexus_recipe_propose`,
`agent-spec-writer`, `stack-detector`. Rastreia agents/skills/MCPs/tools/plugins/hooks/rules/shortcuts.

**Gaps exatos:**
1. **Sem passada de enriquecimento por item** que anote tier + propósito + quando-usar e **persista**
   para consumo em runtime. Temos recipe-lint/propose (nível squad), falta o nível item→enriquecido→
   consumido-na-missão.
2. **Sem faixa MÍDIA** e **sem itens de LLM/CLI** no arsenal (as abas MÍDIA e LLMS·CLIS do print deles).
3. Rank chefe/worker + tier scout/builder/reviewer não expostos como **filtros navegáveis** do arsenal.

**Como superar:**
- Adicionar `src/main/orch/harness-enrich.ts`: passada de LLM (reusar o `jarvis-brain` chain — já
  temos Gemini/OpenAI/Groq) que classifica cada item em tier + blurb + when_to_use, persiste em
  `~/.nexus/harness-enriched.json`, e é lida pelo `squad-architect`/mission-launcher.
- Estender o catálogo/overlay com `kind:'media'` (modelos de mídia do 3.1) e `kind:'llm'` (os
  adapters instalados já existem — só projetar como itens do arsenal).
- UI: filtros RANK (chefe/worker) · TIER (scout/builder/reviewer) · ORIGEM na `CatalogSections`.
- **Superar:** recipe-lint **já é mais rigoroso** que o deles (rejeita ref inexistente sem `gap`
  declarado) — manter e ligar o enriquecimento por cima. E o `agent-spec-writer` já edita frontmatter,
  algo que o harness deles resolve por convenção.
- **Esforço:** médio (a maior parte é glue + UX sobre motor existente).

### 3.4 Modo Agêntico — motor existe, falta o wiring

**Overclock (fatos):** 3º card em "Nova Missão", rotulado **OVERCLOCK HARNESS** — "Descreve o que quer
— a IA monta o time e entrega". Intenção livre → harness monta squad a partir do arsenal enriquecido →
executa. Suportado por `overclock_navigate` (dirige a UI, dispara runs agênticas) + `proposeRecipes` +
maquinaria de squad.

**Nexus hoje:** `MissionWizard` só tem `type Mode = 'libre' | 'squad'` (`MissionWizard.tsx:22`). Mas
`squad-architect.ts::designSquadForWorkspace()` **já** manda o perfil do projeto pra um LLM e recebe
um squad sob medida (papéis derivados da stack, `orchestratorInstructions`, distribuição entre CLIs
instaladas, regras fortes: sempre QA que roda o app, security reviewer quando toca auth/pagamento,
UX designer com mandato anti-"look de IA"). É **mais opinativo** que o harness deles — só que é
disparado pelo *workspace*, não por *intenção livre*, e **salva** o squad sem auto-lançar.

**Como superar:**
- Adicionar `designSquadFromIntent(intent, workspacePath, arsenal)` — variação do arquiteto que recebe
  o texto livre + perfil do workspace + catálogo enriquecido (do 3.3).
- 3º card "Agêntico" no `MissionWizard` → chama a variação → encadeia no `launchSquadMission` (já
  existe).
- **Superar:** o nosso arquiteto já embute QA-que-roda-o-app + security + UX anti-genérico; combinar
  isso com intenção livre entrega um agêntico **mais confiável** que o deles.
- **Esforço:** baixo (UX + 1 prompt sobre motor existente). **Melhor relação ganho/esforço depois de
  Mídia.**

## 4. Gaps adicionais encontrados

- **Cron / squads agendados (ausente):** `cronTickLoop` (60s), `crons.json`, parser cron 5-campos,
  `agentName` XOR `squadId`, skip-if-stale >5min, tools ocultas `overclock_cron_*`. → criar
  `src/main/orch/cron-loop.ts` + `crons.json` + tools `nexus_cron_create/list/delete`. Esforço baixo.
- **Injeção MCP nos CLIs não-Claude (raso no Nexus):** o Overclock escreve config MCP real em Codex
  (`-c mcp_servers.overclock.url`), Gemini (`.gemini/settings.json`) e Antigravity (`mcp_config.json`)
  — logo um worker Codex/Gemini deles **chama as tools de orquestração** e submete handoff. No Nexus,
  só Claude tem `--mcp-config`; codex/gemini/kimi/grok/agy recebem **env var apenas** (consciência por
  prompt, não acesso à tool). → estender `hooks-gen`/`mcp-server` para escrever config MCP por CLI.
  **Gap de profundidade multi-CLI real** — importante porque o Nexus tem *mais* adapters mas
  orquestração efetivamente Claude-cêntrica. Esforço médio.
- **Cliente phone (parcial):** a bridge WSS existe e é mais endurecida que a deles; falta só um thin
  client. P2.

## 5. Onde o Nexus já está à frente — manter e não copiar

1. **Isolamento de processo** — PTY host em `utilityProcess` com re-fork; o sidecar do Overclock é
   monólito único (voz+PTY+bridge+telemetria num processo = SPOF). **Não migrar para Tauri.**
2. **Segredos** — safeStorage/Keychain, nunca-plaintext, 0600. Overclock teve `session.json` de auth
   0644 e `providers.json` plaintext. **Não degradar para plaintext** ao adicionar keys de mídia.
3. **Failover multi-conta** — troca de credencial Claude no Keychain + `--resume` na conta nova. O
   Overclock **não tem** — vantagem grande para quem bate limite. Manter e divulgar.
4. **Roteamento por custo** — `nexus_route_task` + `reserveClaude`. Estender para mídia (3.1).
5. **Voz offline/keyless** — wake ONNX + `say` + whisper.cpp com zero key. Manter como fallback
   sempre; Live é opcional por cima.
6. **Confirmação de `run_command` ON** — o oposto do default deles (OFF, UI removida). Manter ON.
7. **Recipe-lint mais rigoroso** — rejeita ref inexistente sem `gap`. Manter; ligar enriquecimento
   por cima, não substituir.

## 6. Plano de integração priorizado

Ordem por **ganho competitivo ÷ esforço**, começando pelo que cai sobre infra existente.

### P0 — fecha os gaps de maior alavancagem
1. **`media-generation`** — módulo + `media-keys-store` (safeStorage) + tools `nexus_image/video/
   audio_generate` + `nexus_media_providers` + allowlist por squad + output no workspace + wire no

   (vídeo), ElevenLabs (áudio). **Superar:** key no Keychain + custo de mídia no painel + roteamento

2. **Modo Agêntico** — `designSquadFromIntent()` + 3º card no `MissionWizard` + auto-launch via
   `launchSquadMission`. *Baixo esforço, motor pronto.*

### P1 — profundidade competitiva
3. **`harness-enrich`** — passada de LLM (brain chain existente) por item → tier + blurb + when_to_use
   persistido → consumido pelo `squad-architect`/mission-launcher; + faixas MÍDIA e LLMS·CLIS no

7. **Cliente phone** sobre a bridge existente (com confirmação no Mac para escrita).

## 7. O que NÃO copiar

1. Migração para Tauri (nosso isolamento de processo é melhor).
2. Sidecar monolítico (SPOF).
