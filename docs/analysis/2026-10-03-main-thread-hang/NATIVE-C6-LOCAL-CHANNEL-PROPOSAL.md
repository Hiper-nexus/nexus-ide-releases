# Scoped native admission over an existing permitted Unix channel

**Observed boundary.** Real OpenCode 2.0.20 needs `--standalone` to own its server within the pane's inherited environment/sandbox. Its actual shell is zsh with the Nexus spawn's inherited SHELL; the existing hook starts A/B, but direct Main TCP is denied and no proxy is inherited. Under the unchanged SDK policy, an independent control wrote a file in private TMP outside cwd and received an HTTP reply over a Unix socket there (47904, exit 0). Curl's absolute socket pathname exceeded its limit; a relative socket with only the transport child's cwd set to TMP passed. Target cwd stays unchanged.

**Paths and ownership.** Add `src/main/orch/native-heavy-local-channel.ts` and a fixed `resources/heavy-command/local-channel.cjs` transport process. Main creates one random private subdirectory under the already prepared per-pane TMP; no new read/write/network grant. The helper starts with that directory as cwd, binds only the fixed short name `heavy.sock`, and never executes a target. It uses bounded Unix HTTP and a private fork IPC channel back to Main. No Main/global process.chdir, global dropbox, user profile or settings mutation. A narrow pty-manager registration after private TMP is final supplies the exact Main-created AgentGateContext; incoming requests supply no role, scope or permission. OpenCode 2 argv isolation is a separate F-891 milestone, gated by asynchronous/cached version proof; OpenCode 1 keeps its existing argv.

**Protocol.** `request.cjs` receives Main-reasserted channel directory, request nonce and Ed25519 public key through scoped env. Main retains the request key/private signing key only in memory. A request has a random UUID, timestamp, the existing bounded native admission body (pid/kind/proof/optional lease), and HMAC over those fields. The transport caps body/reply at 2 KiB, active clients and request deadlines; it correlates socket and Main IPC by UUID. Main calls the existing `nativeHeavyCommands.admit(ctx, body, signal)`; Host must authenticate live A+B/signature/image/ancestry and register A's observation before any grant/target. Main signs schema/UUID/body digest/context epoch/result; the client verifies the Main signature before returning a lease. A replaced socket or forged/replayed response cannot grant work. No bearer/account token or signing key is written to disk, sent in argv or logged. Remote URLs remain rejected. No release endpoint is added.

**Cancellation and drain.** Client/socket close sends a correlated Main cancellation and aborts the existing admission. Gate revocation/epoch change and stopAdmission deny fresh/late grants. The transport remains alive through native physical drain; only the canonical whole-cohort observation releases an active permit. Main then closes the transport, waits its actual exit, removes only its owned socket/directory, and reports cleanup failure for retry rather than manufacturing success. Main/IPC owner death closes the byte transport; it never claims to prove target exit. Existing A/B owner and whole-PTY termination remain responsible for process teardown; A loss remains explicit unknown/failure.

**Review and proof before integration.** Test tampered nonce/context/signature/digest, replay, remote URL, disconnect during RAM wait, late response after epoch/stop, descriptor/long-path handling, cleanup failure/retry, helper death, and unchanged human shell env. Repeat actual OpenCode baseline and scheduled Make with the same standalone private server and SDK policy, target marker absent before signed grant, original output/exit/cwd/env retained, and physical release. Claude/Grok/Kimi controls must stay green. No candidate-signed proof is inferred from these source controls.
