# F-875: native admission inside the existing Claude inner sandbox

The valid baseline and scheduled control both use the real Claude Code 2.1.289 CLI under the Nexus supervisor, with a private synthetic HOME, an offline loopback provider gateway, the same cwd/stdio/argv and `sandbox.enabled=true`. Neither case adds an outer Seatbelt or changes allowedDomains. Make writes its in-workspace marker in both; a write to an independent fixture outside the workspace is denied in both.

Two existing boundaries caused the previous failures. The original nested stage zero receives PT_TRACE_ME errno 1 (EPERM) inside the inner sandbox, before target birth. After an exclusive untraced job launcher, curl tried Main directly because its transport discarded the proxy. Even inherited proxy env alone chooses direct loopback: the CLI's NO_PROXY contains 127.0.0.1. Routing the admission request explicitly through the inherited authenticated HTTP loopback proxy works under the unchanged policy.

The fixed source is limited to `nestedHeavyJobBaseCommand`: its SIP Apple Perl controller preserves taint/env cleanup and process ownership, but omits the nested pre-exec trace barrier. Before any target is spawned, the external Host observer must validate the live image/mode/signature/uniqueID/idversion of A and B, their exact responsibility/parent relationship, and install A's kqueue observation. Provider qualification, the general supervisor and the external observer keep their original two-exec authentication barriers. This mode-specific tradeoff remains subject to independent review.

`request.cjs` selects only an inherited HTTP proxy on localhost/127.0.0.1/::1 with a port, no query/hash or control characters in credentials. A remote/HTTPS/invalid proxy is rejected before any bearer egress. Curl configuration, Main bearer and existing proxy auth travel on stdin; configuration and credentials never enter argv, files or logs. No redirect follows. When an inherited proxy exists, its refusal/407 denies admission and never falls back to a direct connection, including with NO_PROXY=`*`. No new filesystem broker or account transport was introduced.

Local evidence: proxy tests first failed 6/6 against the old transport and then passed 6/6; real Claude controls passed 3/3, and the original traced-launcher negative independently confirmed EPERM with no admission/target. The general/observer barrier regression passed. The focused union passed 121 tests in 7 suites, including native cohort/kill/owner controls; full TypeScript check passed. Native fixtures build an ad-hoc universal helper; these tests do not constitute the final signed/notarized candidate proof.

The result closes the concrete Claude inner transport failure. Full C6 still requires Root's boot integration and independent review, plus faithful native adapter controls. A separate Grok control found a Bash wrapper evaluating the actual command from $1 after restoring an FD3 snapshot. That follow-up now rechecks positional args before Bash's first command and preserves only the caller's already-existing FD3 pipe/socket, observed in Bash before Node initializes its own descriptors. Real Grok and a standalone native fixture verify the physical job grant, snapshot function, $0/argv and whole-cohort release. This does not extrapolate native compatibility to other installed CLIs.
