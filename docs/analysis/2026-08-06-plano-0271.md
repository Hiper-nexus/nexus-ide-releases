## F1 — Hook com a forma certa, instalado em TODO CLI

### O gap, medido (não inferido)

`hooks-gen.ts:19-60` (`HOOK_SCRIPT`) hoje:
- **síncrono**: `await fetch` inline; o CLI espera a rede terminar;
- **fail-closed em QUATRO pontos**: sem credencial → `exit 2`; stdin não-JSON →
  `exit 2`; `allow===false` → `exit 2`; gate inalcançável → `exit 2`;
- **mesmo script para todos os eventos** (`process.argv[2]`), então `stop`
  herda a postura de `pretool`.

Overclock (`handoff-deliver.mjs:400-430`, `handoff-stop.mjs:497-520`):
- **pai**: lê stdin → grava payload em arquivo → `spawn(detached)` de si mesmo
  (`OVERCLOCK_*_CHILD=1`) → `child.unref()` → **`exit 0` em ms**;
- **neto**: faz TODA a rede, falha em silêncio;
- **fail-open** no `stop`;
- falha do auto-handoff vira **nag DIFERIDO** (`handoff-fail-<pane>`), lido pelo
  Stop seguinte a custo de um `existsSync`, com **cap de 2** para nunca virar
  loop.

### A distinção que NÃO pode ser perdida

> Desacoplar e virar fail-open vale **só para `stop`**. `pretool` continua
> **síncrono e fail-closed** — ali bloquear com o gate fora do ar é o
> comportamento CORRETO (é gate de segurança de tool call, não de entrega).

É exatamente o que `0fe423aa` já havia especificado: *"fail-open apenas no
evento `stop`, nunca em `pretool`"*. Copiar a forma inteira sem essa distinção
transformaria o skill-gate num convite.

### Passos

1. `HOOK_SCRIPT` ganha dois modos por evento:
   - `pretool` → caminho atual, intacto (síncrono, fail-closed);
   - `stop` → pai grava payload + relança detached + `exit 0`; neto faz a rede;
     qualquer falha → silêncio + `handoff-fail-<sessão>`.
2. Nag diferido com cap 2 (portado verbatim; citar as medições datadas).
3. Instalar no **caminho de HOME real** (`writeClaudeFamilyZeroClickSettings`,
   `hooks-gen.ts:186-203`), fechando o furo do `operator-choice`.
4. Estender a **todo CLI** que aceita hook — é onde superamos o Overclock, cujo
   hook é preso ao Claude Code.
5. `worker-handoff-enforcement` (`b9739896`) **permanece** como cinto do
   suspensório: cobre quem não tem hook nenhum.

### Testes
- pai retorna em <50ms e `exit 0` mesmo com endpoint morto;
- `stop` com gate fora do ar **não** bloqueia (fail-open);
- `pretool` com gate fora do ar **bloqueia** (fail-closed preservado);
- nag dispara no Stop seguinte e para após 2.

## F2 — Encher o socket vazio: `ownershipFiles` nos templates

### O gap, medido

`wave-pack-templates.ts`: `landing`/`saas`/`fix`, stories
`{id, epicStoryId, title, body}` — **zero `ownershipFiles`**.
`mission-wave-pack.ts:466-470`:
```ts
const allStoriesDeclareFiles = input.stories.every(
  (story) => (story.ownershipFiles?.length ?? 0) > 0,
);
```
**Confirmado: é tudo-ou-nada.** UMA story sem arquivos ⇒ `false` ⇒ **todas**
recebem `input.ownershipFiles` (inventário compartilhado) e **nenhuma** recebe
`WAVE_PACK_DISJOINT_FILES_DOMAIN` ⇒ o leque inteiro colapsa.

### Passos

1. `WavePackTemplateStory` ganha `ownershipFiles: readonly string[]`.
2. Preencher os 3 templates com fatias disjuntas, no espírito do Overclock
   (1 unidade por tela/fonte/superfície):
   - `saas` → `auth ∥ dados ∥ billing` (o exemplo literal deles);
   - `landing` → uma story por seção/superfície;
   - `fix` → mantém 1 unidade quando o conserto é single-writer (honesto).
3. **Amolecer o colapso** (pedido explícito): decisão **por story**, não global.
   - story COM arquivos → seus arquivos + domínio disjunto (entra no leque);
   - story SEM arquivos → inventário compartilhado + `sequential-only`
     (slot exclusivo: pode tocar qualquer coisa, então não divide onda com
     escritor declarado).
   Resultado: uma incógnita **serializa atrás**, não afunda o leque.
4. Provar no spike: objetivo templated abre **N>2** workers concorrentes,
   medido no `runtime.sqlite3`, nunca na UI.

### Segurança preservada
Story sem declaração continua sem poder provar disjunção — e continua tratada
como tal. O que muda é o **escopo do castigo**: dela, não de todas.
