# F-815 — Git síncrono no hook de integração bloqueia o Main

## F-815 | categoria: performance | severidade: alta | status: corrigido
- Tela/fluxo: `/hook/integration` executado por comandos Bash dos panes de missão.
- Arquivo: `src/main/orch/hook-integration-endpoint.ts` e `integration-review-gate.ts`.
- Passos: enviar `git merge --ff-only origin/main`, ou merge/push que exige revisão, pelo hook.
- Esperado: checagens Git assíncronas, com timeout por chamada e orçamento total; o Main continua atendendo terminais/IPC.
- Observado: a isenção de fast-forward do F-778 fazia aproximadamente nove processos Git síncronos por comando.
- Evidencia: testes instrumentam `spawnSync`/`execFileSync`/`execSync` e o runner assíncrono real no bloco F-815 de `hook-integration-endpoint.test.ts`; snapshot integrado `d4424369`. Registro documental original ausente, recuperado sem renumerar a ocorrência.
- (resolvedor) Correcao: `AsyncProcessGitRunner`, configurações locais seguras, timeout de até 5000 ms por chamada e orçamento de 8000 ms por requisição. A decisão autoritativa de revisão continua no Main; falha de infraestrutura do hook não concede aprovação.
- Validação atual: `n4-and-documentation-final.log`, 291 testes/11 suítes aprovados, incluindo endpoint e portão assíncrono; typecheck, renderer sinks (0) e ratchet de processos síncronos passaram. O limite mede espera do subprocesso; não declara bloqueio síncrono de 8 segundos.
