# F-1208 — OCR (tesseract) não carregava no app empacotado: dependências do worker ficavam presas no app.asar

## F-1208 | categoria: funcional | severidade: alta | status: corrigido
- Tela/fluxo: Jarvis Vision / OCR (`ocrImage`, `recognizeLinesWithBoxes` em `src/main/vision/ocr.ts`).
- Arquivo:linha (antes): `forge.config.ts:519` (`asar.unpack`); `src/main/vision/ocr.ts:51-58` (`resolveTesseractWorkerPath` troca `app.asar` por `app.asar.unpacked`).
- Passos: no app empacotado (0.76.234), pedir OCR de uma captura.
- Esperado: o worker do tesseract sobe e reconhece o texto.
- Observado: o worker morre ao carregar com `Cannot find module 'regenerator-runtime/runtime'`.
- Causa: o worker roda de `Resources/app.asar.unpacked/node_modules/tesseract.js/src/worker-script/node/index.js`. A busca de módulos do Node a partir dali sobe por `app.asar.unpacked/node_modules` e `Resources/node_modules`, nunca por dentro do `app.asar` (o Electron só filtra caminhos fora de `resourcesPath`). O glob de unpack levava `tesseract.js`, `tesseract.js-core` e `wasm-feature-detect`, mas não `regenerator-runtime` (`worker-script/index.js:12`), `is-url` (`:13`) nem `bmp-js` (`utils/setImage.js:3`). Os testes rodam o worker do `node_modules` do repo, onde tudo é arquivo real, e o smoke empacotado só confere a existência do `index.js` do worker.
- Evidencia: header do `app.asar` instalado lista `/node_modules/regenerator-runtime/package.json`, `/node_modules/is-url/package.json` e `/node_modules/bmp-js/package.json` (empacotados); `app.asar.unpacked/node_modules` só tem `@ennuicastr @lydell @napi-rs better-sqlite3 cpu-features fs-xattr macos-alias onnxruntime-node shiki ssh2 tesseract.js tesseract.js-core wasm-feature-detect zod`. Uma cópia do `app.asar.unpacked` REAL da 0.76.234, fora de qualquer `node_modules`, iniciando o worker pelo mesmo caminho: `WORKER_ERROR MODULE_NOT_FOUND Cannot find module 'regenerator-runtime/runtime'`.
- (resolvedor) Correcao: `asar.unpack` passa a incluir `regenerator-runtime/**`, `is-url/**` e `bmp-js/**` (o `node-fetch` só é exigido sem `fetch` global, que o worker do Electron tem).
- Validacao: teste novo `src/main/vision/ocr-packaged-worker.test.ts`. Ele monta o `app.asar.unpacked/node_modules` com o matcher do próprio `@electron/asar` (`minimatch(..., unpack, { matchBase: true })`) sobre o fecho de dependências do `tesseract.js`, sobe o worker pelo caminho que o `ocr.ts` usa e manda `load`. Com o glob anterior falha com o mesmo `MODULE_NOT_FOUND` do app; com a correção o core sobe (`{ loaded: true }`). `forge.config.test.ts` e `scripts/smoke-packaged-app.test.mjs` seguem verdes.
- Limite: a prova de ponta a ponta (OCR de uma captura real no `.app` assinado) depende de um build empacotado novo.
