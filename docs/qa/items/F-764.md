# F-764 (visual) — Campo de cupom do Pro usa `--surface`, token que não existe, e o teste de tokens do CSS falha no main

## F-764 | categoria: visual | severidade: baixa | status: corrigido
- Tela/fluxo: Pro, escolha de período e campo de cupom de desconto (`.checkout-choices__coupon input`).
- Arquivo:linha: `src/renderer/styles/home-billing.css:572`.
- Passos: `npx vitest run src/renderer/styles/css-tokens.test.ts` no `main` depois de d24073cb ("Períodos trimestral, semestral e anual e cupons de desconto no Pro").
- Esperado: todo `var()` sem valor de reserva aponta para um token definido.
- Observado: `AssertionError: expected [ 'home-billing.css: --surface' ] to deeply equal []`. Sem o token, o `background` do campo vira inválido e o campo fica sem fundo próprio.
- Causa: o commit d24073cb escreveu `var(--surface)`; os tokens do design system são `--surface-0..3`, `--bg` e `--bg-elevated` (`DESIGN.md`).
- (resolvedor) Correcao: `background: var(--bg)`, o mesmo do `.settings-input` (`settings-controls.css`), que é o campo de texto padrão do app e dos outros campos desta tela. Teste: `css-tokens.test.ts` passa.
- Como foi achado: o CI local em Docker (`scripts/ci-local-docker.sh`) falhou neste teste no commit bd5bdb37. O Actions estava bloqueado por orçamento, então nenhum run do `main` o tinha acusado. Falta ver o campo a olho num app instalado.
