# F-629 — Modal "Chaves Não Encontradas" vindo de dentro dos panes (conta Claude gerenciada)

## F-629 | categoria: funcional | severidade: alta | status: corrigido

- Tela/fluxo: pane Claude de conta gerenciada (multi-conta, F-153) aberto pela
  mão do operador. Aparece em todo Mac que usa mais de uma conta Claude.
- Observado: modal do sistema "Chaves Não Encontradas — Não foi possível
  encontrar as chaves para armazenar '<x>'" com `Cancelar` /
  `Reajustar Para Padrões`. Contas vistas em 22/09: `cleofasvolarehost`
  (gh/git) e `4d6036….EOxaH1L9QA` (`com.alibaba.pc.sgsdk`); em 16/09,
  `cleofasrocha` (= `$USER`, item do próprio Claude Code).
  "Reajustar Para Padrões" pode apagar o keychain do operador.
- Causa: o pane roda com `HOME=~/.nexus/ephemeral/<tok>`. O macOS resolve o
  keychain padrão a partir do `$HOME` do processo. O F-575 linka
  `Library/Keychains` só para a conta NATIVA (`carryNativeClaudeAuth`), que é
  zerada quando há `managedClaudeAuthDir`. A conta gerenciada recebe o HOME
  inteiro do operador (tier 2 do F-579, que exclui `Library`) e fica sem
  keychain. Qualquer escrita no keychain dentro do pane abre o modal: refresh
  OAuth do Claude, gh migrando token, git osxkeychain ou SDKs de terceiros.
- Por que os fixes anteriores não resolveram: `a69e2d47`, `bece5740`,
  `0a88ba07` e `a1184cad` tratam o cofre do MAIN (`safeStorage`). Este modal
  vem dos processos filhos do pane.
- Correção (`hooks-gen.ts` `prepareEphemeralHome`): o link dos
  `*.keychain-db` vale para Claude primeiro-parte não gated, tanto a conta
  nativa quanto a gerenciada. Isso é seguro para a gerenciada: o binário
  2.1.280 (função `RD`) usa, com `CLAUDE_SECURESTORAGE_CONFIG_DIR`, o serviço
  `Claude Code-credentials-<sha256(dir)[:8]>`, o mesmo de
  `managedClaudeKeychainService`, e nunca lê o item nativo. O marcador de
  sync-back e a identidade nativa continuam fora da conta gerenciada.
- Limites mantidos: gated (env token) e terceiros (GLM/LongCat) seguem sem
  keychain. Nessas lanes o modal ainda pode aparecer se git/gh gravarem.
  Esse é o próximo passo, que muda a política de segurança e pede decisão.
- Evidência RED→GREEN: um teste novo em `hooks-gen.claude-auth.test.ts`
  (falha sem a correção e passa com ela). Os testes focados de hooks-gen,
  spawn-home-policy e governed-profile passam (114/114), e o typecheck está
  limpo.
- Vale para panes abertos DEPOIS do rebuild. Os panes vivos precisam ser
  reabertos.
