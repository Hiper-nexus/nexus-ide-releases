# F-1156 — Gateway do exercício de runtime lia a instrução errada após uma entrega de handoff

## F-1156 | categoria: funcional | severidade: alta | status: corrigido
- Tela/fluxo: exercício de runtime canônico (`scripts/smoke-packaged-runtime-gates.mjs`), passo de recuperação do worker.
- Arquivo:linha: `scripts/runtime-gateway.mjs` (seleção de `kind`).
- Passos: o exercício encerra o writer; o Nexus entrega ao líder o handoff "failed" mecânico, que cita a última tela do pane (com o prompt `RT_GATE IDLE …`); depois o exercício envia `RT_GATE RECOVER …` como mensagem separada.
- Esperado: o gateway trata o `RECOVER` como a instrução corrente e emite `nexus_pane_spawn({ resume })`.
- Observado: o gateway escolhia o último marcador de uma concatenação que põe blocos de texto (a mensagem mais nova chega em forma de array) antes das strings antigas; o `IDLE` citado na colagem vencia e ele respondia `RT_DONE_IDLE`, sem recuperação. Determinístico quando a entrega e o `RECOVER` chegam separados (na 0.76.225 chegavam fundidos). Provado com proxy de log transparente e com os transcritos da CLI.
- Evidencia: `mac227-runtime-2`, `mac227-runtime-diag-3` (proxy), `runtime231-f1156-gateway-instruction-red.log`.
- (resolvedor) Correcao: a instrução é o último `RT_GATE` em ordem de conversa entre os textos do próprio usuário; colagens entregues pelo Nexus (`<pasted_content …>…</pasted_content …>`) nunca são instrução, nem no fallback. Nenhum critério, prazo ou asserção do exercício mudou.
- Validação: `scripts/runtime-gateway.test.mjs` (forma real separada, forma fundida da 0.76.225, entrega sozinha) com RED; suítes do gateway 101/101.
