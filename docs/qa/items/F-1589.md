# F-1589 — Serviços de mídia e Estúdio de Mídia quebram sem projeto aberto

## F-1589 | categoria: funcional | severidade: media | status: corrigido

- Tela/fluxo: Ajustes → Serviços de mídia (`MediaSection`) e o Estúdio de Mídia (`MediaStudioPanel`), abertos sem projeto (tela inicial, projeto fechado ou removido da barra).
- Arquivo:linha (antes): `src/main/media/media-ipc.ts:105-110` (`media:usageTotals`), `:118` (`media:generate`), `:211-216` (`media:listArtifacts`), `:221`/`:233` (revelar e ler prévia) — todos chamavam `requireRendererWorkspaceScope`, que lança `renderer has no authorized workspace scope` sem projeto; `src/renderer/components/settings/MediaSection.tsx:137-143` (`Promise.all` de serviços + totais); `src/renderer/components/MediaStudioPanel.tsx:147-161` (`Promise.all` de serviços + galeria, sem `catch`).
- Passos: 1) Abrir o app sem projeto. 2) Ajustes → Serviços de mídia. 3) Clicar em "Abrir Estúdio de Mídia".
- Esperado: conectar a chave de um serviço não depende de projeto (chaves e provedores são globais, no cofre); o Estúdio diz que precisa de um projeto para salvar o que gera.
- Observado: Serviços de mídia mostrava só "Não foi possível carregar os serviços de mídia." (a leitura dos totais lançava e derrubava a lista inteira): sem projeto não dava para conectar chave nenhuma. O Estúdio abria com o seletor de modelo vazio e o botão Gerar apagado, sem explicação; a promessa rejeitada ficava sem tratamento. O estado vazio do Estúdio mandava para "Ajustes → Mídia" e "Configurar API key" — a tela se chama "Serviços de mídia".
- Causa raiz: totais, galeria e geração são do projeto (gravam em `.nexus/media` e no banco do checkout), mas a tela juntava essa leitura com a lista global de serviços numa só promessa, e o Main lançava a recusa crua de escopo em vez de dizer "sem projeto".
- (resolvedor) Correcao:
  - Main (`media-ipc.ts`): sem escopo de projeto, `media:usageTotals` e `media:listArtifacts` devolvem `null`; `media:generate`, `media:revealArtifact` e `media:readArtifactDataUrl` devolvem `{ ok: false, error: MEDIA_NO_PROJECT_ERROR }` sem tocar o motor nem o disco. A frase vive em `src/shared/media-types.ts`. Nada de outro projeto vaza: a resposta só existe para o escopo do próprio remetente, como antes. Tipos do preload em `src/shared/types.ts`.
  - Serviços de mídia: a lista de serviços é lida sozinha e os totais são opcionais (`null` ou falha não derrubam a tela).
  - Estúdio: serviços e galeria lidos separadamente; sem projeto, aviso fixo "Abra um projeto para gerar: as imagens e os vídeos são salvos na pasta do projeto aberto.", Gerar desabilitado e a galeria explica que as criações ficam na pasta de cada projeto; falha ao ler serviços vira aviso, não formulário mudo. Estado vazio: "Nenhum serviço de imagem conectado… Ajustes → Serviços de mídia", botão "Conectar serviço de mídia"; o grupo sem chave diz "sem chave (Serviços de mídia)".
- Evidencia/validacao:
  - RED no código antigo: `MediaSection.test.tsx` › "F-1589: sem projeto aberto os serviços continuam na tela…" falhou (a tela caía no erro); `MediaStudioPanel.test.tsx` › "mostra os serviços, explica que falta o projeto…" e "a galeria falhar não esconde os serviços" falharam (e o teste do estado vazio, pela cópia nova).
  - GREEN: `npx vitest run src/renderer/components/settings/MediaSection.test.tsx src/renderer/components/MediaStudioPanel.test.tsx src/main/media/media-ipc.test.ts` (`media-ipc.test.ts`: totais `null` sem projeto e sem vazar outro projeto; galeria `null`; revelar/ler e gerar sem projeto devolvem a frase e não chamam o motor nem o Explorador).
- Limite: não vi no app empacotado. Mensagens de erro do motor ("configure em Settings → Mídia") são tratadas no F-1584.
