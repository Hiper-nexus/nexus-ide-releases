# F-772 — Skill do Jev sugerida para todo papel e todo CLI; "auditoria" virava bug

## F-772 | categoria: funcional | severidade: media | status: corrigido
- Tela/fluxo: sugestão de skill do Jev no delegate (bundle + projeto) e classificação heurística `classifyWorkKind`.
- Arquivo:linha: `src/main/orch/jev-skill-suggestion.ts` (~305: catálogo inteiro ia ao Jev), `src/main/orch/jev-task-routing.ts` (~105: critério de especialidade), `src/shared/mission-work-kind.ts` (`collectSignals`), `src/main/orch/hook-delegate-endpoint.ts`, `src/main/orch/tools-domain.ts`.
- Passos: a) Observar as sugestões de skill numa missão com papéis e CLIs mistos. b) Pedir "auditoria de uso das contas — aponte erros e desperdícios" e conferir a especialidade.
- Esperado: a) catálogo filtrado pelo papel da tarefa (read-only → scout/conveyor; writer → builder/debugging) e pela superfície de skills do CLI roteado; b) auditoria/inventário = general, bug só com defeito relatado/ordem de reparo.
- Observado (evidência da missão): `oc-scout` saiu para TODAS as 20 tarefas sugeridas em 14 dias (confiança até 0,95) e um writer Codex recebeu `systematic-debugging`, skill que a sessão dele não tinha. "Auditoria de uso" classificava `bug` por mencionar "erros" — o achado esperado de um inventário não é um defeito a consertar.
- Evidencia: `npx vitest run src/main/orch/jev-skill-suggestion.test.ts src/shared/mission-work-kind.test.ts` — 40 testes no primeiro arquivo + 2 novos casos de escopo de auditoria; todos verdes (os casos novos falham no código base por construção: as funções `skillCatalogForTaskRole`/`cliSupportsSkillSurface` e o gate de auditoria não existiam).
- (resolvedor) Correcao: a causa era o catálogo completo ir ao Jev sem contexto de papel nem de CLI, e o classificador tratar qualquer substantivo de defeito como sinal de bug. (a) `skillCatalogForTaskRole` remove as skills de investigação de tasks writer e as de escrita de tasks consult; `cliSupportsSkillSurface` só pergunta ao Jev quando o CLI alvo recebe skills (claude-family + codex/agy/kimi/grok/opencode/mimo-code/qwen via `cliSkillDirs`/layout claude; builtin sem superfície → null sem consultar; adapter desconhecido/custom → fail-open, sugere). `hook-delegate-endpoint` passa o provider do pane; `tools-domain` pós-filtra a sugestão pelo adapter roteado. (b) `REPAIR_VERB` + `AUDIT_SCOPE` em `collectSignals`: defeito + verbo de reparo continua bug forte; defeito dentro de escopo de auditoria/inventário sem reparo é suprimido; "audit log/trail" é artefato e não dispara o escopo. Critério explícito adicionado à pergunta de especialidade do Jev. Arquivos: `src/main/orch/jev-skill-suggestion.ts(.test.ts)`, `src/shared/mission-work-kind.ts(.test.ts)`, `src/main/orch/jev-task-routing.ts`, `src/main/orch/hook-delegate-endpoint.ts`, `src/main/orch/tools-domain.ts`. Validação: vizinhos verdes + `npm run typecheck` limpo.
- Como foi achado: lacuna G7 da auditoria de roteamento (sugestões 20/20 = oc-scout; skill inexistente na sessão Codex; "auditoria de uso" → bug).
