# F-1507 — Windows: sonda do Kimi e descoberta de modelos quebram com espaço no caminho

## F-1507 | categoria: funcional | severidade: alta | status: corrigido
- Renumerado na integração com a origin (0.76.252): este achado era o F-1453 da frente de squads (nunca publicado) e virou F-1507 para não colidir com a numeração que a origin publicou (F-1436..F-1451).
- Tela/fluxo: assento do Kimi numa missão/squad → `pty/pre-spawn-probe.ts` (~311-336) → `refreshKimiSeatReadiness` (`src/main/adapters/kimi-seat-probe.ts`); "Atualizar modelos" e descoberta viva → `execDiscovery` (`src/main/adapters/model-discovery.ts`).
- Arquivo:linha: `src/main/adapters/kimi-seat-probe.ts:30-40` e `src/main/adapters/model-discovery.ts:455-466` (antes) — `execFile(binPath, args, { shell: true })` no win32.
- Passos: 1) Windows com usuário que tem espaço no nome (npm em `C:\Users\Ana Maria\AppData\Roaming\npm`). 2) Kimi instalado pelo npm e logado. 3) Usar um squad com assento Kimi.
- Esperado: a sonda `kimi provider list --json` lê `source=oauth` e o Kimi assume o assento; a descoberta lista os modelos da CLI.
- Observado: o cmd.exe recebia `C:\Users\Ana Maria\…\kimi.cmd provider list --json` sem aspas e procurava `C:\Users\Ana`; a sonda saía com erro (não ENOENT) → `unreadable` → `[missing-credential] kimi: rode \`kimi login\`` ou troca de assento em silêncio. A descoberta viva marcava a listagem como falha.
- Causa raiz: com `shell: true` o Node junta arquivo e argv com espaço, SEM aspas, e passa a linha ao `cmd.exe /d /s /c "…"`. Qualquer caminho com espaço quebra.
- Correcao: novo `windowsCliProbeLaunch` em `windows-npm-shim.ts`, reaproveitando o lançador verificado do F-668 (`windowsNpmShimSpawn`): atalho do npm verificado → `node.exe` + entrypoint do pacote, sem cmd.exe; `.cmd`/`.bat` não verificado ou nome nu → cmd.exe com o caminho sempre entre aspas e o argv citado por `quoteWindowsArg` (`pty/windows-command-line.ts`), `windowsVerbatimArguments`; `.exe` → direto. A sonda do Kimi e a descoberta de modelos usam o helper; nenhum `shell: true` sobra nos dois. POSIX inalterado. Commit: ver `git log --grep F-1507`.
- Evidencia:
  - RED (código antigo): `kimi-seat-probe.test.ts` "caminho com espaço no Windows (F-1507)" → `expected 'unreadable' to be 'present'` nos dois casos (atalho npm verificado e `.cmd` solto, ambos em `…\Ana Maria\npm\`); `model-discovery.test.ts` "F-1507" → `status: 'failed', models: []` em vez de `ok` com `opencode/fake-model`.
  - GREEN: `npx vitest run src/main/adapters/kimi-seat-probe.test.ts src/main/adapters/model-discovery.test.ts src/main/adapters/windows-npm-shim.test.ts` → 28 passaram, 2 pulados (só POSIX); `model-discovery-mimo.test.ts` → 1/1.
