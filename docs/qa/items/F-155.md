# F-155 — MCP não oferece criação de PR no checkout do operador

## F-155 | categoria: funcional | severidade: media | status: corrigido
- Tela/fluxo: pane do operador → ferramentas MCP de GitHub, sem missão/worktree.
- Arquivo:linha: `src/main/orch/tools-pr.ts:66`.
- Passos: 1) Abrir pane do operador num checkout comum. 2) Pedir criação de PR de uma branch publicada. 3) Consultar ferramentas `nexus_pr_*`.
- Esperado: criar PR com título, descrição, head/base e draft sem exigir worktree ou missão; credencial GitHub válida continua obrigatória.
- Observado: catálogo oferecia somente inspect/enqueue/auto_merge, sem ferramenta de criação.
- Evidencia: RED em `tools-pr.test.ts`: criação ausente no catálogo, schema ausente e classe de efeito genérica (22 falhas antes da implementação). Regressão Unicode também reproduzida antes do ajuste do schema.
- (resolvedor) Correcao: adicionada `nexus_pr_create` via provider GitHub existente, com `create-review` explícito, schema estrito, root do escopo e checkpoint de autoridade. Operador usa a política vibe existente; worker sem missão, token read-only e writer isolado permanecem bloqueados. Restrição a origin GitHub.com impede envio da credencial a outra forge. Não há push automático. Ausência/expiração de credencial retorna `auth_needed` com instrução de autenticação nesta máquina. Refnames Unicode são aceitos; refs inválidas são recusadas. Corpo segue como JSON literal, sem shell. Exceções de transporte não expõem headers/segredos e orientam inspecionar antes de repetir.
- Validacao (2026-09-21): 229 testes passaram em 8 suites: `tools-pr`, `mcp-args-validation`, `mcp-effect-policy`, `mcp-dispatch-security`, `gate`, `tools-git-isolated-writer`, `forge-provider`, `forge-registry`. `npm run typecheck` passou. `npm run security:renderer-sinks`: 0 executable DOM sinks. `git diff --check` passou nos arquivos alterados.
- Limite: validado com transporte HTTP controlado; nenhum PR real criado nem branch publicada. O app instalado precisa receber build/restart para expor a ferramenta nova. Head deve estar publicado no origin; forks e GitHub Enterprise ficam fora deste contrato.

- Revisao de credencial (2026-09-21): fallback `getGithubToken` agora fixa `gh auth token --hostname github.com`; `GH_HOST`/host padrão Enterprise não pode selecionar token destinado a outro host. Contrato `glab auth token` preservado. Três regressões falharam em RED antes da correção; testes usam somente credenciais fictícias e subprocesso mockado.
- Validacao adicional: 40 testes passaram em `token-vault.test.ts`, `tools-pr.test.ts` e `forge-token-resolver.test.ts`; typecheck global e renderer sinks passaram novamente após a correção. Nenhuma credencial real consultada.
