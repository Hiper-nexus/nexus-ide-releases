# F-587 — Padrão de 1M de janela de contexto e compactação segura para LLMs de grande contexto (Codex)

## F-587 | categoria: provider-compat | severidade: media | status: corrigido
- Tela/fluxo: Spawning de Panes Codex / Sessões Isoladas / Squads / Helpers de Missão
- Arquivo:linha: `src/main/orch/cli-mcp-session-codex.ts:485`, `src/main/orch/cli-mcp-session-codex.ts:668`, `src/main/orch/cli-mcp-session-config.test.ts:358`, `src/main/orch/cli-mcp-session-config.test.ts:874`
- Passos:
  1) O operador abria um pane de agente ou iniciava uma missão/squad utilizando o Codex com modelos de fronteira que suportam janelas de 1M (como `gpt-5.6-sol`, `gpt-5.6-luna`, etc.).
  2) Por padrão de fábrica da OpenAI, o binário do Codex impõe um limite conservador de 256.000 tokens (`model_context_window = 256000`), compactando as conversas precocemente e exigindo edição manual do `config.toml` pelo usuário fora do Nexus.
  3) Nos ambientes isolados do Nexus (governed sessions, squads e overlays de missão), o Nexus gerava um `config.toml` limpo sem explicitar `model_context_window`, fazendo o Codex regredir ao padrão de 256k mesmo quando o usuário já havia configurado 1M em seu perfil nativo.
- Esperado:
  1) Todo pane do Codex gerado pelo Nexus (seja em squad, missão de operador ou helper isolado) deve ter como padrão a janela de contexto de 1.000.000 de tokens (`model_context_window = 1000000`) e limite de compactação automática elevado (`model_auto_compact_token_limit = 950000`).
  2) Caso o usuário já declare um valor ainda maior em sua configuração nativa (ex.: 2M), o Nexus deve preservar o valor maior; caso contrário, eleva o teto conservador de 256k para 1M.
- Observado:
  - Omissão de `model_context_window` no `config.toml` dos overlays privados gerados pelo Nexus, forçando o limite conservador de 256k.
- Evidencia:
  - `src/main/orch/cli-mcp-session-codex.test.ts` (aprovado).
  - `src/main/orch/cli-mcp-session-config.test.ts` (26 testes aprovados, incluindo elevação de 256k para 1M).
  - `npm run typecheck` (0 erros).
  - `npm run security:renderer-sinks` (0 sinks).
- (resolvedor) Correcao:
  - `prepareCodexGovernedSession`: configurado explicitamente `model_context_window: 1_000_000` e `model_auto_compact_token_limit: 950_000` no `config.toml` imutável.
  - `prepareCodexOperatorMissionHome`: leitura do `userConfig` com piso garantido de 1.000.000 para `model_context_window` (elevando automaticamente o valor padrão de 256k para 1M) e 950.000 para `model_auto_compact_token_limit`.
