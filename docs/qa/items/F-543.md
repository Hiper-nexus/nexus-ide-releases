# F-543 — Instaladores de CLI misturavam comandos entre sistemas operacionais

## F-543 | categoria: build | severidade: alta | status: verificado
- Tela/fluxo: Configurações → Providers → instalar CLI e matriz de release do Electron Forge.
- Arquivo:linha: `src/main/adapters/cli-install-recipes.ts:1`, `src/main/persistence/provider-config-store.ts:1080`, `forge.config.ts:464`
- Passos: 1) Abrir Providers no Windows. 2) Tentar instalar Antigravity ou Devin. 3) Observar o comando exibido/executado.
- Esperado: Cada SO usa seu canal oficial: PowerShell no Windows, bash/Homebrew somente no macOS/Linux; cada release produz apenas o maker nativo do alvo.
- Observado: O Windows recebia `curl ...install.sh | bash`/Homebrew e falhava com `bash: CommandNotFoundException`; a UI também oferecia comandos incompatíveis para CLIs sem instalador Windows.
- Evidencia: screenshot/log PowerShell fornecido pelo operador; testes de receita e matriz de makers adicionados para reproduzir o contrato.
- (resolvedor) Correcao: `cli-install-recipes` agora seleciona PowerShell `.ps1` para Antigravity/Devin no Windows, mantém `.sh` apenas em macOS/Linux e usa `uv` para Aider; comandos declarados incompatíveis são filtrados antes de chegar à UI. `runPowerShellScriptInstall` baixa o arquivo HTTPS e o executa com `powershell.exe -File`; a matriz do Forge fixa Squirrel em win32, DMG/ZIP em darwin e DEB/RPM em linux. Commit `b876a5a7`. Validação: 203 testes focados, 28 testes de packaging/updater Windows, `npm run typecheck` e `npm run security:renderer-sinks` passaram.
