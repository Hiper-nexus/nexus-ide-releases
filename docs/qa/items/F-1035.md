# F-1035 — O host Nexus do app mobile nunca tinha sido renderizado

## F-1035 | categoria: qa/visual | severidade: media | status: corrigido (harness) + achados abertos
- Tela/fluxo: app móvel (`mobile/`) › parear (`app/pair-scan.tsx`) › host Nexus (`mobile/src/nexus-host/NexusHostScreen.tsx`) › pane › Alterações / Arquivos (`NexusPaneWorkspace.tsx`) › revogação.
- Contexto: sem Xcode, simulador iOS, Android SDK nem Tailscale nesta máquina, F-994/F-1014/F-1015 só tinham sido provados em Node (`remote-bridge.mobile-app.test.ts`); nenhuma tela do host Nexus tinha sido vista.
- Correção (harness): `npm run mobile:visual` (docs/MOBILE-VISUAL.md) — export web do app real (React Native Web) num Chrome headless 390×844 DPR 3, contra a Remote Bridge REAL em processo (HTTPS/WSS, pareamento, desafio assinado, política mobile, broker de aprovação, Git/arquivos do checkout), com panes/PTY/missões simulados como no teste de F-994. **Não é teste de aparelho.**
  - `scripts/mobile-visual/` — `run.mjs` (export + esbuild trocando os 5 módulos do Electron por `desktop-fakes.ts`), `bridge-fixture.ts` (bridge + checkout git real + servidor HTTPS que serve o export e repassa o WebSocket sem `Origin`, como o WS nativo do RN), `cdp.ts`/`drive.ts` (Chrome headless por CDP com `ws` cru, perfil temporário, `--use-mock-keychain`; `--ignore-certificate-errors` só para o certificado local).
  - Exceção de host só para o harness: `mobile/src/transport/nexus-bridge-visual-harness.web.ts` aceita `127.0.0.1` apenas no alvo web E com `EXPO_PUBLIC_NEXUS_VISUAL_HARNESS=1` no export; o bundle nativo usa `nexus-bridge-visual-harness.ts` (sempre `false`). A checagem de produção em `nexus-bridge-pairing.ts` continua recusando IP/localhost.
  - `mobile/metro.config.js`: `watchFolders` recebe o caminho real de `node_modules` quando ele é um link (worktree que compartilha a instalação de outro checkout); sem isso o Metro falha no SHA-1.
- Evidência: `docs/qa/evidence/mobile-web/` — `report.json` (passos, verificações, auditoria de layout, escritas no PTY, console) e:
  - `01-inicio-sem-host.png`, `02-parear.png`, `03-colar-link.png`, `04-apos-parear.png` (onboarding), `05-inicio-com-host.png`

- Verificado de ponta a ponta (bridge real ↔ app real no web):
  - pareamento colando o link do QR; o código de uso único foi consumido; o host salvo aparece na lista e conecta (token + desafio assinado pela chave do aparelho);
  - snapshot com 3 missões e 3 panes; aprovação aberta no broker aparece ao vivo; **Allow** chega ao broker como `accept`, sem nenhuma escrita no PTY;
  - saída inicial do pane pelo stream; `git status` digitado chega ao PTY simulado como `git status\n`, sem diálogo de confirmação (rotina), e a saída volta empurrada pelo `pane.stream.data`; o item da fila fica "enviado";
  - Alterações (branch, seções, `.env` com cadeado), diff de texto e de código com quebra de linha, Arquivos sem `.env`/`.git`, leitura com número de linha;
  - revogação no desktop → "sessão encerrada" + "Parear de novo" → pair-scan.
  - Auditoria automática: nenhuma tela com rolagem horizontal; único texto fora do viewport é a página seguinte do onboarding (carrossel, esperado). Console: só avisos do web (`expo-notifications` push token, `useNativeDriver`).
- Achados visuais corrigidos (pequenos, re-capturados):
  1. `07`: o card de aprovação ficava recuado 16 pt em relação às linhas de missões/panes (o card compartilhado do chat tem margem própria somada ao padding da lista) — `NexusHostScreen.tsx` `approvalItem` compensa a margem.
  2. `08`/`09`: placeholder do campo de comando cortado no meio ("comando completo (Enter") — agora `comando + Enter` / `sem conexão: vai à fila` (`NexusCommandInput.tsx`).
- Achados abertos (maiores ou fora do host Nexus) — os oito foram corrigidos em F-1037 (`docs/qa/items/F-1037.md`):
  1. `05` Início: com o LegendList (harvest T3, 008799ea3) o `paddingHorizontal` do `contentContainerStyle` da lista de hosts não é aplicado — "Welcome back", títulos de seção e cards encostam nas bordas da tela. Confirmar no aparelho (pode ser só do LegendList no web).
  2. `05` card do host Nexus mostra "Connected · Direct · LAN" e "Worktree list unavailable" (textos do Orca; o caminho real é Tailscale Serve e worktrees não existem no host Nexus); atalhos "Tasks GitHub"/"New Workspace" também não têm equivalente.
  3. Marca e idioma: "Orca" em início/onboarding, telas de pareamento e o card de aprovação em inglês ("Allow Bash?", "Allow", "Deny") dentro de um host pt-BR.
  4. `06`/`07`: estados crus do desktop em inglês — missões `running`/`done`, panes `busy`/`idle`.
  5. `17`: com a credencial revogada, o card "Parear de novo" aparece em cima mas o conteúdo antigo (arquivo/diff/pane) continua na tela e as abas Alterações/Arquivos seguem tocáveis — esconder ou desabilitar o detalhe no `auth-failed`.
  6. `04`: o onboarding oferece "Use Chat UI" mesmo para host Nexus, que não tem a UI de chat.
  7. `12`: ordem das seções Alteradas → Novas → Preparadas (o painel Git do desktop mostra Preparadas primeiro).
  8. `08`/`10`: a mesma nota longa de limitações aparece na lista e no pane, e a caixa de saída tem altura fixa com muito vazio — densidade a revisar com o design.
