# F-1215 — fixtures Python do teste do supervisor darwin esperavam o arquivo de release para sempre (daemon órfão de 31 h)

## F-1215 | categoria: funcional | severidade: media | status: corrigido
- Tela/fluxo: suíte nativa `scripts/darwin-pty-supervisor.test.mjs`, que roda fora do pane: launchd ou terminal comum.
- Arquivo:linha (antes): 7 laços `while not os.path.exists(<release>): time.sleep(..)` nas fixtures Python (`:1069`, `:1159`, `:1160`, `:1294`, `:1296`, `:1337`, `:1373`). Vários são daemons `setsid` com SIGTERM ignorado, órfãos de propósito (ppid 1).
- Passos: 1) rodar a suíte; 2) a execução morre no meio (Ctrl-C, timeout do job heavy, crash ou SIGKILL do worker). O helper `supervise-job` está no mesmo grupo do vitest e morre junto.
- Esperado: a fixture some com a execução que a criou.
- Observado: o arquivo de release nunca é escrito. Nem o `finally` nem o `afterAll` rodam. O daemon fica em laço para sempre com ppid 1. No caso `:1046` (sem `try/finally`), até uma simples falha de asserção deixa o helper e o Python esperando, e o `afterAll` ainda apaga o diretório onde o release seria criado.
- Evidencia:
  - Órfão real na máquina: `59836 1 01-07:05:01 .../Python -c ... job-f57b1d07a742d ...`. O fixture dir `nexus-darwin-supervisor-real-a82zos/` mostra `job-f57b1d07a742d.daemon=59836` e `.primary=59828` (gone), sem nenhum arquivo `release-*`. Vem do caso "supervise-job holds a detached setsid daemon … natural completion". Não foi morto: não fui eu que o criei.
  - Reprodução via launchd, fora do pane (`f1215-driver.mjs`): roda o caso real e dá SIGKILL no grupo do vitest assim que a fixture sobe.
    - antes: `daemon=12648` → `ps 3s after abort: 12648 1 ... Python` (órfão, preso esperando `release-daemon`).
    - depois: `daemon=64333` → `ps 3s after abort: 64333 1 ... Python`, e `ps 135s after fixture birth: (gone)`.
- (resolvedor) Correcao: todo laço de espera das fixtures passou a usar `pythonWaitRelease(file)`, que desiste sozinho 120 s depois de montar o script. Isso fica bem acima de qualquer timeout de teste (30 s/60 s), então o caminho feliz não muda. Um teste guarda (`F-1215: no Python fixture waits for its release file forever`) falha se alguém voltar a escrever um laço sem prazo.
- Validacao:
  - O teste guarda falha antes (`expected [ …(7) ] to deeply equal []`) e passa depois.
  - Reprodução antes/depois acima.
  - Suíte completa `darwin-pty-supervisor.test.mjs` via launchd, fora do pane: 28/28 verde. Antes e depois dela, `pgrep -f nexus-darwin-supervisor-real` só mostra o 59836 pré-existente.
  - `tsc --noEmit` verde.
- Limite: o prazo só limita a vida do órfão; não impede que ele exista. A causa de fundo é o helper morrer junto com o vitest (mesmo grupo). Quem garante a limpeza em produção é o `supervise-job` vigiando o dono, que este teste cobre no caso "exact Main owner dies".
