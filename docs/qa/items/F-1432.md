# F-1432 — portão de merge/push mede o cwd do pane quando o cd não é o formato nu

## F-1432 | categoria: funcional | severidade: alta | status: corrigido
- Tela/fluxo: POST `/hook/integration` com o pane aprovado e uma worktree `.harvest/<x>` sem veredito. `nexus_review_verdict` por branch. Entrega de brief (`deliverAgentPrompt`) quando o retry só-Enter lança.
- Arquivo:linha: `src/main/orch/hook-integration-endpoint.ts:87` (opções globais do git) e `:259` (diretório do comando); `src/main/orch/review-verdict-target.ts:115` (`refs/heads`) e `:122` (`verifyHeadSha`); `src/main/orch/tool-util.ts:1161` (retry Enter-only).
- Passos: 1) Aprovar só o HEAD do pane. 2) `cd -P <wt> && git push`, `cd -- <wt> && git push`, `builtin cd`, `command cd`, `\cd`, `pushd`, `popd` e `( cd <wt> && git push )`. 3) `git -C <wt> -c k=v push` e `git -C <wt> --no-pager push`. 4) Veredito na branch `release` com tag homônima. 5) `headSha` de 4–6 hex ou igual a um nome de branch. 6) Enter-only de `deliverAgentPrompt` lança.
- Esperado: comando já reconhecido como integração, com troca de diretório que o parser não resolve, bloqueia com `checkout do merge/push não resolvível` — não mede o cwd do pane. `cd <wt>` simples e `git -C <wt> push` continuam medindo a worktree. `git -C` com `-c` ou `--no-pager` também. Branch resolve `refs/heads/<nome>`. `headSha` exige hex ≥ 7 e o SHA resolvido começa pelo valor pedido. Enter-only que lança encerra a entrega; o brief sai uma vez.
- Observado: as variantes de `cd`/`pushd`/subshell devolviam `{}` (o pane aprovado liberava o push da worktree sem veredito). `git -C <wt> -c … push` nem entrava no portão. `release^{commit}` seguia a tag. Prefixo de 6 hex gravava o commit. Enter-only que lançava caía no catch externo e a tentativa 2 re-colava o brief.

## Causa
- `CD_COMMAND` só casa `cd` nu mais um operando. `cd -P`, `cd --`, `builtin`/`command`/`\cd`, `pushd`/`popd` não atualizam o cwd. `( cd <wt> && git push )` parte no `&&`: o segmento `git push )` é integração e o diretório medido é o do pane.
- `GIT_C_PREFIX` era um único `-C` colado em `git`. `-c` ou `--no-pager` no meio tiravam o segmento do detector.
- `verifyCommit(branch)` pede o nome solto; o git prefere `refs/tags`. `verifyHeadSha` aceitava 4–64 hex e não conferia se o objeto resolvido começava pelo texto pedido.
- O `try` de `deliverAgentPrompt` envolvia a colagem e o retry. `break` só existia no caminho sem exceção.

## Correção
- Comando já integrador: segmento que muda de diretório e não é um `cd` simples resolvível (`cd` com flag, `--`, `builtin`/`command`/`\cd`, `pushd`/`popd`, subshell com `cd`/`pushd`/`popd`) lança o mesmo `INTEGRATION_REVIEW_REQUIRED` de caminho com `$`/`~`. Comando sem push/merge continua `{}`.
- Prefixo linear: zero ou mais `-C <path>`, `-c <arg>` e `--no-pager`, em qualquer ordem. O último `-C` vale, relativo ao anterior. `-C` vazio, `-` ou operando que começa com `-` recusa.
- `measureBranch` usa `refs/heads/<branch>`. `verifyHeadSha` exige `[a-f0-9]{7,64}` e `sha.startsWith(raw)`.
- O retry `injectWithBusyProof(…, '')` tem try próprio; exceção ou Enter não aceito faz `break`. A colagem do brief, se lançar, ainda pode repetir.

## Evidência RED (antes do código)
- Hook, Node 22: `cd -P <wt> && git push` e `git -C <wt> -c user.name=Nexus push` receberam `{}`. O teste pedia `decision: 'block'` (`checkout do merge/push não resolvível` / SHA da worktree). `cd` simples já media a worktree (regressão do F-1423 verde).
- Veredito: tag `release` devolveu `44219b4d03ce3e68b9902f8fc558434147249823`; a branch era `9f4db5e78f93ed2d616f2c7151cabf9928efa415`. `headSha` com 6 hex não lançou.
- `deliverAgentPrompt`: Enter-only lançando escreveu o brief 2 vezes (esperado 1).

## Limite
- `( git push )` e `cd <wt> && ( git push )` não entram no portão: o segmento não começa com `git`.
- Heredoc sem aspas que cita `( cd … )` num comando já integrador recusa. Texto entre aspas não.
- `||` continua partido como `&&`. `~` literal no nome do diretório recusa. Aspas sem fechar escondem o resto.
- `--git-dir` e `--work-tree` não são lidos. `git merge <outro>` cuja sonda de branch falha continua `{}`.
