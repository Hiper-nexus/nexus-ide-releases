# F-403 — Erro do npm audit apresentado como auditoria aprovada

## F-403 | categoria: seguranca | severidade: alta | status: verificado
- Tela/fluxo: laudo automático da missão civil, sensor de auditoria de dependências.
- Arquivo:linha: `src/main/context/mechanical-sensors.ts:280`.
- Passos: 1) Executar a auditoria em projeto com lockfile aceito pelo sensor. 2) `npm audit --json` falha e devolve JSON `{"error":{"code":"ENOLOCK"}}` ou erro de rede. 3) Ler o resultado do sensor.
- Esperado: status `unavailable`, sem findings inventados e sem afirmar auditoria aprovada.
- Observado: erro JSON era convertido para `AuditPayload` sem validação; ausência de vulnerabilidades produzia `passed` e “nenhuma vulnerabilidade conhecida”. JSON `null` ou entrada de vulnerabilidade nula também lançava exceção fora do tratamento de parse.
- Evidencia: RED inicial em `npx vitest run src/main/context/mechanical-sensors.test.ts`: 8 falhas; ENOLOCK/EAI_AGAIN e formatos inválidos retornavam `passed`, e null causava TypeError. Revisão independente identificou relatório contraditório: contagens critical/high positivas com mapa vazio. Mais 3 casos RED reproduziram esse falso verde e 4 cobriram divergências por severidade. GREEN final: 24/24 testes do sensor e 18/18 testes de `civilian-auto-review.test.ts` passaram; `npm run typecheck` e `git diff --check` passaram.
- (resolvedor) Correcao: substituir cast por schema Zod para o relatório consumido, exigir contagens e registros válidos, recusar o campo `error` e verificar igualdade das contagens critical/high/moderate/low com os registros. Total/info não são exigidos. As duas fixtures antigas com contagens diferentes do mapa foram corrigidas: no Arborist do npm 11.19.0 instalado, `lib/audit-report.js:75-86` monta mapa e incrementa contagens no mesmo laço. Falhas de schema usam `unavailable` sem fabricar findings. A política civil de indisponibilidade continua sem bloqueio e com nota honesta. Relatórios válidos com vulnerabilidades e exit não-zero continuam gerando findings. Sem commit.
- Revisao independente: complemento de coerência revisado e função real reexecutada com processo injetado; critical=1/high=2 sem registros agora retorna `unavailable`, relatório válido crítico/alto retorna `failed` e relatório limpo retorna `passed`. Nenhum bloqueador restante neste complemento.
