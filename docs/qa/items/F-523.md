# F-523 — Windows não oferece shell e passaria `-l` aos shells nativos

## F-523 | categoria: funcional | severidade: alta | status: corrigido
- Tela/fluxo: primeira abertura Windows, probe `settings-ipc` e criação de
  terminal do operador.
- Arquivo:linha: `src/main/persistence/shell-catalog.ts`,
  `src/main/pty/pty-manager.ts`.
- Passos: 1) iniciar o NUPKG empacotado no Windows; 2) consultar
  `settings.listShells`; 3) abrir o shell padrão.
- Esperado: PowerShell 7 existente é preferido; Windows PowerShell e `cmd.exe`
  são fallbacks aprovados, e nenhum recebe argumento Unix `-l`.
- Observado: o catálogo continha somente caminhos Unix, então `listShells`
  devolvia vazio e o smoke encerrava em `functional-failed: settings-ipc`. O
  spawn também adicionava `-l` a qualquer shell que não fosse bash com rcfile.
- Evidencia: Actions run 9 montou renderer sem erros SQLite e falhou somente no
  predicate não vazio de `settings-ipc`. Testes RED confirmaram catálogo Windows
  ausente, seleção configurada sem equivalência case-insensitive e `-l` para
  PowerShell/cmd.
- (resolvedor) Correcao: catálogo Windows restrito a caminhos absolutos em
  `ProgramFiles`, `SystemRoot` e `ComSpec`, todos existentes/executáveis, com
  PowerShell 7 primeiro e deduplicação case-insensitive. Configuração e pedido
  continuam obrigados ao mesmo executável aprovado. PowerShell e cmd iniciam
  sem flags Unix; zsh/bash preservam o comportamento de login existente.
  Validado com 94 testes de catálogo/PTY, 60 testes de catálogo/settings/IPC,
  typecheck, renderer sinks e parsing YAML. A verificação exige o próximo smoke
  no Windows empacotado.
