# F-190 — Pane com missão órfã no layout nunca mais abria ("renderer payload does not match main-sealed persisted pane request")

## F-190 | categoria: funcional | severidade: alta | status: corrigido
- Tela/fluxo: pane de agente restaurado ("Agente em pausa — … use Retomar") → Reiniciar ou Retomar.
- Arquivo:linha: `src/main/orch/main-owned-agent-spawn.ts` — `authorizeMainOwnedAgentSpawn` (≈404-503) e `canonicalizePersistedSpawnRequest` (≈226-327).
- Passos: 1) Pane cujo layout guarda o `missionId` de uma missão que o Main não tem mais, enquanto a spec persistida do mesmo pane aponta outra missão. 2) Reiniciar o pane.
- Esperado: o Main, que é a autoridade, abre o pane pela spec persistida; um vínculo órfão do layout não pode travar o pane para sempre.
- Observado (29/09 ~00:30, app 0.76.122): "[nexus] retomando a sessão anterior…" seguido de "[nexus] failed to start: renderer payload does not match main-sealed persisted pane request — divergências: missionId[mission-b10baa6c-9c02-44b2-a4db-42e0cfbdea26 != mission-1c4624c4-98cd-4153-9c54-a1c9ec82d185]". A missão `b10baa6c` não existe em lugar nenhum do disco (nenhuma linha em banco, nenhuma pasta de missão); a `1c4624c4` existe. Com resume a fence recusava o `missionId`; sem resume o gate ignorava a spec e o spawn morria em "stale persisted mission pane authority: pane is no longer registered by Main".
- Evidencia: print do operador; busca em `~/Library/Application Support/NexusIDE` (bancos, `Local Storage`, pastas de missão) sem nenhuma ocorrência de `b10baa6c`; os 3 testes de comportamento novo abaixo falhavam no código anterior com a mesma divergência.
- Relacionado: F-188, F-372, F-634/F-635.
- (resolvedor) Correcao: quando o renderer alega para um pane uma missão que não existe no escopo, o Main trata o vínculo como órfão: com spec persistida, o pedido passa a carregar o `missionId` da spec antes do gate e da fence (resume e fresh); sem spec, o `missionId` e o `orchRequestId` órfãos são descartados e o pane abre como pane direto. Missão alegada que EXISTE continua sendo divergência real e segue recusada, e as demais fences (adapter, modelo, conta, esforço, cwd, pane, modo) não mudaram. Aviso único por pane e missão órfã. Testes: `renderer-mission-authority-adoption.test.ts` (stores reais: órfã com resume e com fresh usam a spec; missão existente diferente continua recusada; sem spec com órfã abre sem missão; sem spec com missão existente continua recusado) e `main-owned-agent-spawn.test.ts`.
