# F-421 — preferências Clef se perdem com configuração legada ou regravada

## F-421 | categoria: funcional | severidade: alta | status: corrigido
- Tela/fluxo: Configurações › Chaves de API › Modelos de decisão, em instalações de clientes.
- Arquivo: `src/main/persistence/settings-store.ts` (`load`, `persist`, `orchSet`, `replaceOrchSettings`).
- Passos: salvar Automático e Account ID válido; carregar um settings.json com outro campo de orch inválido, ou executar uma cópia anterior à introdução de Clef que regrava o arquivo sem decisionModels; abrir a versão atual e salvar outra preferência.
- Esperado: modo e Account ID válidos continuam salvos; token continua exclusivamente no cofre.
- Observado: falha de validação do objeto orch descartava toda a seção. Ausência de decisionModels após regravação também restaurava os padrões `jev` e ID vazio. A versão anterior a ce329e6c5 não conhecia o campo e o retirava ao normalizar/gravar.
- Evidencia: dois testes falharam antes do fix, obtendo `jev` e ID vazio em vez de `auto` e o ID salvo. A ocorrência particular do operador não foi atribuída a esses dois caminhos sem prova; F-932 cobria separadamente a perda causada pela suíte de desenvolvimento.
- (resolvedor) Correcao: `~/.nexus/decision-models.json` passa a guardar somente modo, modelo, Account ID e consentimento visual. Leitura independente da validade do restante de settings.json; migração de seção legada válida quando o arquivo próprio não existe. Arquivo próprio válido tem precedência. Escritas de outras preferências não o alteram. Dados inválidos não são adotados. Se a autoridade própria estiver corrompida/inacessível, a cópia de compatibilidade só recupera o ID válido: não restaura consentimento antigo de egress (modo Jev, visão desligada). Token não é copiado para esse arquivo.
- Semântica de falha: cada escrita é atômica, mas os dois arquivos não formam uma transação. Sucesso exige ambas as escritas; falha lança erro e não atualiza a memória. Em falha parcial a cópia de compatibilidade pode conter a tentativa, sem confirmação de sucesso para a UI.
- Validação: 51 testes em sete arquivos (persistência, UI de decisão, IPC, schemas e os dois antigos gatilhos do F-932), typecheck e renderer sinks aprovados; revisão independente sem bloqueadores. Inclui recarga, outra preferência, JSON geral inválido, regravação por versão antiga e opt-out visual em Somente Jev. Arquivo real do operador permaneceu com `auto` e Account ID presente após os testes.
