# F-1586 — Prévia do Estúdio podia mostrar a criação de outro (a "mais nova do mesmo tipo")

## F-1586 | categoria: funcional | severidade: baixa | status: corrigido

- Tela/fluxo: Estúdio de Mídia → depois de "Gerar", o cartão de resultado (prévia, nome, "Mostrar no Explorador de Arquivos").
- Arquivo:linha (antes): `src/renderer/components/MediaStudioPanel.tsx:222-236` (`arts.find((a) => a.kind === res.kind)` — o artefato mais novo do mesmo tipo na galeria do projeto); `src/main/media/media-ipc.ts:175-188` (o id gravado por `recordMediaUsage` era descartado); `:55-57` (`basename` só separava por `/`).
- Passos: 1) Gerar uma imagem no Estúdio enquanto um agente gera outra imagem no mesmo projeto (`nexus_image_generate`). 2) Ver a prévia e clicar em "Mostrar no Explorador".
- Esperado: a prévia e o atalho são do arquivo que o Estúdio acabou de gerar.
- Observado: se a criação do agente terminasse por último, o cartão mostrava e abria a imagem do agente com o modelo e o custo do Estúdio; sem artefato gravado, o nome no Windows saía como o caminho absoluto inteiro.
- Causa raiz: o renderer adivinhava o artefato pela ordem da galeria; o Main já sabia o id exato (retorno de `recordMediaUsage`) e não o devolvia.
- (resolvedor) Correcao:
  - `media-ipc.ts`: o sucesso do `media:generate` devolve `artifactId` (a linha da galeria gravada para ESTE resultado); tipo em `src/shared/media-types.ts`.
  - Estúdio: a prévia, o nome e o atalho usam o artefato com esse id; sem id, não há prévia (nunca o arquivo de outro) e o nome vem do caminho do resultado, separado por `\` ou `/`.
- Evidencia/validacao:
  - RED no código antigo: `MediaStudioPanel.test.tsx` › "mostra o arquivo deste resultado, não o mais novo do mesmo tipo" (a prévia saía com a imagem do agente) e "sem o id da criação não mostra o arquivo de outro…" falharam.
  - GREEN: `npx vitest run src/renderer/components/MediaStudioPanel.test.tsx` (13); `npx tsc --noEmit -p tsconfig.json` sem erros.
- Limite: o caminho de sucesso do `media:generate` no IPC não tem teste unitário: o gravador de uso é carregado por `require` preguiçoso (para não arrastar Electron), que o vitest não resolve nem intercepta — a mudança no Main (`return { ...result, artifactId }`) está coberta só pelo typecheck.
