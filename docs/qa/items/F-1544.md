# F-1544 — nexus-heavy recusa o filho de um comando pesado admitido (Windows)

## F-1544 | categoria: funcional/orquestração | severidade: alta | status: corrigido (não visto no app real)
- Tela/fluxo: pane de missão rodando build/instalação pesados (`npm ci`, `electron-forge make`).
- Observado (15/10, Windows 11, app 0.76.257): `npm ci` e `npm run make` do pane saem com exit 78 — `nexus-heavy: the inherited admission could not be proved for pid N` / `Heavy command not started: Nexus did not admit it`. O pai (`npm`) é admitido; o filho que herda o lease (`node install.js` do esbuild, `electron-forge make`) é recusado.
- Esperado: o filho do comando já admitido herda o lease, ou a recusa diz como rodar.
- Evidência: `main.trace.ndjson` — 4× `heavy-command-denied`, todas `heavy_command_nested_ownership_unproved` (380/371/375/571 ms), sessão do pane do Maestro.

## Causa
`borrow` (`owned-command-process.ts`) exige que o filho apareça entre os descendentes com identidade de início inequívoca. `hasUnambiguousStartIdentity` recusa linha cujo início cai no segundo inteiro da captura (cerca do `ps lstart`, F-1479). O filho de um comando pesado (`node install.js` do esbuild, `electron-forge`) pede o lease nos primeiros ms de vida, dentro desse segundo, então era sempre negado: `heavy_command_nested_ownership_unproved` → exit 78. Confirmado pelo código e pelas 4 negações do trace; não reproduzido com o app real.

## Correção
`borrow` espera a virada do segundo (≤1,5 s) e reamostra UMA vez antes de decidir. A cerca F-1479 fica intacta (o teste que trava "linha do Windows no segundo da captura é ambígua" continua passando): pid ausente, outro pai e identidade ainda ambígua seguem negados. Testes novos em `owned-command-process.test.ts`.

## O que NÃO fazer
Não afrouxar `borrow`/`hasUnambiguousStartIdentity` às cegas: é a cerca que impede pid forjado de pegar lease alheio (`src/main/pty/` e `src/main/orch/` são fronteira de segurança, AGENTS.md).

## Verificar no app
Depois de instalar a versão com esta correção: `npm ci` e `npm run make` num pane de missão não devem mais sair com exit 78; o trace não deve registrar `heavy_command_nested_ownership_unproved`.

## Contorno
Rodar o comando pesado fora do pane (terminal do operador).
