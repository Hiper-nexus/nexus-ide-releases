# F-596 — Muse pane imprime `--help` e sai com code 2

## F-596 | categoria: funcional | severidade: alta | status: corrigido
- Tela/fluxo: `+ Pane` → Muse Code.
- Arquivo:linha: `src/adapters/builtin/muse.json` (`quirks.mcpAutoload` / `nexusMcp`)
- Passos: 1) Abrir um pane Muse. 2) Observar o terminal.
- Esperado: TUI interativa do Muse Code.
- Observado: dump do `--help` (flags `--approval-mode`, `--yolo`, `--subagent-worktree-isolation`) e `[nexus] process exited (code 2)`.
- Evidencia: print 2026-09-19T22-27-45; reprodução local Muse 1.3.0: `muse --mcp-config x --settings y` → code 2 + o mesmo help; `muse --trust-workspace` sobe a TUI.
- Causa: o adapter builtin copiava o contrato Claude (`mcpAutoload: true`, `nexusMcp: autoload`). `prepareAgentSpawnDecoration` injetava `--mcp-config` e `--settings`, que o Muse não tem.
- (resolvedor) Correcao: `mcpAutoload: false`, `nexusMcp: none`; `--trust-workspace` no `spawn.extraArgs`. Lei do binário: `usesClaudeHomeLayout` / `acceptsClaudeMcpCliFlags` não tratam um `muse`/`kimi`/`codex` como Claude só porque o JSON copiou `mcpAutoload`. `--mcp-config`/`--settings` só saem no argv de `claude` e `openclaude`.
