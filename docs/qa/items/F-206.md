# F-206 — Codex no Windows encerra antes de iniciar por linha de comando longa

## F-206 | categoria: funcional | severidade: alta | status: corrigido

- Tela/fluxo: abrir um pane Codex padrão no Windows.
- Arquivo:linha: `src/main/path-resolver.ts`
  (`resolveWindowsCodexNpmShimLaunch`) e `src/main/pty/pty-manager.ts`
  (`spawnAgentSession`).
- Passos: 1) instalar Codex globalmente pelo npm; 2) abrir um pane Codex com
  a configuração de hooks do Nexus; 3) observar o processo do pane.
- Esperado: o Codex inicia e mantém o prompt funcional.
- Observado: o pane mostrava `Linha de comando muito longa.` seguido de
  `process exited (code -1)` antes de abrir o prompt.
- Evidência:
  - captura do operador com o erro no pane Codex;
  - o `codex.cmd` npm desta máquina invoca `cmd.exe`, que possui limite menor
    que os argumentos de hook aplicados pelo Nexus;
  - os testes de regressão primeiro falharam ao esperar `node.exe` no spawn e
    agora cobrem a resolução verificada e a chamada final do PTY.
- (resolvedor) Correcao:
  - Causa raiz: o launcher `codex.cmd` passa por `cmd.exe`; a configuração de
    status hook legítima ultrapassava seu limite de linha de comando, sem que o
    processo Codex fosse iniciado.
  - Para o launcher npm padrão, já verificado por caminho, conteúdo do shim,
    `node.exe` e `codex.js`, o PTY inicia o Node nativo diretamente e prefixa o
    mesmo entrypoint. O caminho é exclusivo de Windows, Codex embutido e spawn
    direto; planos sandbox permanecem inalterados. Commit `9bd4b38f`
    (`fix(pty): F-206 — bypass Codex cmd length limit`).
  - Validação: `npx vitest run src/main/path-resolver.test.ts -t
    "resolves the npm Codex cmd shim"`, `npx vitest run
    src/main/pty/pty-manager.test.ts -t "starts a long-argument Codex pane"`,
    `npm run typecheck` e `npm run security:renderer-sinks` passaram. A
    execução real de `node.exe codex.js --version` retornou `codex-cli 0.154.0`.
