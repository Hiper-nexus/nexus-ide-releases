## F-1509 | categoria: funcional | severidade: alta | status: corrigido
- Renumerado na integração com a origin (0.76.252): este achado era o F-1455 da frente de squads (nunca publicado) e virou F-1509 para não colidir com a numeração que a origin publicou (F-1436..F-1451).
- Tela/fluxo: missão/squad → `prepareMissionExecutionScope` (`orch/mission-execution-scope.ts:23-39`) cria a worktree da aba → `WorktreeManager.create` → `readRepositorySnapshotAsync` (`src/main/runtime/worktree-manager-git.ts`).
- Arquivo:linha: `src/main/runtime/worktree-manager-git.ts:57-62` e `:208-213` (antes) — `topLevel !== rootRealPath` com a raiz de `persistence/project-identity.ts:201` (`fs.realpathSync`).

Vale para as duas provas (síncrona e assíncrona). Continua exigindo o MESMO diretório: subpasta do repositório segue recusada (coberto no teste). ## macOS (mesma causa raiz, APFS case-insensitive)
- Sintoma: o APFS do macOS é case-insensitive por padrão. Quando o workspace chega com outra caixa (deep-link, argv, atalho: `/Users/x/Dev/Nexus-IDE` em vez de `/Users/x/dev/nexus-ide`), o `fs.realpathSync` (JS) preserva a caixa digitada — provado nesta máquina: `realpathSync('<tmp>/subdir')` devolveu `.../subdir` e `realpathSync.native` devolveu `.../SubDir` —, enquanto `realpathSync.native` e o `git rev-parse --show-toplevel` devolvem a caixa do disco. `project-identity` grava a raiz com a caixa errada, `readRepositorySnapshot(Async)` recusa com "scope root must equal the canonical Git top-level" e TODA missão do workspace falha. Mesmo relato do F-1509 no Windows (98b2964e7).
- Correcao: `isGitTopLevel` em `worktree-manager-git.ts` estende o gate ao darwin — compara as formas `fs.realpathSync.native` dos dois lados (já na caixa do disco) via `areWorktreePathsEqual(..., 'darwin')`, que trata o desvio `/tmp ↔ /private/tmp` e compara em igualdade exata (não é case-insensitive; não mudou o comportamento global dele). Em volume case-sensitive a caixa errada não existe (ENOENT) e o `catch → false` continua correto. Linux segue igualdade exata. Continua exigindo o MESMO diretório.
- Evidencia:
  - RED (código antigo): `node_modules/.bin/vitest run src/main/runtime/worktree-manager.test.ts -t F-1509 --maxWorkers=2` → `Error: scope root must equal the canonical Git top-level` em `readRepositorySnapshotAsync` (`worktree-manager-git.ts:234`) com o repo em `CaseRepo` e a raiz passada como `caserepo`.
  - GREEN: o mesmo comando passa — (a) raiz com outra caixa aceita nas duas provas (`create` assíncrono + `inspectIntegration` síncrono, `ready`); (b) subpasta com outra caixa (`caserepo/subdir`) recusada; (c) subpasta de outro repositório recusada; (d) teste Windows existente permanece no arquivo (`runIf(win32)`).
  - Vizinhos: `worktree-manager.test.ts` inteiro → 65 passam, 1 pulado (win32); `project-identity.test.ts` + `project-identity-cache.test.ts` → 26 passam. `npm run typecheck` → 0.
