# F-205 — Shell do Windows perde o Path e não encontra CLIs instaladas

## F-205 | categoria: funcional | severidade: alta | status: corrigido

- Tela/fluxo: abertura de shell, login de provider e execução de CLI no pane
  do Windows.
- Arquivo:linha: `src/main/pty/pty-manager.ts` (`baseChildEnv`).
- Passos: 1) iniciar o Nexus por um processo Windows que herda `Path`; 2)
  abrir um shell PowerShell; 3) executar uma CLI instalada no PATH do usuário,
  como `claude auth login`.
- Esperado: o pane herda o caminho de busca do Windows e encontra a CLI.
- Observado: comandos instalados pelo npm respondiam que não eram reconhecidos,
  embora funcionassem fora do Nexus.
- Evidência: captura do operador com `claude : O termo 'claude' não é
  reconhecido`; teste de regressão em `pty-manager.test.ts` falhou sem `Path`.
- (resolvedor) Correcao:
  - Causa raiz: a allowlist do ambiente era sensível a maiúsculas, enquanto
    Windows trata nomes de variável sem distinguir `PATH` de `Path`. Node
    preservava a grafia herdada e ela era descartada antes do spawn.
  - A allowlist agora compara somente os nomes já permitidos de forma
    case-insensitive no Windows, preservando a fronteira de segurança e o
    `Path` original. Commit `a5fb95f7`
    (`fix(pty): F-205 — preserve Windows shell Path`).
  - Validação: `npx vitest run src/main/pty/pty-manager.test.ts -t
    "preserves Windows Path spelling"`, `npm run typecheck` e
    `npm run security:renderer-sinks` passaram.
