# F-1307 — CLI sem superfície bundled perdia a skill de projeto

## F-1307 | categoria: funcional | severidade: baixa | status: corrigido
- Tela/fluxo: `suggestSkillForTask` → early-return por `adapterId` sem superfície de skill bundled; a skill de PROJETO era descartada junto.
- Arquivo:linha (antes): `src/main/orch/jev-skill-suggestion.ts:486` — `if (opts.adapterId !== undefined && !cliSupportsSkillSurface(opts.adapterId)) return null;` (antes de montar o catálogo de projeto).
- Passos:
  1. Um pane de CLI sem superfície bundled (muse, minimax-code…) pede uma tarefa com uma skill de projeto instalada no workspace.
  2. `suggestSkillForTask` roda.
- Esperado: a dica de skill de PROJETO (um `SKILL.md` dentro do workspace, legível por qualquer CLI) continua valendo; só o catálogo bundled (HOME) esvazia.
- Observado: o early-return abortava antes do catálogo de projeto — até a dica de projeto era perdida.
- Evidencia (RED): `jev-skill-suggestion.test.ts` › `F-1307: pane sem superfície bundled ainda recebe a dica de skill de PROJETO` — com `adapterId: 'muse'` a sugestão voltava `null`; esperado `{ name: 'bmad-create-prd', pkg: 'project', … }`.
- (resolvedor) Correcao:
  - O early-return vira `const bundledSurface = opts.adapterId === undefined || cliSupportsSkillSurface(opts.adapterId);`. Só o catálogo bundled esvazia (`bundledSurface ? skillCatalogForTaskRole(...) : []`); o de projeto segue para o Jev.
