# F-611 — Overlay Kimi nasce sem catálogo de modelos (`config.invalid`)

## F-611 | categoria: funcional | severidade: alta | status: corrigido
- Tela/fluxo: pane Kimi da mão do operador (OAuth, `--model kimi-code/k3`).
- Arquivo:linha: `src/main/orch/cli-mcp-session-kimi.ts` (`prepareKimiMcpSession`).
- Passos: 1) Abrir um pane Kimi no Nexus. 2) Mandar um prompt (ou trocar o
  modelo na TUI). 3) Observar `config.invalid` para `kimi-code/k3` e fallbacks.
- Esperado: o overlay `$KIMI_CODE_HOME/config.toml` carrega `models` +
  `providers` (e `services`/`default_model`) do perfil nativo
  (`~/.kimi-code/config.toml` ou o home da conta gerenciada). O spawn
  `kimi --model kimi-code/k3` resolve. Uma reescrita da TUI que apague o
  catálogo não deixa o pane sem modelos.
- Observado: o overlay em `~/.nexus/ephemeral/mcp-clients/kimi/<tok>/` ficou
  sem `config.toml` (e sem `mcp.json`). O perfil real e o home gerenciado
  tinham o catálogo completo. O Kimi 2.0.2 recusou o modelo. O merge de
  hooks no overlay é best-effort e, se falhar ou se a CLI substituir o
  arquivo, o catálogo some em silêncio.
- Evidencia: print `mu9wyqps-d89dac09c5ff25b9-print-2026-09-20T14-30-44.png`;
  overlay `7bf5ed12d4dbc083ef90daba9ca18116` sem toml/json na raiz; nativo
  `~/.kimi-code/config.toml` com `[models."kimi-code/k3"]`.
- (resolvedor) Correção: `projectKimiNativeCatalog` copia `models` /
  `providers` / `services` / `default_model` do perfil nativo (segue
  symlink de conta gerenciada) para o `config.toml` privado do overlay.
  Merge de hooks que falha cai para o catálogo, nunca para overlay vazio.
  Um guarda `fs.watch` no overlay restaura o catálogo se a TUI substituir
  o arquivo e apagar os modelos; o `default_model` da TUI prevalece.
  Validação: `npx vitest run src/main/orch/cli-mcp-session-kimi.test.ts`
  (7/7) e `cli-mcp-session-config.test.ts` (26/26, `GROK_HOME` isolado).
