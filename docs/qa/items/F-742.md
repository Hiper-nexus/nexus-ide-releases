# F-742 — Worker MiMo retomado saía em 5 s: o brief confirmava "No, exit" no aviso de bypass

## F-742 | categoria: funcional | severidade: alta | status: corrigido
- Tela/fluxo: worker MiMo Code de missão aberto com `resume` (o Maestro retoma a conversa de um worker anterior).
- Arquivo:linha:
  - `src/main/adapters/mimo-skip-permissions.ts`;
  - `src/main/pty/pty-manager.ts` (spawn do agente, antes do sandbox/launcher);
  - `src/main/orch/tool-util.ts` (`waitUntilPasteComposerReady`, `MIMO_COMPOSER_READY`).
- Passos:
  1. Missão com Maestro Codex.
  2. O Maestro chama `nexus_pane_spawn` com `adapterId: mimo-code` e `resume` de um pane MiMo antigo (12:13:35, 02/10).
- Esperado: o MiMo sobe, recebe o brief e trabalha.
- Observado (texto colado pelo operador): "Performing one time database migration… WARNING: Bypass Permissions mode … ◇ │ No, exit (recommended)". O trace mostra `agent-pty-exit` com code 0, saída espontânea, 5,2 s depois do spawn. Ao digitar no pane, o Nexus responde "este pane é histórico".
- Evidencia:
  - MiMo 0.1.15 (bundle): com `--dangerously-skip-permissions` e stdin TTY, o handler do `$0` SEMPRE abre um `select` do @clack ("No, exit (recommended)" marcado, cancelar = sair). Não guarda o aceite. Aceitar só faz `process.env.MIMOCODE_DANGEROUSLY_SKIP_PERMISSIONS = "1"`.
  - A doc embutida do MiMo lista a variável como superfície oficial ("Any surface (env)"). Com ela, a config vira `permission: {"*": "allow"}`.
  - Retomada não leva o brief no argv (`nativeInitialPrompt` exige `!req.resume`): ele é colado depois do boot, cru (`bracketedPaste: false`). O MiMo não tinha regex de composer pronto, então a colagem saía na primeira borda de idle, antes de qualquer tela. O primeiro `\n` do brief, lido pelo `select`, confirmou o item marcado.
  - Reprodução isolada (mesmo binário, `MIMOCODE_HOME` temporário): o auto-responder do Nexus casa o diálogo com os bytes reais e o Down+Enter aceita. O defeito é a colagem prematura, não a assinatura.
- (resolvedor) Correcao:
  - O spawn do MiMo troca `--dangerously-skip-permissions`/`--yolo` por `MIMOCODE_DANGEROUSLY_SKIP_PERMISSIONS=1`. É o mesmo modo, sem diálogo, equivalente ao `skipDangerousModePermissionPrompt` da família Claude. Sem a flag (operador que escolheu pedir permissão), nada muda.
  - A colagem no MiMo espera o rodapé do composer (`tab switch mode`), como Devin, Kimi e Qwen. A assinatura `mimo-bypass-permissions` do auto-responder fica como rede para builds que voltem a mostrar o aviso.
  - Testes que reprovam o código antigo:
    - `mimo-skip-permissions.test.ts`;
    - `tool-util-workspace.test.ts`: "F-742: retomada do MiMo não cola o brief antes da TUI".
