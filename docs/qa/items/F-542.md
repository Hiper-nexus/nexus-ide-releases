# F-542 — Falha de OOM no CI e typecheck por estouro de heap do Node.js

## F-542 | categoria: build | severidade: alta | status: corrigido
- Tela/fluxo: GitHub Actions CI / Release Candidate / `npm run typecheck`
- Arquivo:linha: `package.json:37-38`, `.github/workflows/ci.yml:21`, `.github/workflows/windows-release.yml:28`, `scripts/nexus-notary.mjs:34`
- Passos:
  1) Executar `npm run typecheck` em ambiente com limite de heap padrão do Node.js (~2 GB), como os runners do GitHub Actions (`ubuntu-latest`).
  2) Push para `main` na versão 0.76.31 (que adicionou mais de 600 arquivos ao monorepo).
- Esperado:
  - O typecheck e a pipeline de CI devem concluir sem erro de memória.
- Observado:
  - O runner do GitHub Actions falha com `exit code 134` e `FATAL ERROR: Ineffective mark-compacts near heap limit Allocation failed - JavaScript heap out of memory`, impedindo a validação do CI e a publicação da release 0.76.31.
- Evidencia:
  - Log da run 34907970472 no GitHub Actions com erro de OOM após 45 segundos de checagem.
  - Reproduzido localmente com `--max-old-space-size=2048` (falha com OOM).
  - Validado com `--max-old-space-size=4096` passando com sucesso (exit 0).
- (resolvedor) Correcao:
  - Configurado `NODE_OPTIONS: "--max-old-space-size=4096"` em `.github/workflows/ci.yml` e `.github/workflows/windows-release.yml`.
  - Configurado `--max-old-space-size=4096` nos scripts `lint` e `typecheck` do `package.json` e no step de typecheck em `scripts/nexus-notary.mjs`.
