# F-1577 — "Equipes salvas" some sem projeto aberto e Criar/Importar mostram erro cru em inglês

## F-1577 | categoria: funcional | severidade: media | status: corrigido

- Tela/fluxo: Ajustes → Equipes e modelos → Equipes (`SquadsSection`, `src/renderer/components/settings/ModuleSections.tsx`) → `window.nexus.orch.listSquads/saveSquad/deleteSquad/exportSquads/importSquads` → handlers `orch:squads.*` (`src/main/orch/orch-ipc.ts`).
- Arquivo:linha (antes): `src/main/orch/orch-ipc.ts:2625` (`squadsList`), `:2724` (`squadSave`), `:2863` (`squadDelete`), `:2900` (`squadExport`), `:3270` (`squadImport`) — todos chamavam `requireLiveRendererWorkspaceScope(event.sender)`; `src/renderer/state/orch-store.ts:266-277` (`resetProjectState` zerava `squads`), `:132-133`/`:180` (o catálogo só era lido no `hydrate` de um projeto) e `:330-334` (`setSquads` descartava o broadcast sem workspace); `src/renderer/orch/orch-bridge.ts:764-767` (reset a cada troca de workspace, hidratação só com projeto).
- Passos: 1) Abrir o app sem projeto aberto. 2) Ajustes → Equipes e modelos → Equipes. 3) Abrir um projeto pela barra. 4) Remover o projeto da barra. 5) Sem projeto, clicar em "Criar equipe" (salvar) e em "Importar".
- Esperado: as equipes salvas (as originais e as do usuário, como "Full-Stack - GBX") aparecem sempre; criar, editar, importar, exportar e apagar funcionam sem projeto, porque o catálogo é global.
- Observado (vídeo do cliente): sem projeto, "Nenhuma equipe salva"; ao abrir um projeto as equipes "aparecem do nada"; ao remover o projeto somem de novo. "Criar equipe" e "Importar" sem projeto mostram o texto cru `renderer has no authorized workspace scope`.
- Causa raiz: as equipes moram numa tabela GLOBAL (`squads` no `nexus.db` do userData, `src/main/persistence/db.ts:260-269`, `initSquadStore` uma vez no boot), mas os handlers do catálogo exigiam o escopo de workspace do renderer — que só existe com projeto aberto — e o renderer tratava `squads` como estado de projeto: zerava na troca de workspace, só lia com projeto e descartava o broadcast sem projeto.
- Evidencia:
  - RED (código antigo, testes novos): `npx vitest run src/main/orch/orch-ipc-authority.test.ts` → 7 falhas novas (lista, criar, apagar, apagar com janela que deixou de ser confiável, exportar, importar sem projeto; recusa após diálogo) com `renderer has no authorized workspace scope`; `npx vitest run src/renderer/state/orch-store.workspace.test.ts src/renderer/state/project-scoped-controllers.test.tsx src/renderer/components/settings/SettingsSquads.capabilities.test.tsx` → 7 falhas novas (catálogo sem projeto, troca de projeto não zera, broadcast sem projeto, broadcast vence leitura atrasada, abrir projeto não amarra o catálogo, ponte no boot, texto cru na tela).
- (resolvedor) Correcao:
  - Main (`src/main/orch/orch-ipc.ts`): `squadsList`, `squadSave` (caminho do catálogo), `squadDelete`, `squadExport` e `squadImport` passam a ser `handleTrusted` — a mesma guarda das configurações globais (`settings:orch:set`): janela principal viva, frame principal, origem esperada. Depois de cada diálogo nativo (confirmação de exclusão, picker e confirmação de importação, diálogo de salvar da exportação) o remetente é conferido de novo (`assertLiveTrustedCatalogSender`). A cópia selada de missão (`purpose: 'mission-runtime'`, ids `mission-runtime-*`/`agentic-runtime-*`) continua exigindo o escopo do projeto, e `squadDesign` e o resto do que toca checkout não mudaram. `assertSquadsNotExecuting` não exige mais o escopo do renderer: varre os escopos abertos (e o do projeto atual, se houver) e o inventário físico de PTY/pane; registro de stores não inicializado continua recusando. Os diálogos nativos dizem `Workspace solicitante: nenhum projeto aberto` quando não há projeto.
  - Renderer: `squads` deixou de ser estado de projeto (`src/renderer/state/orch-store.ts`) — `resetProjectState` não o zera, `hydrateSquads()` lê o catálogo com época própria (broadcast mais novo vence a resposta atrasada), `setSquads` aceita o broadcast sem workspace e o `hydrate` do projeto só relê o catálogo. `useOrchBridge` (`src/renderer/orch/orch-bridge.ts`) lê o catálogo no boot, com ou sem projeto.
  - Texto: `squadErrorCopy` (`src/renderer/lib/squad-error-copy.ts`) troca a recusa crua de escopo por "Abra um projeto para …" em Importar/Exportar/Apagar (`ModuleSections.tsx`) e Salvar (`SquadEditor.tsx`). A voz deixou de dizer "Este projeto ainda não tem squads salvos" (`jarvis-action-executor.ts`).
  - Testes: `orch-ipc-authority.test.ts` simula `handleTrusted` (remetente confiável por padrão, `untrustedSenders` para o alheio); o caso "requires a live workspace scope for global inventory read" deixou de incluir `squadsList`; "recusa troca de workspace durante picker ou confirmação" virou "recusa se a janela deixa de ser confiável durante picker ou confirmação" (a autoridade do catálogo é a janela, não o projeto). `mission-direct-bootstrap.integration.test.ts` (opt-in, `NEXUS_DIRECT_BOOTSTRAP_CONTROLLED_CLI=1`) registra a janela confiável antes do `squadSave`.
