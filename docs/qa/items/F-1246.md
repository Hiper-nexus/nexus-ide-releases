# F-1246 — Teste do F-1184 não era portável para Linux (bashrc do sistema e zsh ausente)

## F-1246 | categoria: funcional | severidade: media | status: corrigido
- Tela/fluxo: `src/main/orch/heavy-shell-strict-mode.test.ts`, criado no F-1184 (0.76.236).
- Observado no CI Linux local:
  - `bash -u` imprimia `/etc/bash.bashrc: line 7: PS1: unbound variable`. O stdin herdado do libuv é um socket, e o bash do Debian/Ubuntu se acha "shell remoto" e lê o bashrc do sistema.
  - Sem zsh instalado, `spawnSync('/bin/zsh')` devolvia `stderr` indefinido.
  - O teste falharia no CI real do GitHub.
- (resolvedor) Correcao: stdin `ignore` nos três spawns, e o caso do zsh pula quando `/bin/zsh` não existe. O guard em si não mudou.
- Validacao: macOS 3/3; CI Linux local com zsh 3/3.
- Tipagem (revisão antes da tag): `quiet` com `as const` virava tupla readonly e o `tsc --noEmit` dava TS2769 em cada `...quiet`. Agora é `SpawnSyncOptionsWithStringEncoding` (`stdio: ['ignore', 'pipe', 'pipe']`, `encoding: 'utf8'`), com o mesmo comportamento. `tsc --noEmit` 0; macOS 3/3.
- CI Linux (`.github/workflows/ci.yml`, passo "Install Linux sandbox provider (bubblewrap)"): passa a instalar também o `zsh`. O caso do zsh deste teste e os testes do guard zsh deixam de pular no CI.
