# F-687 — Pane Codex no Windows parava em "Hooks need review"

## F-687 | categoria: funcional | severidade: alta | status: corrigido
- Tela/fluxo: qualquer pane Codex no Windows (mão do operador, helper ou worker).
- Arquivo:linha: `src/main/orch/codex-cli-version.ts` (`resolveCodexCliVersion`), consumido por `codexHookTrustBypassArgs` em `mcp-server.ts`.
- Passos: 1) Codex instalado pelo npm (`~/.local/bin/codex.cmd`, 0.159). 2) Abrir um pane Codex.
- Esperado: o pane nasce no composer; os hooks do Nexus rodam com `--dangerously-bypass-hook-trust` (como no macOS).
- Observado (29/09, gravação Nexus Shot 18:08): "Hooks need review / 8 hooks are new or changed / 1. Review hooks 2. Trust all and continue 3. Continue without trusting" parado no pane. O operador: "não pedir isto, pular".
- Evidencia: `execFileSync('codex', ['--version'])` → ENOENT; `execFileSync('codex.cmd', …)` → EINVAL (Node recusa batch sem shell). Versão null → a flag, que depende da versão (>= 0.134), nunca entrava no argv.
- Causa: a versão era lida só pelo nome nu do binário. No Windows o `codex` do npm é um `.cmd`, que o `execFileSync` não executa.
- (resolvedor) Correcao: `windowsCodexVersionLaunch` lê a versão pelo mesmo lançador verificado do spawn (`resolveWindowsCodexNpmShimLaunch` / `windowsNpmShimSpawn`: `node.exe` + `codex.js` do pacote, sem cmd.exe; `.exe` direto). Nesta máquina: 0.159.0 → `['--dangerously-bypass-hook-trust']`. Versão indeterminável continua omitindo a flag (fail-safe). Testes em `codex-cli-version.test.ts`. A decisão de confiar (flag só para os hooks que o Nexus escreve) é a mesma do macOS: nada de marcar "Trust all" em nome do operador.
