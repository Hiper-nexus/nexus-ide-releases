# F-1341 — substantivo de domínio subia documento e ação mecânica a critical

## F-1341 | categoria: funcional | severidade: media | status: corrigido
- Tela/fluxo: roteamento de tarefa → `classifyTask` (tier → modelo/esforço).
- Arquivo:linha (antes): `src/main/orch/task-router.ts:331-348` (`CRITICAL_SIGNALS` mistura dificuldade com domínio) e `:454` (qualquer sinal decisivo de domínio vira critical). O work-kind doc não rebaixava nada.
- Passos:
  1. `classifyTask('corrigir typo no README da integração de webhook')`
  2. `classifyTask('escrever documentação do endpoint de billing')`
  3. `classifyTask('listar os webhooks cadastrados')`
- Esperado: easy / easy / trivial. O domínio diz onde a tarefa mexe, não quão difícil ela é.
- Observado: os três davam `critical`, com sinais `[webhook]`, `[billing]` e `[webhook]`.
- Evidencia: sonda C (s240) e RED em `task-router.test.ts` › "F-1340/F-1341…": `expected 'critical' to be 'easy'` (2x) e `expected 'critical' to be 'trivial'`.
- (resolvedor) Correcao:
  - Causa raiz: o tier subia por qualquer sinal decisivo de critical, inclusive substantivos que só nomeiam a superfície (webhook, billing, auth, segurança…).
  - `DOMAIN_ONLY_SIGNALS` lista esses substantivos, incluindo os de componente do bucket hard: integração, engine, parser…
  - `isDomainOnlyCheapWork` vale para um pedido de UMA ação só (sem e/and/vírgula/;) que seja documento (work-kind `doc` com confiança alta) ou ação mecânica (typo, renomear, traduzir, listar/liste) sem outro trabalho forte.
  - Nesse caso os sinais só de domínio saem dos buckets critical/hard. Modo de falha (race condition, deadlock, perda de dados), migração e defeito de segurança (vulnerabilidade, acesso não autorizado) continuam subindo.
  - O nudge de tamanho continua olhando o domínio, então o pedido não desce abaixo do bucket que sobrou.
  - `listar` entrou em `TRIVIAL_SIGNALS` por palavra inteira. "listagem" segue fora.
  - Guardas (seguem critical): "corrigir auth", "implementar OAuth e atualizar o README", "renomear a variável e ajustar o fluxo OAuth", "Analise o módulo de pagamentos e liste os riscos", "corrigir typo no README do deadlock do webhook", "listar as migrações pendentes do banco".
  - Limite conhecido (marcado `ponytail:`): um pedido composto de partes todas baratas não ganha o rebaixamento.
  - Testes: `task-router.test.ts` (RED → verde) e as suítes task-router*, mission-work-kind, mission-route-specialty, mission-routing-matrix, route-tools* e jev-task-routing* verdes. As duas falhas `ERR_DLOPEN_FAILED` (better-sqlite3 com ABI do Electron) já aconteciam na base.
