# F-229 — Pane AGY falha no spawn: "Provider credential link points outside its auth source"

## F-229 | categoria: spawn | severidade: alta | status: corrigido
- Tela/fluxo: abrir pane AGY → `[nexus] failed to start: Provider credential link points outside its auth source`
- Arquivos: `src/main/adapters/managed-credentials.ts`, `src/main/pty/provider-state-env.ts`, `src/main/adapters/managed-credentials.test.ts`

## Causa raiz
A CLI do AGY consolida aliases de config em links **dentro do próprio provider-state** — na máquina real, `antigravity-cli/mcp_config.json` virou link para o irmão `config/mcp_config.json` (mesmo comportamento que o bloco de `skills` já tolerava). Na materialização seguinte, o loop de credenciais resolvia o link, via que o alvo não era o auth source e lançava o erro — falso positivo que matava todo spawn AGY do checkout.

## Correção
- `managed-credentials.ts`: link de credencial/config cujo alvo resolvido fica dentro de `providerHome` (consolidação interna) ou `sourceHome` (materialização antiga) é re-apontado para o source — o link nunca é seguido. Alvo fora das duas raízes continua fail-closed.
- `provider-state-env.ts`: mesma regra de cura para o overlay TUI (droid/hermes/cursor/pi/goose/copilot/command-code/amp/prime-agent).
- Estado na máquina do usuário reparado manualmente (link re-apontado para `~/.gemini/antigravity-cli/mcp_config.json`).

## Testes
- `re-points AGY config links consolidated inside the managed home instead of failing the spawn` — reproduz o estado observado (link interno da CLI) e exige respawn sem erro.
- `still rejects a credential link resolving outside the auth source and managed home` — alvo estranho continua lançando e o link é preservado.
