# F-247 — Hub MCP entrava inteiro em pane de missão

## F-247 | categoria: orquestração | severidade: alta | status: corrigido
- Tela/fluxo: spawn de orquestrador/worker de missão — `nexus_pane_spawn` e a
  rota automática herdavam TODOS os servidores de `.nexus/mcp-hub.json`.
- Arquivos: `src/main/mcp-hub/mcp-hub-spawn.ts`,
  `src/main/mcp-hub/mcp-hub-spawn.test.ts`,
  `src/main/orch/mcp-server.ts`,
  `src/main/orch/tools-panes.ts`,
  `src/main/orch/mcp-server-governed-profile.test.ts`

## Evidência
- `.nexus/mcp-hub.json` do operador: 22 servidores — 16 stdio (`npx -y …`) e
  6 remotos OAuth interativos (cloudflare-api, sentry, hf-mcp-server?login,
  higgsfield, mercadopago, openaideveloperdocs).
- Boot de worker lento: 16 processos `npx` levantados por pane.
- 3 workers MiMo mortos pelo watchdog com "mcp auth failure": remoto pedindo
  login OAuth que um worker nunca consegue completar (F-702).
- `selectHubServersForSpawn` devolvia o hub inteiro para pane de missão; só
  `operatorChild` filtrava por `allowedTools`.

## Causa raiz
A seleção do hub ignorava o papel do pane: `role` nunca entrava na decisão.
O único caminho de opt-in (`allowedTools` do spawn) não existia como arg de
`nexus_pane_spawn` para worker de missão.

## Correção
- `selectHubServersForSpawn(servers, { operatorChild, allowedTools, role })`:
  - `worker` de missão = `operatorChild`: só os servidores nomeados em
    `allowedTools` (`mcp__<server>__*`); sem pedido, `[]`.
  - `orchestrator`: todos os stdio + remotos COM `headers` (autenticados);
    remoto sem headers (OAuth interativo) fica fora.
  - `user`/indefinido (pane do operador): hub inteiro, inalterado.
- Trace `mcp-hub-filtered` com `{ role, kept, dropped: [keys] }` — só chaves,
  nunca valores de header/env.
- `mcp-server.ts` passa `meta?.role` para o seletor.
- `nexus_pane_spawn` ganhou o arg `allowedTools`: atenuado duas vezes
  (`attenuateTools` sobre o caller/roster e depois sobre o arg) — só estreita,
  nunca alarga. É o opt-in documentado para o Maestro pedir MCPs do hub ao
  worker (ex.: `mcp__github__*`), com a dica na descrição do arg.
- Nomes de servidor continuam sanitizados; `computer-use` segue renomeado
  para `user-computer-use` (a CLI reserva o nome).

## Validação
- `npx vitest run src/main/mcp-hub src/main/orch/mcp-server
  src/main/orch/tools-panes` — inclui worker sem pedido → `[]`, worker com
  `mcp__github__*` → só github, orquestrador com 2 stdio + remoto autenticado
  + remoto OAuth → 3, operador → hub inteiro, `operatorChild` inalterado.
- `npm run typecheck` limpo; `npm run security:renderer-sinks` → 0 sinks.
