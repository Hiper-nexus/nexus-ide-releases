# F-1160 — Missão nativa recusada (pane_unavailable) para pane recém-aberto

## F-1160 | categoria: funcional | severidade: alta | status: corrigido
- Fluxo: pane novo do operador cria a missão nativa logo após nascer (runtime canônico, depois de encerrar a missão padrão).
- Arquivo:linha: `src/main/orch/renderer-mission-authority.ts` (`ownedPaneSession`).
- Causa: o `sessionId` do espelho de panes do Main só chega no sync do renderer, agendado para o próximo quadro; o pedido de criar a missão chegava antes e era recusado com `pane_unavailable` em milissegundos.
- (resolvedor) Correção: com o pane já no espelho como `cli-agent` e sem sessão, a sessão vem da ficha PTY do próprio Main, só quando há exatamente um PTY vivo daquela janela para aquele pane; sem PTY, PTY de outra janela ou mais de um continua recusado. Demais checagens inalteradas. O roteiro de runtime passa a reportar o código exato de uma recusa de adoção.
- Validação: `renderer-mission-authority-adoption.test.ts` (RED no HEAD com `pane_unavailable`; guardas dos três casos de recusa); suítes de autoridade 214/214.
