# F-744 — Maestro Codex levava minutos para abrir panes: roteava tudo antes de abrir

## F-744 | categoria: desempenho | severidade: alta | status: corrigido
- Tela/fluxo: missão da aba com Maestro Codex (GPT-6.1-Sol medium), Windows. O operador pede "solte os demais CLI para te ajudar".
- Arquivo:linha:
  - `src/main/orch/orchestrator-doctrine.ts` (bullet DELEGAÇÃO);
  - `src/main/orch/tools-domain.ts` (descrição de `nexus_route_task`);
  - `src/main/orch/tools-panes.ts` (descrição de `nexus_pane_spawn`).
- Passos:
  1. Pedir ao Maestro para abrir vários workers.
- Esperado: os panes nascem logo depois do pedido.
- Observado (relato do operador, 02/10): "parece que codex tem dificuldade abrir panes aqui windows"; "ele demora demais abrir panes". O primeiro pane nasceu 3 min 17 s depois do pedido.
- Evidencia (rollout do Codex + audit, turno de 238 s):
  - Raciocínio e geração do modelo: ~170 s em 5 rodadas.
  - Uma rodada inteira (~60 s de raciocínio + script de 3.965 caracteres) só para chamar `nexus_route_task` 5 vezes. Depois outra rodada para os 5 `nexus_pane_spawn` com `routeReservationId`.
  - A descrição da `nexus_route_task` dizia "Call it for every delegation" e a doutrina do kickoff dizia "nexus_route_task e nexus_pane_spawn". Mas, desde 0.76.110, o spawn sem `adapterId` dentro da missão já roteia, com reserva, na mesma chamada (`missionAutoRoute`).
  - Execução das ferramentas: 45 s, serializados pelo Codex (`supports_parallel_tool_calls` é falso por padrão em servidor MCP) mesmo com o modelo pedindo `Promise.allSettled`.
  - Cada chamada pagou ~1–2 s de hooks: no Windows cada hook do Nexus é um `powershell.exe -EncodedCommand` com `Invoke-WebRequest` dentro do PowerShell que o próprio Codex abre para rodar o hook.
- (resolvedor) Correcao:
  - A doutrina e as descrições ensinam a delegação de uma chamada: `nexus_pane_spawn({task, prompt})` sem `adapterId`. `nexus_route_task` fica para inspecionar uma rota antes de decidir (juiz, alternativas, custo). Some uma rodada inteira do modelo por leva de workers.
  - Testes que reprovam o código antigo:
    - `orchestrator-doctrine.test.ts`: "delegar não passa por nexus_route_task";
    - `route-tools.test.ts`: a descrição não manda rotear antes de cada spawn.
  - Pendente (medido, sem correção nesta versão): o custo dos hooks por chamada e a serialização das chamadas MCP do Codex. Hooks `async` reordenariam o status contra o `Stop` (o portão de regressão devolve o turno sem novo prompt), então a troca precisa de outro desenho.
