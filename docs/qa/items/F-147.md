# F-147 — Kimi não abre: tela "Trust this folder?" do Kimi Code 0.41+ fica sem resposta

## F-147 | categoria: funcional | severidade: alta | status: corrigido
- Tela/fluxo: pane Kimi (worker de missão ou pane aberto pelo operador) sobe e
  fica mudo, sem composer — o prompt inicial é colado no modal e engolido.
- Arquivo:linha: `src/main/orch/cli-prompt-autoresponder.ts:111` (assinatura
  nova), `src/main/orch/mcp-server.ts:1184` (bind por pane),
  `src/main/orch/boot-prompt-hold.ts` (hold da injeção pelo `earlyPhrase`).
- Passos: 1) abrir um pane Kimi num cwd ainda não confiado (o auto-update
  0.41→0.42 pode zerar o store de trust); 2) observar a tela "Trust this
  folder?" parada.
- Esperado: o pane responde a tela, chega ao composer e recebe o prompt.
- Observado: tela parada, nenhuma tecla, o brief da missão é engolido — o
  operador descreve como "o Kimi não está nem abrindo".
- Evidencia (ao vivo, CLI real nesta máquina): probe de PTY com
  `kimi --model kimi-code/k3` numa pasta nova mostrou
  `Trust this folder?` / `↑↓ navigate · Enter select · Esc exit`, com
  `❯ Trust this folder` já destacado e `Don't trust` cuja descrição é
  `Exit Kimi Code. Asked again next launch.`. `kimi "texto"` responde
  `unknown command 'texto'. See 'kimi --help'.` — por isso o canal do prompt
  inicial do Kimi é colagem, não posicional (`src/shared/cli-initial-prompt.ts`).
  `BUILTIN_PROMPT_SIGNATURES` cobria Claude/GLM/LongCat/AGY/Grok e não tinha
  Kimi: a tela ficava para sempre e a pane parecia não abrir.
- Correcao: assinatura `kimi-folder-trust` (multi-sinal: `trust this folder?`,
  `trust starts the listed project mcp targets`, `don't trust`) respondendo
  `\r` — Enter no item já destacado "Trust this folder", mesma forma do
  `grok-folder-trust` — com `earlyPhrase` para segurar a injeção do prompt até
  a tela sair. O bind é por pane (`onSpawned`), então cobre pane de missão e
  pane aberto pelo operador; o kill switch de Settings › Mission Driver
  continua valendo e a resposta é uma só por sessão.
- Validacao: `npx vitest run src/main/orch/cli-prompt-autoresponder.test.ts`
  (16/16, 1 novo com a transcrição ao vivo) e
  `src/main/pty/first-run-interstitial.test.ts` (47/47);
  `npx vitest run src/main/orch src/main/pty` 4087/4087;
  `npm run typecheck` limpo.
- Nota: o Kimi se auto-atualiza no launch (0.41.0 → 0.42.0 durante o probe);
  a assinatura foi transcrita da 0.42 e a 0.41 mostra a mesma redação.
