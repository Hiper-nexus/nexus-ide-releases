# F-1648 — Muse macOS exige Homebrew apesar do instalador nativo oficial

## F-1648 | categoria: funcional | severidade: media | status: corrigido

- Tela/fluxo: Providers → instalar Muse Code no macOS sem Node/npm e sem Homebrew.
- Arquivo:linha: `src/main/adapters/cli-install-recipes.ts:313`.
- Passos: oferecer somente bash como runner disponível e selecionar a receita Muse para darwin.
- Esperado: selecionar o instalador nativo oficial via transporte script existente, sem exigir npm/Homebrew, sem iniciar login automático e sem gravar PATH em perfis de shell.

Env exato: `{ MUSE_LOGIN: '0', MUSE_NO_MODIFY_PATH: '1' }`. Confirmação e comando manual preservam essas escolhas; o comando manual usa o helper de quoting POSIX existente. Transporte/download/executor não foram reimplementados. Update de Muse instalado por cask continua coberto pela suíte existente. `builtin/muse.json` permanece com o canal cask válido de backup.

A leitura atual mostra encaminhamento de `recipe.env`; este executor não editou `provider-config-store`, `path-resolver` ou seus testes. O mapa deve chegar ao filho bash, com precedência sobre o ambiente herdado. Verificação integrada do executor fica com Newton.
