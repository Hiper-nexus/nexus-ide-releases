# F-1648 — Muse macOS exige Homebrew apesar do instalador nativo oficial

## F-1648 | categoria: funcional | severidade: media | status: corrigido

- Tela/fluxo: Providers → instalar Muse Code no macOS sem Node/npm e sem Homebrew.
- Arquivo:linha: `src/main/adapters/cli-install-recipes.ts:313`.
- Passos: oferecer somente bash como runner disponível e selecionar a receita Muse para darwin.
- Esperado: selecionar o instalador nativo oficial via transporte script existente, sem exigir npm/Homebrew, sem iniciar login automático e sem gravar PATH em perfis de shell.
- Observado antes do fix: somente `brew install --cask muse-code`; seleção recusava o Mac sem brew. Distinto de F-514 (URL antiga `/muse/install.sh` dava 404); relacionado ao fluxo geral F-1647.
- Correcao: Muse darwin recebe script `https://dev.meta.ai/install.sh` primeiro e cask como backup quando bash não existe. `scriptRecipe` aceita `env?: Readonly<Record<string, string>>`, clonado/congelado; o tipo `ScriptInstallRecipe` já possuía o campo. Env exato: `{ MUSE_LOGIN: '0', MUSE_NO_MODIFY_PATH: '1' }`. Confirmação e comando manual preservam essas escolhas; o comando manual usa o helper de quoting POSIX existente. Transporte/download/executor não foram reimplementados. Update de Muse instalado por cask continua coberto pela suíte existente. `builtin/muse.json` permanece com o canal cask válido de backup.
- Integracao Newton: `runInstallRecipe`/`runScriptInstall` pertencem a Newton. A leitura atual mostra encaminhamento de `recipe.env`; este executor não editou `provider-config-store`, `path-resolver` ou seus testes. O mapa deve chegar ao filho bash, com precedência sobre o ambiente herdado. Verificação integrada do executor fica com Newton.
- Evidencia TDD: antes da implementação, `npx vitest run src/main/adapters/cli-install-recipes.test.ts -t F-1648` → 4 falhas esperadas/1 passado. Depois, suíte completa → **51/51 passados**, incluindo seleção sem npm/brew, preferência nativa, backup cask, env na confirmação/comando manual e atualização do cask existente. Oxlint focado e `git diff --check` passaram. `npx tsc --noEmit --incremental false` → **exit 0**. Status corrigido na receita; não verificado por instalação nativa em Mac.
- Fontes primarias verificadas por leitura HTTP, sem executar downloads: [docs Meta](https://dev.meta.ai/docs/muse-code), [install.sh oficial](https://dev.meta.ai/install.sh), [launcher oficial](https://api.meta.ai/muse-launcher.sh), [canal estável](https://api.meta.ai/muse-code/channels/muse-stable), [manifesto 1.4.12-R6909.1](https://lookaside.facebook.com/lookaside/muse/download/?channel=muse&version=1.4.12-R6909.1&file=manifest.json), [cask fixado](https://github.com/Homebrew/homebrew-cask/blob/41f8878ffeb52c42c53ac352fe64307f6f63d2e3/Casks/m/muse-code.rb).
- Comportamento do fornecedor: default `${HOME}/.local/bin/muse` (sobrescrevível por MUSE_INSTALL_DIR); `MUSE_NO_MODIFY_PATH` evita alterações em `.zshrc`/outros perfis; `MUSE_LOGIN=0` impede iniciar device login após recusa do download. A fase de instalação chama `MUSE_LAUNCHER_INSTALL=1` e termina após provisionar, sem iniciar sessão interativa. MUSE_LOGIN=0 não é garantia de ausência de leitura de credencial já existente pelo launcher.
- Limites: fabricante publica `aarch64_macos` e `x86_macos`; o cask declara macOS ≥12. Não houve execução em Mac Intel/ARM, instalação global/local real, login, uso de credenciais, alteração de PATH nativo ou validação Mach-O. Testes provam seleção/composição da receita, não instalação ponta a ponta no macOS. O canal estável e o launcher oficial são atualizáveis; não foi introduzido pin novo. Monitor permanece desligado; nenhuma ação de CI/release. Sem commit.
