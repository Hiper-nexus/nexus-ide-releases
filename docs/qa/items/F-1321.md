# F-1321 — Code map lia o checkout de coordenação (a raiz) e o cache colidia entre raízes

## F-1321 | categoria: funcional | severidade: alta | status: corrigido
- Tela/fluxo: as quatro ferramentas MCP do mapa estrutural (`nexus_code_map_get`, `nexus_code_map_refresh`, `nexus_code_map_query`, `nexus_code_map_blast_radius`) num worker com execução isolada (worktree `.harvest/…`, `.nexus-worktrees/…`).
- Arquivo:linha (antes):
  - `src/main/orch/tools-code-map.ts:21,23,55,69,97,99,110`: os handlers usavam `ctx.scope` (coordenação) e ignoravam `executionScopeFor` (`src/main/orch/gate.ts:410`), ao contrário de `tools-terminal.ts`, `tools-domain.ts`, `tools-handoff.ts` e `mcp-dispatch.ts`.
  - `src/main/context/orientation/orientation-service.ts:129-130`: `scopeKey` = `projectId\0checkoutId`.
  - `src/main/context/orientation/orientation-cache.ts:14-22`: `orientationCacheDirectory` = `project-…/checkout-…`, só com os dois ids.
  - `src/main/context/orientation/orientation-structural-index-cache.ts:24-30`: herda o mesmo diretório.
- Passos: 1) `mintToken` com `scope` = raiz do projeto e `executionScope` = worktree (os dois escopos exigem os mesmos `installationId/projectId/checkoutId`; só a raiz física difere). 2) Chamar `nexus_code_map_get` / `nexus_code_map_query` do worker.
- Esperado: o mapa descreve a árvore da worktree onde o worker escreve.
- Observado (sonda A1, worker em `.harvest/s240-base` com HEAD `cb3191f3f`): `nexus_code_map_get({})` devolveu HEAD `5d2323f12` (o checkout raiz) e uma query devolveu caminhos de `.harvest/f1251/...`. `orientationCacheDirectory` para os mesmos projectId/checkoutId com raízes diferentes gerava o mesmo diretório, então o mapa e o índice estrutural de uma raiz eram servidos para a outra.
- Evidencia (RED, antes da correção):
  - `tools-code-map.test.ts` › "F-1321: lê o escopo de execução, nunca o de coordenação": `expected [] to include 'src/exec-only.ts'` — a query devolveu vazio porque o mapa montado era o da raiz de coordenação.
  - `orientation-cache.test.ts` › "F-1321: raízes físicas distintas com os mesmos ids não compartilham o cache": `expected '…/checkout-…' not to be '…/checkout-…'` — mesmo diretório para as duas raízes.
- (resolvedor) Correcao:
  - Os quatro handlers passaram a usar `executionScopeFor(ctx)` em todos os sete pontos (`get`, `ensure`, `refresh`, `indexedPaths`, `ensureBlastRadius`).
  - `orientationCacheDirectory` ganhou um segmento `root-<hash da raiz>` (novo tipo `OrientationCacheScope`, que exige `rootRealPath`). `orientationCurrentPath` e `orientationStructuralIndexPath` herdam o diretório, então mapa e índice estrutural nunca cruzam de raiz; cache antigo simplesmente deixa de ser encontrado e é reconstruído.
  - `scopeKey` do `ProjectOrientationService` (memória, inflight, índices estruturais em RAM) ganhou a raiz: mesma lógica, memória isolada por árvore.

  - `npx vitest run src/main/orch/tools-code-map.test.ts src/main/context/orientation/`: 18 arquivos, 99/99.
  - `npx tsc --noEmit -p tsconfig.json`: 0 erros.
