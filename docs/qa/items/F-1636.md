# F-1636 — Grok OAuth renovável recusado pela idade do access token

## F-1636 | categoria: funcional | severidade: alta | status: corrigido

- Arquivo:linha: `src/main/adapters/auth-freshness.ts:269`; consumidor em `src/main/adapters/managed-auth-spawn-gate.ts:308` e `src/main/pty/pty-ipc.ts:402`.
- Relacionado a F-1485: o veto por idade do token foi aplicado também a sessões OIDC que possuem material completo de renovação.
- Passos: 1) usar uma fixture de auth Grok OIDC com access token vencido e emissão há 21 dias; 2) manter key, refresh_token, oidc_issuer e oidc_client_id na mesma entrada; 3) chamar o gate de spawn com `refuseExpiredGrokSession: true`.
- Esperado: o gate serializa a renovação e permite que a CLI seja líder; não declara o token fresco, não renova por HTTP no Nexus e não exige login só pela idade do access token.
- Observado: o predicado rejeitava a sessão após sete dias e impedia a CLI de iniciar. A presença de refresh_token e dos metadados OIDC não era considerada.

- Contrato do fornecedor: [autenticação](https://github.com/xai-org/grok-build/blob/main/crates/codegen/xai-grok-pager/docs/user-guide/02-authentication.md) permite renovação OIDC pela CLI; [teste do backend](https://github.com/xai-org/grok-build/blob/main/crates/codegen/xai-grok-login/src/refresh/auth_backend_contract_tests.rs) distingue rejeição `invalid_grant` de falha transitória. A idade de um access token não é prova de revogação do refresh token.

Mantém o veto legado sem esse material, o lock/família de refresh e as negativas reais reportadas pela CLI. Mensagens de recusa deixam de afirmar um prazo universal de renovação.
