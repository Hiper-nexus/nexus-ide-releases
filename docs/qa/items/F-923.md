# F-923 — operatorChoice ignorado quando o pedido chega no meio do turno

## F-923 | categoria: funcional | severidade: alta | status: corrigido
- Tela/fluxo: spawn com `operatorChoice:true` após o operador digitar o nome da CLI no pane do orquestrador.
- Arquivo:linha: `src/main/orch/operator-cli-mentions.ts` (`remember`, `operatorRecentlyNamedCli`).
- Passos: 1) Com o orquestrador ocupado, digitar "solta grok solta agy" no pane. 2) O agente chamar `nexus_pane_spawn` com `adapterId:"grok", operatorChoice:true`.
- Esperado: o pin é honrado (o operador nomeou a CLI).
- Observado (05/10): o spawn foi redistribuído para muse com o motivo `operatorChoice-sem-pedido-do-operador`.
- Causa (duas, ambas no mesmo detector):
  1. `operatorRecentlyNamedCli` juntava os chunks de input com `join(' ')`. A digitação tecla a tecla vira um chunk por caractere — "grok" ficava "g r o k" e o `\bgrok\b` nunca casava.
  2. `remember` descartava chunks com `!text.trim()` — a tecla espaço digitada sozinha sumia, e "solta grok" virava "soltagrok".
  O tap só grava input humano efetivamente escrito no PTY; com esses dois bugs o texto digitado durante o turno nunca casava o alias.
- (resolvedor) Correcao:
  - `join('')` em vez de `join(' ')` — as fronteiras de palavra já vêm dos próprios keystrokes (sanitize converte Enter em espaço).
  - `if (!text) return` em vez de `if (!text.trim()) return` — espaços são fronteira de palavra e precisam ficar.
  - Testes: `operator-cli-mentions.test.ts` ("reconhece a CLI digitada tecla a tecla no meio do turno").
- Como foi achado: relato do operador em 05/10 ("solta grok solta agy" redistribuído).
