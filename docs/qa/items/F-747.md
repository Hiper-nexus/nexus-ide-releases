# F-747 — "Atualizar CLI" do Devin falhava com um pane Devin aberto

## F-747 | categoria: funcional | severidade: media | status: corrigido
- Tela/fluxo: Ajustes › Providers › Devin CLI › "Atualizar CLI", Windows, com um worker Devin rodando.
- Arquivo:linha:
  - `src/main/adapters/cli-install-recipes.ts` (receita win32 do Devin, `replacesLocalAppDataExecutable`);
  - `src/main/adapters/in-use-executable.ts`;
  - `src/main/persistence/provider-config-store.ts` (`runPowerShellScriptInstall`).
- Passos:
  1. Deixar um pane Devin aberto.
  2. Clicar em "Atualizar CLI" no Devin.
- Esperado: o Devin atualiza; os panes abertos seguem no binário antigo até fechar.
- Observado (print do operador, 02/10): "atualização falhou: Command failed: …powershell.exe … -File …nexus-cli-install-….ps1 Copy-Item : O processo não pode acessar o arquivo 'C:\Users\…\AppData\Local\devin\cli\bin\devin.exe'".
- Causa:
  - O instalador oficial (`static.devin.ai/cli/setup.ps1`, o mesmo do `install.ps1` que o `devin update` indica) termina com `Copy-Item <novo> devin.exe -Force`.
  - O Windows recusa sobrescrever um executável em uso.
  - O updater da TUI do Devin contorna isso renomeando o binário (`devin.exe.old-3000.10.27` na máquina); o script não.
- (resolvedor) Correcao:
  - A receita declara o executável que o script sobrescreve. O runner:
    - apaga cópias `.old-*` antigas que não estão em uso (~190 MB cada);
    - renomeia o atual para `devin.exe.old-<marca>` (renomear .exe em uso é permitido);
    - roda o script;
    - se ele falhar sem deixar binário novo, devolve o antigo ao lugar.
  - Validado à mão na máquina do operador: 3000.11.1 → 3000.11.3 com panes Devin abertos.
  - Testes: `in-use-executable.test.ts` (renomear, restaurar, limpar sem tocar a cópia em uso).
