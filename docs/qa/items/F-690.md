# F-690 — Nexus matava helper reaproveitado pelo Maestro ("encerrou sem entregar")

## F-690 | categoria: funcional | severidade: alta | status: corrigido
- Tela/fluxo: missão da aba, 29/09. O Maestro reaproveita um helper que já entregou, mandando trabalho novo com `nexus_pane_write`.
- Arquivo:linha: `src/main/orch/worker-handoff-ttl.ts` (`hasCleanHandoff`).
- Passos: 1) Worker entrega um handoff e o Maestro o consome. 2) O Maestro escreve trabalho novo no mesmo pane. 3) Na primeira pausa (idle) do trabalho novo, o worker é encerrado.
- Esperado: o helper reaproveitado continua até entregar o trabalho novo.
- Observado: o Maestro disse "o helper de código encerrou sem entregar". O trace mostra `agent-pty-terminate` com `origin: pane-registry:owned-mission-session`, seguido de `worker-died-without-delivery`, às 16:06:42, 16:57:30 e 18:14:28. Nenhum `nexus_pane_close` do Maestro nesses horários.
- Evidencia: handoff consumido 16:04:22 → `nexus_pane_write` no mesmo pane 16:04:27 → morto 16:06:42; consumido 16:29:28 → write 16:29:38 → morto 16:57:30; consumido 16:22:02 → writes 16:22:11, 16:29:33, 17:47:12 → morto 18:14:28 (5,25 h de vida).
- Causa: o TTL pós-handoff (default ON) fecha o worker ocioso 30 s depois que todos os handoffs dele foram consumidos. O handoff antigo continuava `consumed`, e o trabalho novo não entrava no critério.
- (resolvedor) Correcao: o TTL guarda por sessão o último início de trabalho (transição para `working` e toda submissão nativa via `tapAgentTurnStart`). Se houve trabalho depois do último consumo, o worker está reaproveitado e só fecha depois de entregar um handoff novo e ele ser consumido. Testes: três casos F-690 em `worker-handoff-ttl.test.ts`.
