# F-224 — Enforcement de licença quebrou 21 arquivos de teste no merge

## F-224 | categoria: teste | severidade: alta | status: corrigido
- Tela/fluxo: `npm test` no `main` após o merge fbaf15fc (licença fases 4A/4B).
- Arquivos: `src/main/license-access.ts` (evaluate chama `deps.accountId()` → `require('./auth-client')`); `src/renderer/state/access-store.ts` (canUseApp fail-closed) + `access-guard.ts`.
- Esperado: merge não derruba a suíte — arquivos de teste que exercitam spawn/missão/renderer ganham o mock/fixture de licença no mesmo commit.
- Observado: 73 testes / 21 arquivos falharam. Duas causas irmãs:
  1. **Main**: `license-access.ts` faz `require('./auth-client')` (lazy, anti-ciclo) dentro de `evaluate()`. Sob Vitest, `require` não resolve `.ts` → MODULE_NOT_FOUND em qualquer caminho que consulte `getAccessState()`: spawn de worker, criação de missão, golden path de cron, stores de uso/memória, registry de worktree (16 arquivos de `src/main/`).
  2. **Renderer**: `useAccessStore` nasce fail-closed (`canUseApp: false`). O picker recusa a entrada "Terminal" (`allowPaneCreation`), o split de vacancy não cria pane e, no App, `useAccess()` → `connectAccessStore` → `refreshAccess` zera o estado sincronamente e só devolve via `billing.get` assíncrono — diálogos gated por `canUseApp` não montam nos asserts síncronos (5 arquivos em `src/renderer/`).
- Por que escapou: os ~20 arquivos de teste atualizados pela própria branch de licença receberam `vi.mock('../license-access')` / `useAccessStore.setState`; os 21 restantes foram criados/tocados no `main` fora do alcance da branch ou passaram despercebidos — o gate de release com a suíte inteira no estado mesclado é quem detectou.
- Correção: mock `licensed-access` aplicado nos 16 arquivos de main e estendido com `applyLicenseToken`/`applyOnlineLicenseToken`/`onAccessChanged`/`clearAccess`; nos 5 de renderer, concessão `useAccessStore.setState({ canUseApp: true, loading: false, maxAgents: null, cloudSync: true })` no setup — e em `App.overlays.test.tsx` o mock `billing.get` retorna licença utilizável + flush `await act(async () => {})` após `mountApp()` nos 3 testes cujos asserts são síncronos (o refresh do mount zera o estado e o resolve sai num microtask).
- Decisão: NÃO se relaxou o fail-closed — o defeito era só de isolamento de teste. `require` lazy de módulo TS segue sendo padrão do repo (quebra de ciclo auth-client ↔ license-access); fora do test runner o bundle resolve normalmente.
- Validação: 16 arquivos de main = 164 testes verdes; 5 de renderer = 114 testes verdes; `App.overlays` 11/11.
