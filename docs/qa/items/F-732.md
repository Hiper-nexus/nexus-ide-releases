# F-732 — Linux: dentro do sandbox, `node`/`npm` instalados no home davam "command not found"

## F-732 | categoria: funcional | severidade: alta | status: corrigido
- Tela/fluxo: `nexus_terminal_run` e qualquer execução pelo Bubblewrap (perfil `workspace-net`, o padrão do Autopilot no Linux) quando a ferramenta chamada mora no home: Node de mise/nvm/volta/asdf, `~/.local/bin`, `~/.cargo/bin`, npm global.
- Arquivo:linha: `src/main/runtime/process-sandbox.ts` (`linuxPlan`, `LINUX_MASKED_ROOTS`).
- Passos: 1) Linux com Node instalado pelo mise (`~/.local/share/mise/installs/node/<v>/bin` no PATH). 2) Um agente chama `nexus_terminal_run` com `node -e "console.log(1)"`.
- Esperado: o comando roda, como no macOS.
- Observado (02/10, Omarchy, bubblewrap 0.12.0): `{"exitCode":127,"stderr":"/bin/sh: line 1: node: command not found"}`. `ls ~` e `ls /home` dentro do sandbox voltam vazios. O PATH do filho lista o diretório do mise, mas ele não existe lá dentro.
- Evidencia: `npm test` nesta máquina reprovou `tools-terminal.test.ts` em "drops environment variables outside the allowlist" e "caps stdout at 1 MB" (`expected '' to be 'missing'`). Esses testes usam `node` e só rodam onde o Bubblewrap funciona de verdade; o runner hospedado do GitHub nega user namespaces aninhados e os pula, por isso o defeito nunca apareceu no CI.
- Causa: o plano do Linux cobre `/home` com tmpfs e remonta só o workspace, o runtime e os caminhos suplementares. O macOS tem `collectToolchainReadRules`, que libera a leitura dos diretórios do PATH; o Linux não tinha equivalente.
- (resolvedor) Correcao:
  - `collectLinuxToolchainMounts`: monta somente-leitura o diretório de cada entrada do PATH que mora sob uma raiz mascarada, o alvo real de cada executável dele e a árvore de runtime das ferramentas Node.
  - Nunca monta uma raiz mascarada, o home, um ancestral do home, nem nada que contenha ou esteja contido no workspace/runtime. Entrada larga demais é descartada inteira. Teto de 512 mounts.
  - Testes: `process-sandbox.test.ts` ("Linux toolchain mounts") e, com Bubblewrap real, os dois casos de `tools-terminal.test.ts` que falhavam.
- Limite conhecido: entrada do PATH que é symlink para outro lugar e shims que precisam de configuração no home (`mise shims`) continuam sem funcionar dentro do sandbox.
