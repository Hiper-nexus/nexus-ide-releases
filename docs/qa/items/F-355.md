# F-355 — "Abrir login da CLI" morre com `process is not defined` no renderer sandboxed

## F-355 | categoria: funcional | severidade: alta | status: corrigido
- Tela/fluxo: Configurações → Providers → detalhe da CLI (reproduzido com Muse
  Code) → "Abrir login da CLI" / "Entrar" / "Entrar novamente" / "+ Pane" →
  Adicionar conta. Afeta TODOS os adapters, não só o Muse.
- Arquivo:linha: `src/renderer/components/settings/cli-login-terminal.ts:50`
  (`cliLoginTypeLine`).
- Passos: 1) Abrir Providers, selecionar uma CLI com `loginCommand` (ex.: Muse
  Code). 2) Clicar "Abrir login da CLI". 3) Observar o aviso "Não foi possível
  abrir o terminal de login.", toast "Login <CLI>" de erro e o banner do
  detalhe — sem nenhum terminal aberto.
- Esperado: um pane "Login <CLI>" recebe o comando de login da ferramenta.
- Observado: exceção engolida pelo catch genérico de `openLoginTerminal`
  (AccountsManager). A causa real nunca aparecia na UI nem em log.
- Evidencia: print do painel (`.nexus/attachments/mission-context/
  mua17112-8addb3695b041a19-print-2026-09-20T16-29-09.png`). Causa raiz:
  `cliLoginTypeLine` lia `process.platform`, mas a janela é `sandbox: true` +
  `nodeIntegration: false` + `contextIsolation: true` (`src/main/window.ts`)
  e o bundle do renderer não tem shim — `process` é `ReferenceError`. Era a
  ÚNICA leitura de `process` runtime em `src/renderer/` (conferido no bundle
  empacotado `index-*.js`). Regressão introduzida em `4efa6636` (F-354, exec
  do Kimi) — vitest roda com `process` de verdade, então a suíte não via o
  erro. Efeito colateral: o pane "Login X" era criado e ficava órfão, pois a
  exceção saía depois do `addShellPane`/`waitForSession` e antes da escrita.
- (resolvedor) Correcao: `cliLoginTypeLine` agora resolve a plataforma por
  `input.platform` → `window.nexus.platform` (preload expõe
  `process.platform` na linha 1402 do preload.ts) → `process.platform` só como
  fallback fora do Electron (testes). A escrita do comando no pane ganhou
  try/catch próprio: se falhar, o pane órfão é fechado
  (`cli-login-write-failed`) e a função devolve `{ ok: false }` com mensagem
  honesta em vez de propagar para o catch genérico. O catch do
  `openLoginTerminal` passou a logar o erro real
  (`console.warn('[cli-login] …')`). Testes novos cobrem a fonte
  `window.nexus.platform` e o fechamento do pane quando a escrita falha.
  Verificação: `npx vitest run
  src/renderer/components/settings/cli-login-terminal.test.ts` +
  `npx tsc --noEmit`.
