# F-514 — Falha na instalação do Meta Muse e falta de terminal visível para instalar CLIs

## F-514 | categoria: usabilidade | severidade: alta | status: corrigido
- Tela/fluxo: Configurações > Provedores / Terminal de login (`ProvidersPanel.tsx`, `cli-login-terminal.ts`, `cli-install-recipes.ts`)
- Arquivo:linha: `src/main/adapters/cli-install-recipes.ts:152`, `src/renderer/components/settings/ProvidersPanel.tsx:428`, `src/renderer/components/settings/cli-login-terminal.ts:135`
- Passos:
  1) Em uma máquina sem a CLI do Meta Muse (ou outra CLI suportada) instalada, clicar em "Instalar" ou tentar efetuar login.
- Esperado:
  - Uma receita válida e verificada que instale a CLI para uso real no macOS/Linux.
  - Opção de instalar visivelmente via terminal interativo no Nexus para acompanhar o progresso e saídas de erro/permissão.
  - O terminal de login alertar sobre a ausência da CLI no PATH em vez de abrir um shell quebrado com `command not found`.
- Observado:
  - A receita do Muse apontava para `https://dev.meta.ai/muse/install.sh`, que retornava HTTP 404.
  - A instalação em background falhava silenciosamente e o login resultava em `command not found: muse`.
- Evidencia:
  - Atualizada a receita do Meta Muse para o Homebrew Cask oficial (`brew install --cask muse-code`).
  - Adicionado botão "Instalar via terminal" em `ProvidersPanel.tsx`, abrindo um pane dedicado com o comando correto.
  - Em `cli-login-terminal.ts`, adicionada verificação prévia de instalação com mensagem de orientação formatada de forma segura via printf.
  - 10 testes passando em `cli-install-recipes.test.ts`.
- (resolvedor) Correcao:
  - `src/main/adapters/cli-install-recipes.ts`: suporte a casks e comando textual de instalação.
  - `src/renderer/components/settings/ProvidersPanel.tsx`: adição de `installInTerminal`.
  - `src/renderer/components/settings/cli-login-terminal.ts`: aviso prévio ao tentar login de CLI ausente.
