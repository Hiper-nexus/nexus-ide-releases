# F-1493 — Editor de equipe: o seletor de Modelo mostrava um modelo e salvava outro

## F-1493 | categoria: funcional | severidade: media | status: corrigido
- Renumerado na integração com a origin (0.76.252): este achado era o F-1439 da frente de squads (nunca publicado) e virou F-1493 para não colidir com a numeração que a origin publicou (F-1436..F-1451).
- Tela/fluxo: Configurações › Equipes › Criar/Editar equipe › linha do agente › Modelo (`src/renderer/components/SquadEditor.tsx`).
- Arquivo:linha: `src/renderer/components/SquadEditor.tsx:253-279` (antes) — `<select value={agent.model ?? ''}>` sem opção vazia.
- Passos: 1) Criar equipe (o rascunho de "Criar equipe" nasce sem `model`) ou abrir uma equipe com agente sem modelo. 2) Olhar o seletor de Modelo e salvar.
- Esperado: o que aparece é o que é salvo; "sem modelo" aparece como uma escolha explícita.
- Observado: com `model` indefinido, o seletor exibia o primeiro modelo da lista (o React marca a primeira opção habilitada quando o valor não casa com nenhuma), mas o agente era salvo sem modelo. Escolher de volta "nada" também não existia.
- Causa raiz: faltava a opção para o valor `''` que o próprio `value={agent.model ?? ''}` usa; o `onChange` gravava a string crua.
- (resolvedor) Correcao: `SquadEditor.tsx` ganha a primeira opção `""` "Padrão da ferramenta" (mesmo texto do cartão da Equipe em `MissionSetupRosterRow`) e o `onChange` grava `undefined` para ela, nunca `''`.
- Evidencia:
  - RED (código antigo): `npx vitest run src/renderer/components/SquadEditor.test.tsx -t "F-1493"` → `expected 'sonnet' to be ''` (a tela mostrava `sonnet` com o agente sem modelo).
  - GREEN: `npx vitest run src/renderer/components/SquadEditor.test.tsx src/renderer/components/settings/SettingsSquads.capabilities.test.tsx` → 20/20; o teste exibe "Padrão da ferramenta", troca para `opus`, volta para o padrão e o `saveSquad` recebe `model` indefinido.
