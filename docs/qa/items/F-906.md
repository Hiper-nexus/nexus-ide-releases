# F-906 — comando pesado do AGY roda sem admissão quando o shell não carrega os hooks do Nexus

## F-906 | categoria: performance | severidade: media | status: corrigido
- Fluxo: pane AGY (Antigravity CLI 1.2.16) com `NEXUS_GATE_TOKEN` no macOS executando build/teste via `run_command`; relacionado a F-764 e F-907.
- Arquivo:linha: `src/main/pty/pty-manager.ts:2972` (readiness), `src/main/orch/native-heavy-agy-plugin.ts:114`, `resources/heavy-command/agy-tool-hook.cjs`.
- Passos: rodar o AGY real autenticado com `--dangerously-skip-permissions --print-timeout 20s --output-format json --print <make>` num workspace Git próprio com Makefile, token de gate, canal de arquivo e job base do Nexus, mas sem `BASH_ENV`/`ZDOTDIR` do Nexus.
- Esperado: todo `make` passar pela admissão física (claim `darwin-job`, grant antes do alvo, release só depois da saída física do job).
- Observado: o `make` rodou e escreveu o marcador (`done:4`) com zero admissões e zero grant. A única rota de admissão do AGY eram os arquivos de inicialização do shell (`shell.bash`/`.zshenv`) e o HTTP loopback. Com zsh e esses hooks (ambiente de produção), a rota de shell já admitia (recibo `agy-real-shell-route-receipt.json`); qualquer caminho em que o shell do AGY não os carregue escapava. O AGY não tinha admissão na camada de ferramenta nem canal de arquivo.
- Evidencia: fase `unadmitted` de `PLAN/claude-0192/agy-real-final-receipt.json` (12,5 s, marcador `done:4`, `admissions: []`, `transitions: []`).
- Correcao: plugin global exclusivo `nexus-native-heavy-command` instalado pela CLI oficial (`agy plugin validate` + `install`, assíncrono, sem shell, teto de 20 s, `AGY_CLI_DISABLE_AUTO_UPDATE=1`) no HOME do pane. O hook PreToolUse (`agy-tool-hook.cjs`) devolve `decision:'ask'` (nunca `allow`; política e Autopilot preservados): sem token, `ask` sem overwrite; comando pesado com contexto incompleto, `deny`; contexto completo, só `CommandLine` reescrito para o `job-launch.cjs` existente. No Main, AGY darwin com token só nasce depois de `ensureAgyNativeHeavyPlugin` + `createNativeHeavyLocalChannel(..., { transport: 'file' })`, com `assertDeferredCurrent()` após cada await; `registered:false` cancela o nascimento. Readiness medida contra o que a CLI grava: dono por igualdade semântica (ordem de chaves livre), entrada em `import_manifest.json` e flag `enabled` em `config/config.json` (plugin desativado é reativado pela CLI; se continuar desativado, `agy_heavy_plugin_disabled`). Symlink no destino ou nos arquivos do plugin é recusado sem executar a CLI.
- Validacao: RED do registro 2 falhas/10 (`agy-plugin-unit-red.log`: ordem de chaves e plugin desativado) → 10/10. RED da readiness com o bloco AGY desligado 3 falhas/4 (`agy-pty-readiness-red.log`) → 4/4. Focados (plugin, prova real sem opt-in, pty-manager e suítes de shutdown/tap): 164 passaram, 9 pulados, 13,80 s (`agy-focused-pane.log`). Prova real como job launchd (`agy-real-5.log`): 1/1 em 60,54 s. `baseline` sem token: hook `ask` sem overwrite, marcador `done:0`, nenhuma admissão. `scheduled` só com o plugin: overwrite `CommandLine` → `job-launch.cjs 'build'`, uma admissão `darwin-job`, `grant`→`release`, marcador ausente no grant, presente no release, job fisicamente fora no release, alvo vê as 4 variáveis do canal (`done:4`), 0 acessos TCP. `scheduled-with-shell-hooks` (ambiente de produção): uma única admissão `darwin-job` e um único grant/release. Segundo `ensure` com outro Node atualizou só o `hooks.json` próprio, sem reinstalar. HOME nativo: plugins, `import_manifest.json` (ausente antes e depois), `config.json` e `stat` das contas idênticos; nome exclusivo desinstalado pela CLI. `tsc --noEmit` exit 0 (112 s), sinks do renderer 0, `lint:main-sync` sem processo síncrono novo (91 legados), `check-main-sync.test.mjs` 26/26.
