# F-551 — Candidata Windows ficava presa ao gate de publicação macOS

## F-551 | categoria: funcional | severidade: alta | status: corrigido

- Tela/fluxo: publicação de release e atualização automática Windows.
- Arquivo:linha: `scripts/publish-release.mjs` (publicador único exigia uma
  candidata macOS antes de aceitar a candidata Windows assinada).
- Passos: 1) gerar uma candidata Windows assinada no workflow protegido; 2)
  não gerar uma candidata macOS; 3) tentar publicar a atualização Windows.
- Esperado: o canal Windows publica seus três assets Squirrel assinados sem
  aguardar macOS; o recibo/waiver ficam apenas na release canônica.
- Observado: a candidata Windows permanecia privada e o app instalado seguia
  vendo somente a versão pública anterior.
- Evidência: app instalado mostrou `v0.76.37` como mais recente enquanto o
  workflow Windows assinado `35106755397` para `v0.76.40` terminou com sucesso.
- (resolvedor) Correcao: o publicador único chamava o gate macOS e combinava
  os inventários antes de aceitar o artifact Windows; foi criado o comando
  selado `release:publish:windows`, que usa somente a candidata Windows
  assinada e publica primeiro a canônica e depois o espelho Squirrel. O filtro
  de monotonicidade agora ignora releases sem Setup Windows. Arquivos:
  `scripts/publish-release.mjs`, `scripts/windows-release-candidate.mjs`,
  testes e runbooks; commit `514e78ec`. Validado com
  `npx vitest run scripts/publish-release.test.mjs scripts/windows-release-candidate.test.mjs scripts/windows-release-workflow.test.mjs`,
  `npm run typecheck` e `npm run security:renderer-sinks`.
