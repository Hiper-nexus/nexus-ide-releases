# F-1276 — Linha legada inválida de missão `blocked` nunca era arquivada, e a recusa era silenciosa

## F-1276 | categoria: funcional | severidade: media | status: corrigido
- Tela/fluxo: abertura do escopo (`WorktreeRuntimeRegistry.forScope`), que chama `recoverInvalidState` antes de qualquer leitura do estado de worktrees.
- Arquivo:linha (antes):
  - `src/main/runtime/sqlite-workflow-state-stores.ts:92`: `TERMINAL_MISSION_STATUSES = {'done','failed'}`, aplicado em `:237`.
  - `src/main/runtime/worktree-runtime-registry.ts:142-152`: só logava `quarantined`.
- O enum de missão é `pending|running|blocked|done|failed` (`src/shared/orch-types.ts:220-226`). O próprio registry trata como vivas só `pending|running` (`worktree-runtime-registry.ts:73`).
- Mesma família do F-1253 e do F-1257 (estado durável sem saída). Achado da revisão de persistência.
- Passos:
  1. Uma missão termina `blocked` e deixa no `worktree_state` uma linha `failed` que o validador atual recusa (por exemplo, posse `../…` de antes do validador).
  2. O app abre o escopo.
- Esperado:
  - A linha terminal vai para `worktree_state_quarantine` e a projeção é zerada, como já acontece com missão `done`/`failed`.
  - Se a recuperação for recusada, o log diz por quê.
- Observado:
  - `blocked` não contava como terminal, então a recuperação devolvia `blocked/unproven-invalid-state` sem log nenhum.
  - Logo depois, `reconcileInterruptedReservations` (`worktree-runtime-registry.ts:161`) lançava `ScopedStoreCorruptionError` sem nomear a causa, e todo `forScope` do escopo falhava.
- Evidencia (RED, fontes anteriores restauradas com `git show HEAD:` em `sqlite-workflow-state-stores.ts` e `worktree-runtime-registry.ts`):
  - `sqlite-workflow-state-stores.test.ts` › "F-1276: archives the terminal legacy projection of a mission that ended blocked" falha com `expected { action: 'blocked', reason: 'unproven-invalid-state' } to match object { action: 'quarantined', reason: 'terminal-legacy-state' }`.
  - `worktree-runtime-registry.test.ts` › "F-1276: names the unproven invalid worktree state it keeps fail-closed" falha com `expected "warn" to be called with arguments: [ StringContaining{…} ]`.
  - Resumo: `Tests  2 failed | 36 skipped (38)`.
- (resolvedor) Correcao:
  - Causa: o conjunto de missões terminais da recuperação divergia do registry, que já tratava `blocked` como terminal na liberação de donos mortos.
  - `sqlite-workflow-state-stores.ts`: `TERMINAL_MISSION_STATUSES` passa a incluir `blocked`. As outras provas continuam valendo:
    - o registro precisa estar `integrated|failed|abandoned`;
    - a tarefa, se existir, precisa estar `done|failed`;
    - o dispatch, se existir, precisa ser terminal.
  - Nada no Git é tocado: o checkout fica e só a projeção é arquivada.
  - `worktree-runtime-registry.ts`: quando a recuperação devolve `blocked`, o registry escreve `console.warn` com a razão (`unproven-invalid-state`) antes da leitura que vai falhar.
  - Testes:
    - variante do caso "archives a terminal legacy projection" com `missions.status='blocked'`, que agora vai para `quarantined` e deixa a projeção vazia na revisão 5;
    - no registry, linha `[{}]` não provável: `forScope` ainda lança e o aviso nomeia `kept fail-closed (unproven-invalid-state)`.
- Validacao: `sqlite-workflow-state-stores.test.ts` + `worktree-runtime-registry.test.ts`, `Test Files  2 passed (2)`, `Tests  38 passed (38)`.
