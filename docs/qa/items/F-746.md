# F-746 — Retomada e rota mandam trabalho para CLI de login nativo com a cota medida em 0%

## F-746 | categoria: funcional | severidade: media | status: aberto
- Tela/fluxo: missão com Maestro Codex. O Maestro retoma um worker Devin (`nexus_pane_spawn` com `resume`) quando a conta Devin está em 0%.
- Arquivo:linha:
  - `src/main/persistence/account-store.ts` (`hasAvailableAccount`);
  - `src/main/orch/tools-panes.ts` (ramo `resume`).
- Passos:
  1. Um worker Devin gasta o restante da cota da conta.
  2. O Maestro retoma esse worker com outro brief (11:54, 02/10).
- Esperado: o Nexus recusa a retomada com o motivo (sem cota até o reset) e a delegação vai para outra CLI pela rota.
- Observado (print do operador): o pane Devin nasce com "Max · 0% remaining (resets in 1d 17h)". Mesmo com o Enter, só responderia que a cota acabou.
- Evidencia:
  - A cota do Devin é medida (`quota/devin-usage.ts`, GetUserStatus).
  - `hasAvailableAccount` devolve `true` para adapter sem contas cadastradas (login nativo) e não consulta a cota medida. A retomada mantém a CLI do pane retomado sem nenhuma checagem de cota.
- (resolvedor) Correcao: pendente. Direção:
  - leitura medida com janela esgotada torna o login nativo indisponível para a rota (como o cooldown das contas gerenciadas);
  - a retomada numa CLI nessas condições é recusada com hint para abrir sem `resume`.
