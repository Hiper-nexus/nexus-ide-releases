# F-605 — AGY pane dispara diálogo de Keychain "Chaves Não Encontradas" em loop

## F-605 | categoria: integração | severidade: alta | status: mitigado
- Tela/fluxo: pane AGY (Antigravity) ativo; diálogo do macOS "Chaves Não
  Encontradas — Não foi possível encontrar as chaves para armazenar
  'antigravity'" reaparecendo continuamente sobre o app.
- Arquivo:linha: `src/main/pty/pty-manager.ts:2189-2199` (grant read-only de
  `~/Library/Keychains` para AGY); `src/main/pty/pre-spawn-probe.ts:265+`
  (AGY guarda sessão OAuth no Keychain nativo).
- Passos: 1) Abrir pane AGY sem credencial `antigravity` existente no
  Keychain. 2) O CLI tenta ler/renovar a sessão repetidamente.
- Esperado: uma falha de auth clara, uma vez, orientando re-login.
- Observado: o binário AGY (pane 6, 19:32–21:40, 17 min de CPU) ficou em
  loop tentando armazenar/renovar a credencial; o macOS reabria o diálogo a
  cada tentativa; Jev classificou a tela como `waiting_for_human` (19:33).
- Evidencia: `security find-generic-password -s antigravity` → item
  inexistente; keychain default íntegra (login.keychain-db, desbloqueada).
  Mitigação aplicada: pane fechado; SecurityAgent não reabriu.
- Orientação ao operador: NUNCA clicar "Reajustar Para Padrões" (reseta a
  keychain default e órfã senhas salvas); clicar "Cancelar" e refazer o
  login do AGY num Terminal comum (fora do pane governado), para que o item
  seja criado com permissão de escrita.
- (aberto) Follow-up de produto: avaliar se o pane AGY precisa de grant de
  ESCRITA na Keychains (hoje read-only por design) ou de um detector de
  "auth ausente" que aborte o spawn com orientação, em vez de deixar o CLI
  girar diálogos do sistema.
