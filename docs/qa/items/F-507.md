# F-507 — Estado de runtime de missão (`.nexus/swarms/`) commitado; a política do `.gitignore` não o cobria

## F-507 | categoria: infra | severidade: media | status: corrigido
- Tela/fluxo: higiene de repositório. Não há superfície de UI.
- Arquivo:linha: `.gitignore:140-145` (bloco "Artefatos de runtime do próprio
  Nexus") e os 12 arquivos sob `.nexus/swarms/`.
- Passos: 1) rodar uma missão neste checkout; 2) `git status`.
- Esperado: o `.gitignore` declara a política explicitamente — "Artefatos de
  runtime do próprio Nexus (logs, execuções, auditoria visual): são gerados por
  uso local e não pertencem ao histórico" — e lista `/.nexus/logs/`,
  `/.nexus/pet-hatch-runs/`, `/.nexus/ui-audit/`, `/.nexus/attachments/`,
  `/.nexus/mcp-hub.json`, `/.nexus/tmp-cdp/`, com `.nexus/project.json` como a
  única identidade que deve ser versionada (comentário na linha 81).
- Observado: `/.nexus/swarms/` **não estava na lista**, e o commit `3af14cb1`
  ("fix(orch): F-143 …") adicionou 12 arquivos de estado de missão em execução:
  marcadores `.nudge` de inbox de PTY e transcripts JSON de três missões
  (`mission-a7b285ee…`, `mission-cb0bbc72…`, `mission-eae4c012…`), referenciando
  sessões de PTY reais (`pty-mtruu775-7`, `pty-mtruzpft-13`, `pty-mtru7v31-4`,
  `pty-mtrvh5jf-15`).

  `git check-ignore -v .nexus/swarms/` não retornava nada antes da correção.
  O conteúdo é regenerado a cada missão e **cresce sem limite**: cada execução de
  agente adiciona arquivos. Não é um vazamento de segredo — verifiquei que não há
  token nem caminho absoluto de usuário nesses JSONs — mas é estado de runtime
  num histórico que vai para uma release.
- Evidencia: `git diff --name-only 3c61b149..HEAD | grep "^\.nexus/"` → 12
  arquivos. `git diff --stat 3c61b149..HEAD -- .nexus/` → "12 files changed, 92
  insertions(+)". `git log --oneline --diff-filter=A -- .nexus/swarms/` →
  `3af14cb1`.
- Correcao: `/.nexus/swarms/` acrescentado ao bloco de artefatos de runtime do
  `.gitignore`, com comentário dizendo o que é e por que cresce sem limite; e
  `git rm -r --cached .nexus/swarms` para destrackear os 12 arquivos **mantendo
  todos no disco** (verificado: `find .nexus/swarms -type f | wc -l` → 12 depois
  do `--cached`). `git check-ignore -v` agora resolve para `.gitignore:147`.
- Validacao: `git check-ignore -v .nexus/swarms/mission-a7b285ee…/transcript/` →
  `.gitignore:147:/.nexus/swarms/`. `git diff --cached --name-status` → 12
  entradas `D` mais `.gitignore`, nenhum arquivo de código. Os 12 arquivos
  continuam no disco. `npx tsc --noEmit` não é afetado (nenhum `.ts` tocado).
- Limites: os 12 arquivos **permanecem no histórico** em `3af14cb1` e nos commits
  seguintes. Removê-los do histórico exige rewrite, que não foi feito. Como o
  conteúdo não é sensível, o custo é só de ruído, não de segurança.
- Relacionado: F-508 (o mesmo mecanismo, com escopo e peso muito maiores, já em
  `origin/main`).
