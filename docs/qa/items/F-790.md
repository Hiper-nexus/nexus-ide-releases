## Sonda `--version` fora do Main (03/10, pós F-764)
- Causa: incidente F-764 e a blindagem C.5, "zero `*Sync` pesado no main" (`docs/analysis/2026-10-03-main-thread-hang/HANDOFF.md`). A primeira resolução de uma CLI de IA com mais de uma instalação rodava `execFileSync --version` (até 1,5 s por candidato) no Main — no boot (`initAdapterRegistry` → inventário), no spawn e no gate de versão do Codex (`--dangerously-bypass-hook-trust`).
- Correção: `resolveCliBinary` continua síncrono, mas só lê versões já em cache (caminho real + mtime, falhas incluídas). Se falta a versão de algum candidato, mantém a ordem do PATH (comportamento antigo) e dispara `probeCliBinaryVersion`: `execFile` assíncrono, sem shell, mesmo teto de 1,5 s, deduplicado por caminho real + mtime. Quando a sonda aprende uma versão, o registry refaz o cache de binários e avisa o renderer (`onCliVersionLearned`), então a próxima resolução — e o próximo spawn — já usa a mais nova. Aquecimento sem bloquear no boot (`initAdapterRegistry` → `warmCliBinaryVersions`, junto do inventário e da descoberta de modelos), aguardado no "Reexaminar CLIs" e no pós-atualização (`rescanAdapterBinaries`). O gate do Codex mantém a API síncrona: lê o mesmo cache (a instalação única do Codex também é aquecida); versão ainda não sondada conta como desconhecida — o gate age como antes com versão desconhecida (sem a flag) — e a sonda sai em segundo plano.
- Validação (mesmo Mac; duas instalações do `codex`, CLI falsa em Node; base `00ecf538` lida via `git show HEAD:`): 1ª resolução bloqueava o Main por 310,7 ms com 2 `execFileSync`; agora 5,9 ms e 0 `execFileSync` (ordem do PATH na 1ª, a mais nova logo após o aquecimento). Testes do F-790 em `path-resolver.test.ts` aguardam o aquecimento e mantêm a cobertura (mais nova vence, memória de sucesso/falha por caminho real + mtime, ordem do PATH com versão ilegível/igual, alias do mesmo arquivo não sonda, node/git nunca sondam, aviso sem caminhos); novos: a resolução nunca chama `execFileSync` (sondas via `execFile`, sem duplicar em voo) e `alsoSingle` só sonda a instalação única quando pedido; gate do Codex com cache frio em `codex-cli-version.test.ts`. 11 suítes da validação acima: 343 passaram, 4 ignoradas (Windows).
- Limites: até o aquecimento terminar (o tempo de um `--version` por instalação, em paralelo — ~0,15 s por CLI em Node na medição acima; ou após uma atualização feita fora do Nexus), a escolha fica na ordem do PATH e o primeiro pane Codex pode abrir sem `--dangerously-bypass-hook-trust` (cai na revisão de hooks, como em versão desconhecida). A sonda `--help` do `--no-daemon` (F-689, só Windows) segue síncrona: ali "desconhecido → sem flag" derruba o pane elevado, e não há Windows nesta validação.
