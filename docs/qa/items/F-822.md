# F-822 — Failover rodava git síncrono e cru no Main para montar o pacote de continuidade

## F-822 | categoria: performance/seguranca | severidade: alta | status: corrigido
- Tela/fluxo: failover de conta de worker de missão main-owned (F-775 item 1) — montagem do pacote de continuidade com "Touched files" e "Diff (stat)".
- Arquivo:linha: `src/main/orch/failover-mission-respawn.ts` (`planMainOwnedFailoverRespawn`, antigo `collectGitTaskState`/`resolveGitState`; `collectFilesModified` em `worker-files-modified.ts`).
- Passos: 1) Worker de missão main-owned com conta gerenciada. 2) A cota da conta acaba (ou acaba para vários panes de uma vez). 3) O failover planeja o respawn na conta irmã.
- Esperado: o planejador é puro; o estado da tarefa é coletado fora dele, sem bloquear o Main, com o envelope seguro de git e só na worktree do próprio pane.
- Observado (revisão adversarial `review-ec8524a8.md`, M4 e B6): o planejador "puro" rodava três processos git SÍNCRONOS no Main — `execFileSync git rev-parse` (3 s), `git status --porcelain` (5 s) e `git diff --stat` (3 s): até 11 s por pane, em série quando a cota acaba para N panes. Com git cru (sem `safeGitArgv` nem `assertSafeLocalGitConfig`), um `core.fsmonitor` ou `diff.*.textconv` plantado no checkout executaria fora do sandbox. Em checkout compartilhado da missão, "Touched files" listava o trabalho de outros workers. O teste `failover-mission-respawn.test.ts:157` dizia verificar o recibo "pinned" sem verificar, e rodava git real contra `/workspace/mission-checkout` (inexistente).

### Causa
O item 1 do F-775 coletou o estado com as funções síncronas de `worker-files-modified.ts` (feitas para o fechamento de writer, não para o failover) dentro do planejador.

### (resolvedor) Correcao
- `collectGitTaskState(worktreePath, { sharedRootPath, git })` (novo, exportado): assíncrono, com `AsyncProcessGitRunner` (hooks nulos, `core.fsmonitor=false`, ambiente limpo) e `assertSafeLocalGitConfigAsync` ANTES de qualquer `status`/`diff`; `diff --stat --no-ext-diff --no-textconv`; timeout de 1 s em CADA consulta (`GIT_STATE_TIMEOUT_MS`, imposto por um runner que embrulha o injetado); qualquer falha → estado vazio (a seção some do pacote, o failover segue).
- Só a worktree do PRÓPRIO pane: coleta apenas quando `executionScope` do pane é diferente da raiz de coordenação (`scope`). Checkout compartilhado → nada (o pacote não lista trabalho alheio).
- `planMainOwnedFailoverRespawn` voltou a ser puro: recebe `touchedFiles`/`diffStat` prontos. Quem coleta é `respawnMainOwnedPaneWithAccount` (assíncrono, com `deps.git` injetável para teste); sem worktree a coletar, nem há `await` antes do spawn.
- O parâmetro `cwd` (caminho arbitrário passado pelo chamador) saiu: o alvo vem do meta do próprio pane.

### Validacao
- `PATH=/opt/homebrew/opt/node@22/bin:$PATH npx vitest run src/main/orch/failover-mission-respawn.test.ts` → **12 testes passando**, todos herméticos (git falso injetado, diretórios temporários reais para o `realpath`; `node:child_process` com `execFileSync`/`spawnSync` substituídos por espiões que lançam — nenhum é chamado no caminho do respawn nem no planejador).
- Casos novos: checkout compartilhado não roda git; worktree própria confere a config local antes, `diff` sem driver externo, timeout de 1 s em tudo; config executável plantada (`core.fsmonitor`) recusa sem rodar `status`/`diff`; git lento/quebrado devolve vazio; planejador puro sem git.
- O teste da linha ~157 foi renomeado e passa a afirmar o que de fato prova: a conta EXPLÍCITA vai para o spawn (`accountId: 'account-b'`), que é o que faz o recibo nascer `source: 'pinned'` — o recibo em si é coberto em `provider-config-spawn.test.ts:1791`.

### Riscos
- Worker em checkout compartilhado perde "Touched files"/"Diff" no pacote (intencional: era trabalho dos outros).
- Repositório com config local executável legítima (ex.: fsmonitor do próprio dono) fica sem a seção de estado no pacote.

### Fora do escopo
- `worker-files-modified.ts` continua síncrono para o seu uso original (fechamento de writer); só o failover deixou de usá-lo.
