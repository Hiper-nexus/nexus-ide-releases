# F-716 — No Windows, a guarda de link do F-229 aceitava a raiz do perfil e pastas irmãs como "dentro"

## F-716 | categoria: seguranca | severidade: media | status: corrigido
- Tela/fluxo: spawn de pane com overlay de provider (droid, cursor, copilot, AGY…) quando o link de credencial/config no provider-state não aponta para o arquivo esperado.
- Arquivo:linha: `src/main/pty/provider-state-env.ts` (`materializeProviderState`), `src/main/adapters/managed-credentials.ts` (`prepareCheckoutProviderHome`), `src/main/util/path-inside.ts` (novo).
- Passos: 1) Materializar o provider-state de um checkout. 2) Trocar `.factory/auth.json` no overlay por uma junction para a pasta do perfil nativo (ou para `C:\Users\operator2`). 3) Abrir o pane de novo.
- Esperado: link que resolve fora de `targetDir`/`sourceDir` (incluindo a própria raiz e irmãs com o mesmo prefixo) é adulteração, e o spawn falha fechado: "Provider config link points outside its auth source".
- Observado: no Windows o spawn seguia. O link era removido e re-apontado em silêncio. O teste `rejects redirected auth before writing outside checkout state` passava no Mac e falhava no Windows (candidato 0.76.154).
- Evidencia: `path.toNamespacedPath(root + sep)` no win32 chama `path.resolve`, que tira o separador final. A raiz vira prefixo solto: `\\?\C:\…\native` "contém" `\\?\C:\…\native` e `\\?\C:\…\native2\auth.json`.
- Causa: a contenção do F-229 usava `startsWith` sobre caminhos namespaced. A comparação também ignorava a caixa do Windows.
- (resolvedor) Correcao:
  - `isStrictlyInside(root, candidate)` usa `path.relative` e respeita a fronteira de segmento e a caixa do win32. Os dois pontos do F-229 usam essa função.
  - O efeito antes da correção era limitado: o link nunca era seguido, só re-apontado para o arquivo certo. Mesmo assim, a detecção de adulteração tinha sumido no Windows.
  - Testes: casos `sibling` em `provider-state-env.test.ts` e `managed-credentials.test.ts`, mais `path-inside.test.ts`. Os casos novos reprovam o código antigo no Windows.
  - O teste do AGY consolidado comparava `realpath`; no Windows o link é hardlink, então agora compara `dev`/`ino`.
