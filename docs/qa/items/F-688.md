# F-688 — Codex no Windows sem ferramentas: host fora do MAX_PATH

## F-688 | categoria: funcional | severidade: alta | status: corrigido
- Tela/fluxo: pane Codex no Windows (pré-revisão da missão, 29/09 17:09).
- Arquivo:linha: `src/main/pty/pty-manager.ts` (resolução do `bin` do agente); `src/main/adapters/cli-install-recipes.ts` (`selectCliUpdateRecipe`, ramo npm).
- Passos: 1) Node portátil do WinGet (prefixo global do npm = pasta do Node). 2) `npm i -g @openai/codex` (ou o "Update now" da própria TUI). 3) Abrir um pane Codex e pedir qualquer ferramenta.
- Esperado: as ferramentas rodam; ou o Nexus diz o que fazer.
- Observado: o Maestro — "o Codex da pré-revisão não conseguiu rodar ferramentas". `logs_2.sqlite` do provider-state: `failed to spawn code-mode host C:\Users\Administrador\AppData\Local\Microsoft\WinGet\Packages\OpenJS.NodeJS.22_…\node-v22.23.2-win-x64\node_modules\@openai\codex\node_modules\@openai\codex-win32-x64\vendor\x86_64-pc-windows-msvc\bin\codex-code-mode-host.exe … (os error 3)` em toda chamada.
- Evidencia: o Codex >= 0.157 roda toda ferramenta por `codex-code-mode-host.exe`, no próprio pacote npm. Nesse prefixo o caminho tem 262 caracteres; o Windows aceita até 259. Nesta máquina o Codex já tinha ido para `~/.local/bin` às 17:40, mas os panes abertos antes seguiam no executável antigo. O "Atualizar CLI" reinstalava no mesmo prefixo longo (F-364 mantém o dono).
- Causa: nada no Nexus olhava o comprimento do caminho do host. Um cliente com Node do WinGet e nome de usuário comprido recebe um Codex que conversa mas não executa nada.
- (resolvedor) Correcao: `codex-windows-prefix.ts` calcula o caminho do host (x64/arm64). No spawn, `windowsCodexShimWithinMaxPath` troca o `codex.cmd` de prefixo longo pela instalação curta verificada (`%USERPROFILE%\.local\bin`, que o resolvedor já busca) ou recusa com a correção exata; atalho curto, `.exe` nativo e Codex sem host passam intactos. O "Atualizar CLI" de um Codex em prefixo longo reinstala em `%USERPROFILE%\.local\bin`. Testes: `codex-windows-prefix.test.ts`, `cli-install-recipes.test.ts`.
