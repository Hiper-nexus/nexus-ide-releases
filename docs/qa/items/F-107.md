# F-107 — Quarentena de identidade aceita fork com origin divergente (teste vermelho no HEAD)

## Status
aberto — investigar antes da próxima release

## Descrição
`src/main/persistence/project-identity.test.ts` › "rejects a reachable anchor
when portable origins explicitly diverge" falha de forma DETERMINÍSTICA no
HEAD limpo (v0.65.0, sem nenhuma mudança local): um fork clonado localmente
com o manifest copiado e `origin` reescrito para outro repositório
(`git@github.com:acme/trusted.git` → `https://github.com/acme/fork.git`)
deveria ser posto em quarentena (`repository-lineage-mismatch`) e NÃO é —
`resolveProjectExecutionScope` aceita a identidade.

O cenário git do teste reproduzido à mão se comporta como o teste espera
(origin reescrito corretamente, história compartilhada), então a suspeita é
regressão na lógica de divergência de origins portáveis (normalização
SSH/HTTPS × comparação de repo), não no teste.

## Por que importa
É a fronteira que impede um checkout/fork de ADOTAR a identidade (e o
runtime/project-runtime) de outro projeto. Aceitar origem divergente abre
adoção indevida de identidade de projeto — classe de bug de segurança, não
cosmético.

## Reproduzir
```bash
npx vitest run src/main/persistence/project-identity.test.ts
# 1 failed | 23 passed — determinístico (3/3 tentativas)
```

## Notas
- Pré-existente: falha igualmente em HEAD limpo (verificado com stash).
- As outras 23 verificações de quarentena passam — o buraco parece
  específico do caminho "anchor alcançável + origins divergentes".
