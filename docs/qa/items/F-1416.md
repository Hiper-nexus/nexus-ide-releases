# F-1416 — "sessão expirada" falsa na conta que é a sessão do CLI, e o Redline sem a cota dela

## F-1416 | categoria: funcional | severidade: alta | status: corrigido
- Tela/fluxo: Configurações › Contas › Claude. A conta "retorno"
  (retornoja@gmail.com) mostrava as etiquetas "Em uso", "sessão do CLI" e
  "assinatura" e o aviso vermelho "sessão expirada — entre novamente". Essa
  conta está logada e funcionando. No Redline faltava a cota dela.
- Esperado: a conta logada aparece saudável, com 5 Horas e Semanal lidas da
  própria credencial, no app e no Redline.

### Causa raiz (Claude)
1. `src/main/quota/claude-native-account.ts:90`: `probeClaudeCredentialIdentity`
   devolve `'auth-expired'` só porque `expiresAt <= now`, sem olhar o refresh
   token.
2. `src/main/quota/claude-account-usage.ts:508-509` (base `42395c825`): para a
   conta que é o login nativo (passo 2, perfil `~/.claude.json` com o mesmo
   e-mail), esse `'auth-expired'` virava o hint da linha. Entre dois usos, a
   CLI deixa no Keychain um access token vencido junto com um refresh token
   válido, e é ela que renova a linhagem sob o `.oauth_refresh.lock`.
3. `src/main/quota/quota-service.ts:733` → `src/main/main.ts:898-901`: com o
   hint `auth-expired`, `markAccountAuthExpired` grava um cooldown de auth de
   12 h ("oauth session expired — sonda de quota").
4. `src/main/persistence/account-store.ts:2042`: `needsRelogin` sai `true`, e
   a tela mostra "sessão expirada". O Redline exclui a linha
   (`excludedReason: "needs-relogin"`) e publica as janelas nulas.
5. O flag não sai sozinho. A limpeza (`clearRefutedAuthCooldown`) só acontece
   numa leitura saudável da API do provider, e essa leitura nunca vinha. A
   cada tick, a sonda marcava a conta de novo, inclusive logo depois de o
   operador limpar o aviso pela ativação manual.

### Evidência (somente leitura; nenhum segredo foi impresso)
- `nexus.db` (`accounts` / `account_cooldown_blocks`):
  - A conta `acct-mrqvpdwz-1` (retorno) tinha
    `last_error = "conta sincronizada pelo operador"` em 1791839347825: o
    operador ativou a conta e o cooldown foi limpo.
  - Cerca de 3 minutos depois, a mesma conta voltou com
    `cooldown_until = 1791882757196` e
    `last_error = "oauth session expired — sonda de quota"`, ou seja, a sonda
    a marcou de novo.
- Keychain `Claude Code-credentials` (o login nativo; `~/.claude.json`
  `oauthAccount` aponta para retornoja@gmail.com):
  - campos: `accessToken`, `refreshToken`, `expiresAt`,
    `refreshTokenExpiresAt` e outros;
  - `expiresAt` = 2026-10-12T11:58:52Z, vencido no momento da inspeção
    (21:22Z);
  - `hasRefresh` = true;
  - `refreshTokenExpiresAt` = 2026-11-08T09:16:32Z, ainda no prazo.

  A sessão é renovável. Não houve revogação.
- `~/.nexus/redline-last-good.json`:
  - todas as contas estão em `entries`, incluindo as duas do Claude e as duas
    do Codex;
  - a linha `claude:acct-mrqvpdwz-1` tem `excludedReason: "needs-relogin"` e
    janelas `null`;
  - `ranking.claude` lista só a outra conta.

  Ou seja, o feed do Redline não descarta contas. Ele exclui a que foi
  marcada sem motivo.
- Codex (mesmo sintoma, causa diferente):
  - `acct-muvwgxma-1` (admin@volarehost.com.br, a conta ativa no Nexus) tem
    o cooldown "oauth session expired — sonda de quota";
  - um GET de leitura em `chatgpt.com/backend-api/wham/usage` com o
    `auth.json` gerenciado dela respondeu **401 `token_revoked`**, mesmo com o
    access token dentro do prazo (`exp` 2026-10-16);
  - o `~/.codex/auth.json` nativo é de outra conta (gmail), que respondeu 200.

  Nesse caso o aviso é verdadeiro: o grant da conta admin no Codex foi
  revogado no servidor.

### Correção
- `src/main/quota/claude-oauth-refresh.ts`: novo `claudeBlobIsRenewable`. É
  verdadeiro quando o blob tem refresh token e o `refreshTokenExpiresAt`, se
  existir, ainda está no prazo.
- `src/main/quota/claude-account-usage.ts`:
  - Login nativo com access token vencido e refresh token vivo: roda um
    `claude /usage` print-only no perfil nativo, sem escopo gerenciado. A CLI
    renova a própria linhagem sob o lock dela. Depois a credencial é relida e
    a identidade é provada de novo, e a cota é lida desse token. O Nexus
    nunca rotaciona o grant.
  - Sem leitura possível agora, o hint fica `unavailable`, e
    `unavailable` não liga o cooldown de auth.
  - O re-login só é pedido com prova: a própria CLI recusou a sessão, ou não
    existe refresh token no prazo.
  - A mesma regra vale para o escopo gerenciado (`ownedWindows`).
- Com a leitura saudável, o `clearRefutedAuthCooldown` que já existe limpa o
  cooldown de 12 h que está gravado hoje. Não é preciso migração.
