# F-1406 — lixo de escape ">4;0m>7u" na primeira linha do pane (CSI privado)

## F-1406 | categoria: funcional | severidade: media | status: corrigido
- Tela/fluxo: primeira linha do pane Codex e `nexus_pane_read` mostravam `>4;0m>7u>4;0m>7u>_ OpenAI Codex (v0.162.1)` (print do operador 12/10).
- Arquivo:linha (antes): `src/shared/ansi-text.ts:3` (`CSI_PATTERN = /\x1b\[[0-9;?]*[ -\/]*[@-~]/g`) e cópias irmãs (lista abaixo).
- Observado (608bd46eb):
  - O Codex CLI 0.162 emite no boot `ESC[>4;0m` (reset XTMODKEYS) e `ESC[>7u` (kitty keyboard push) — confirmado ao vivo: PTY gravado replicando o bootstrap perl do darwin-node-pty, 877 bytes capturados, stream abre com `ESC[?2004h ESC[>4;0m ESC[>7u ESC[?1004h …`.
  - Parâmetros de CSI no ECMA-48 são os bytes 0x30–0x3F (`0-9 : ; < = > ?`). A classe usada nas cópias (`[0-9;?]`) exclui `< = >` — `ESC[>4;0m` não casa o CSI e cai no escape genérico `\x1b[@-_]`, que come só o `ESC[`: o corpo `>4;0m` vira texto visível. O padrão CORRETO já existia no projeto (`CSI_SEQUENCE_PATTERN` em `src/shared/ansi-escape-sequences.ts`, classe `[0-?]*`) — as cópias é que eram estreitas.
- Evidência (RED contra 608bd46eb, só testes novos; fixture = prefixo real capturado):
  - `ansi-text.test.ts` › "remove XTMODKEYS e kitty keyboard do boot do Codex 0.162": `stripAnsi` devolvia `'>4;0m>7u>_ OpenAI Codex'`.
  - `pane-output-digest.test.ts` › F-1406: `expected '>4;0m>7u>_ OpenAI Codex (v0.162.1)' to be '>_ OpenAI Codex (v0.162.1)'` em `normalizeRedrawLine` (o `RESIDUAL_ESCAPE` do digest tem a mesma classe estreita).
  - `screen-buffer.test.ts` › F-1406 (2 testes): `SessionScreenBuffer` deixava `>4;0m>7u` no texto da tela, e um CSI privado cortado no meio do chunk vazava `>4;0` (o `CSI_PREFIX` do hold de escape incompleto também era estreito).
  - Total RED: 5 falhas novas (10 com as do F-1405 no mesmo passe).
- (resolvedor) Correção — todas as cópias que processam bytes de pane, preferindo o padrão compartilhado:
  - `src/shared/ansi-text.ts` — `stripAnsi` passa a usar `CSI_SEQUENCE_PATTERN` importado (o removedor que alimenta o `nexus_pane_read` full, o buffer de tela fallback e o dev-server-detect). UMA função/padrão de verdade para CSI.
  - `src/main/orch/pane-output-digest.ts` — `RESIDUAL_ESCAPE` com a classe `[0-?]*` (limpador residual do digest; regex composto, classe alinhada ao padrão compartilhado).
  - `src/main/detect/screen-buffer.ts` — `CSI_PREFIX` com `[0-?]*` (hold de escape cortado no meio do chunk; sem isso o corpo do CSI parcial vazava como texto).
  - `src/renderer/terminal/terminal-host.ts` — `stripAnsiForExcerpt` (resumo de scrollback do continuity pack) usa o padrão importado.
  - `src/main/orch/cli-prompt-autoresponder-core.ts` — `MENU_CSI` = `CSI_SEQUENCE_PATTERN` (texto de menu lido da tela para derivar teclas de trust).
  - `src/main/orch/boot-prompt-watchdog.ts` — `ANSI_RE` = `CSI_SEQUENCE_PATTERN` (a forma antiga `[0-9;?]*[A-Za-z]` também perdia intermediários `[ -/]*`).
  - `src/main/orch/operator-cli-mentions.ts` — classe local `[0-?]*` SEM importar o padrão compartilhado: o padrão compartilhado tem o introducer alternativo `(?:\x1b\[|\x9b)` (forma C1 de 8 bits) e este tap roda em TODA tecla do operador — a alternativa extra estourava o teto linear do F-818 (52,8 ms vs 50 ms; voltou a ~44 ms com o introducer literal). Input humano é 7-bit ESC; a forma C1 não ocorre nesse caminho.
  - `src/shared/ansi-escape-sequences.test.ts` — alfabeto do fuzz de equivalência ganha `> = <` (o padrão correto agora é exercitado com parâmetro privado também).
