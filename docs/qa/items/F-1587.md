# F-1587 — Vídeo nativo do Google ficava sem modelo em 22/10/2026: Gemini Omni Flash integrado ao `google-video`

## F-1587 | categoria: funcional | severidade: alta | status: verificado

- Tela/fluxo: Estúdio de Mídia → Vídeo (serviço "Google nativo"); ferramenta `nexus_video_generate` com `provider: google-video`; Ajustes → Modelos de mídia; Ajustes → Chaves de API (Google Gemini).
- Arquivo:linha (antes): `src/main/media/media-providers.ts:128-139` (`google-video` só com os três `veo-3.1-*-generate-preview`, padrão `veo-3.1-generate-preview`); `src/main/media/media-generation.ts:1084-1231` (só `models/<id>:predictLongRunning` + polling de operação); `src/shared/media-video-models.ts:55-58` (substituto apontado: `google/veo-3.1` pelo Replicate, outra chave); `src/main/media/media-errors.ts:35-70` (erro do Google lido só como objeto, e por status).
- Passos: 1) Ajustes → Serviços de mídia com a chave do Gemini (sem Replicate). 2) A partir de 22/10/2026, Estúdio → Vídeo, ou um agente chamando `nexus_video_generate` com `provider: google-video`.
- Esperado: a chave do Gemini continua gerando vídeo com o modelo que o Google indica no lugar dos Veo 3.1 preview.
- Observado: o Google desliga `veo-3.1-generate-preview`, `-fast-` e `-lite-` na API do Gemini em 22/10/2026 (`ai.google.dev/gemini-api/docs/deprecations`, atualizada em 12/10). Depois disso o serviço "Google Veo nativo" não tinha modelo nenhum: o Estúdio o desabilitava e o motor recusava mandando usar o Replicate, que exige outra conta e outra chave. O substituto do Google, `gemini-omni-1.1-flash`, usa outra API e não estava integrado.
- Causa raiz: o provedor `google-video` só conhecia o contrato do Veo (`predictLongRunning` + operação). O Omni é outro contrato: `POST /v1beta/interactions` síncrono, vídeo em `steps[].content[]` (base64 ou arquivo da Files API), sem campo de duração, preço por segundo e resolução.
- Fontes (conferidas em 19/10/2026): `ai.google.dev/gemini-api/docs/omni` (atualizada 23/09: corpo, `response_format`, `video_config.task`, resposta, `delivery: "uri"` → `files/{id}` até `ACTIVE` → `:download?alt=media`, sintaxe `[# Sources <FIRST_FRAME>@Image1]`); `ai.google.dev/api/interactions-api` (o `video_config` só tem `task`: não existe duração no pedido); preço na tabela do anúncio do Google (`blog.google`, "Gemini Omni 1.1 Flash lets you build with more control", 27/08/2026): 360p US$ 0,03/s, 720p 0,10, 1080p 0,15, 4k 0,30, que bate com `ai.google.dev/gemini-api/docs/pricing` (16/10/2026: ~US$ 0,10/s em 720p = 5.792 tokens/s × US$ 17,50/M de saída de vídeo; só tier pago).

O substituto dos Veo preview agora é "gemini-omni-1.1-flash, com a mesma chave do Gemini".
  - `src/main/media/media-generation.ts`: `geminiOmniRequest` monta `{ model, input, response_format: { type: "video", delivery: "uri", aspect_ratio, resolution }, generation_config: { video_config: { task } }, store: true }` (o Google exige `store=true` com entrega por URI, visto ao vivo); imagens (inicial, final, referências) vão antes do texto, com o papel declarado no início do prompt pela sintaxe da documentação, e imagem final sem inicial é recusada. `extractGeminiOmniOutput` lê `steps[]` (`model_output` → item `video`), `outputs[]` e `output_video`, com `data` ou `uri`. Com `uri` da Files API o id vira job salvo (`recoverJobId` baixa sem gerar de novo), espera `ACTIVE` e baixa por `downloadAuthenticatedProviderAsset`; resposta sem vídeo diz o status e o texto do modelo. O `fetch` do Node desiste depois de 5 min sem cabeçalho: vira frase do que fazer. O custo é o que o Google cobra: tokens do `usage` da resposta × preço por token da página de preços (entrada US$ 1,50/M; saída com raciocínio US$ 9,00/M de texto e US$ 17,50/M de vídeo; `geminiOmniCostUsd`).
