# F-647 — No Windows todo workspace com `.nexus/project.json` recusava abrir ("manifesto não bate")

## F-647 | categoria: funcional | severidade: critica | status: corrigido
- Tela/fluxo: abrir/trocar pasta de projeto (wizard "Trocar pasta", abertura de workspace) no Windows, em qualquer repositório com `.nexus/project.json` — inclusive o próprio `nexus-ide`.
- Arquivo:linha: `src/main/persistence/project-git-lineage.ts:94` (`processGitRunner` rodava o git com `GIT_CONFIG_GLOBAL: os.devNull`).
- Passos: 1) Windows com Git para Windows 2.55.0.windows.3. 2) Nexus → Trocar pasta → escolher `C:\Users\Administrador\Documents\Projetos\nexus-ide`.
- Esperado: o workspace abre com a identidade do manifesto.
- Observado: toast "Workspace não pôde ser aberto — O manifesto .nexus/project.json não bate com este repositório. Confirme a origem/histórico e regenere o manifesto, ou abra o clone correto." O manifesto está correto (anchor alcançável, origin igual): o erro real é do git.
- Evidencia: no Windows `os.devNull` vale `\\.\nul`, e o git recusa esse caminho como arquivo de config — `git rev-parse --is-inside-work-tree` sai 128 com `fatal: unable to access '\\.\nul': Invalid argument`. A prova de linhagem quarentena como `repository-lineage-unverifiable` ("lineage cannot be verified") e o renderer (`workspace-open-error.ts`) traduz `/lineage/` para a mensagem de manifesto divergente. Medido em 25/09: `GIT_CONFIG_GLOBAL` = `\\.\nul` → 128; `nul`, `NUL`, `/dev/null` → 0. Repro com o código real (`resolveProjectExecutionScope`) no `nexus-ide` → quarentena antes, `identitySource: manifest` depois.
- (resolvedor) Correcao: `processGitRunner` usa `/dev/null` literal — o idioma documentado do Git, que o Git para Windows mapeia para `nul` — em vez de `os.devNull`. O isolamento da config global/sistema continua (a prova de linhagem não confia no `~/.gitconfig`). Teste: `project-git-lineage.test.ts` › "roda o git com a config global neutralizada em todas as plataformas" (git real num repo temporário, `.gitconfig` sentinela no HOME; falha no código antigo com o erro de campo).
