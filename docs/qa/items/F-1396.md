# F-1396 — O Maestro usa o atalho de subagentes internos em vez de panes

## F-1396 | categoria: funcional | severidade: media | status: corrigido
- Tela/fluxo: Maestro (pane Claude) de uma missão viva, na hora de dividir o trabalho.
- Arquivo:linha (antes): `src/main/orch/hook-delegate-endpoint.ts:138` (`MAESTRO_TURN_REMINDER`, que só fala de `nexus_pane_spawn` no prompt do operador) e `src/main/orch/hook-status-config.ts:119-132` (`PreToolUse` só tinha o portão de integração do `Bash` — nada observava a tool de subagente).
- Observado (0.76.241, pelo operador): o Maestro Claude delegou a versão inteira pela tool interna `Agent`/`Task` do Claude Code — subagentes in-process, todos no mesmo modelo, dentro do próprio pane. O Nexus tinha **ZERO workers vivos** e as outras LLMs paradas; nada no trabalho, no quadro ou no handoff. O lembrete existe, mas só entra no `UserPromptSubmit` do operador: no momento exato em que o Maestro escolhe o atalho interno, nada reage.
- Esperado: ao chamar a tool de subagente, o Maestro receber ali mesmo uma linha de contexto dizendo quantos workers Nexus tem vivos e que o atalho do Nexus abre LLMs diferentes — **sem bloquear** a chamada.
- Evidencia (RED, fonte revertida e testes mantidos):
  - `hook-triage-endpoint.test.ts` › F-1396: `Error: Cannot find module './maestro-agent-nudge'`.
  - `hook-status-config.test.ts` › "adds start/notification/stop status hooks preserving gate + user hooks" e "is idempotent": falha na contagem de entradas Nexus (13/14 → 14/15), porque o hook `Agent|Task` não existia.
- (resolvedor) Correcao:
  - `maestro-agent-nudge.ts` (novo): decisão pura sobre o payload `PreToolUse` — parse (só `tool_name`, `tool_input.subagent_type` e `tool_input.model`; **o prompt nunca sai do parser**), o que é trabalho de pane, o texto do aviso e o contador por missão.
  - `mission-worker-inventory.ts` (novo): workers vivos da missão pelo inventário Main-owned (PTY + ACP), import lazy e memoizado, `role === 'worker'`.
  - `hook-triage-endpoint.ts`: ramo novo no `/hook/triage` já existente (mesmo bearer, mesmo `hookSpecificOutput.additionalContext` da fila do Maestro/F-1359 e da triagem). A contagem é o **último** passo: leitura curta, `fable` ou pane que não é o Maestro não custa leitura de inventário. Falha ao contar degrada para `{}`.
  - `hook-triage-command.ts`: `makeClaudeAgentNudgeHookCommand` — posta o payload **real** por stdin (`--data-binary @-`, sem `--output /dev/null`) com o menor timeout da superfície (2 s), porque hook lento no `PreToolUse` atrasa toda chamada de subagente.
  - `hook-status-config.ts`: entrada `PreToolUse` com matcher `Agent|Task`, no mesmo array do portão do `Bash` (reescrita por spawn segue idempotente).
  - `trace({ kind: 'agent-nudge', …, count, liveAgents })`: quantas vezes a missão escolheu o atalho. `count` e `liveAgents` já são campos promovidos por `traceContextEvent`, então nenhum campo novo foi necessário.
- Silêncios deliberados (o aviso **não** sai quando): pane que não é o Maestro da missão (worker, mão do operador, sem missão); leitura curta `Explore`/`Plan`/`claude-code-guide`; e `model` `fable` — o revisor obrigatório do F-234 só existe via `Agent`, então ali o atalho é o uso certo e corrigi-lo seria chamar o uso errado de errado.
- Validacao: `npx vitest run src/main/orch/maestro-agent-nudge.test.ts src/main/orch/hook-triage-endpoint.test.ts src/main/orch/hook-status-config.test.ts` — 55/55; vizinhos `hook-script-shape`, `hooks-gen.ephemeral-settings`, `hook-status-endpoint` — 49/49. `npx tsc --noEmit -p tsconfig.json` limpo. `npm run security:renderer-sinks` — 0 sinks.
- Limite: só a família Claude (é o único CLI com `Agent`/`Task` + hook `PreToolUse` nesta superfície). O hook só é instalado na reescrita por spawn — panes já abertos continuam sem ele até o próximo spawn. O aviso é aditivo: ele **não** impede o subagente de rodar, só torna o atalho visível; nada aqui converte o atalho interno em pane por conta própria.
