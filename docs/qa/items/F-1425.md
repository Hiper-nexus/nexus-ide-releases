# F-1425 — Spinner da TUI classificado como `errored` (pane_read) e devolvido como resposta (pane_ask)

## F-1425 | categoria: correção/observabilidade | severidade: alta | status: corrigido
- Tela/fluxo: `nexus_pane_read`/`nexus_pane_read_many` (modo digest) e `nexus_pane_ask` sobre panes Claude Code / Devin ocupados.
- Arquivo:linha:
  - `src/main/orch/pane-output-digest.ts` (classificação F-1356 e helper compartilhado)
  - `src/main/orch/tools-panes.ts` (`paneDigestResult` e handler do `nexus_pane_ask`)
- Passos para reproduzir (observado 3× hoje pelo orquestrador):
  1) Pane Claude Code (Fable 5.1, "still thinking with xhigh effort") ou Devin exibindo só quadros de spinner (braille ⠤⠄ ⣀⡀ ⠋ / "✽ ✻ ✶ ✳ ✢ ·" com dígitos soltos);
  2) `nexus_pane_read` digest do pane → `state: "errored"`, `stateConfidence 0.2569`, `needsHuman 0.2152`, texto "TUI sem texto legível" — com o pane trabalhando;
  3) `nexus_pane_ask` num pane Devin ocupado → `{ ok: true, state: "idle", answer: "⠤⠄" }` — um glifo de spinner como resposta.
- Esperado: quadros de spinner/braille/dígitos sem texto significam TUI animando = **working** (no pior caso `unknown`), nunca `errored` — erro exige evidência textual. E `pane_ask` não devolve glifo como resposta.
- Observado: o digest F-1356 devolvia o texto-placeholder "TUI sem texto legível", que era alimentado ao classificador Jev (`classifyPaneTailForDigest`); o Jev classificava aquele texto sem sentido como `errored` com baixa confiança. No `pane_ask`, `newOutputSince` devolvia os quadros de redesenho recém-desenhados e qualquer texto não-vazio era tratado como resposta (`ok: true`).

## Causa Raiz
1. **pane_read:** `digestPaneTail` colapsava todo o redesenho (comportamento F-1356 correto) e emitia o placeholder "TUI sem texto legível"; `paneDigestResult` passava esse placeholder ao Jev como se fosse conteúdo do pane. Texto sem informação → resposta de baixa confiança (`errored` ~0.25) → o orquestrador podia fechar pane vivo.
2. **pane_ask:** a resposta era `newOutputSince(before, after).trim()` sem nenhum filtro de decoração de TUI — quadros de spinner redesenhados depois da pergunta contavam como "texto novo".
3. Latente: `SPINNER_GLYPHS.test(raw)` usava regex com flag `g` (stateful via `lastIndex`) no cálculo do contador de spinner — resultados podiam variar conforme chamadas anteriores.

## Correção Implementada
1. **Helper único (`pane-output-digest.ts`):** novo `isSpinnerFrameLine(line)` — verdadeiro para linha vazia, só-moldura (box-drawing/braille/glifos, `GLYPH_ONLY_PATTERN`) e contador de spinner (glifo + resto de dígitos/espaços). Dígitos soltos SEM glifo (uma resposta "42") não são spinner: ficam. A decisão de drop por linha do digest foi unificada nesse helper (e sai o `.test()` stateful).
2. **Digest estruturado:** `PaneTailDigest` ganhou `noReadableText?: 'spinner' | 'static'`, preenchido no ramo F-1356: spinner visível no tail ⇒ `'spinner'`; só quadro estático sem letra nenhuma ⇒ `'static'`.
3. **`paneDigestResult` (pane_read e read_many):**
   - `noReadableText === 'spinner'` → classificação determinística `{ state: 'working', confidence: 1, needsHuman: 0 }`, **sem chamar o Jev** (economiza orçamento e elimina o falso `errored`);
   - `noReadableText === 'static'` → sai **sem** campos de estado (unknown honesto), também sem Jev;
   - caso normal → fluxo de sempre (`classifyPaneTailForDigest`).
4. **`nexus_pane_ask`:** a resposta passa por `isSpinnerFrameLine` linha a linha. Restando algo legível, é isso que volta; só de quadros de spinner (ou nada) → `ok: false` com `reason: 'pane ocupado, sem resposta legível (só quadros de spinner) — repita mais tarde ou leia o pane'`.
5. O texto-placeholder "TUI sem texto legível" permanece no digest (contrato F-1356), mas nunca mais chega ao classificador.

# Parte 2 — Quadros reais que `SPINNER_GLYPHS` não pegava (Kimi K3 e MiMo Code)

## Sintoma
- Kimi K3: tail só com fases da lua (🌒 🌓 🌔 🌕 🌖 🌗 🌘 — U+1F311–U+1F318) → `pane_read` devolvia `idle_prompt` com o Kimi trabalhando (as linhas só de lua não eram moldura nem spinner).
- MiMo Code: quadro "🛸˙·∙˙·  🛸·∙˙·∙  ·∙˙·∙🛸∙˙·∙˙" (OVNI com pontos ˙·∙) tratado como conteúdo.

## Correção
1. `SPINNER_GLYPHS` (e `SPINNER_TEST` via `source`) ganhou o intervalo `\u{1F311}-\u{1F319}` (fases da lua + 🌙) e 🛸 — a flag `u` cobre os emoji fora do BMP.
2. `GLYPH_ONLY_PATTERN` ganhou `\u{1F311}-\u{1F319}`, 🛸 e `˙` (U+02D9; `·∙•` já estavam) — linhas só desses caracteres são moldura.
3. Efeito: tail só de luas/OVNI → `noReadableText: 'spinner'` → `working` determinístico (sem Jev); no `pane_ask`, as linhas são filtradas da resposta.
4. `"🌓 · Tip: ctrl-s to add guidance"` continua legível: tem letras, não é moldura nem spinner-only — vai ao Jev (a lua sai na normalização como decoração, o texto fica).
