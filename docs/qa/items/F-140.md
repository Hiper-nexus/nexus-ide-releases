# F-140 — Push solicitado se perdia na conclusão assíncrona

## F-140 | categoria: funcional | severidade: alta | status: verificado
- Tela/fluxo: `nexus_mission_set_status` com `status: done` e `push` explicitamente solicitado.
- Arquivo:linha: `src/main/orch/tools-domain.ts:358`, `src/main/orch/mission-intent-gate.ts:202`.
- Passos: 1) Solicitar done+push em uma missão standard com squad. 2) A verificação demora além de um turno do event loop. 3) A missão conclui posteriormente. 4) Repetir done+push com a sessão corrente.
- Esperado: a chamada que pediu push aguarda sua verificação e publica apenas após conclusão e revalidação de autoridade. Reparo/espera informa que o push continua pendente. Um pedido novo após done pode publicar com autoridade atual.
- Observado: o `Promise.race` retornava antes dos sensores e descartava `args.push`; o early return de missão done também ignorava a repetição. Além disso, o intent gate rejeitava o checkpoint pós-conclusão e o retry real, pois a própria conclusão muda a missão para done.
- Evidencia: RED unitário demonstrou retorno antecipado, ausência de pushPending, retry ignorado e falta de checkpoint MCP. RED no dispatcher real demonstrou recusa `dispatch_required` após done e no retry. Git foi mockado em todos esses testes; nenhum push real foi executado.
- (resolvedor) Correcao: somente chamadas que pedem push aguardam a reconciliação daquela tentativa. Sem push, o turno continua liberado. O helper reobtém a missão no scope, verifica done/resultado/intentVersion, exige sessão de orquestrador explicitamente gravada e corrente e revalida o MCP imediatamente antes de Git. Retry done+push usa o mesmo helper. Exceção estreita no intent gate permite apenas done→done dessa sessão, preservando negativas de token revogado, sessão antiga, scope forjado, reabertura e outros efeitos após done.
- Limite: se a reconciliação retorna espera/reparo, responde `pushPending: true`, `pushExecuted: false` e informa a necessidade de nova solicitação após conclusão. Não há fila persistente nem push solto em background. O timeout de Git continua 60s; verificadores mantêm seus próprios limites.

Sem commit nesta tarefa.
- Relacionado: F-137, cuja unificação da conclusão introduziu a espera assíncrona.
- Revisão independente final: confirmado checkpoint MCP imediatamente antes de Git, missão done com resultado e intentVersion esperada, sessão explicitamente ligada e corrente, negativas para token revogado/sessão substituída/escopo forjado e ausência de publicação em background. Chamadas sem push continuam liberando o turno. Rodada independente de status, intent, dispatcher, prova efêmera, reconciliação e limite de produção passou 203/203; diff-check limpo.
