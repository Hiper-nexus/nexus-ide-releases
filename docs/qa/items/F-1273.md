# F-1273 — Classificador de comando pesado varre texto inteiro e falsifica a vaga

## F-1273 | categoria: funcional | severidade: media | status: corrigido
- Tela/fluxo: admissão de comando pesado (`nexus_terminal_run` / `nexus_bg_run`)
- Arquivo:linha: `src/main/orch/heavy-command-classifier.ts:8-51` (antes da correção)
- Passos: 1) Rode `git commit -m "fix: make tsc and vitest stop queueing; npm test passes"` via `nexus_terminal_run`. 2) Enquanto isso, rode um `npx vitest run` real no mesmo root.
- Esperado: o commit é leve (o texto da mensagem cita ferramentas, mas não as roda) e o vitest pega a vaga pesada.
- Observado: `classifyHeavyCommand` varria o texto inteiro com fallbacks regex (linhas 45-51): a mensagem do commit classificava como `tests`, `echo "run vite build later" # npm run build` como `build`, heredoc como `tests`. A vaga é UMA por root (`heavy-command-permit.ts`); o falso positivo a ocupava e o job pesado real esperava 300 s e morria com `heavy_command_wait_timeout` (exit 74).
- Evidencia: RED em `src/main/orch/heavy-command-classifier.test.ts` ("ignores tool names that are not the program"): 4 de 6 casos falhavam (`git commit -m "…npm test…"` → `tests`, heredoc → `tests`, grep → `tests`, etc.), contra os mesmos casos já nulos em `catalog.commandKind` (`heavy-command-catalog.test.ts`, describe "commandKind ignores tool names that are not the program being run").
- (resolvedor) Correcao: `classifyHeavyCommand` agora delega ao mesmo `catalog.commandKind` de `resources/heavy-command/catalog.cjs` que os hooks do lado do recurso usam — citado em mensagem, comentário e corpo de heredoc nunca é o programa; comando acima de 16384 caracteres continua `build` (regra já embutida no catálogo). Caminho do catálogo espelha `native-heavy-preload.ts` (empacotado: `process.resourcesPath/heavy-command`; dev: `app.getAppPath()/resources/heavy-command`; fora do app: relativo ao arquivo-fonte). GREEN: 182/182 (classifier + catalog), 32/32 (heavy-command-permit, tools-terminal-isolated-writer, tools-terminal-triage). RED reproduzido revertendo só `heavy-command-classifier.ts`.

## Revisão de ponta (12/10)
Com o Main lendo o catálogo, a revisão confirmou regressões em `resources/heavy-command/catalog.cjs` (`programKind`) e uma fragilidade em `heavy-command-classifier.ts`. Mudou: (1) `pnpm|yarn|bun <bin>` e `… run <bin>` com bin conhecido (`vitest|jest|mocha|tsc|tsgo|vite|webpack|rollup|esbuild|pytest`) agora classificam o programa a partir do verbo (`pnpm vitest run`, `yarn jest`, `bun vitest` → `tests`; antes `null`); `pnpx` virou runner como `npx`/`bunx`. (2) `python*` com `-m MOD` classifica o módulo (`python -m pytest` → `tests`; `-c`, script e stdin seguem `null`), e `poetry|uv|pipenv run CMD` / `uvx CMD` classificam CMD (opções com valor como `--with`, `-C`, `--directory` puladas). (3) `node -e|-p|--eval|--print CODE`: one-liner trivial → `null` (antes `build`, esperava até 300 s atrás de tsc/vitest). Não virou `null` cego porque `native-heavy-preload.test.ts` (F-877) exige que `NODE_OPTIONS= node -e "require(vite)…"` siga medido pelo hook de shell — sem preload, o texto é a única guarda; então código inline que cita módulo pesado (via `moduleKind` dos literais), `child_process`, mais de 64 literais ou código só conhecido em execução (`"$CODE"`) continua medido. (4) `classifyHeavyCommand` não lança mais sem catálogo: `console.warn` único e fallback degradado — mede só a palavra em posição de programa de cada comando simples quando é ferramenta pesada finita, direta ou atrás de package manager/runner (`npx vitest`, `npm run build`, `uv run pytest`) e script >16384 → `build`; `git status`, `npm run dev` e mensagem de commit ficam `null` (medir tudo prenderia servidor de dev na única vaga do root; não medir nada soltaria tsc/vitest sem reserva). RED: revertendo só `catalog.cjs` (`git show HEAD:…`), 31 falhas (catálogo + classificador); revertendo só `heavy-command-classifier.ts`, 1 falha ("degrades without throwing…": `Cannot find module` lançado). GREEN: `heavy-command`, `tools-terminal`, `tools-bg`, `native-heavy` 484 passed / 21 skipped (29 arquivos); demais suítes que carregam os hooks (governed-profile, mission-shim, pty) 300/300; `tsc --noEmit` exit 0. O describe "commandKind ignores tool names that are not the program being run" segue todo `null`.
