# F-426 — sprintf-js bloqueia o audit da toolchain

## F-426 | categoria: seguranca | severidade: media | status: corrigido
- Tela/fluxo: segurança das ferramentas de build da release.
- Arquivo: `package.json`, `package-lock.json`.
- Passos: executar `npm audit --json` com npm 12.0.0 na candidata.
- Esperado: zero vulnerabilidades reportadas na toolchain.
- Observado: A toolchain trazia sprintf-js 1.1.3 por roarr/global-agent/@electron/get. A falha de precisão sem limite pode lançar RangeError em formatação controlada externamente; npm propaga o finding aos dependentes. Não há versão corrigida publicada no advisory consultado.
- Evidencia: `/tmp/nexus-206-audit-all.json`; [advisory](https://github.com/advisories/GHSA-hp3w-g68c-fv3c).
- (resolvedor) Correcao: Override restrito a global-agent@3.0.0 para roarr 3.3.0: preserva o proxy original e a API default.child/níveis de log, removendo sprintf-js. A tentativa global-agent 4.1.3 foi rejeitada após reproduzir perda de opções TLS. A combinação final passou por HTTP e HTTPS CONNECT reais com CA válida, recusa de certificado desconhecido e logger habilitado com contexto contendo %.101f. Os 14 callsites deste consumidor usam mensagens literais; fast-printf não é anunciado como seguro para formatos arbitrários. Nenhuma verificação TLS foi desabilitada. Candidata 0.76.206 ainda sem publicação.

- Validação: npm 12.0.0 audit completo com zero vulnerabilidades; typecheck exit 0 e 42 testes focados aprovados. Revisão independente do diff sem P1/P2. Suíte completa em dd22512a3: 22.597 aprovados, zero falhas e 59 skips. Depois, o delta exclusivo da toolchain (logger do proxy) passou por audit completo zero, typecheck, 44 testes de release e HTTP/HTTPS real com validação de certificados. Nova candidata empacotada ainda pendente.
