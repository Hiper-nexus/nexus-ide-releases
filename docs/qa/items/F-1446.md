# F-1446 — Windows mostrava «[nexus] processo caiu (code 129)» para pane encerrado pelo próprio Nexus

## F-1446 | categoria: usabilidade | severidade: media | status: corrigido
- Renumerado no merge com a origin (0.76.250): este achado era o F-1437 local (nunca publicado) e virou F-1446 para não colidir com a numeração que a origin publicou (até F-1435).
- Tela/fluxo: pane de missão/orquestrador no Windows encerrado pelo Nexus (fim de missão, teardown) → aviso de saída no terminal.
- Arquivo:linha:
  - `missionOwnedExitNotice` / `orchestratorOwnedExitLines` (texto do aviso de saída de pane de missão).
  - `src/renderer/terminal/terminal-host.ts` (entrega do aviso; não repassava `terminationOrigin`).
- Passos:
  1. No Windows, deixar o Nexus encerrar um pane de missão (conclusão/teardown normal).
  2. Ler o aviso impresso no terminal.
- Esperado: aviso de encerramento normal («encerrado pelo Nexus»).
- Observado: `[nexus] processo caiu (code 129)` — texto de crash para um encerramento deliberado.
- Evidencia: 129 é o código de saída do ConPTY quando o pseudo-console é fechado por quem o criou (o próprio Nexus ao encerrar o pane); o Main já enviava `terminationOrigin` na notificação de saída e o renderer o ignorava, tratando toda saída com código ≠ 0 como queda.

## Causa raiz
- O renderer classificava a saída só pelo código. No Windows, encerrar o ConPTY devolve 129, então todo pane encerrado pelo Nexus era anunciado como crash. A origem do encerramento já viajava do Main (`terminationOrigin`), mas nenhum consumidor a lia.

## Correção
- `missionOwnedExitNotice` e `orchestratorOwnedExitLines` recebem `terminationOrigin`; com origem do Nexus, o texto vira «encerrado pelo Nexus» em vez de «processo caiu». O terminal-host repassa o campo ao montar o aviso. Saída sem origem do Nexus mantém o texto de queda com o código.
