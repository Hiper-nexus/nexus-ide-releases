# F-216 — Pane de Claude/GLM com a tela embaralhada: linhas quebradas na largura errada e restos abaixo da barra de status

## F-216 | categoria: visual | severidade: alta | status: corrigido
- Tela/fluxo: pane de agente com o renderizador fullscreen do Claude Code (`"tui": "fullscreen"` em `~/.claude/settings.json`, copiado para o HOME efêmero dos panes), numa grade que muda de forma enquanto o Maestro abre e fecha helpers.
- Arquivo:linha: `src/renderer/terminal/terminal-host.ts:484` (`propagateHostSize` só manda `pty.resize` quando a grade difere da última reportada); `src/main/pty/pty-manager.ts:3207` (`resizeSession` descarta em silêncio o resize de sessão que não é do remetente).
- Passos: 1) Missão com vários helpers abrindo e fechando (a grade redimensiona). 2) Olhar um pane GLM/Claude ativo.
- Esperado: a TUI sempre desenhada no tamanho do pane; no renderizador fullscreen todo resize é um redesenho completo.
- Observado (29/09 ~14:45, pane GLM "Briefing visual", print do operador): linhas do diff continuam no início da linha seguinte ("no e quand-"), mostrando que a CLI desenhava mais larga que o xterm; e sobra conteúdo velho abaixo da barra de status, mostrando que o xterm tinha mais linhas do que a CLI desenhava. As duas coisas juntas indicam que o PTY ficou com um tamanho diferente do pane. Não reproduzido: o pane já tinha fechado quando o caso foi analisado, e nenhum trace registra resize.
- Evidencia: print do operador; `strings` do Claude Code 2.1.285 ("a resize is a redraw (ui.invalidate)"; "tui" = "fullscreen" usa o renderizador alt-screen com scrollback virtualizado); settings do operador com `tui: fullscreen`.
- Relacionado: F-009, F-356, F-369, F-673.
- (resolvedor) Correcao: auto-cura + evidência + ação manual para drift de grade PTY↔pane. `resumeVisibleHost` (`terminal-host.ts`) reafirma o tamanho após o fit com `pty.resize(sessionId, cols, rows, { assert: true })` mesmo quando a grade é igual à reportada; a flag `assert` (opcional, schema strict em `pty-ipc.ts`, `shared/ipc.ts`/`types.ts`, preload) atravessa até o Main. `resizeSession` (`pty-manager.ts`) passa a rastrear a última grade aplicada por sessão (`Session.grid`, atualizada também pelo `orchResizeSession` confiável): com `assert` e dimensões divergentes emite `pty-grid-drift`; resize de renderer que não possui a sessão é descartado e emite `pty-resize-dropped` no máximo uma vez por sessão (limpo no destroy). Ação manual: `repaintPaneTui(paneId)` exportada (no-op sem host/disposed/parked/virtualized/sem sessão; fit → reafirma → bounce `(rows-1, rows)` → refresh das linhas visíveis) e item "Redesenhar tela" no `PaneToolbar` só para `cli-agent` com sessão viva. Testes: `terminal-host.test.ts` (resume reafirma com grade inalterada — expectativa F-369 corrigida para distinguir assert de bounce; `repaintPaneTui` reafirma + bounceia + dá refresh; guards), `PaneToolbar*.test.tsx` (item só com sessão viva), `pty-ipc.test.ts` (assert boolean ok / não-boolean rejeitado no schema strict), `pty-manager.test.ts` (drift só quando difere, dropped uma vez por sessão e limpo no destroy, grid do orch resize), `preload.test.ts` (forward condicional).
