# F-1497 — Maestro sem modelo herdava o modelo padrão de outra CLI

## F-1497 | categoria: funcional | severidade: alta | status: corrigido
- Renumerado na integração com a origin (0.76.252): este achado era o F-1443 da frente de squads (nunca publicado) e virou F-1497 para não colidir com a numeração que a origin publicou (F-1436..F-1451).
- Tela/fluxo: preparar/aprovar missão com uma equipe cujo Maestro não fixa modelo → `resolveProductionMissionOrchestratorRuntime` (`src/main/orch/mission-orchestrator-runtime.ts`), que sela o runtime do orquestrador no contrato (prepare, review fence, cron).
- Arquivo:linha: `src/main/orch/mission-orchestrator-runtime.ts:299-305` (antes) — `present(settings.defaultModel)` entrava sem conferir se `settings.defaultAdapterId` era a CLI do Maestro.
- Passos: 1) Em Configurações, CLI padrão Codex com modelo `gpt-6.1-sol`. 2) Criar uma equipe com Maestro Claude sem modelo (ou equipe antiga sem o campo). 3) Usar a equipe numa missão.
- Esperado: o Claude sobe no padrão da própria CLI.
- Observado: o runtime selado era `{ adapterId: 'claude', model: 'gpt-6.1-sol' }`. O spawn não corrige: em `tool-util.ts` (resolução contra a lista da CLI) um id sem variante da mesma família na lista do Claude é mantido como pedido ("não piora"), e o Claude é aberto com `--model gpt-6.1-sol`, que ele não serve.
- Causa raiz: o renderer já só usa o padrão global quando a CLI é a padrão (`TeamStep.tsx`: `coordinator.id === settings.defaultAdapterId ? settings.defaultModel : undefined`); o Main não fazia a mesma conferência.
- Correcao: o modelo das Configurações só vale quando `defaultAdapterId` é a CLI do Maestro; fora disso a cadeia segue para `defaultSquadModelForAdapter` (e, sem ele, o default da própria CLI no spawn). Modelo selado no roster continua vencendo. Conta padrão não precisava de ajuste: ela já é filtrada pela CLI (`accounts` só do `adapterId`).
- Efeito colateral conhecido: um agendamento de cron aprovado com o modelo cruzado selado passa a acusar `cron_execution_authority_stale: approved orchestrator runtime changed; recreate the schedule` — o mesmo aviso de quando o operador troca o modelo padrão. Esse agendamento já subia o Claude com o modelo do Codex.
