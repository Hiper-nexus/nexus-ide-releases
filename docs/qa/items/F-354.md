# F-354 — Login do Kimi deve perguntar kimi.ai vs kimi.com e abrir a CLI

## F-354 | categoria: usabilidade | severidade: alta | status: corrigido
- Tela/fluxo: Ajustes → CLIs / + Pane → login da CLI Kimi.
- Arquivo:linha: `src/renderer/components/settings/cli-login-terminal.ts`;
  `src/renderer/components/settings/kimi-login-region.ts`;
  `src/shared/kimi-login-command.ts`.
- Passos: 1) Entrar no Kimi (Ajustes ou cadastro de conta). 2) Observar o
  pane que abre e a URL do device-code.
- Esperado: o Nexus pergunta qual site usar (kimi.ai internacional / kimi.com
  China) e o pane é a CLI `kimi login --region …` (TUI com
  `https://www.kimi.ai/code/authorize_device?user_code=…` ou o equivalente
  .com). Outro cliente pode precisar da outra URL.
- Observado: o comando ia sempre com `--region global` (F-595) ou, no disco
  do operador, `~/.kimi-code/region = mainland-cn`; o pane era um shell cru
  que digitava o comando e ficava no prompt depois.
- Evidencia: URL do operador `https://www.kimi.ai/code/authorize_device?user_code=VT55-GG7L`;
  `kimi login --help` expõe `--region mainland-cn|global`.
- (resolvedor) Correcao: `askChoice` no login do Kimi (kimi.ai marcado
  como recomendado fora de `zh_CN`); o comando vira `kimi login --region`
  da escolha; no POSIX o pane faz `exec` da CLI para não deixar um terminal
  cru. Cancelar a pergunta não abre pane nem pinta erro.
  Validação: `npx vitest run src/shared/kimi-login-command.test.ts
  src/renderer/components/settings/kimi-login-region.test.ts
  src/renderer/components/settings/cli-login-terminal.test.ts
  src/renderer/components/settings/AccountsManager.test.tsx
  src/adapters/builtin/login-commands.test.ts`.
