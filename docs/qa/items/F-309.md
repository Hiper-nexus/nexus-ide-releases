# F-309 — Squads salvos sem ação visível para usar os integrantes

## F-309 | categoria: funcional | severidade: media | status: corrigido
- Tela/fluxo: Configurações → Squads → Nova missão; seleção de equipe por voz.
- Arquivo:linha: `src/renderer/components/settings/ModuleSections.tsx:358`, `src/renderer/voice/jarvis-action-executor.ts:522`, `src/renderer/components/SquadEditor.tsx:189`.
- Passos: 1) Criar ou importar um squad. 2) Procurar como usar essa equipe em Nova missão. 3) Pedir por voz para abrir os squads salvos.
- Esperado: aplicar os integrantes por uma ação visível, com limites claros sobre o que é reaproveitado; a voz abre o catálogo efetivamente selecionável.
- Observado: CRUD, SQLite e catálogo MCP estavam implementados, mas Configurações só oferecia edição/importação/exportação/exclusão. O seletor por voz abria TeamStep sem lista de squads. A voz por nome copiava somente agents, enquanto a UI prometia squads disponíveis para novas missões. Instruções globais não pertencem ao contrato canônico de preparo. O draft padrão também não incluía o revisor exigido pela lane standard.
- Evidencia: regressões RED em SettingsSquads.capabilities e jarvis-action-executor-mcp-result. Leitura atual do IPC/store confirmou persistência real e consumidores Pet/MCP/runtime; o grafo Graphify de julho foi usado apenas como índice. Capturas e estados do preview isolado em `docs/qa/evidence/2026-09-04-squads/`.
- (resolvedor) Correcao: Usar integrantes aplica o roster pelo store já existente e abre Nova missão, preservando o objetivo e o catálogo. Novos squads incluem Coordenador, Executor e Revisor. Squads antigos não são alterados: quando falta executor/revisor, abrem Equipe com aviso exato para completar os papéis. O setter de roster retorna o aceite da validação existente, evitando anunciar aplicação de um roster rejeitado. O picker de voz abre Configurações → Squads; respostas de abrir/desenhar equipe descrevem a cópia parcial e tratam rejeição. Pet Studio segue para Aparência, sem copiar sua autoridade para missão comum.
- Limites explícitos: a ação copia papéis, ferramentas/modelos e instruções individuais. Permissões e skills continuam governadas pela política Main. As instruções globais permanecem em uma seção avançada do editor, disponíveis na definição consultada via MCP; não entram por Usar integrantes. Nenhum campo do contrato crítico, backend de squads ou dado persistido foi removido.
- Validação: 146 testes passaram em sete arquivos (SettingsSquads.capabilities, SquadEditor, MissionSetup, mission-setup-store, jarvis-action-executor-mcp-result, jarvis-action-executor-navigation e squad-edit). `npm run typecheck`, `npm run security:renderer-sinks` e `git diff --check` passaram. O preview Chromium com componentes reais confirmou catálogo → objetivo preservado → três papéis/modelos na equipe; nenhuma chamada prepare/start ocorreu. A equipe antiga manteve dois integrantes e mostrou “Adicione ao menos uma pessoa independente para verificar a entrega.”
