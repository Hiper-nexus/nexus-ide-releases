# F-692 — MiniMax Code pedia permissão a cada ferramenta

## F-692 | categoria: funcional | severidade: alta | status: corrigido
- Tela/fluxo: pane MiniMax Code (`mcode`) aberto pelo Nexus, helper ou "+ Pane".
- Arquivo:linha: `src/main/orch/cli-mcp-session-minimax.ts` (`ensureMinimaxFullAccess`); chamada em `src/main/pty/pty-manager.ts` (argv final do agente).
- Passos: 1) Abrir um pane MiniMax. 2) Pedir qualquer tarefa que rode comando ou edite arquivo.
- Esperado: roda livre, como Claude/Codex/Grok/Kimi/AGY/MiMo nos panes do Nexus.
- Observado (29/09): o operador disse "o MiniMax Code fica pedindo permissão toda hora, deixa ele livre e todas as demais CLI". `~/.minimax/permission.json` acumulava aprovações comando a comando.
- Evidencia: mcode 0.5.8 — a TUI só tem `--model/--lane/--session/--continue/--tui-mode`; `--permission` existe só no `exec`. O modo vem da chave de topo `permissionMode` do `config.yaml` (`default` = Ask, `auto`, `acceptEdits`, `bypassPermissions` = Full access, `off`). A única ENV de configuração, `MCODE_CONFIG_DIR`, é das ferramentas de sandbox. As demais CLIs já nascem livres (`defaultPermissionMode` = sequência yolo verificada: `--dangerously-skip-permissions`, `--dangerously-bypass-approvals-and-sandbox`, `--yolo`, `--always-approve`, `--yes-always`, `--auto`); o adapter MiniMax tinha `yolo: []`.
- Causa: sem flag, o pane MiniMax ficava no modo padrão da CLI (Ask).
- (resolvedor) Correcao: antes do spawn de pane MiniMax gravável, o Nexus garante `permissionMode: bypassPermissions` no `~/.minimax/config.yaml`. A edição é textual e idempotente: troca só a linha de topo ou a acrescenta no fim, preservando comentários e CRLF, e cria o arquivo se faltar. Lane somente leitura não é liberada. Nesta máquina a chave foi aplicada à mão em 29/09 (backup `config.yaml.bak-20260929-f692`). Testes em `cli-mcp-session-minimax.test.ts`.
