# F-539 — Falso positivo de cota esgotada no Codex com refutação viva e paridade do observer

## F-539 | categoria: backend | severidade: crítica | status: corrigido
- Tela/fluxo: Orquestração / Detecção de Limites de Provedor / Failover de Contas (Codex)
- Arquivo:linha: `src/vendor/omp/rate-limit/classify.ts:44`, `src/main/orch/limit-detector.ts:68`, `src/main/orch/limit-refutation.ts:38`, `src/main/orch/failover.ts:536`, `src/main/quota/provider-usage-auth.ts:161`
- Passos:
  1) Executar tarefas no Codex usando conta ativa com cota disponível (ex: retornoja@gmail.com, WHAM reportando 72% de uso semanal, `limit_reached: false`).
  2) O Codex emite payloads de telemetria ou logs contendo chaves como `"limit_reached": false` ou `token_limit_reached=false`.
  3) Observar a resposta do sistema de orquestração.
- Esperado:
  - O sistema deve reconhecer que a conta possui cota livre (28% restante), não disparar failover prematuro, não colocar a conta em quarentena de 12 horas e não exibir toast de cota esgotada.
- Observado:
  - Em produção, uma mensagem na tela acusava falsamente "Cota esgotada em retornoja@gmail.com".
  - A regex em `classify.ts` continha `\blimit_reached\b`, que casava com `"limit_reached": false`.
  - `limit-refutation.ts` usava `REFUTE_HEALTHY_RATIO = 0.5`, rejeitando a refutação viva da API do provedor mesmo quando esta indicava `limit_reached: false` e headroom disponível (72% de uso semanal).
  - Em `failover.ts`, a refutação via API do provedor só era consultada para frames de `scrollback`, ignorando sinais provenientes do observer.
  - Em `provider-usage-auth.ts`, o token do Codex não resolvia o fallback para `~/.codex/auth.json` quando o e-mail da conta correspondia ao token ativo no disco.
- Evidencia:
  - `classify.ts`: regex de `limit_reached` endurecida para nunca casar com negações (`false`, `null`, `0`).
  - `limit-detector.ts`: guarda explícita de negação `[:=]\s*(?:false|null|0)` no `detectLimit`.
  - `limit-refutation.ts`: `REFUTE_HEALTHY_RATIO` elevado para `QUOTA_HIGH_USAGE_THRESHOLD` (0.8), permitindo refutação viva para contas com margem saudável (como 72%).
  - `failover.ts`: refutação viva estendida para todos os sinais de limite (incluindo observer) e proteção contra falsos hits.
  - `provider-usage-auth.ts`: adicionado fallback seguro para `~/.codex/auth.json` com validação de subject/e-mail.
  - 109 testes unitários dedicados passando: `classify.test.ts`, `limit-detector.test.ts`, `limit-refutation.test.ts`, `failover.test.ts`, `codex-usage.test.ts`, `provider-usage-auth.test.ts`.
- (resolvedor) Correcao:
  - `src/vendor/omp/rate-limit/classify.ts`, `src/main/orch/limit-detector.ts`, `src/main/orch/limit-refutation.ts`, `src/main/orch/failover.ts`, `src/main/quota/provider-usage-auth.ts`, `src/main/quota/provider-usage-auth.test.ts`.
