# F-685 — shot-bridge recusava todo envio do Nexus Shot no Windows

## F-685 | categoria: funcional | severidade: alta | status: corrigido
- Tela/fluxo: Nexus Shot para Windows → "Enviar para o NexusIDE" (captura, gravação ou pacote da revisão).
- Arquivo:linha: `src/main/shot-bridge/shot-bridge-server.ts` (`validateShotIngestFiles`: `if (!raw.startsWith('/')) return path-not-absolute`; `shotAllowedRoots`: só `~/Pictures` e `~/Movies`); `src/renderer/state/shot-ingest.ts` (`parentDirOf` só com `/`).
- Passos: 1) No Windows, com o IDE aberto, capturar no Nexus Shot (grava em `C:\Users\<u>\Pictures\Nexus Shot\…png`). 2) "Enviar para o NexusIDE". 3) Repetir com uma gravação (`C:\Users\<u>\Videos\Nexus Shot\…\recording.mp4`).
- Esperado: 200 `{ ok: true }`, toast no IDE e o caminho colado no pane ativo (F-613).
- Observado: 400 `path-not-absolute` para qualquer arquivo. O teste de caminho só aceitava `/…`, e `C:\…` nunca passa. Mesmo corrigido isso, a gravação cairia em `path-outside-allowed`: no Windows o Shot grava em Vídeos (`dirs::video_dir`), e a raiz permitida era `~/Movies`. Com Imagens ou Vídeos redirecionadas ao OneDrive, a raiz `~/Pictures` também não bate. No toast de lote, "Abrir pasta" abria o primeiro arquivo, porque `parentDirOf` não reconhece `\`.
- Evidencia: nesta máquina, 6 dos testes de `shot-bridge-server.test.ts` falham no código antigo, todos com `path-not-absolute` (os `mkdtemp` são `C:\…`). O endpoint vivo da 0.76.134 instalada (29/09) responde `400 {"ok":false,"reason":"path-not-absolute"}` a um ingest com caminho `C:\Users\…\Pictures\Nexus Shot\…png`.
- Relacionado: F-577, F-613 (última milha do shot-bridge); port do Nexus Shot para Windows (repo nexus-shot, branch `feat/windows-port`).
- (resolvedor) Correcao: `isAcceptedAbsolute` por plataforma. No Windows aceita só letra de unidade (`C:\`); UNC e device paths (`\\host\share`, `\\?\`, `\\.\`) seguem recusados, porque o realpath de um UNC abriria SMB com o host informado. `shotAllowedRoots(home, platform, knownFolders)` usa `Pictures` + `Videos` no Windows (Movies no macOS, sem mudança) mais `app.getPath('pictures'|'videos')`, passados pelo `main.ts`, que cobrem as pastas redirecionadas. A comparação de raiz ignora caixa no win32 (NTFS). `parentDirOf` corta no último `/` ou `\`. Verificação: `npx vitest run src/main/shot-bridge/shot-bridge-server.test.ts src/renderer/state/shot-ingest.test.ts` 24/24 no Windows, com 5 testes novos (raízes por plataforma e pastas conhecidas, recusa de UNC/device, pasta redirecionada fora da home, caixa no Windows, `parentDirOf`). `npm run typecheck` 0.
