# F-577 — "Enviar para o NexusIDE" não produzia nada visível: shot-bridge sem consumidor no renderer

## F-577 | categoria: funcional | severidade: média | status: corrigido

- Tela/fluxo: Nexus Shot (app de captura) → botão "Enviar para o NexusIDE"
  na tela de revisão da gravação.
- Arquivo:linha: `src/renderer/state/shot-ingest.ts` (novo);
  `src/renderer/App.tsx` (wiring do listener); diagnóstico em
  `src/main/shot-bridge/shot-bridge-server.ts`,
  `src/main/main.ts:873-887`, `src/preload/preload.ts:720`.
- Passos: 1) gravar um trecho no Nexus Shot; 2) "Enviar para o NexusIDE";
  3) o Shot mostra "Enviado para o NexusIDE ✓" e o ack HTTP é honesto
  (200 `{"ok":true}`); 4) dentro do IDE nada aparece — nem toast, nem
  arquivo, nenhum feedback além do foco da janela e da notificação do macOS.
- Esperado: o IDE confirma a entrega dentro do app e permite abrir o
  arquivo recebido.
- Observado: silêncio. O evento `shot:files-received` chegava ao renderer
  via preload (`nexus.app.onShotFilesReceived`) e morria lá: nenhum
  componente ou store assinava a API.
- Causa: os commits `cb1c5638`/`a58a18ab` (15/09) entregaram o pipeline até
  o preload (main + contrato + exposição) sem nenhuma linha no renderer —
  a última milha da feature nunca foi construída. Reproduzido e confirmado
  com probe HTTP ao vivo contra o app empacotado (ingest aceito com 200;
  dentro do app, nada).
- Correção (`src/renderer/state/shot-ingest.ts`): consumidor no renderer no
  padrão `initDevServerStore` — assina `onShotFilesReceived` e empurra toast
  de confirmação: arquivo único → "Nexus Shot: <nome>" com ação **Abrir**
  (abre pelo app padrão via `openTerminalPath`, validação de caminho
  permanece no Main); lote → contagem + primeiros nomes com ação **Abrir
  pasta**. Falha de abertura vira toast de erro. Sem novo canal IPC e sem
  novo sink de renderer: consome só a superfície que já existia no preload.
- Limites deliberados: os arquivos NÃO são copiados nem movidos (contrato do
  shot-bridge: já vivem sob as raízes permitidas); anexar o shot como
  contexto no compose de um pane é próximo passo de produto, não deste fix.
- Validação: `npx vitest run src/renderer/state/shot-ingest.test.ts`
  (6 testes), `npm run typecheck`, `npm run security:renderer-sinks`
  (0 sinks executáveis).
