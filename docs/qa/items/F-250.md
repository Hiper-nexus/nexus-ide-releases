# F-250 — Release gate morria no smoke empacotado: probe mission-prepare sem licença

**Status:** corrigido
**Severidade:** alta para release (o gate `release:candidate` não passava),
sem impacto no usuário final
**Encontrado por:** primeira execução do `release:mac` de 0.76.154 —
`smoke-packaged-app.mjs` → `functional-failed: mission-prepare` com
`license_access_denied: login-required`.

## Sintoma

O smoke empacotado (`--smoke-test`, `NEXUS_PACKAGED_SMOKE=1`) abre o app com
userData descartável, roda 22 probes funcionais e encerra. O probe
`mission-prepare` (`src/preload/functional-smoke.ts` ~405) chama
`api.mission.prepare` — que desde a entrada do modelo de licença
(F-220/F-412 e cia., ainda nesta release) passa pelo gate
`assertLicenseAccess` e exige conta + selo + token assinado. O smoke não tem
nada disso: `login-required`, probe falha, gate de candidato falha.

## Decisão

O modo `--smoke-test` **nunca vira produto utilizável**: roda os probes,
imprime `functional-ready`/`functional-failed` e encerra — é a mesma
concessão que `smoke-core` já faz para vault real (`shouldAccessSecureStorage`),
auto-updater, hooks gerenciados e microfone. Conceder licença `pro` dentro
desse modo não vaza acesso: um Nexus "de graça" nesse modo só executa a
suíte de probes e morre.

Alternativa rejeitada: semear licença assinada no userData do smoke —
dependeria da chave privada na máquina que roda o smoke, o que quebraria
builds de Windows/CI (que são exatamente o motivo da chave pública
commitada).

## Correção

- `license-access.ts`: constante `SMOKE_LICENSE` (pro, verified,
  maxAgents ilimitado, cloudSync true, `canUseApp: true`) devolvida por
  `evaluate()` quando `isCurrentProcessSmokeTest()`. O funil único cobre
  `requireAccess`, `maxAgents`, `getAccessState` e listeners.
- `license-access.test.ts`: dois casos — smoke bypassa via argv +
  `vi.resetModules`, e sem a flag o mesmo estado sem licença continua
  fechado.

## Verificação

- `license-access.test.ts`: 30/30 verdes.
- `npm run package` + `smoke:package`: smoke chega a `functional-ready`
  (o sandbox_extension do verify-dir foi investigado separadamente).
