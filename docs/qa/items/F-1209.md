# F-1209 — Sessões ACP ficavam sem as ferramentas do Nexus no app empacotado (ponte MCP stdio morta)

## F-1209 | categoria: funcional | severidade: alta | status: corrigido
- Tela/fluxo: missão com `orch.agentTransport = 'acp'`; o harness ACP recebe em `session/new` o servidor MCP `nexus` montado por `buildAcpMcpStdioServer` (`src/main/orch/acp-mission-spawn.ts:165`).
- Arquivo:linha (antes): `src/main/acp/acp-mcp-stdio-bridge.ts:129-132` (`command: process.execPath` + `ELECTRON_RUN_AS_NODE=1`); `:91`, `:97`, `:99` (`+ '\\n'` dentro de `String.raw`); `:28` (`/[\\r\\n]+/g`).
- Passos: no app empacotado, abrir uma missão com transporte ACP; o agente tenta subir o MCP `nexus`.
- Esperado: o agente fala JSON-RPC com o Nexus pela ponte stdio.
- Observado: nenhuma resposta. Duas causas, ambas fora do alcance dos testes:
  1. O `forge.config.ts` desliga o fuse `RunAsNode`. No binário instalado o fio de fuses é `010011001` (posição 0 = RunAsNode = `0`). Com o fuse desligado o executável ignora `ELECTRON_RUN_AS_NODE` e `--eval` e só sobe o NexusIDE (segunda instância, sai). Em teste, `process.execPath` é o Node e a ponte "funcionava".
  2. O script fica num `String.raw`, então `'\\n'` virava a string de dois caracteres `\n`: cada resposta saía sem quebra de linha real e o cliente MCP stdio, que separa mensagens por linha, nunca recebia uma mensagem completa. O mesmo escape transformava `/[\r\n]+/` numa classe que apagava as letras `r` e `n` das mensagens de erro.
- Evidencia: fio de fuses lido do `Electron Framework` da 0.76.234 após o sentinel `dL7pKGdnNz796PbbjQWNKmHXBZaB9tsX`: `\x01\t010011001`. Teste novo com um executável que se comporta como o app com o fuse desligado: antes, stdout vazio; só com a troca do executável, stdout `{"jsonrpc":"2.0","id":7,"result":{"ok":true}}\n` com `\n` literal.
- (resolvedor) Correcao: a ponte roda no Node do sistema (`resolveCliBinary('node')?.binPath ?? 'node'`), como as pontes stdio de minimax, muse e qwen; sai o `ELECTRON_RUN_AS_NODE`. No `String.raw`, as quebras de linha e a regex passam a usar um único escape.
- Validacao: `src/main/acp/acp-mcp-stdio-bridge.test.ts` sobe um endpoint MCP HTTP local, troca `process.execPath` por um executável que ignora `--eval` (o app empacotado) e roda o spec como o agente ACP roda (command + args, env mesclado). Exige exatamente uma linha JSON-RPC terminada em `\n`. Falha antes, passa depois. `src/main/acp`, `main-owned-pane-runtime` e `acp-mission-spawn-account`: 8 arquivos verdes.
- Limite: a ponte depende de um `node` no PATH, como as demais pontes stdio e os harnesses ACP (que são CLIs Node). A sessão ACP real no `.app` assinado só se prova com build empacotado.
