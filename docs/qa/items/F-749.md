# F-749 — Atualização diária das CLIs deixava o Devin para trás

## F-749 | categoria: usabilidade | severidade: media | status: corrigido
- Tela/fluxo: atualização automática das CLIs (`startCliAutoUpdate`): uma vez por dia por CLI, sem pane ativo, com o PC ocioso.
- Arquivo:linha:
  - `src/main/adapters/cli-auto-update.ts` (`isSafeAutomaticCliRecipe`);
  - `src/main/adapters/cli-install-recipes.ts` (receitas do Devin, `automaticUpdate`);
  - `src/main/persistence/provider-config-store.ts` (`automaticCliCandidate`, `describeAutomaticCliCandidate`).
- Passos: atualização automática ligada (`cli-auto-update.json` `enabled: true`) e Devin instalado pelo canal oficial.
- Esperado: o Devin também é mantido atualizado.
- Observado (02/10): o arquivo de preferências registra checagens de agy, claude, codex, grok, kimi, mimo-code, openclaude e opencode, nunca do Devin. O operador atualizava à mão e o botão falhava (F-747). Pedido: "ideal nexus todo dia quando iniciado ele fazer varredura e atualizar todas cli por padrão".
- Causa: o passe automático só aceitava receitas `argv`. Script remoto ficava sempre no fluxo manual, e o canal oficial do Devin é script (`setup.ps1` no Windows, `install.sh` no Mac/Linux).
- (resolvedor) Correcao:
  - A tabela de receitas marca `automaticUpdate` só no canal oficial do Devin.
  - O passe aceita script com essa marca e HTTPS. Qualquer outro script continua manual, assim como WinGet e instaladores com privilégio.
  - O diálogo de consentimento lista "script oficial <url>" para esses candidatos.
  - No Windows o runner já tira o `devin.exe` do caminho (F-747).
  - O passe continua sem rodar com pane ativo da CLI e sem PC ocioso.
  - Testes: `cli-auto-update.test.ts` (Devin no Mac e no Windows entra; script genérico, `http://` e instalação desconhecida não entram).
