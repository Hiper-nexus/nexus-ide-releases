# F-1254 — Recusa de `cwd` mandava passar uma worktree que o spawn também recusa

## F-1254 | categoria: usabilidade | severidade: media | status: corrigido
- Tela/fluxo: `nexus_pane_spawn` / worker de missão com `cwd`.
- Arquivo:linha (antes):
  - `src/main/orch/nested-worktree-execution.ts:111-114`, a mensagem de `requestedCwdInside`;
  - `src/main/orch/tools-panes.ts:900`, a descrição do parâmetro `cwd`.
- Passos:
  1. `git worktree add ~/.nexus-worktrees/f1251.noindex` (worktree ligada a este repositório, fora do checkout).
  2. `nexus_pane_spawn {cwd: "~/.nexus-worktrees/f1251.noindex", task: …}` de um Maestro.
- Esperado: a recusa diz o que funciona.
- Observado: "cwd descartado: … não é uma pasta dentro de <root> **nem a raiz de outra worktree Git deste repositório** … ou passe a raiz de uma worktree ligada a este repositório". A pasta ERA a raiz de uma worktree ligada. A regra real (F-981, testada em `nested-worktree-execution.test.ts`) só aceita worktree ligada **dentro** do checkout. A descrição da ferramenta prometia o mesmo que a mensagem.
- Evidencia: ao vivo no app 0.76.238 (12/10). Dois spawns recusados com a mensagem acima. Movidas para `<root>/.harvest/f1251` e `.harvest/f1252`, as worktrees foram aceitas e os writers nasceram.
- (resolvedor) Correcao:
  - O comportamento fica como o F-981 decidiu: worktree fora do workspace não vira escopo de execução.
  - Mensagem e descrição passam a dizer a regra e a saída que funciona: `git worktree add <root>/.harvest/<nome>` ou `isolatedWriter:true`.
  - Teste: a recusa traz o caminho `.harvest/<nome>` e "Worktree fora do checkout não vira cwd de pane", e não traz mais "nem a raiz de outra worktree".
