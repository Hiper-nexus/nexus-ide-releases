# F-591 — Pacing do retry EAGAIN (1ms) + retire do master fd no dispose (porte Orca #15319/#17914)

## F-591 | categoria: orca-parity | severidade: alta | status: corrigido
- Tela/fluxo: Todos os panes de agente (PTY host) sob leitor travado — busy-loop de CPU no thread que detém todos os ptys
- Arquivo:linha: `scripts/patch-node-pty-darwin.mjs:17-124`, `scripts/patch-node-pty-darwin.test.mjs:58-140`
- Orca: `stablyai/orca#15319` (pacing) + `#17914` (fd retire no dispose)

## Passos
1) Nosso `@lydell/node-pty-darwin` tem o mesmo `CustomWriteStream` com retry EAGAIN via `setImmediate` (`lib/unixTerminal.js:319`).
2) Quando o filho para de drenar o stdin, o retry vira busy-loop no thread de todos os ptys — medido no Orca (macOS arm64): 121.316 EAGAIN/s a 101,6% CPU vs 805/s a 4,1% com pacing de 1ms.

## Esperado
- Retry EAGAIN com `setTimeout(..., 1)` (`EAGAIN_RETRY_DELAY_MS = 1`); `dispose` usa `clearTimeout`, aposenta o master fd (`_fd = -1`) e descarta a fila — nada pós-dispose alcança um fd reutilizado e nenhum retry dispara após dispose.
- Pastes em leitor saudável não degradam (0–3 EAGAINs/MB em todas as medições do Orca); 1ms (não 5ms) preserva entrega em leitores por rajadas (agentes).

## Observado
- Nosso patch darwin selava só o spawn-helper (`/usr/bin/perl`); write-loop intocado, sem pacing e sem fd retire.

## Evidencia
- `npx vitest run scripts/patch-node-pty-darwin.test.mjs` → 4 passed (end-to-end seal+pacing, upgrade selado→final, drift fail-closed, guarda de helper).
- `npm run typecheck` → 0 erros.
- Aplicado end-to-end no `node_modules` vivo: hash final `f69e167f…14f0322f` == pin.
- Escopo: darwin-only (nosso patch só cobre darwin); Linux herda o fix quando o mesmo pacing for levado ao patch das demais plataformas — registrado, não feito aqui.

## (resolvedor) Correcao
- `applyEagainPacing()` com 5 âncoras `replaceExactlyOnce` fail-closed; fluxo em 3 estados (pristine→final, selado→final, final→verifica); pin `PATCHED_UNIX_TERMINAL_SHA256` atualizado; `SEALED_...` preservado como caminho de upgrade.
- Mudança de comportamento assumida: writes pós-dispose viram no-op silencioso (antes: `console.error` + limpeza) — impede escrita em fd reutilizado; verificado contra o fluxo de close do pty-manager (sem writes pós-dispose no caminho normal).
