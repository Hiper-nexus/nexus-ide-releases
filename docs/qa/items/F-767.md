# F-767 — "auto-update" pinava o modelo utilitário codex-auto-review

## F-767 | categoria: funcional | severidade: media | status: corrigido
- Tela/fluxo: roteamento de `nexus_pane_spawn` / `mentionedRoute` quando o texto da tarefa cita um modelo.
- Arquivo:linha: `src/main/orch/task-router.ts:645` (`MENTION_GENERIC_TOKENS`), `:654` (`MENTION_UTILITY_MODELS`), `:777` (sufixo) e `:787` (token solto).
- Passos: 1) Spawn cujo texto diz "…preferir a mais nova, alinhar auto-update e descoberta de modelos…".
- Esperado: ninguém pediu modelo; a rota segue a tabela, sem pin de `codex-auto-review`.
- Observado: a rota saiu `codex:codex-auto-review` com motivo "modelo pedido no texto". O token "auto" era o único ≥ 4 letras desse modelo entre os instalados, não estava em `MENTION_GENERIC_TOKENS`, e "preferir" conta como palavra de escolha.
- Evidencia: antes do fix, `mentionedRoute` da frase devolvia `{ adapterId: 'codex', model: 'codex-auto-review' }` (`task-router-review-floor.test.ts`, teste F-767). Depois o mesmo teste exige modelo indefinido nessa frase e ainda pina quando o texto diz "use o codex-auto-review neste diff". `npm run typecheck` saiu 0.
- (resolvedor) Correcao: `auto`, `review` e `update` entraram nos tokens genéricos (`preview` e `latest` já estavam). Modelo utilitário (`codex-auto-review`) não é escolhido por token solto nem por sufixo parcial (`from > 0`, ex. "auto review"). A sequência completa do id, a partir do início, continua pinando quando o operador pede o nome. Hash do commit no handoff (o doc entra no mesmo commit).
