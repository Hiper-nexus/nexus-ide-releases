# F-531 — Orquestrador em pane ad-hoc reutiliza squad salvo sem cair em gpt-5.5 e delega via nexus_route_task e nexus_pane_spawn sem executar missões sozinho

## F-531 | categoria: funcional | severidade: alta | status: corrigido
- Tela/fluxo: Painel / terminal do orquestrador ou operador (pane direto sem wizard de missão)
- Arquivo:linha: `src/main/orch/squad-architect.ts:484`, `src/main/orch/orch-ipc.ts:2414`, `src/main/orch/tools-panes.ts:501`, `src/main/orch/tools-domain.ts:1386`, `src/main/orch/orchestrator-doctrine.ts:42`
- Passos:
  1) Abrir o orquestrador em um pane de terminal e solicitar execução de tarefas do projeto.
  2) O orquestrador precisa delegar tarefas abrindo novos panes no grid.
- Esperado:
  - O sistema deve priorizar o squad configurado pelo usuário para o workspace, respeitando os modelos e configurações salvos (evitando cair no modelo default obsoleto `gpt-5.5`).
  - O orquestrador deve ter permissão para chamar `nexus_route_task` para selecionar a CLI e o modelo mais inteligentes e uniformes para cada tarefa.
  - O orquestrador deve delegar o trabalho abrindo novos panes via `nexus_pane_spawn` em vez de executar toda a missão sozinho em seu próprio terminal (a menos que o usuário peça explicitamente para ele trabalhar sozinho).
- Observado:
  - `designSquadForWorkspace` não verificava `preferSavedSquad`, sintetizando equipes com modelos padrão que traziam `gpt-5.5` indesejado.
  - `tools-panes.ts` no spawn ad-hoc não consultava os integrantes do squad do usuário quando nenhum modelo explícito era informado, caindo no default estático do adapter.
  - `nexus_route_task` em `tools-domain.ts` bloqueava qualquer chamador que não possuísse `role === 'orchestrator'` com uma missão selada vinculada, impedindo panes interativos do operador de rotear tarefas.
  - A doutrina de coordenação carecia de diretriz explícita instruindo a delegação via `nexus_route_task` em vez de autoexecução em pane avulso.
- Evidencia:
  - `designSquadForWorkspace` e `orch-ipc.ts` agora utilizam `preferSavedSquad: true`.
  - `nexus_pane_spawn` utiliza o modelo/effort configurado no squad caso não seja fornecido explicitamente.
  - `nexus_route_task` permite chamadas de sessões interativas (`role === 'user'` ou orquestrador sem missão vinculada).
  - `orchestrator-doctrine.ts` reforça a doutrina de delegação inteligente e uniforme através do motor do Nexus.
- (resolvedor) Correcao:
  - `src/main/orch/squad-architect.ts`: suporte a `preferSavedSquad` em `designSquadForWorkspace`.
  - `src/main/orch/orch-ipc.ts`: repasse de `preferSavedSquad: true`.
  - `src/main/orch/tools-panes.ts`: consulta a `findAgentInAnySquad` para herdar modelos configurados.
  - `src/main/orch/tools-domain.ts`: liberação de `nexus_route_task` para `ctx.role === 'user'`.
  - `src/main/orch/orchestrator-doctrine.ts`: doutrina atualizada.
