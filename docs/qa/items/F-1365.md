# F-1365 — MCP stdio com command em string única ("npx pkg@latest") morre ENOENT no spawn

## F-1365 | categoria: funcional | severidade: alta | status: corrigido
- Tela/fluxo: importação de MCP de terceiros (Cursor/Claude/Codex/OpenCode) para o hub e materialização do hub no spawn dos panes.
- Arquivo:linha (antes): `hubFromStdioLike` (`src/main/mcp-hub/mcp-hub-sync.ts:118/:136`) copiava `command` como string única; `stringList` (`:95-98`) descartava `args: []`; `toSpawnServer` e `claudeFamilyHubMcpServers` (`src/main/mcp-hub/mcp-hub-spawn.ts:98-113/:271-275`) reemitiam o command inteiro; `nativeStdioServerDescriptors` (`src/main/mcp-hub/mcp-stdio-bridge.ts`) idem para o hub bridge.
- Passos: 1) `~/.cursor/mcp.json` com `Playwright: {command: "npx @playwright/mcp@latest", args: []}`. 2) Sync importa para o hub (`source: cursor`, primeiro hit vence — a forma correta do Codex é descartada). 3) Export/spawn repassa a string inteira como argv0.
- Esperado: `command: "npx"`, `args: ["@playwright/mcp@latest"]`.
- Observado (sonda s240-D): sessão Claude `b66e76cb` com `failedMcpServers playwright ENOENT: posix_spawn 'npx @playwright/mcp@latest'`. `npx` existe em `/opt/homebrew/bin`. Docs oficiais do Claude Code (2026-10) confirmam o contrato: executável em `command`, argumentos em `args`; nada promete shell.
- Evidencia (RED, fonte anterior): `mcp-hub-sync.test.ts` › "parte 'npx @playwright/mcp@latest' em command + args", › "respeita aspas ao partir o command", › "export para cursor/claude nunca emite command com espaço e args vazio"; `mcp-hub-spawn.test.ts` › "hub legado com command 'npx @playwright/mcp@latest' chega ao spawn partido". Todos falhavam com `command` inteiro e `args` vazio.
- (resolvedor) Correcao:
  - `splitQuotedArgv` + `normalizeHubServerArgv` novos em `mcp-hub-core.ts`: quando o command tem espaço e `args` está vazio, parte em argv respeitando aspas simples/duplas (transportes http não são tocados). teto (ponytail): caminho com espaço e sem args também é partido — não partir é ENOENT garantido.
  - Aplicado em três fronteiras: importação (`hubFromStdioLike`), export do sync (`applyMcpSync` normaliza os servers antes de escrever nas tools — hubs legados gravados antes do fix são corrigidos na saída) e spawn (`toSpawnServer` em `mcp-hub-spawn.ts`, cobrindo família Claude, Codex, OpenCode e Grok; `nativeStdioServerDescriptors` em `mcp-stdio-bridge.ts` para o hub bridge, que lê o `~/.claude.json` real do operador).
  - Com a importação normalizando, cursor (não partido) e codex (partido) convergem para a mesma forma — o "primeiro hit vence" deixa de importar.
- Investigação do `posix_spawn 'stdio'`: a variante literal NÃO foi encontrada nem nos logs (a sonda varreu a sessão) nem em nenhum escritor deste código — todos emitem `command` string e `type` separado. Formato que o Claude lê (`~/.claude.json` mcpServers e `.mcp.json`, mesmo esquema): `type` opcional (ausente = stdio), `command`, `args`, `env`; entrada malformada é pulada com aviso. Registrado como não confirmado; o fix elimina a família de erro (command passa a ser token único sem espaço).
- Validacao: `mcp-hub-sync.test.ts`, `mcp-hub-spawn.test.ts`, `mcp-hub-core.test.ts`, `mcp-stdio-bridge.test.ts` verdes; `tsc --noEmit` 0 erros.
