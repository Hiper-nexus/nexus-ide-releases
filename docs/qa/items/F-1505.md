# F-1505 — Windows: arquivo de squads em UTF-16 (PowerShell) ou com BOM era recusado ou ignorado

## F-1505 | categoria: funcional | severidade: media | status: corrigido
- Renumerado na integração com a origin (0.76.252): este achado era o F-1451 da frente de squads (nunca publicado) e virou F-1505 para não colidir com a numeração que a origin publicou (F-1436..F-1451).
- Tela/fluxo: Configurações › Squads › Importar com um JSON salvo no Windows; migração de primeiro boot de `~/.nexus/squads.json` (`src/main/orch/squad-store.ts`).
- Arquivo:linha: `src/main/orch/squad-store.ts:852` (`new TextDecoder('utf-8', { fatal: true })`) e `:286` (`fs.readFileSync(candidate, 'utf8')` na migração), antes da correção.
- Passos: 1) Gerar/editar o arquivo no PowerShell 5.1 (`... | Out-File squads.json`, que grava UTF-16 LE com BOM). 2) Importar. / Ter `~/.nexus/squads.json` com BOM UTF-8 e abrir o Nexus com o banco vazio.
- Esperado: aceitar UTF-8 com/sem BOM e UTF-16 LE/BE com BOM; outro conteúdo é recusado com mensagem clara.
- Observado: importar UTF-16 falhava com o erro cru `The encoded data was not valid for encoding utf-8`; a migração lia o arquivo como texto `'utf8'`, o BOM ia junto para o `JSON.parse`, que falhava, e o `catch` pulava o arquivo sem aviso — os squads antigos simplesmente não apareciam. JSON inválido também chegava cru (`Unexpected token…`).
- Causa raiz: o decoder só conhecia UTF-8, e o caminho da migração não passava por decoder nenhum (o `readFileSync(..., 'utf8')` não remove BOM).
- Correcao: `decodeSquadsFile` escolhe o decoder pelo BOM (FF FE → UTF-16 LE, FE FF → UTF-16 BE, senão UTF-8; o `TextDecoder` consome o BOM) e recusa o que não decodifica com `O arquivo de squads não está em UTF-8 nem em UTF-16 com BOM; salve-o como UTF-8 e importe de novo.`. `parseSquadsFileText` tira um BOM que sobrou no texto e troca o erro do `JSON.parse` por `O arquivo de squads não é um JSON válido (…).`. A importação, o funil interno `importSquadsJson` e a migração (agora lendo bytes) usam os dois. O limite de 1 MiB continua sobre os bytes brutos e o hash bruto do IPC não muda.
- Evidencia:
  - RED (código antigo): `npx vitest run src/main/orch/squad-store.test.ts -t "F-1505"` → 9 falhas: UTF-16 LE/BE com BOM `TypeError: The encoded data was not valid for encoding utf-8`; texto com BOM `SyntaxError: Unexpected token U+FEFF (BOM)`; Latin-1/UTF-16 sem BOM/byte sobrando com a mensagem crua do decoder; JSON inválido com `Unexpected token…`; migração com BOM `expected undefined to be 'Equipe do Windows — ação'`. Contraprova: o mesmo teste de migração sem o BOM passa no código antigo — o que falhava era só o BOM.
  - GREEN: `npx vitest run src/main/orch/squad-store.test.ts src/shared/squad-roster-rules.test.ts` → 57/57.
