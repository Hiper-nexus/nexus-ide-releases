# F-648 — No Windows a mesma pasta escrita com outra caixa ou nome curto 8.3 caía em quarentena de manifesto

## F-648 | categoria: funcional | severidade: media | status: corrigido
- Tela/fluxo: abrir workspace com `.nexus/project.json` no Windows quando o caminho chega numa grafia diferente da do disco — `c:\users\…` digitado/colado, `C:\Users\ADMINI~1\…` (nome curto 8.3, o `%TEMP%` do Windows), ou o mesmo checkout registrado antes com outra grafia.
- Arquivo:linha: `src/main/persistence/project-git-lineage.ts:340` (raiz do worktree comparada por string com a raiz recebida), `project-git-lineage.ts:315` (`--git-common-dir` relativo resolvido contra a grafia recebida, `--absolute-git-dir` na grafia do disco), `src/main/persistence/project-identity.ts:681` (duplicado de checkout comparado por string).
- Passos: 1) Com o F-647 corrigido, abrir `c:\users\administrador\documents\projetos\nexus-ide` (ou `C:\Users\ADMINI~1\Documents\Projetos\nexus-ide`).
- Esperado: é a mesma pasta — abre com o mesmo checkout.
- Observado: `project manifest must live at the Git worktree root` (o git devolve `C:/Users/Administrador/…`, o `fs.realpathSync` do Node mantém a grafia recebida), depois `Git worktree directory is outside its common directory`, e com registro anterior `duplicate-checkout-token`. O toast mostra o mesmo "manifesto não bate" do F-647.
- Evidencia: repro com `resolveProjectExecutionScope` em 25/09 — antes, as grafias minúscula e 8.3 do `nexus-ide` quarentenavam; depois, as três grafias resolvem o mesmo `checkoutId` e o worktree `nexus-ide-wt-hookfix` segue com id próprio. `project-identity.test.ts` falhava 18 de 24 no Windows (o `os.tmpdir()` é 8.3); agora passa 24/24.
- (resolvedor) Correcao: `isSameDirectory` compara a forma canônica do sistema (`fs.realpathSync.native`, que resolve caixa e nome curto) em vez da string, na raiz do worktree e no teste de checkout duplicado; os diretórios administrativos do git são resolvidos com o mesmo canônico. Subdiretório do worktree e token vivo em outra pasta continuam recusados. Testes: `project-git-lineage.test.ts` › "aceita a raiz do worktree escrita com outra caixa" (falha no código antigo) e "continua recusando manifesto num subdiretório do worktree".
