# F-114 — Erro 401 de auth exibe falsamente como "esgotada", oculta botão de login e trava sessão ativa

## F-114 | categoria: funcional | severidade: alta | status: corrigido
- Tela/fluxo: Configurações › Providers › Contas e login (multi-conta Claude / provedores OAuth); gerenciamento de contas com failover
- Arquivo:linha: `src/main/persistence/account-store.ts` (`listAccountInfos`, `isAuthCooldownReason`, `addActiveSessionAccount`, `activateAccount`), `src/renderer/components/settings/AccountsManager.tsx` (`cooldownText`, `renderRow`, `autoSaveSessionAfterLogin`, `useAccount`)
- Passos: 1) Ter 2 contas Claude salvas no Nexus (ex.: `retornoja@gmail.com` ativa e `admin@volarehost.com.br` na reserva) 2) Um terminal sofre 401 (OAuth token expired / sessão expirada) 3) Abrir Contas e login em Configurações
- Esperado:
  1) A conta com erro de autenticação indica claramente "sessão expirada — entre novamente" com botão primário "Entrar novamente" visível.
  2) O erro não é rotulado como "cota esgotada" ("esgotada · volta em Xmin").
  3) Se a conta for a sessão ativa do CLI (já conectada e com credencial válida no Keychain), o Nexus verifica o login vivo e limpa qualquer cooldown/401 residual.
  4) Ao reautenticar uma conta existente via terminal de login, o Nexus atualiza o vault e limpa os erros daquela conta em vez de ignorar o salvamento.
- Observado:
  1) Ambas as contas exibiam "esgotada · volta em 1min" e "esgotada · volta em 9min" em amarelo/vermelho, mesmo com a assinatura ilimitada e com cota disponível.
  2) Não aparecia o botão "Entrar novamente" nem local para logar na conta (botão `Usar` desabilitado com tooltip de "Em cooldown").
  3) A conta ativa estava logada no CLI (Claude Code Max) com badge "conectado" no topo, mas o Nexus continuava exibindo "esgotada" por causa do registro no banco SQLite não refutado.
  4) `autoSaveSessionAfterLogin` continha `if (known) return;` que ignorava re-logins de contas já existentes no vault.
- Correção (04/09/2026):
  1) `src/main/persistence/account-store.ts`:
     - `isAuthCooldownReason` exportado e expandido para cobrir padrões adicionais de falha de autenticação (401, token inválido, sessão expirada, stored token rejected).
     - `listAccountInfos` atualizado para:
       * Detectar se a conta é a sessão nativa ativa da CLI no Keychain e refutar/limpar stale auth cooldowns automaticamente (`clearCooldown`).
       * Projetar `onCooldown: false` quando o erro for de autenticação (não é esgotamento de cota).
       * Projetar `needsRelogin: true` quando houver falha de autenticação/401 (`isAuthCooldownReason` ou `hasRecentClaudeRefreshFailure`), permitindo à UI exibir o alerta e o botão de login.
     - `addActiveSessionAccount` atualizado para que, ao atualizar uma conta existente (`existing`), limpe o cooldown, resete `lastError` e remova a marcação de falha de refresh.
     - `activateAccount` atualizado para limpar `isAuthCooldownReason` e a marca de falha de refresh quando o operador clica para sincronizar ou usar a conta.
  2) `src/renderer/components/settings/AccountsManager.tsx`:
     - Adicionado `cooldownText` diferenciando cota esgotada (`cota esgotada · volta em ...`) de limite de requisições temporário (`limite temporário · volta em ...`).
     - `renderRow` prioriza `needsRelogin` exibindo `sessão expirada — entre novamente` e renderiza o botão primário `Entrar novamente` para contas ativas e reservas.
     - `autoSaveSessionAfterLogin` atualizado para não descartar contas conhecidas que precisem de relogin ou estejam em cooldown, atualizando suas credenciais e limpando seus erros.
     - `useAccount` aprimorado com mensagem de feedback contextual para sincronização com o CLI.
- Validação:
  1) `npx vitest run src/renderer/components/settings/AccountsManager.test.tsx src/main/persistence/account-store.test.ts src/main/persistence/account-store-cooldown.test.ts` (passando com 5 novos testes de regressão).
  2) `npm run typecheck` (0 erros).
  3) `npm run security:renderer-sinks` (0 sinks).
