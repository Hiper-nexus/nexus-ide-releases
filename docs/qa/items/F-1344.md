# F-1344 — "migrar o banco de produção" e "corrupção de dados" caíam em medium

## F-1344 | categoria: funcional | severidade: media | status: corrigido
- Tela/fluxo: roteamento de tarefa → `classifyTask` (tier → modelo/esforço).
- Arquivo:linha (antes): `src/main/orch/task-router.ts:331-348` (`CRITICAL_SIGNALS`) e `:385-392` (`CRITICAL_STEMS`). Havia `migration`/`migração` (substantivo), mas não o verbo (`migrar`, `migre`, `migrate`) nem corrupção de dados.
- Passos:
  1. `classifyTask('migrar o banco de dados de produção sem downtime')`
  2. `classifyTask('migre o schema do postgres para a v2')`
  3. `classifyTask('corrigir corrupção de dados que afeta todos os clientes')`
- Esperado: critical. Migração de banco em produção e corrupção de dados são o risco em si.
- Observado: `medium`, sem sinal. "produção" é ambíguo (F-1289) e não decide sozinho.
- Evidencia: sonda C (s240) e RED em `task-router.test.ts` › "F-1344…": `expected 'medium' to be 'critical'` nos 5 casos (pt/en).
- (resolvedor) Correcao:
  - Causa raiz: a lista de risco tinha só o substantivo da migração e nenhum termo de corrupção.
  - O verbo entra por palavra inteira, para não duplicar o sinal `migration`/`migração` (o teste do F-1289 confere `signals: ['migration']`): `migrar`, `migre`, `migra`, `migrem`, `migrando`, `migrate`, `migrated`, `migrating`.
  - Corrupção entra por radical: `corrup` (corrupção/corrupt/corrupted/corruption) e `corromp` (corrompido/corromper).
  - Nenhum dos dois é sinal só de domínio (F-1341), então segue valendo em pedido de documento ou de ação mecânica.
  - Testes: `task-router.test.ts` (5 RED → verdes) e as 18 suítes task-router* + mission-routing-matrix verdes (568).
