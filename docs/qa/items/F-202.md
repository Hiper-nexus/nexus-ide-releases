# F-202 — LANG UTF-8 inexistente herdado (en_BR) cuspia warnings em todo boot de worker

## F-202 | categoria: funcional | severidade: baixa | status: corrigido
- Tela/fluxo: boot de qualquer pane (shell, CLI, missão) em máquina com locale inválido herdado.
- Arquivo:linha: `src/main/pty/pty-env-locale.ts:27`.
- Passos: 1) Shell com `LANG=en_BR.UTF-8` (idioma en + região BR no macOS — termina em UTF-8 mas não existe em `locale -a`). 2) Abrir qualquer pane. 3) Todo filho cuspia `perl: warning: Setting locale failed` + `Falling back to the standard locale ("C")`.
- Esperado: sufixo UTF-8 não é prova — só locale instalado vale; inexistente cai para o fallback sem warnings.
- Observado: `ensureUtf8Locale` confiava em qualquer valor terminado em UTF-8. Campo em 07/09/2026: todo boot de worker no dev mostrava os warnings (o próprio shell do operador tinha `LANG=en_BR.UTF-8`, confirmado com `locale -a` sem `en_BR`).
- Evidencia: print do operador com warnings de perl em todos os panes + `locale -a` sem `en_BR.UTF-8` e shell com `LANG=en_BR.UTF-8`.
- (resolvedor) Correcao: `ensureUtf8Locale` agora valida o herdado contra `locale -a` (cache por processo, `execFileSync` sem shell, argv fixo) e descarta o inexistente antes do fallback `en_US.UTF-8` assumir. Sem UTF-8 herdado, nem consulta o sistema (spawn do Finder continua barato). Sem como verificar (binário ausente, erro) ou lister que lança: fail-open, confia como antes — locale nunca trava spawn.
