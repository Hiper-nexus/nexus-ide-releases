# F-1238 — Code map lê o índice estrutural do disco de forma síncrona na main a cada query até cachear

## F-1238 | categoria: performance | severidade: baixa | status: corrigido
- Tela/fluxo: `nexus_code_map_query` → `ProjectOrientationService.indexedPaths()`.
- Arquivo:linha: `src/main/context/orientation/orientation-service.ts:204-213`, chamado em `src/main/orch/tools-code-map.ts:110`.
- Origem: revisão cruzada da 0.76.236 (achado 6, PLAUSIBLE). O F-1226 introduziu a chamada.
- Observado (por leitura): enquanto o índice estrutural não está no cache em memória, cada query lê o JSON do disco de forma síncrona no processo principal. Em repositório grande (~11 mil arquivos) isso custa alguns ms por chamada.
- Sugestão: carregar de forma assíncrona e reusar a promessa em voo.
- Evidencia: `src/main/orch/tools-code-map.test.ts`, caso "F-1238". Main frio (mapa e índice só no disco), duas `nexus_code_map_query` concorrentes. Com a fonte anterior, o índice era lido por `fs.readFileSync` (`expected 1 to be +0`).
- (resolvedor) Correcao:
  - Causa: `indexedPaths()` era síncrono e chamava `readOrientationStructuralIndex` (`lstatSync` + `readFileSync`) no Main enquanto o índice não estava em memória.
  - `orientation-structural-index-cache.ts`: novo `readOrientationStructuralIndexAsync` (`fs.promises.lstat` + `fs.promises.readFile`). A validação foi extraída para `parseOrientationStructuralIndex` e é a mesma do leitor síncrono, que fica só para testes.
  - `orientation-service.ts`: `indexedPaths()` agora é `async` e passa por `#loadStructuralIndex`. Esse método guarda a promessa em voo por escopo, então chamadas concorrentes dividem uma leitura. Se um build ou merge publicar um índice enquanto o disco é lido, o da memória vence. Índice ausente não é cacheado, como antes.
  - `tools-code-map.ts:110`: `await service.indexedPaths(ctx.scope)`. A busca não mudou.
- Validacao (launchd): `tools-code-map.test.ts` + `src/main/context/orientation`: 17 arquivos, 96/96. O teste novo segura a leitura até as duas queries pedirem os caminhos e exige 1 `fs.promises.readFile` do índice e 0 `readFileSync`.
- Fora do escopo: `get()` ainda lê o `current.json` do mapa com `readFileSync` (`orientation-cache.ts:105`) quando o mapa não está em memória.
