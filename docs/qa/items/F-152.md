# F-152 — Novo login Kimi é substituído pelo token antigo da conta gerenciada

## F-152 | categoria: funcional | severidade: alta | status: corrigido
- Tela/fluxo: cadastrar/reautenticar uma conta Kimi e abrir novos panes depois de renovar o token.
- Arquivo:linha: `src/main/adapters/managed-credentials.ts` (`freshnessFromAuthContents`, `shouldWriteAuthFile`, `readBackFresherAuth`).
- Passos: materializar token antigo de uma conta; salvar novo login com `expires_at` maior; preparar novo pane; ler auth atualizada de volta para o cofre.
- Esperado: novo login vence o snapshot antigo; rotações posteriores da CLI vencem o snapshot anterior, sem tocar outras contas.
- Observado: o comparador reconhecia somente `last_refresh`/JWT aninhado do Codex. Kimi com `access_token`/`expires_at` no topo era desconhecido; o arquivo antigo era mantido e depois importado sobre o novo login.
- Evidencia: dois testes sintéticos (expiração em segundos e milissegundos) falharam antes da correção, preservando o token antigo em vez do novo.
- (resolvedor) Correcao: reconhecer expiração OAuth do Kimi e access JWT no topo; preservar a ordenação já usada para Codex. Testes cobrem novo login, rotação posterior da CLI, read-back e conta B independente.
- Validacao: `npx vitest run src/main/adapters/managed-credentials.test.ts` passou; regressões em segundos e milissegundos falharam antes do patch. Typecheck e renderer-sinks passaram. Somente credenciais sintéticas nos testes.
