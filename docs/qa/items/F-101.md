# F-101 — Missão para quando adapter perde credencial e não faz fallback

## F-101 | categoria: funcional | severidade: alta | status: corrigido
- Tela/fluxo: Orquestração de missão civil / Via Rápida
- Arquivo:linha: `src/main/orch/tool-util.ts` (`spawnPaneAndMaybePrompt`), `src/main/orch/spawn-seat-fallback.ts` (novo)
- Passos:
  1. Criar missão "pergunte a cada pane quanto é 1+1 e consolide as respostas".
  2. Roster inclui worker cujo adapter (ex: cursor-agent) reporta `missing-credential`.
  3. O spawn falha e o worker não é re-alocado para outro adapter disponível.
  4. O Maestro continua esperando handoff do assento que nunca nasceu.
- Esperado: O orquestrador remapeia o assento para outro adapter com credencial disponível (Codex, Grok, deepseek, etc.) e a missão continua.
- Observado: `[missing-credential] cursor-agent: no-credential — remint silencioso`; o assento some e o Maestro pode travar esperando resposta.
- Evidencia: Log E2E v3: `tool nexus_pane_spawn FALHOU (Coordenar e revisar): [missing-credential] cursor-agent: no-credential — remint silencioso`.

## Correção aplicada (21/08/2026)
- `src/main/orch/spawn-seat-fallback.ts`: cadeia de sucessão de assento
  (`shared/seat-chains`, mesma regra do remint do revisor) caminha quando o
  pre-spawn probe falha com classe credencial (`missing-credential`,
  `key-missing`). Erros não-credenciais (binary-missing, sandbox, modelo
  selado) continuam fail-closed visíveis.
- `src/main/orch/tool-util.ts` (`spawnPaneAndMaybePrompt`): ao falhar a
  sonda de credencial, cada candidato da cadeia é sondado; o primeiro que
  passa senta com `model` descartado (modelo é do adapter original) e log
  único `[pane-spawn] … assento remapeado`. Sem elo viável, a falha original
  sobe visível (nunca troca silenciosa por algo também quebrado).
- Paridade Overclock confirmada na varredura 21/08: capacidade ausente
  DEGRADA (troca de tier), nunca bloqueia a missão.
- Validação: `npx vitest run src/main/orch/spawn-seat-fallback.test.ts`
  (8/8), suites civilian-pronto/delivery/via-rapida (69/69),
  tools-handoff/circuit-break/respawn/idle-delivery (82/82),
  `npx tsc --noEmit` limpo.

## Notas de investigação
- O E2E atual usou worker Codex (`gpt-5.5`) e deepseek (`deepseek-v4-flash`) com sucesso.
- A falha ocorreu em um terceiro assento alocado para cursor-agent, que não tinha credencial configurada.
- Solução provisória adotada no E2E: reduzir/esperar que o Maestro ignore o assento faltante e complete com as respostas dos panes que responderam.
- Correção definitiva aplicada no ponto único de spawn main-owned
  (`spawnPaneAndMaybePrompt`), cobrindo tanto MCP spawn quanto revisor.
