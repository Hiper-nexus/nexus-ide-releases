# F-925 — nexus_pane_close dizia "unknown pane" enquanto o inventário listava o pane vivo

## F-925 | categoria: funcional | severidade: alta | status: corrigido
- Tela/fluxo: `nexus_pane_close` num pane de missão (agy idle).
- Arquivo:linha: `src/main/orch/pane-registry.ts` (`getPaneAuthzInfo`).
- Passos: 1) Com um pane agy idle vivo, chamar `nexus_pane_close("pane-muv26zi7-1b")`.
- Esperado: o pane fecha; ou a recusa nomeia um pane que não existe.
- Observado (05/10): `unknown pane: pane-muv26zi7-1b (panes vivos desta missão: pane-muv26zi7-1b agy idle; …)` — a própria mensagem listava o pane como vivo. O mesmo com `pane-muv262dk-14`.
- Causa: divergência entre inventário e resolução. `listPaneSnapshots` concatena o espelho do renderer E o registro main-owned; `getPaneAuthzInfo` juntava os matches de identidade e exigia `length === 1`. Um pane presente nos DOIS registros (adoção sem remoção do main-owned) gerava 2 matches do MESMO paneId → `null` → "unknown pane", enquanto o inventário o listava.
- (resolvedor) Correcao:
  - Matches de identidade são deduplicados por `(paneId, sessionId)`. Ambiguidade real (panes DIFERENTES) continua `null`; duplicata do mesmo id resolve para um.
  - Testes: `pane-registry-pane-number.test.ts` ("F-925: o mesmo pane nos dois registros não é ambiguidade" e "panes DIFERENTES com o mesmo sessionId continuam ambiguidade").
- Como foi achado: relato do operador em 05/10 (close devolvendo unknown para pane listado como vivo).
