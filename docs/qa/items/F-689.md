# F-689 — Codex no Windows morria em segundos com o Nexus elevado

## F-689 | categoria: funcional | severidade: critica | status: corrigido
- Tela/fluxo: missão da aba, 29/09 18:47–18:48: o Maestro abriu dois Codex seguidos para a pré-revisão.
- Arquivo:linha: `src/main/pty/pty-manager.ts` (argv final do agente, depois de `secureAutonomousCliArgs`); `src/main/orch/codex-cli-version.ts` (`codexNoDaemonArgs`).
- Passos: 1) Nexus aberto como administrador (processo principal elevado; os panes herdam). 2) Codex 0.159 instalado. 3) Abrir qualquer pane Codex.
- Esperado: o Codex abre e trabalha.
- Observado: `agent-pty-exit` com `exitCode: 0` após 12–20 s, `worker-died-without-delivery` × 3 e `writer_circuit_break` (codex fora da missão). O Maestro: "o Codex da pré-revisão não conseguiu rodar ferramentas".
- Evidencia: reproduzido num PTY real no mesmo contexto elevado. O Codex desenha o composer e sai com "Error: start the Windows daemon from a non-elevated terminal; shared clients must not inherit administrator privileges. To work without the background server, rerun the same command with --no-daemon". Com `--no-daemon` ele continua vivo (tela de "Trust this folder?", como esperado). Elevação medida pelo token: `nexus-ide` MAIN ELEVATED desde 08:33.
- Causa: o Codex 0.159 do Windows passou a usar um servidor compartilhado em segundo plano, que recusa cliente elevado. O argv governado é reconstruído por allowlist; nada do Nexus pedia o modo sem servidor.
- (resolvedor) Correcao: no Windows todo pane Codex recebe `--no-daemon` no início do argv, depois da reconstrução governada (o Codex aceita a flag antes de qualquer subcomando: resume, fork, exec). Ela só entra quando o `--help` do Codex instalado a anuncia; o `--help` é lido pelo lançador verificado do `.cmd` do npm e memorizado (145 ms na primeira vez). Rodar sem o servidor também é o que o isolamento por pane pressupõe (CODEX_HOME próprio). Testes em `codex-cli-version.test.ts`.
