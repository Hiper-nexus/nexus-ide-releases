# F-1251 — `**/` no meio do glob não casava zero diretórios

## F-1251 | categoria: funcional | severidade: media | status: corrigido
- Tela/fluxo: ferramenta MCP `nexus_file_search` (motor `searchWorkspaceFiles`), chamada de dentro de um pane no app 0.76.238.
- Arquivo:linha (antes): `src/main/orch/workspace-file-search.ts:217-219`. O `globToRegex` convertia `**` para `.*` sem tratar os delimitadores de diretório `/`, fazendo `/**/` virar `/.*\/`, o que exigia pelo menos um diretório intermediário entre as barras.
- Passos: 1) Executar `nexus_file_search` com pattern `src/main/orch/**/*heavy*.ts` ou `a/**/target.ts` onde o arquivo está diretamente no diretório base (`src/main/orch/heavy-command-permit.ts` ou `a/target.ts`).
- Esperado: casar arquivos na raiz do glob (`a/b`) e em qualquer profundidade (`a/x/b`, `a/x/y/b`), pois `**/` representa zero ou mais níveis de diretório.
- Observado: `pattern: "src/main/orch/**/*heavy*.ts"` retornava count 0 (scanned: 974 files, 5 directories); `a/**/target.ts` não encontrava `a/target.ts`.
- Evidencia: teste novo `F-1251: a/**/b casa a/b e a/x/y/b com poda por prefixo literal` em `src/main/orch/tools-files-search-budget.test.ts`. Antes da correção (RED):
  ```
  FAIL  src/main/orch/tools-files-search-budget.test.ts > nexus_file_search budgets > F-1251: a/**/b casa a/b e a/x/y/b com poda por prefixo literal
  AssertionError: expected [ 'a/x/target.ts', 'a/x/y/target.ts' ] to deeply equal [ Array(3) ]

  - Expected
  + Received

    [
  -   "a/target.ts",
      "a/x/target.ts",
      "a/x/y/target.ts",
    ]
  ```
  Após a correção (GREEN): 9/9 testes passando em `tools-files-search-budget.test.ts`.
- (resolvedor) Correcao:
  - Em `globToRegex` (`src/main/orch/workspace-file-search.ts`), tratou-se especificamente `/**/` como `/(?:.+/)?`, permitindo casar zero diretórios intermediários (`a/**/b` casa `a/b`), bem como `**/` no início do padrão como `(?:.+/)?` (permitindo casar arquivos na raiz como `**/b` casando `b`), e `/**` no final como `/.*`.
  - A poda por prefixo literal (`literalDirectoryPrefix`) continua preservada e intacta (para `a/**/b`, prefixo é `['a']`, lendo apenas os 4 diretórios relevantes em vez das árvores irmãs).
- Validacao: `tools-files-search-budget.test.ts` (9/9), `tools-files.test.ts` (19/19), `tools-files-project-scope.test.ts` (2/2) e `files-ipc.test.ts` (23/23) verdes; `npm run typecheck` e `npm run security:renderer-sinks` passaram sem erros.
