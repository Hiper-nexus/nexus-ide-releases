# F-673 — Panes no Windows com texto sobreposto, como se o terminal não emulasse direito

## F-673 | categoria: visual | severidade: alta | status: corrigido
- Tela/fluxo: Windows 11 (build 26200), grade de panes com TUIs (Claude Code). Abrir/fechar panes redimensiona os outros.
- Arquivo:linha: `src/renderer/terminal/terminal-host.ts` (`buildTerminal`: xterm.js 6 criado sem `windowsPty`), `src/preload/preload.ts`, `src/renderer/lib/platform.ts` (novo `xtermWindowsPty`).
- Passos: 1) Missão com 5–6 panes Claude. 2) Soltar/fechar panes (a grade redimensiona).
- Esperado: cada pane mostra só o estado atual da TUI.
- Observado (28/09 19:51): linhas escritas por cima de outras, trechos do brief antigo misturados à saída nova, colunas desalinhadas nos quatro panes (print do operador).
- Evidencia: sem `windowsPty` o xterm.js trata o PTY como Unix: ao ganhar linhas, puxa o histórico para o viewport; o ConPTY cria linhas vazias e repinta por cima — a documentação do xterm ("Not having this behavior can result in missing data as the rows get replaced") descreve exatamente a mistura.
- (resolvedor) Correcao: o preload expõe `windowsBuild` (`process.getSystemVersion()`), e no Windows o terminal nasce com `windowsPty: { backend: 'conpty', buildNumber }`, ligando as heurísticas de ConPTY do próprio xterm. macOS/Linux sem mudança. Teste: `platform.test.ts` (F-673); `terminal-host.test.ts` e `security:renderer-sinks` verdes. Validação visual no app instalado pendente com o operador.
