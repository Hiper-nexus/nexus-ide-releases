# F-580 — `nexus_git_push`/push-before-PR falham em todo remoto HTTPS: runner do Main descarta config global e de sistema do git

## F-580 | categoria: funcional | severidade: alta | status: corrigido

- Tela/fluxo: `nexus_git_push`, `nexus_git_pull`, `nexus_git_sync` (fetch de
  repo privado) e o push-antes-do-PR do renderer
  (`src/main/integrations/git-workspace.ts`) — todo remote HTTPS.
- Arquivo:linha: `src/main/runtime/git-command.ts` `safeGitEnvironment`
  (~L175: `GIT_CONFIG_NOSYSTEM=1` + `GIT_CONFIG_GLOBAL=/dev/null`).
- Passos: 1) chamar `nexus_git_push` (ou o fluxo de PR da UI) num checkout
  com remote HTTPS do GitHub; 2) o git morre pedindo usuário.
- Esperado: o Main usa a mesma credencial do operador — helper do `gh`,
  osxkeychain ou GCM — como qualquer `git push` num terminal.
- Observado: `fatal: could not read Username for 'https://github.com':
  terminal prompts disabled` em todo push/pull HTTPS. Reproduzido nesta
  máquina com os mesmos envs do runner:

  ```
  $ GIT_CONFIG_NOSYSTEM=1 GIT_CONFIG_GLOBAL=/dev/null GIT_TERMINAL_PROMPT=0 \
      git push --dry-run origin HEAD
  fatal: could not read Username for 'https://github.com': terminal prompts disabled

  $ git push --dry-run origin HEAD     # sem os dois vars
  Everything up-to-date
  ```
- Causa: o scrub de segurança do runner zerava TODA config global e de
  sistema — junto iam o credential helper (`gh auth git-credential` no
  `~/.gitconfig`, osxkeychain no gitconfig de sistema do Xcode, GCM no
  Windows), `user.name`/`user.email`, `url.insteadOf` e proxies. O modelo
  de ameaça confia em tudo EXCETO conteúdo do repositório; config global do
  usuário não é conteúdo de repo.
- Correção (`git-command.ts`): removidas as duas linhas
  `GIT_CONFIG_NOSYSTEM`/`GIT_CONFIG_GLOBAL`. Mantidos: scrub dos envs
  `GIT_`/`LD_`/`DYLD_`, `GIT_TERMINAL_PROMPT=0`, pager/editor,
  `GIT_ALLOW_PROTOCOL`, `LC_ALL`, os `-c` de `safeGitArgv`
  (hooksPath=/dev/null, fsmonitor=false, gpgSign=false, protocol.*=never) e
  a recusa de config LOCAL executável por `assertSafeLocalGitConfig`.
- Limites deliberados: config local do repo continua inspecionada e
  recusada quando executável; a recusa a protocolos `ext:`/`file:` segue
  pinada por argv.
- Evidência: teste novo em `git-command.test.ts` — RED antes da correção
  (`GitCommandError: Git command failed with exit 1`), GREEN depois
  (`stdout.trim() === 'runner@example.test'`, 11/11 no arquivo). Prova
  física: `new ProcessGitRunner().run(repo, ['push','--dry-run','origin',
  'HEAD'])` não lança "could not read Username" (`/tmp/nexus-f579-proof.log`).
