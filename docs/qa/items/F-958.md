# F-958 — Sessão do Codex prende a vaga de comando pesado do projeto

## F-958 | categoria: performance | severidade: alta | status: corrigido
- Tela/fluxo: missões com vários agentes no mesmo projeto; comandos pesados (`tsc`, testes, build, install) dos agentes
- Arquivo:linha: `resources/heavy-command/child-process.cjs:21` (`catalog.commandKind([file, ...args].join(' '))` para filho não-Node)
- Passos: 1) o Nexus abre um pane do Codex (`node /opt/homebrew/bin/codex …`, entry `@openai/codex/bin/codex.js`); 2) o lançador Node do Codex executa o motor nativo do próprio pacote (`vendor/aarch64-apple-darwin/bin/codex`) com o prompt inteiro no argv; 3) o hook de child_process classifica esse filho pelo texto da linha de comando.
- Esperado: o motor do agente roda como a própria sessão; só comandos finitos que o agente executa (shell, `npm test`, `tsc`…) entram na fila de comandos pesados.
- Observado (07/10/2026, app 0.76.208): PID 49532 `nexus-pty-supervisor __run-disclaimed-heavy-job typescript -- …/codex --model gpt-6.1-sol … <prompt>` segurando a vaga do projeto há 54 min, enquanto 10 a 22 `job-launch.cjs` (`tests`, `typescript`, `build`, `install`) de outros agentes esperavam com nada mais rodando, e os pedidos estouravam com `nexus-heavy: local admission request failed` (exit 74). O prompt citava "typecheck"/"node", e qualquer linha acima de 16 KB vira `build` em `commandKind`.
- Evidencia: `src/main/orch/native-heavy-agent-engine.test.ts` — o lançador de um pacote `@openai/codex` falso executa o motor com "typecheck" no prompt: sem a correção o filho cai em `dispatch.cjs` ("Heavy command not started"); com ela roda direto. Binário fora do pacote e processo que não é o entry do agente continuam classificados.
- (resolvedor) Correcao: `catalog.isAgentEngine` reconhece só o caso estreito — o processo atual é o `NEXUS_HEAVY_AGENT_ENTRY`, o exec é direto (sem shell) e o binário (realpath) fica dentro do pacote npm desse entry. Esse filho não é classificado; os hooks de BASH_ENV/ZDOTDIR/NODE_OPTIONS continuam valendo para o que ele executar. O catálogo só agenda recurso e não autoriza efeito de shell. Entra na 0.76.209.
