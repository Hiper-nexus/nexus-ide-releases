# F-763 — Linux: o RPM não declarava `alsa-lib` e num Fedora enxuto o app não abria

## F-763 | categoria: funcional | severidade: media | status: corrigido
- Tela/fluxo: instalação do `.rpm` no Fedora, openSUSE e derivados.
- Arquivo:linha: `forge.config.ts` (`createLinuxRpmMakerConfig`).
- Passos: 1) Container `fedora:latest` limpo. 2) `dnf install ./nexus-ide-0.76.189-1.x86_64.rpm`. 3) Abrir `/usr/lib/nexus-ide/nexus-ide`.
- Esperado: o `dnf` traz tudo que o app precisa e o app abre.
- Observado (02/10, pacote 0.76.189 gerado em Ubuntu 22.04): `error while loading shared libraries: libasound.so.2: cannot open shared object file`. `ldd` lista só essa biblioteca como faltando. O `rpm -qR` já traz gtk3, nss, libdrm, mesa-libgbm, at-spi2-core, libnotify e libxcb; falta `alsa-lib`.
- Evidência de que o DEB não tem o problema: Debian 12, Ubuntu 22.04 e Ubuntu 24.04 enxutos (`--no-install-recommends`, sem Xvfb) instalam e `ldd` não acusa nada; a `libasound2` vem pelas dependências do GTK.
- Causa: o instalador de RPM soma os `requires` do projeto aos padrões dele, e o padrão não inclui a biblioteca de áudio que o Electron liga direto. Em desktops Fedora comuns ela costuma estar instalada, por isso ninguém reparou; vale para toda versão Linux anterior.
- (resolvedor) Correcao: `LINUX_RPM_EXTRA_REQUIRES = ['alsa-lib']` em `forge.config.ts`; os dois workflows de Linux e o script de build em container exigem `alsa-lib` em `rpm -qpR`. Testes: `forge.config.test.ts`, `linux-release-workflow.test.mjs`, `linux-preview-workflow.test.mjs`.
- Como foi achado: instalando o pacote de verdade em containers de cada distribuição e abrindo o app. O smoke do CI instala só o DEB, no Ubuntu do runner.
