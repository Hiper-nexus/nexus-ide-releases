# F-1624 — Padrão do Jev era o alias móvel, não a versão em que os limiares foram calibrados

## F-1624 | categoria: funcional | severidade: media | status: corrigido

- Tela/fluxo: toda consulta ao Jev sem versão escolhida pelo operador (guarda de despacho, rota de tarefa, delegação, revisão de handoff, sugestão de skill…); Chaves de API › Modelos de decisão › Versão do Jev.
- Arquivo:linha (antes): `src/main/decision-models/decision-routing.ts:7` (`?? 'jev-latest'`), `decision-evaluation.ts:18`, `decision-calibration.ts:103`, `DecisionModeControls.tsx:29`.
- Passos: 1) Sem escolher versão, usar o Nexus. 2) A TypeSafe move `jev-latest` para uma versão nova (hoje ele aponta para o 1.13.0; o 1.14 saiu em 14/10 como `jev-preview`).
- Esperado: os limiares continuam valendo para o modelo que os mediu até alguém recalibrar.
- Observado: o padrão era o alias `jev-latest`. Quando ele mudar, os cortes da guarda (0,8 / 0,35 / 0,6, medidos em 17/09 no 1.13.0), a rubrica de tier (F-194), a revisão de handoff (F-707) e a sugestão de skill (F-753) passariam a julgar com outro modelo sem nenhuma mudança no código.
- Evidencia: docs.typesafe.ai/models.md (lido em 21/10/2026): "An alias moves when a new release ships"; para quem calibrou limiares numa versão, "send that version's ID instead of the alias". `npx vitest run src/main/jev/jev-client.test.ts` (padrão `jev-1.13.0`; versão aposentada volta a `jev-latest` uma vez).
- (resolvedor) Correcao: `JEV_CALIBRATED_MODEL = 'jev-1.13.0'` em `shared/decision-models.ts` é o padrão de `jevModel`, da avaliação e da estimativa de calibração. Escolha explícita (`jev-latest`, 1.14, preview) e `NEXUS_JEV_MODEL` continuam vencendo. Se a TypeSafe aposentar o 1.13.0, o retry existente para modelo recusado (400/404) refaz com `jev-latest`. A UI mostra "Jev 1.13.0 (calibrado, padrão)" e explica por quê. Hoje `jev-latest` = 1.13.0, então não há mudança de comportamento agora: a proteção vale para quando o alias andar. decision-models, jev, settings do renderer: 1.391 testes passaram.
