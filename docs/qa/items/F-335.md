# F-335 — Fallbacks de `var(--surface-*)` defasados, anteriores ao Pink City

## F-335 | categoria: visual | severidade: baixa | status: corrigido
- Tela/fluxo: rail de missões do workspace (repouso/hover/selecionado), filtros da
  timeline de atividade do agente (hover/ativo) e botão `+` de anotação no gutter do
  diff (hover).
- Arquivo:linha: `src/renderer/styles/app-shell.css:607,618,623`,
  `src/renderer/styles/mission-board.css:1580,1585`,
  `src/renderer/styles/git-scm.css:506`.
- Passos: 1) carregar o app com os tokens ainda não aplicados no `<html>` — janela
  entre o primeiro paint e o `applyUiTheme`, ou qualquer contexto onde `base.css` não
  tenha definido a variável; 2) observar a superfície dos três componentes.
- Esperado: `DESIGN.md` §2 define a regra — "Fallbacks de `var()` devem ter o valor
  ATUAL do token (ex.: `var(--bg, #0a0e15)`". O próprio documento já catalogava a
  dívida: "há fallbacks defasados catalogados para follow-up; ao tocar num arquivo,
  corrija os dele".
- Observado: os seis fallbacks de `--surface-*` carregavam valores `rgba()` da paleta
  anterior ao Pink City, translúcidos sobre branco, enquanto os tokens atuais são hex
  opacos:
  | Token | Fallback encontrado | Valor atual em `base.css` |
  |---|---|---|
  | `--surface-1` | `rgba(255, 255, 255, 0.035)` | `#121115` |
  | `--surface-2` | `rgba(255, 255, 255, 0.065)` / `0.05` | `#16151a` |
  | `--surface-3` | `rgba(255, 255, 255, 0.10)` / `0.12` / `0.15` | `#201e25` |

  Além de defasados, os três fallbacks de `--surface-2` e os três de `--surface-3`
  divergiam entre si (0.05 / 0.065 / 0.12 / 0.10 / 0.15), então o pré-paint não era
  nem consistente com o tema nem consistente entre componentes. E translucidez não é
  substituível por hex: um `rgba` branco compõe sobre o que estiver atrás, enquanto o
  token é uma superfície opaca — o resultado pré-JS era uma elevação errada.
- Evidencia: `grep -rn "var(--surface-[0-9]*, *rgba\|var(--surface-sidebar, *rgba"
  src/renderer/styles/` retornava 6 linhas antes da correção e retorna vazio depois.
  Panorama restante: 258 ocorrências de `var(--x, <literal>)` em
  `src/renderer/styles/`; as 6 acima eram as únicas com token de superfície conhecido
  e fallback comprovadamente defasado.
- Correcao: os seis fallbacks substituídos pelo valor atual do token em `base.css:54-56`
  (`#121115`, `#16151a`, `#201e25`), sem alterar nenhuma outra propriedade.
- Validacao: `npm run security:renderer-sinks` — "renderer sink audit: 0 executable DOM
  sinks". `npx vitest run src/renderer/styles/ui-theme.test.ts` — 18 testes verdes
  (esse teste lê `base.css` como texto e assera os blocos `[data-theme=…]`, que não
  foram tocados). Mudança somente em CSS; nenhum arquivo `.ts`/`.tsx` alterado, logo
  `npx tsc --noEmit` não é afetado por este finding.
- Limites: os outros 252 fallbacks `var(--x, <literal>)` não foram auditados neste
  finding — a maioria é de tokens derivados (`--radius-*`, `--shadow-*`, `--ease-*`)
  cujo literal coincide com o valor atual. Uma auditoria completa pertence à Fase 3 do
  plano (gerador de paleta + gate de contraste), não a esta correção pontual.
