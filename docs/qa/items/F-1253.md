# F-1253 — Writer isolado não nascia mais depois de o checkout trocar de branch

## F-1253 | categoria: funcional | severidade: alta | status: corrigido
- Tela/fluxo: `nexus_pane_spawn` com `isolatedWriter: true` (e todo caminho que reserva worktree gerenciada: aba nova, missão planejada).
- Arquivo:linha (antes): `src/main/runtime/worktree-state.ts:228-230`. `validateWorktreeStateSnapshot` exigia a mesma `rootRealPath` e o mesmo `integrationRef` em **todos** os registros do escopo, inclusive os encerrados.
- Passos:
  1. Um writer isolado nasce com o checkout em `main` (`integrationRef: refs/heads/main`).
  2. O app reinicia ou o pane fecha. O registro fica `failed`, "worktree and branch retained".
  3. O checkout compartilhado passa para outra branch (outro agente, o operador).
  4. Qualquer `nexus_pane_spawn` com `isolatedWriter: true`.
- Esperado: o writer novo nasce no ref atual. Os encerrados ficam como histórico.
- Observado: `{"error":"invalid worktree state record","effectMayHaveCommitted":true}`. Nenhum writer isolado nasce mais neste checkout, sem prazo e sem dizer o motivo.
- Evidencia:
  - Ao vivo, no app 0.76.238 (12/10 01:2xZ): dois spawns `isolatedWriter` recusados com a mensagem acima.
  - Estado salvo (`runtime.sqlite3`, `worktree_state` rev. 256): 4 registros `failed` de 08/10 com `refs/heads/main`. O checkout está em `feat/orc-outbox-command-receipts-boot-reconcile`.
  - Cada registro sozinho e o snapshot salvo inteiro passam no validador. Só o candidato novo, com outro ref, derruba o conjunto.
  - RED (fonte anterior), `worktree-manager.test.ts` › "F-1253: writer encerrado num ref antigo…": `WorktreeStateConflictError: invalid worktree state record`, a mesma mensagem da produção.
- (resolvedor) Correcao:
  - Causa: a regra "um checkout, um ref de integração" existe para a fila de merge, que só trata writers ativos (`reserved`/`ready`/`queued`). Um `failed`/`integrated`/`abandoned` fica no ref em que nasceu, para sempre.
  - `worktree-state.ts`: a unicidade de raiz e ref passa a valer só entre os registros ativos. Dois writers **ativos** em refs diferentes continuam recusados, agora com a mensagem `active worktree writers disagree on checkout root or integration ref`.
  - Continua igual: a retomada de uma task específica (`create` com o mesmo `taskKey`) exige o mesmo root e o mesmo ref (`worktree-manager.ts:426`). A fila de merge integra cada registro no próprio `integrationRef`.
  - Testes: writer encerrado em `main` + troca de branch → o próximo nasce em `refs/heads/feat/outra`; dois ativos em refs diferentes → recusa com a mensagem nova.
- Validacao: `worktree-manager.test.ts` 51/51 (RED 2/2 com a fonte anterior).
