# F-1296 — asar.unpack `*.so*` desembrulha fonte TypeScript `.source.ts`

## F-1296 | categoria: funcional | severidade: baixa | status: corrigido
- Tela/fluxo: empacotamento Electron (`forge.config.ts`, `asar.unpack`).
- Arquivo:linha (antes): `forge.config.ts:522` — `**/{*.node,*.dll,*.dylib,*.so*,*.wasm,…}` com `matchBase`.
- Passos: 1) Aplicar o glob de unpack com `minimatch(caminho, unpack, { matchBase: true })`. 2) Observar `node_modules/zod`.
- Esperado: só bibliotecas nativas (`.so`, `.so.1`, `.node`, `.wasm`, …) saem para `app.asar.unpacked`.
- Observado: `*.so*` casa `language-server.source.ts` (`so` + qualquer sufixo), e o zod vai para `app.asar.unpacked`.
- Evidencia: RED com a fonte revertida — `minimatch('…/language-server.source.ts', unpack, { matchBase: true })` era `true` (`forge.config.test.ts`, teste F-1296).
- (resolvedor) Correcao: o glob passou a `*.so` e `*.so.*`. `libfoo.so` e `libfoo.so.1` continuam desembrulhados; `language-server.source.ts` não.
- Validacao: o mesmo `vitest` dos três arquivos — 139 verdes. RED reproduzido revertendo só `forge.config.ts` (`expected true to be false`).
- Limite: `appdmg` permanece em `optionalDependencies` (`package.json`); não foi movido para `devDependencies`. Não conferi um pacote real para ver se o zod saiu do unpacked.
