# F-610 — Notarização rejeita o Redline ad-hoc dentro do NexusIDE.app

## F-610 | categoria: build | severidade: alta | status: corrigido
- Tela/fluxo: `npm run make:release` da 0.76.61, notarize do ZIP.
- Arquivo:linha: `build/mac-signing.ts` (`shouldIgnoreMacSigningFile`,
  `isNexusRedlineSigningTarget`).
- Passos: 1) F-609 passou o premake. 2) Forge empacota e envia o ZIP à Apple.
- Esperado: o companion em `Contents/Resources/nexus-redline/Nexus Redline.app`
  é reassinado com Developer ID, timestamp seguro e hardened runtime, como o
  `nexus-pty-supervisor`.
- Observado: `shouldIgnoreMacSigningFile` ignora tudo em `Resources/` excepto
  `.node`/`.dylib`/supervisor. O Redline ficou ad-hoc. Notarytool Invalid:
  "not signed with a valid Developer ID", "does not include a secure
  timestamp", "does not have the hardened runtime enabled".
- Evidencia: notary job `7addd824-b397-4e69-8c21-4a6232433167` (2026-09-20).
- (resolvedor) Correção: o bundle e o Mach-O do Redline entram no walk do
  osx-sign, identifier `com.nexuside.redline`, entitlements vazios + hardened
  runtime no release. Ícone/plist continuam ignorados. Validação:
  `npx vitest run build/mac-signing.test.ts`.
