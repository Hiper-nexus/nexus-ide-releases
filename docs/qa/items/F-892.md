# F-892 — controles anteriores ao spawn deferred eram perdidos

## F-892 | categoria: funcional | severidade: alta | status: corrigido
- Fluxo: digitação/injeção de prompt e resize enquanto versão/canal do OpenCode estão preparando.
- Arquivo:linha: `src/main/pty/pty-host-core.ts`.
- Passos: reservar sessão, escrever prompt e redimensionar antes de readiness; resolver readiness.
- Esperado: target recebe input em ordem, nasce com tamanho atual; cancelamento impede input/spawn tardio; fila cheia recusa sem sucesso silencioso.
- Observado: Host ignorava write/resize sem proc; Main retornava sucesso para bytes que sumiam. Review Mimo reproduziu em Node22 real próprio: target sem prompt e dimensão inicial80x24.
- Correção: bridge guarda FIFO com teto128KiB/128 chunks e recusa por exceção antes de aceitar overflow; cancel/reservation change limpa e recusa input stale. Coalescing do resize atualiza sealed spawn. Spawn validado é postado primeiro; writes flush FIFO, incluindo reentrância, antes dos controles posteriores. Pause/credits iniciais seguem depois do spawn com teto de crédito.
- Evidência: Node real recebeu dois prompts na ordem e spec132x44; overflow/cancel não enviaram bytes; bridge+manager176 PASS/8 skips em2 suítes, full tsc, sinks0 e main-sync91 legados passam.
- Limite: recebimento no FIFO é aceitação de transporte, não prova de processamento pela LLM. Falha/cleanup desconhecido continua retida sem exit/prova falsa; candidatos assinados exigem controles Root.
