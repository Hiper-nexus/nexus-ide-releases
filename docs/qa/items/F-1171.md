# F-1171 — Histórico das CLIs vira recurso do operador (importar, buscar, reaproveitar)

## F-1171 | categoria: terminal | severidade: média | status: corrigido
- Fluxo: pane de terminal → botão "Cmds" → seção "Histórico" → "Importar histórico das CLIs"; ou paleta (⌘K) → "Importar histórico das CLIs" (usa o pane focado).
- Causa: o import herdado do T3 Code (`cli-history-import.ts`, `cli-history-sweep.ts`) não tinha chamador nem tela; `CommandBlockStore.search` também não. O operador não tinha como trazer os comandos de shell dos agentes para o histórico nem buscar no histórico gravado (o menu só listava o tracker em memória).
- Arquivo:linha:
  - Contrato: `src/shared/cli-history.ts` (schemas strict de pedido, contagens, entrada do histórico, marca de origem).
  - Adaptador: `src/main/terminal/cli-history-adapter.ts` (`adaptImportedCommandBlock`, `cliHistorySessionId`).
  - Serviço: `src/main/terminal/cli-history-import-service.ts` (`importCliHistoryForScope`).
  - Store: `src/main/terminal/command-block-store.ts` (`insertWithOutcome`, `offset` no `search`, redação do chamador preservada).
  - IPC: `src/main/terminal/terminal-block-actions-ipc.ts` (`terminal-block:import-cli-history`, `terminal-block:search-history`, ambos via `handleTrusted`); canais em `src/shared/channels.ts`; ponte em `src/preload/preload.ts` e `src/shared/types.ts`.
  - Ratchet: `oxlint-plugin-nexus/rules/no-raw-ipc.mjs` — teto do preload 420 → 422 (dois invokes novos da ponte). O teto legado do `terminal-block-actions-ipc.ts` (5) não subiu.
  - UI: `src/renderer/components/CommandBlockMenu.tsx` (seção Histórico), `src/renderer/components/CommandPalette.tsx` (comando), `src/renderer/lib/cli-history-import.ts` (caminho comum + resumo), `src/renderer/lib/action-names.ts` (`CLI_HISTORY_IMPORT_ACTION`), estilos `.cmd-history*` em `src/renderer/styles/product-wave.css`.
- (resolvedor) Correção:
  - **Adaptador:** redige com o mesmo `redactCommandLine` do tracker OSC 133; a chave de idempotência sai de (sessão sintética, início, comando **redigido**, cwd) por `computeCommandBlockIdempotencyKey`, e o id deriva da chave. Reimportar não duplica; o segredo não entra nem no hash. Status `unknown`, sem exit code.
  - **Origem sem migração:** blocos importados nascem com sessionId `cli-import:<adapter>:<hash do caminho relativo>` e paneId `cli-import`. Nenhuma sessão PTY usa esse prefixo, então a origem (importado × gravado) é derivada na leitura. Decisão: evitar uma migração 055 no `project-runtime-schema` enquanto outras frentes da onda T3 mexem no mesmo esquema (colisão de `schemaVersion`); o par sessão/pane já é campo existente e validado.
  - **Escopo:** o serviço só lê `<userData>/provider-state/<adapter>/<checkoutId do escopo>/**.jsonl`. Transcript de outro projeto nunca entra no banco deste. Symlinks não são seguidos; profundidade ≤ 12.
  - **Main sem trava:** I/O em `fs.promises`, cessão do event loop (`setImmediate`) antes de cada arquivo e a cada 200 inserts. O ratchet F-764 (`scripts/check-main-sync.mjs`) mede só `spawnSync/execSync/execFileSync`; o serviço não usa `child_process`. O `sweepCliHistory` síncrono antigo ficou sem chamador (não foi usado aqui).
  - **Tetos:** 200 arquivos, 8 MB por arquivo, 2 000 comandos gravados por importação (abaixo da retenção de 5 000, para o import não empurrar o gravado para fora). Duplicado não gasta o teto: rodar de novo avança. Depois de importar, roda `prune` + `enforceSizeBudget`.
  - **Contagens:** `{files, filesSkipped, found, imported, duplicates, skipped, capped}` com `imported + duplicates + skipped === found`. Linha ilegível é pulada pelo parser; arquivo ilegível ou grande demais vira `filesSkipped`; insert recusado (conflito de chave) vira `skipped`. Nada aborta a importação.
  - **IPC:** zod strict; sessão dona do pane (`isSessionOwnedBy`) e contexto do tracker; escopo derivado no Main. Uma importação por checkout por vez ("Importação já em andamento"). Flag `feature.terminal.commandBlocks` desligada → recusa legível / lista vazia. Busca paginada (`limit` ≤ 50, `offset`, `hasMore` por limit+1), mais novo primeiro.
  - **Store:** `insertWithOutcome` diz se gravou ou achou a chave; `insert` delega. O segundo passe de redação zerava o metadado de quem já redigiu (`[REDACTED]` não casa de novo) — agora o metadado do chamador é mesclado (OR nos booleanos, máximo de `secretHits`), como o comentário já prometia.
  - **UI (menu Cmds):** botão "Importar histórico das CLIs" (nome acessível do registry) com "Importando…" (desabilitado), resumo em `role=status` ("5 importados · 2 já no histórico · 1 ignorado (3 arquivos)", "· teto atingido") e erro em `role=alert`. Lista "Histórico" lê o SQLite (importado + gravado) com etiqueta de origem, filtra pelo mesmo campo de busca do refinador, "Mais antigos" pagina acumulando. Reaproveitar: "Copiar" (clipboard) e "Inserir" (cola no prompt do pane via `pty.write`, **sem Enter**, e fecha o menu). Comando de várias linhas tem "Inserir" desabilitado — o `\n` executaria a primeira linha.
  - **Paleta:** "Importar histórico das CLIs" importa a partir do pane focado e responde por toast (sucesso com contagens ou aviso legível).
- Decisão — sugestões: comandos importados **não** alimentam o `CommandRefineryStore`. Eles têm status `unknown` (transcript não prova exit code) e o `record` do refinador só aceita `success`/`failed`; contar `unknown` como sucesso inflaria a taxa de sucesso e o ranking. O import grava só em `command_blocks`; o refinador continua aprendendo apenas com o que o tracker OSC 133 provou. Os importados ficam acessíveis pela busca do "Histórico".
