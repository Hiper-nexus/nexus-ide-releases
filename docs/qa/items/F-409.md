# F-409 — Modo Hardened no Windows declara OCI, mas não possui runtime distribuído nem mounts suplementares

## F-409 | categoria: seguranca | severidade: alta | status: precisa-decisao
- Tela/fluxo: Configurações › Squads › Hardened e panes Codex de missão em
  Windows.
- Arquivo:linha: `src/main/runtime/process-sandbox.ts:792-920` e
  `src/main/pty/pty-manager.ts:1953`.
- Passos:
  1) Selecionar Hardened no Windows e iniciar um pane Codex de missão.
  2) Sem runtime OCI e imagem digest-pinned configurados, observar a falha
     fechada; mesmo com valores de teste válidos, o plano rejeita as raízes
     suplementares exigidas pelo perfil Codex.
- Esperado: ou o modo Hardened funciona com um provider realmente distribuído e
  validado, ou a interface não o oferece como disponível neste Windows.
- Observado: o modo é exposto como opt-in, porém esta máquina não possui
  Docker/Podman/nerdctl nem as variáveis OCI; o spawn interrompe com
  `secure process sandbox provider is unavailable on win32`. Ao fornecer um
  runtime de teste, ele avança e falha em
  `supplemental process sandbox roots are unavailable on win32`.
- Evidencia:
  - `npx vitest run src/main/pty/pty-manager.test.ts` encontrou oito fluxos
    governados bloqueados pela falta de provider.
  - reprodução focada com runtime/imagem de teste chegou à segunda recusa de
    mounts suplementares.
  - `docs/superpowers/specs/2026-07-11-windows-process-sandbox-spike.md` ainda
    classifica a implementação Windows como spike de design, não produção.
- (resolvedor) Correcao: requer decisão de produto/infra. Não é seguro liberar
  panes governados sem uma fronteira equivalente; as opções são distribuir e
  validar um provider Windows (com imagem, mounts e smoke real) ou manter o
  modo indisponível/claramente bloqueado no Windows. O Autopiloto padrão não
  usa essa trilha e não deve ser degradado para simular o Hardened.
