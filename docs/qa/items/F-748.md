# F-748 — Qwen não abria: "Cannot use both --yolo (-y) and --approval-mode together"

## F-748 | categoria: funcional | severidade: alta | status: corrigido
- Tela/fluxo: "+ Pane" › Qwen, e workers Qwen de missão, no Qwen Code 0.24.7.
- Arquivo:linha: `src/adapters/builtin/qwen.json` (`spawn.interactive`).
- Passos:
  1. Abrir um pane Qwen pelo "+ Pane".
- Esperado: a TUI do Qwen sobe.
- Observado:
  - Texto colado pelo operador (02/10): o pane imprime o `--help` inteiro e "[nexus] process exited (code 1)".
  - Trace das 09:36: workers Qwen com `pane-not-started`/`boot-exit` e reroteamento automático para outra CLI.
- Evidencia:
  - `qwen --model qwen3.8-max --approval-mode auto-edit --yolo` → "Cannot use both --yolo (-y) and --approval-mode together. Use --approval-mode=yolo instead." e exit 1.
  - Cada flag sozinha sobe (exit 0).
- Causa:
  - O argv base do adapter trazia `--approval-mode auto-edit`, e o modo padrão (sem pedir permissão) soma `--yolo`.
  - No modo somente leitura o caminho governado tira as sequências de permissão e acrescenta `--approval-mode plan`, mas o `auto-edit` do base ficava (duas `--approval-mode`).
- (resolvedor) Correcao:
  - O argv base não leva flag de permissão. Quem decide é o controle do adapter:
    - `--yolo` no padrão;
    - `--approval-mode default` no seguro;
    - `--approval-mode plan` no somente leitura.
  - Teste que reprova o JSON antigo: `control-args.test.ts`, "F-748: o argv do Qwen nunca junta --yolo com --approval-mode".
