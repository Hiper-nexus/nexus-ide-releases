# F-117 — Terminais bloqueados no boot por autoridade persistida desatualizada e squad '?' indisponível

## F-117 | categoria: pty / estabilidade | severidade: crítica | status: corrigido
- Tela/fluxo: Boot do app, restauração de layout do workspace e inicialização de panes de missão
- Arquivo:linha: `src/main/orch/main-owned-agent-spawn.ts`, `src/renderer/terminal/terminal-host.ts`, `src/main/orch/mission-fast-lane.ts`, `src/main/orch/tools-domain.ts`
- Passos:
  1) Criar missão via ferramenta/MCP sem `squadId` explícito (persistindo `squad_id: NULL` no SQLite).
  2) Ter pane orquestrador registrado no banco para essa missão.
  3) Reiniciar o app; o layout restaura o pane sem `pane.missionId` preenchido no renderer.
  4) O terminal tenta reconectar com autoridade persistida e falha com erro fatal vermelho:
     `[nexus] failed to start: stale or legacy persisted mission pane authority; replane and approve the current revision — divergências: squad '?' indisponível`.
  5) O pane fica travado com cursor morto `[]` sem permitir digitação nem comandos.
- Esperado:
  1) Se uma autoridade persistida estiver desatualizada, divergente ou sem missão ativa, o terminal deve converter graciosamente o pane para shell livre de operador (`unlockRetiredMissionPane`), permitindo digitação imediata.
  2) Missões criadas sem `squadId` explícito devem assumir fallback transparente para `nexus-fullstack` (ou primeiro squad não-pet disponível), prevenindo crashes de orquestrador indefinido ou squad nulo.
  3) O terminal nunca deve ficar bloqueado com cursor inerte após erro de autoridade no boot.
- Observado:
  1) `assertCurrentPersistedPaneAuthority` comparava `mission.squadId` sem fallback, lançando erro de squad `'?' indisponível` mesmo quando a causa real era a missão em estado `blocked`.
  2) `terminal-host.ts` exigia `Boolean(missionId)` para interceptar o erro de autoridade persistida; como o layout restaurava sem `missionId`, a recuperação era ignorada e o pane morria permanentemente.
- Correção (04/09/2026):
  1) `src/main/orch/main-owned-agent-spawn.ts`:
     - Fallback de `targetSquadId` para `nexus-fullstack` em `assertCurrentPersistedPaneAuthority`.
     - Verificação antecipada de `mission.status !== 'running'` para mensagens diagnósticas precisas.
     - Restrição da busca de panes persistidos a `canonicalRequest.kind !== 'shell'`.
  2) `src/renderer/terminal/terminal-host.ts`:
     - Remoção do pré-requisito `Boolean(missionId)` para a rotina de autoridade persistida, caindo no modo `'unlock-keyboard'` (`unlockRetiredMissionPane`).
     - Tratamento do erro `/persisted mission pane authority/i` no bloco catch assíncrono de spawn para desbloqueio automático do teclado.
  3) `src/main/orch/mission-fast-lane.ts`:
     - Adicionado fallback `resolveFastLaneSquad` para missões sem squad configurado.
  4) `src/main/orch/tools-domain.ts`:
     - Defaulting de `squadId` para `nexus-fullstack` na criação de missão via tool.
- Validação:
  1) `npx vitest run src/main/orch/main-owned-agent-spawn.test.ts src/renderer/terminal/mission-owned-pane-policy.test.ts src/main/orch/mission-fast-lane-resume-guard.test.ts src/main/orch/mission-store.test.ts` (90/90 aprovados).
  2) `npm run typecheck` (0 erros).
