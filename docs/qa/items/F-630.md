# F-630 — "Claude não encontrado" com o Claude instalado (máquina de colega)

## F-630 | categoria: funcional | severidade: alta | status: corrigido

- Tela/fluxo: pane Claude → Reiniciar (retomar a sessão) numa máquina de
  outro cliente. O terminal mostra `[nexus] failed to start: Claude não
  encontrado. Instale: npm install -g @anthropic-ai/claude-code`, com o
  Claude instalado e funcionando no terminal do sistema.
- Causa: app aberto pelo Finder herda PATH mínimo (`/usr/bin:/bin:…`). O
  Nexus soma (a) o PATH do shell de login (`zsh -lic`, prazo de 4 s) e (b) uma
  lista fixa de pastas. Quando a CLI vem de um gerenciador que só entra no
  PATH pelo `.zshrc` (nvm, fnm, mise, pnpm, instalador antigo
  `~/.claude/local`) e o shell de login passa de 4 s (oh-my-zsh + nvm num
  login frio), a sondagem volta vazia e nenhuma pasta fixa cobre a instalação:
  a CLI parece "não instalada" a sessão inteira. Nesta máquina não reproduz
  (shell em 0,4 s e claude em `~/.local/bin`, que está na lista).
- Correção (`src/main/path-resolver.ts`, `src/main/main.ts`):
  - pastas fixas: todas as versões do nvm (mais nova primeiro),
    `~/.claude/local`, fnm (default alias, Linux e macOS), mise shims, proto,
    pnpm (`~/Library/pnpm`, `~/.local/share/pnpm`), `/snap/bin`; no Windows
    `%APPDATA%\npm`, `%LOCALAPPDATA%\pnpm`, Volta e scoop;
  - `retryLoginShellPathIfMissed`: se a sondagem do boot falhou/estourou,
    uma segunda roda em background com prazo de 20 s, soma o PATH e dispara
    `rescanAdapterBinaries` — sem reiniciar o app nem clicar em nada;
  - mensagem: diz que não achou no PATH do Nexus e aponta "Reexaminar CLIs"
    / caminho do binário antes de sugerir instalar.
- Evidência: 4 testes novos em `path-resolver.test.ts` (nvm ordenado, pastas
  novas, resolução via nvm com PATH do Finder, retry só quando o boot falhou),
  todos RED antes; 1003/1007 nos arquivos das áreas; typecheck limpo.
- Pendente: validar na máquina do colega depois da atualização (qual
  instalador ele usa confirma qual pasta resolveu).
