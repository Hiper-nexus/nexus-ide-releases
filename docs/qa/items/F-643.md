# F-643 — No Windows, testes de scripts com shebang nem carregam (CRLF no `#!`)

## F-643 | categoria: funcional | severidade: baixa | status: corrigido
- Tela/fluxo: `npx vitest run bin/nexus-arms.test.mjs` (e outros testes `.mjs`) num checkout Windows com `core.autocrlf=true`.
- Arquivo:linha: `bin/nexus-arms.mjs:1` (`#!/usr/bin/env node\r\n` no working tree); não havia `.gitattributes`.
- Passos: 1) Checkout no Windows. 2) Rodar o teste do conector Arms.
- Esperado: os testes do OVKA-529 (identidade de pane no Arms) rodam.
- Observado: `SyntaxError: Invalid or unexpected token` antes de qualquer teste — o Vite não reconhece shebang seguido de CR. As suítes `bin/nexus-arms`, `scripts/build-macos-menubar`, `scripts/patch-node-pty-darwin` e `scripts/install-electron` ficavam invisíveis no Windows. No app o script roda (o Node aceita CRLF), então só o teste mentia.
- Evidencia: convertendo só a linha do shebang para LF, os 7 testes do `nexus-arms` passam no Windows.
- (resolvedor) Correcao: `.gitattributes` com `*.mjs`/`*.cjs text eol=lf` (os 153 arquivos já eram LF no índice; muda só o working tree do Windows). Resultado no Windows: 32 arquivos `.test.mjs`, suítes falhando de 12 para 9, 15 testes a mais rodando e 14 deles passando. O único que apareceu falhando (`install-electron` › caminho darwin/linux com `path.join` do Windows) é suposição POSIX do próprio teste, da família das falhas antigas do Windows.
