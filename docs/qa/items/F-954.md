# F-954 — GitCommandError no sync de panes derruba o processo principal

## F-954 | categoria: funcional | severidade: alta | status: corrigido
- Tela/fluxo: abrir o Nexus com panes de missão persistidos (aba com worktree própria)
- Arquivo:linha: `src/main/orch/orch-ipc.ts:1852` (`ipcMain.on(panesSync)`) → `src/main/orch/renderer-mission-authority.ts:645`
- Passos: 1) Mac de usuário na 0.76.198 com missão ligada a uma aba (`workspaceBinding.spaceId`); 2) o renderer envia `panesSync`; 3) `restorePersistedPaneAuthority` resolve a worktree da aba com `git rev-parse --path-format=absolute --git-common-dir` síncrono; 4) o git não completa (falha de spawn ou prazo de 30 s).
- Esperado: a autoridade daquele pane não é restaurada e o app continua.
- Observado: "A JavaScript error occurred in the main process — Uncaught Exception: GitCommandError: Git process could not complete" (print do operador, 07/10/2026). A pilha casa com `main-B0ZUPZYR.js` e `project-domain-store-registry-BjKzZe_p.js` do pacote publicado da 0.76.198.
- Evidencia: `src/main/orch/renderer-mission-authority-binding.test.ts` ("a git failure while reading the scope fails closed…") falha sem a correção e passa com ela (17/17).
- (resolvedor) Correcao: `restorePersistedPaneAuthority` falha fechado (commit 47cfee1e7, branch `fix/restore-authority-git-failure`) e o handler `panesSync` inteiro captura e registra a exceção, porque `ipcMain.on` não tem quem receba o erro. Como cada `panesSync` refaz o `git rev-parse` síncrono (prazo de 30 s) do pane de aba, uma falha agora põe a aba inteira (raiz + espaço) em backoff de 5 min em `#tabExecutionScope`, no ponto exato do git: nenhum pane dela refaz o `git rev-parse` até lá (revisão cruzada apontou que o backoff por pane ainda travava 30 s por pane da aba). O religar explícito do operador, que resolve a aba antes de restaurar, limpa o backoff quando o git responde, para não ficar recusado por até 5 min. A causa do git falhar naquele Mac não foi reproduzida. Entra na 0.76.209.
