## F-1343 | categoria: funcional | severidade: media | status: corrigido
- Tela/fluxo: roteamento de tarefa → `classifyRouteSpecialty` → `classifyWorkKind`.
- Arquivo:linha (antes): `src/shared/mission-work-kind.ts:141` (`DOC_ARTIFACT` casa `relatorio` como doc forte, sem olhar a função da palavra na frase) e `:113-119` (doc tem precedência sobre feature).

- Esperado: especialidade `feature`. O relatório é o lugar onde a feature entra, não o entregável.
- Observado: `doc` (work-kind `doc/low`), porque `doc.artifact` forte vence `feature.create` pela precedência. O mesmo vale para "adicionar filtro novo no relatório de vendas".
- Evidencia: sonda C (s240) e RED em `mission-work-kind.test.ts` › "F-1343…": `expected { kind: 'doc', confidence: 'low', … } to match object { kind: 'feature', confidence: 'high' }` nos dois casos.
- (resolvedor) Correcao:
  - Causa raiz: "relatório" é ao mesmo tempo um artefato de documentação e uma superfície do produto. O classificador tratava qualquer menção como entregável.
  - Correção: `DOC_SURFACE_LOCATIVE`. Quando o relatório aparece depois de uma preposição ("no/na/em/ao/de/do/da/para o relatório"), ele sai do teste de `doc.artifact` e vira o sinal fraco `doc.surface`. É o mesmo conceito locativo de `visual.surface`. Como objeto ("escrever o relatório", "relatório dos crashes"), continua doc forte.
  - Fica de fora de propósito: "implementar o relatório de vendas", com o relatório como objeto direto, segue misto (`doc/low`). O "+ verbo de criação" do brief também pegaria "gerar o relatório da auditoria", que é documento.
  - Testes: `mission-work-kind.test.ts` (2 RED → verdes, mais 2 guardas de doc), `mission-route-specialty.test.ts` e `mission-routing-matrix.test.ts` verdes.
