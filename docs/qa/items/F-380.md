# F-380 — Menu nativo de modelo ilegível no Windows

## F-380 | categoria: visual | severidade: media | status: corrigido
- Tela/fluxo: montagem da missão, seletores de Modelo e Esforço; também controles nativos em Ajustes, áudio, fontes e filtros.
- Arquivo:linha: `src/renderer/styles/base.css:36`, `src/renderer/components/mission/MissionSetupRosterRow.tsx:240`, `src/renderer/styles/mission-setup.css:1231`.
- Passos: 1) Usar tema escuro no Windows. 2) Abrir o seletor de Modelo da equipe da missão.
- Esperado: opções legíveis, com menu nativo no mesmo modo claro/escuro da interface.
- Observado: print anexado à missão de 14/10/2026 mostra fundo branco com texto quase branco, exceto a opção selecionada.
- Causa: o controle define `color: var(--text)`, mas a raiz não declara `color-scheme`; o popup nativo pode usar o canvas claro do sistema com a tinta clara herdada. A ausência é compartilhada pelos demais seletores.
- Correcao: declarar `color-scheme: dark` na raiz e `light` em `[data-theme='nexus-light']`. Reutiliza o atributo que `applyUiTheme` já atualiza, inclusive para temas importados; não altera seleção, teclado ou callbacks.
- Evidencia: três testes novos em `ui-theme.test.ts` falham antes da correção (`normal` em vez de `dark`/`light`) e passam depois. Verificação no Chromium headless 153 no Windows confirma herança em `select`, `option` e `optgroup`, no boot, nos sete temas e ao alternar claro/escuro; resultados em `docs/qa/evidence/F-380-native-controls.json`.
- Validacao: `npx --no-install vitest run src/renderer/styles/ui-theme.test.ts src/renderer/styles/vscode-theme-import.test.ts src/renderer/styles/css-tokens.test.ts src/renderer/components/settings/settings-style.test.ts src/renderer/components/mission/MissionSetupRosterRow.test.tsx` — 64/64 passam.
- Checks adicionais: `npm run typecheck` passou; `npm run security:renderer-sinks` passou (0 executable DOM sinks); `git diff --check` passou.
- Limite: o teste Chromium verifica estilos computados; a confirmação visual do popup no aplicativo instalado continua pendente.

### Reforço após revisão independente — 15/10/2026

A revisão achou mais três pontos da mesma família (controle nativo com a superfície do SO no lugar da do tema):

- **P2 — select do diálogo de orquestração sem nenhuma regra.** `confirm__orch-template` e `confirm__orch-template-select` (`OrchestrationModeDialog.tsx:190-209`) não existiam em folha alguma: o select caía no controle do SO (claro, estourando a largura do painel) e o rótulo ficava inline. `panels.css` agora dá superfície por token (`--bg`, `--border-strong`, `--radius-lg`, `--text`), hover quieto só habilitado (`color-mix` de `--bg` com `--text`), foco `2px var(--accent)`, desabilitado em `--text-dim` com `opacity: 1` e piso de 44px em `pointer: coarse` (a regra mora em `panels.css` porque o `min-height` dele vence o de `ui-actions.css`, que carrega antes). Varredura: dos 59 `<select>` do renderer (fora de testes) este era o único com `className` sem regra; os demais sem `className` herdam de seletor de ancestral (`.mission-setup__field select`, `.browser-profile select`, `.terminal-setup__agent select`…) ou é só menção em comentário.
- **P2 — autofill.** `base.css`: `input|textarea|select:-webkit-autofill` e `:autofill` com `-webkit-text-fill-color`, `caret-color`, sombra interna `0 0 0 1000px var(--bg-elevated)` e `transition: background-color 9999s`. O UA crava `color` e o fundo com `!important` (inclusive no valor aceito de um `<datalist>`); só esses três vencem. Os dois pseudo-seletores foram confirmados no Chromium do pane (`@supports selector()`), então a lista não é descartada. `autoComplete="new-password"` nos campos de segredo e `"off"` nos de texto/URL listados: `AccountsManager` (nome da conta de API key, API key), `ProvidersPanel` (key, modelo extra, binário, args), `ApiKeysSection` (passphrase), `OrchestratorDefaults` (gateway). Os outros dois campos de nome de conta de `AccountsManager` (login) ficaram como estavam: não são segredo e não estavam na lista.

Agora `appearanceFromBackground(bg)` (novo, em `vscode-theme-import.ts`, a mesma regra que o importador já usava inline) decide no render e em `applyDraft` com o fundo recém-editado. Os sete temas integrados mantêm o lado que tinham.
