# F-1579 — Textos do Mac no Windows: "Salva no Keychain", "detecção local no Mac", "arraste do Finder" e botões de som que não abrem nada

## F-1579 | categoria: usabilidade | severidade: media | status: corrigido

- Tela/fluxo: Configurações → Chaves de API (card Groq com "SALVA NO KEYCHAIN"), Providers (chave), Voz (wake word), Diagnóstico e HUD da JARVIS (botões de microfone/som), Estúdio de Mídia (revelar arquivo), avisos de arrastar/colar no pane e na missão, Conectores (Arms), seletores nativos no tema escuro ("Transporte realtime").
- Arquivo:linha (antes): `src/renderer/components/settings/ApiKeysSection.tsx:349,450,582,590-591,660-668`; `src/renderer/components/settings/ProvidersPanel.tsx:128,206,234`; `src/renderer/components/VoiceSettings.tsx:848`; `src/renderer/components/settings/DiagnosticsSection.tsx:165,244-249`; `src/renderer/components/VoiceHud.tsx:820,828,852`; `src/main/voice/voice-ipc.ts:1170-1179`; `src/renderer/components/MediaStudioPanel.tsx:566,606`; `src/renderer/lib/mission-shell-file-intake.ts:140,334,351,357,379,396,402`; `src/renderer/terminal/terminal-host.ts:2984`; `src/renderer/components/settings/ArmsSection.tsx:36-37,197`; `src/renderer/styles/base.css:420-437`.
- Passos: 1) Windows, tema escuro. 2) Salvar uma chave em Chaves de API ou Providers. 3) Abrir Voz, Diagnóstico, o HUD com o microfone mudo, o Estúdio de Mídia e Conectores. 4) Abrir o seletor "Transporte realtime".
- Esperado: cada texto nomeia o que existe no Windows (cofre do Windows, Explorador de Arquivos, Ajustes do Windows); os botões abrem as telas do Windows; a opção escolhida do seletor fica legível.
- Observado: "Salva no Keychain", chip "Keychain Seguro", "Keychain de cada Mac", "Nunca clique Reajustar Para Padrões no diálogo do macOS", "detecção local no Mac", "macOS só libera nomes…", "Permissão de mic fantasma — o macOS diz OK…" com o botão de reset que só existe no macOS, "Mostrar no Finder", "arraste do Finder", trecho MCP com `/Applications/NexusIDE.app/...`. Os botões "Abrir privacidade do mic", "Abrir som", "Ajustes" e "Ajustes de som" rodavam `spawn("open", ["x-apple.systempreferences:…"])` sem checar o sistema e sem ouvinte de `error`: no Windows não abriam nada e o `ENOENT` virava exceção sem dono no Main. No seletor nativo, a linha escolhida ficava com o destaque do sistema e a tinta clara do tema ("Grok Voice (principal)" quase invisível).
- Causa raiz: os textos foram escritos para o macOS e nunca passaram pela plataforma; o cofre real é o `safeStorage` do Electron cifrando `~/.nexus/secrets.enc` (Keychain no macOS, DPAPI no Windows, libsecret no Linux). O IPC de Ajustes de som era específico do macOS. O F-380 deu fundo e tinta às `option`, mas não à linha escolhida/destacada.
- (resolvedor) Correcao:
  - `src/renderer/lib/platform-copy.ts` (novo): UM helper `platformCopy()` com a tabela por sistema — nome do cofre (meio e começo de frase, chip, dica), cuidado do cofre só no macOS, gerenciador de arquivos e rótulo de revelar arquivo, se o Main abre as telas de som, se existe reset da permissão, aviso de microfone mudo, aviso de caminho do Arms. Os componentes leem a tabela; nenhum ternário de plataforma no texto.
  - Chaves de API, Providers, Diagnóstico, HUD, Estúdio de Mídia, intake de arrastar/colar e `terminal-host` passam a usar o helper. Wake word: "detecção local neste computador" (o onnxruntime roda no Main em todos os sistemas). Nome dos dispositivos: "só aparecem depois da permissão de microfone" (comportamento do Chromium em qualquer sistema).
  - `src/main/voice/system-sound-settings.ts` (novo): URL fixa por sistema (`x-apple.systempreferences:…` no macOS; `ms-settings:privacy-microphone` e `ms-settings:sound` no Windows) aberta por `shell.openExternal`; sem `spawn`. No Linux não há URL comum: o Main não abre nada e a interface esconde os botões. Falha do shell vira motivo no voice.log, nunca exceção.
  - HUD: com o microfone mudo de verdade ("fantasma"), o macOS mantém "Resetar e reiniciar"; o Windows mostra o aviso do Windows e "Ajustes" (privacidade do microfone); o Linux só o aviso.
  - Arms: o Main devolve o caminho real do `nexus-arms.mjs` (`src/main/connectors/arms-bin-path.ts`: `resources/` do app empacotado, `bin/` em desenvolvimento); o trecho MCP sai de `JSON.stringify` (os caminhos do Windows com `\` geravam JSON inválido). No Windows avisa que a pasta (`app-<versão>`) muda a cada atualização.
  - `base.css`: `select option:checked:not(:disabled)` e `option:hover:not(:disabled)` com `--accent`/`--accent-ink` (par dos CTAs), nos dois temas por token; desabilitadas seguem com o par do F-380.
