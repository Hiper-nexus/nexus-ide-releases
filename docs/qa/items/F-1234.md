# F-1234 — Ponte MCP do ACP sem node resolvível saía como `command:'node'` e o MCP nexus sumia em silêncio

## F-1234 | categoria: funcional | severidade: baixa | status: corrigido
- Tela/fluxo: spawn de pane de missão pelo transporte ACP (`orch.agentTransport === 'acp'`): `spawnMainOwnedAcpMissionPane` → `buildAcpMcpStdioServer` → `mcpServers` da sessão ACP.
- Arquivo:linha (antes): `src/main/acp/acp-mcp-stdio-bridge.ts:134`, com `command: resolveCliBinary('node')?.binPath ?? 'node'`.
- Relacionado a F-1209, que trocou `process.execPath` pelo Node resolvido.
- Passos:
  1. máquina sem Node no PATH que o Nexus resolve (`resolveCliBinary('node')` devolve `null`);
  2. o operador abre um pane de missão com transporte ACP.
- Esperado: o spawn falha dizendo que falta o Node e o que fazer.
- Observado: a spec saía com `command: 'node'` literal. O agente ACP tentava subir `node` no próprio PATH, não achava, e a sessão abria sem o servidor MCP `nexus`. Nenhum erro aparecia para o operador nem no spawn.
- Evidencia: `src/main/acp/acp-mcp-stdio-bridge.test.ts`, teste "F-1234", com o resolvedor mockado devolvendo `null`. Com a fonte anterior: `AssertionError: expected [Function] to throw an error`, porque a spec saiu com o command literal.
- (resolvedor) Correcao:
  - `buildAcpMcpStdioServer` lança `spawn_failed: node não encontrado no PATH — a sessão ACP precisa do Node.js para a ponte MCP do Nexus. Instale o Node.js (ou ponha o diretório dele no PATH do shell de login) e reabra o pane.`
  - A spec é montada dentro do `try` de `acp-mission-spawn.ts`, antes de chamar `spawnAcpHarnessSession`. Por isso nenhum harness sobe, o token MCP é liberado (`releaseSessionByToken`) e o spawn devolve `{ok:false, error:"spawn_failed: …"}`.
  - O prefixo `spawn_failed:` é o código estável que `classifySpawnErrorCode` preserva no trace.
- Validacao (launchd): `acp-mcp-stdio-bridge.test.ts` + `acp-mission-spawn-account.test.ts`: 4/4. Antes do fix, o teste novo falha.
- Limite: as pontes stdio de minimax, muse, qwen, agy e devin (`src/main/orch/cli-mcp-session-*.ts`) têm o mesmo `?? 'node'`. Não havia padrão de erro nelas para seguir, e o escopo deste achado é a ponte ACP. Elas ficam como estão.
