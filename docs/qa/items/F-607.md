# F-607 — Chip de tok/s some na toolbar do pane atrás das ações

## F-607 | categoria: usabilidade | severidade: media | status: corrigido
- Tela/fluxo: Grid de Terminais / PaneToolbar de um `cli-agent` largo, com
  ações em rótulo cheio (Tornar Orquestrador, Fim, Dormir, …).
- Arquivo:linha: `src/renderer/components/PaneToolbar.tsx` (cluster
  `toolbar__telemetry`); `src/renderer/styles/base.css` (`.toolbar__meta`
  wrap+clip).
- Passos: 1) Abrir um pane de agente em janela larga (0.76.60). 2) Deixar o
  modelo trabalhar. 3) Olhar a barra do pane ao lado do badge de custo.
- Esperado: o chip `⚡ N tok/s` (ou `— tok/s` em repouso) permanece visível
  ao lado do custo, como F-585 prometeu.
- Observado: F-585 passou a renderizar o chip, mas ele vivia no
  `.toolbar__meta` (`flex-wrap` + `max-height: 28px` + `row-gap: 160px`).
  Com as ações à direita ocupando a barra, o chip caía na "linha 2" e era
  recortado inteiro. Print 0.76.60: pane 4 Kimi "Trabalhando" + `$58.69`,
  sem tok/s. O operador concluiu que o medidor não existia no Nexus.
- Evidencia: `.nexus/attachments/mission-context/mu9ve6nw-64a27ee2f05db71a-print-2026-09-20T13-46-45.png`
- (resolvedor) Correção: `CostBadge` + `TokenSpeedChip` saem do meta e
  entram em `toolbar__telemetry` (`flex: 0 0 auto`), entre o meta e as
  ações. Título/badges continuam recortando primeiro. Telemetria some só
  abaixo de 96 px (junto com o meta). Validação:
  `npx vitest run src/renderer/components/PaneToolbar.token-speed.test.tsx
  src/renderer/components/PaneToolbar.test.tsx
  src/renderer/components/TokenSpeedMonitor.test.tsx`,
  `npm run typecheck`, `npm run security:renderer-sinks`.
