# F-401 — Sonda de quota tentava credenciais em outros fornecedores

## F-401 | categoria: seguranca | severidade: alta | status: corrigido
- Fronteira: credenciais locais → requisições HTTP de quota.
- Arquivos: `src/main/quota/key-shape-usage.ts`, `src/main/quota/provider-live-usage.ts`, `src/main/quota/provider-usage-auth.ts`, `src/main/persistence/provider-config-store.ts`, `src/main/quota/quota-service.ts`, `src/main/main.ts`.
- Esperado: uma credencial só pode ser enviada ao fornecedor declarado pelo contexto de origem; resultado desconhecido se não existe associação confiável.
- Observado: chave desconhecida ou Anthropic API podia ser tentada em GLM/Zhipu, LongCat e Kimi; qualquer JWT era classificado como xAI. O caminho é alcançável pela frota em produção para LongCat, OpenCode, Aider e adapters genéricos. Isso é um defeito confirmado, não uma comprovação de envio real indevido nesta máquina.
- Evidência: testes RED com chaves fictícias e fetch simulado registraram múltiplos destinos; nenhuma credencial real foi usada nesses testes.
- Correção: fornecedor declarado obrigatório; prefixo apenas rejeita mismatch, nunca autoriza destino. JWT genérico permanece desconhecido. Removidos fallbacks entre fornecedores. OpenCode conserva o providerId junto da chave. Token Anthropic genérico só pode atender GLM/LongCat com baseURL HTTPS explicitamente correspondente. Contas pinadas mantêm a fronteira de F-019.
- Limites: adapters genéricos sem associação de fornecedor e chaves de conta OpenCode sem providerId ficam sem telemetria. Login da CLI não foi alterado por esta correção.
- Validação: testes de zero fetch em fornecedor desconhecido/mismatch, zero fallback entre fornecedores e preservação do providerId; suíte quota isolada 144 testes; typecheck e renderer sinks.

## Revisão independente — 05/09/2026

Os testes anteriores não cobriram lista multi-origem achatada no resolver de upstream, perfil de conta incompatível com o adapter, nem mistura/publicação tardia de cache concorrente. O revisor reproduziu esses casos somente com sentinelas e fetch simulado, reabrindo o finding.

A rota API agora exige `resolveQuotaApiKey`, ligada diretamente pelo main. O resolver valida adapter existente, conta exata, modo e upstream atuais; compartilha com spawn a precedência de chave do owner, launcher do owner, launcher do upstream e ambiente declarado. Cofre frio não é decifrado nem substituído. Perfil incompatível ou órfão não chega à sonda. A lista genérica multi-origem nunca atende uma rota declarada. F-028 protege cache, resposta coalescida e publicação concorrente.

Replay independente em VM aprovou os quatro residuais: Aider/OpenCode não enviam sentinela estrangeira; Claude→GLM usa a chave canônica legítima; conta incompatível/órfã não faz requisição; mudanças de rota/modo, cofre frio, conta pinada, concorrência e publicação tardia não recorrem a fallback. Main wiring foi conferido. Nenhuma API ou credencial real foi usada nesse replay. Gate final: 255 testes em 21 arquivos com HOME/configs temporários e dependências externas simuladas; typecheck e renderer sinks passaram.
