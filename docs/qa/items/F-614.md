# F-614 — Re-login do Grok não substituía a credencial vencida da conta salva

## F-614 | categoria: funcional | severidade: alta | status: corrigido
- Tela/fluxo: Ajustes → Providers → Grok → Entrar novamente; spawn por conta.
- Arquivo:linha: `src/main/adapters/managed-credentials.ts`,
  `src/main/adapters/auth-freshness.ts`.
- Passos: 1) Salvar uma conta Grok; 2) deixar o access token vencer; 3) fazer
  `grok login` de novo; 4) abrir um pane pela conta salva.
- Esperado: o login novo substitui a sessão vencida daquela conta e o próximo
  pane nasce autenticado.
- Observado: o motor de frescor só entendia o JSON do Codex. Para o formato
  real do Grok (`<issuer>::<uuid>` + `create_time` + JWT), vault e managed home
  eram ambos "sem frescor"; o token velho permanecia no disco e ainda podia
  voltar para o vault.
- Evidencia: em 21/09/2026, `~/.grok/auth.json` tinha login do dia e o managed
  home da conta guardava token de 03/09/2026; o scanner antigo devolvia `null`
  para ambos.
- (resolvedor) Correcao: scanner genérico de emissão/expiração (ISO, epoch,
  JWT e snapshots aninhados), trava por identidade e read-back somente quando
  o disco é comprovadamente mais novo. Validação:
  `npx vitest run src/main/adapters/auth-freshness.test.ts
  src/main/adapters/managed-credentials.grok-relogin.test.ts
  src/main/adapters/managed-credentials.test.ts`.
