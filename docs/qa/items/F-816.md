# F-816 — Testes do portão de integração (F-778) dependem do `init.defaultBranch` global do git

## F-816 | categoria: testes | severidade: alta | status: corrigido
- Tela/fluxo: suíte `src/main/orch/hook-integration-endpoint.test.ts` (portão de integração F-234, hook `/hook/integration`).
- Arquivo:linha: `src/main/orch/hook-integration-endpoint.test.ts:54` (`git('init', '-q')` no `beforeEach`; os testes seguintes assumem `main` nas linhas 164, 288 e 307 do commit `ec8524a8`).
- Passos: 1) Máquina em que `git config --global init.defaultBranch` não está definido (git 2.55 cria `master`). 2) `npx vitest run src/main/orch/hook-integration-endpoint.test.ts`.
- Esperado: o resultado não depende da configuração de git de quem roda (CI, outra máquina, `~/.gitconfig` com autor, assinatura ou `url.insteadOf`).
- Observado: 8 dos 15 testes falham com `fatal: branch 'main' does not exist` (`git branch --set-upstream-to=origin/main main`) e `pathspec 'main' did not match any file(s)` (`git checkout main`). Com um `~/.gitconfig` hostil (`init.defaultBranch=trunk`, `commit.gpgsign=true`, `user.useConfigOnly=true`) falham os 15.
- Evidencia: revisão adversarial de `ec8524a8` (item A1/4 de `review-ec8524a8.md`). Reproduzido neste worktree antes da correção: 8 falhas com o git padrão e 15 com o config global hostil. Depois: 15/15 nos dois cenários.
- Causa: o fixture criava o repositório com `git init -q` e assumia o nome da branch inicial; os `execFileSync` de clone e commit herdavam o config global do usuário.
- (resolvedor) Correcao:
  - `git init -q -b main`: o nome da branch deixa de depender da máquina.
  - Todo git do fixture roda com `GIT_CONFIG_GLOBAL=/dev/null` (`NUL` no Windows), `GIT_CONFIG_NOSYSTEM=1`, `GIT_TERMINAL_PROMPT=0` e autor/committer fixos. Os clones "de outro desenvolvedor" passam por um helper único (`pushFromOtherClone`) que usa as mesmas variáveis.
  - O runner de produção (`ProcessGitRunner`) descarta `GIT_*` do ambiente e lê o config global pelo HOME; por isso o `beforeEach` aponta `HOME`, `USERPROFILE` e `XDG_CONFIG_HOME` para um diretório vazio dentro do tmp do teste e o `afterEach` restaura os valores.
  - Varredura dos demais testes que criam repositório com `git init` sem `-b main`: nenhum outro assume o nome da branch inicial (as referências a `main` nesses arquivos são rótulos, caminhos de código ou ref alternativo em teste que usa a branch `nexus/…` da aba). Método: busca por `init` sem `-b`/`defaultBranch` em `src/**/*.test.ts` e fixtures (≈45 arquivos), cruzada com referências a `main`/`master`; a revisão `ec8524a8` já tinha rodado os 184 arquivos que importam módulos alterados numa máquina que cria `master`, e só este arquivo falhou por isso. Nenhum outro arquivo precisou de mudança.
- Validação: `vitest run --maxWorkers=2 src/main/orch/hook-integration-endpoint.test.ts` com o git padrão (15/15) e com `HOME` e `GIT_CONFIG_GLOBAL` apontando para um `.gitconfig` hostil (15/15). O arquivo original (`git show HEAD:…`) no mesmo cenário hostil: 15 falhas.
- Fora do escopo: `failover-mission-respawn.test.ts` (roda `git` real contra `/workspace/mission-checkout`, que não existe; o nome do teste promete verificar o recibo "pinned" e não verifica). O arquivo está em edição pela frente F-765/F-775 e ficou intocado; registrado no relatório da revisão (B6).
