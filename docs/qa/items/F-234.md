## Evidência
- O gate de revisão independente (`mission-independent-review-gate.ts`) só
  cobre squads/PREVC e isenta a Via Rápida (`isCivilianViaRapidaReviewExempt`),
  que é o modo das missões do operador — na prática zero enforcement.
- `review_reports` pertence ao council PREVC com binding por `contractHash`;
  reutilizá-la acoplava a Via Rápida a um contrato que ela não tem.
- `git push` digitado no Bash do pane de missão nunca passava por nenhuma
  ferramenta MCP — o caminho mais fácil era o mais invisível.

## Correção
- **Ledger novo** `mission_review_verdicts` (migração 039): uma linha por
  veredito, atada ao HEAD EXATO (`head_sha` 40/64 hex), `tree_dirty`, veredito
  (`approve`/`reject`), identidade do revisor (adapter/modelo/sessão, medidos
  pelo Main — o agente nunca se autodeclara de ponta), flag `frontier`,
  findings e resumo. Cascade pela FK da missão. `MissionReviewVerdictLedger`
  segue o padrão do route-reservation ledger (binding scoped, zod, prepared
  statements) com `record` e `latestFor(missionId, headSha)`.
- **`isFrontierReviewer(adapterId, model)`** (task-router.ts): casa por LINHA
  com um assento de `JUDGE_FRONTIER_LANE` via `isSameLineAtLeast` — `opus-5-6`
  conta como linha do opus-5-5. Sem modelo → false; GLM → false.
- **`nexus_review_verdict`**: panes de missão (orchestrator/worker) registram
  `{verdict, summary, findings?}`. O Main mede HEAD + sujeira do checkout de
  execução (`measureIntegrationState`) e a identidade do revisor
  (`ctx.providerId` + `getAgentSessionInfo(sessionId).model`). Resposta traz
  `satisfiesGate = approve && frontier && !treeDirty` + hint quando falta
  ponta ou a árvore está suja. A tool é always-allowed no gate MCP para juiz
  read-only registrar o veredito.
- **`assertIntegrationReviewed`** (`integration-review-gate.ts`) é o ponto
  único da decisão: árvore suja → `review_required: árvore suja …`; sem linha,
  `reject` ou `frontier !== 1` → `review_required: push/integração exige
  veredito "approve" de modelo de ponta para o HEAD <sha7> …`. Trace
  `integration-review-gate` com allow/block (só ids/rótulos). Aplicado em:
  `nexus_git_push` (pane com missão), push do `nexus_mission_set_status`
  (sem veredito: status muda, push NÃO roda, resposta traz
  `pushSkipped: 'review_required'`), e o hook `POST /hook/integration`
  (PreToolUse/Bash) que intercepta `git push`, `gh pr create|merge` e
  `git merge … main|master` — `--dry-run` e comandos alheios passam com `{}`;
  cwd fora do checkout de execução é bloqueio deliberado. Panes sem missão
  não têm portão. Hooks instalados para Claude (settings JSON) e Codex
  (`-c hooks.PreToolUse`), idempotentes pelo marker `NEXUS_HOOK_STATUS`.
- Doutrina JULGAMENTO: `registre com nexus_review_verdict`.
