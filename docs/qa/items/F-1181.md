# F-1181 — Aviso nativo de "atualização pronta" prendia a main thread por horas

## F-1181 | categoria: funcional | severidade: alta | status: corrigido
- Tela/fluxo: atualizador macOS (modo `gh`) → evento `update-downloaded` do Squirrel.
- Arquivo:linha (antes): `src/main/updater.ts:1143` — `dialog.showMessageBox({...})` sem janela-mãe.
- Passos: 1) Nexus 0.76.233 aberto, operador ausente. 2) A 0.76.234 é publicada; a checagem de fundo do F-1012 baixa sozinha. 3) Ninguém clica no aviso.
- Esperado: o banner "Atualização pronta" do renderer pede o reinício; o main segue atendendo panes, MCP e missões.
- Observado (11/10): `update.log` → `squirrel:update-downloaded` às 07:38:54Z; o último heartbeat do main é das 07:38:56Z. Daí até 12:33:32Z o watchdog grava uma linha `main-thread-hang` por minuto (`hangDurationMs` 17.675.616, ≈4,9 h). O processo só voltou quando alguém clicou. O `main-hang-2026-10-11T07-39-29-910Z.cpuprofile` mostra 2.024 de 2.030 amostras em `messageBox ← showMessageBox ← emit`.
- Causa: sem janela-mãe, o `showMessageBox` do macOS vira `NSAlert runModal`, que prende a main thread até o clique. Desde o F-1012 o download é automático, então qualquer update de madrugada congelava o app.
- (resolvedor) Correcao: o handler só grava `phase: 'ready'`. O banner já existente (`UpdateModal.tsx`, "Reiniciar agora" → `update:restart`) cobre o aviso. O import de `dialog` saiu.
- Validacao: teste novo em `src/main/updater.test.ts`. Com a fonte anterior ele falha (o `showMessageBox` é chamado); com a correção passa. `updater*`: 60/60.
