# F-734 — Pane que recebeu o brief e teve o turno recusado pelo provedor (401) contava como "começou"

## F-734 | categoria: funcional | severidade: alta | status: corrigido
- Tela/fluxo: worker de missão ou helper do "+ Pane" da família Claude (`deepseek`, `glm`, `longcat`, `claude`…) aberto por `nexus_pane_spawn` com ACK pendente (a ficha do F-723).
- Arquivo:linha: `src/vendor/emdash/hooks/flavors.ts` (`claudeHookSpecs` sem `StopFailure`), `src/main/orch/delegation-supervisor.ts` (`hasPaneStartEvidence`: UserPromptSubmit já era "começou"), `src/shared/agent-hook-listener.ts` (`Stop` e `StopFailure` → `done` sem distinção).
- Regra do operador (F-723): "o Nexus solta um pane e confere se ele está executando; se não está, corrige ali ou manda para outro".
- Passos: 1) O Maestro abre um worker `deepseek` com chave recusada. 2) O brief entra (UserPromptSubmit). 3) Toda chamada de API volta `401 Authentication Fails` ("Retrying in 3s · attempt 8/10"). 4) O turno acaba em "Please run /login · API Error: 401 …".
- Esperado: falha provada de início. O Main fecha o pane, manda a tarefa para outra CLI e avisa quem pediu.
- Observado (campo 02/10): o pane ficou parado. O watchdog de início contou o turno aberto como "começou" (e zerou o disjuntor do adapter). Nada foi reroteado e o Maestro só soube pelo `[travado]` do F-242 (ver F-727). A chave errada em si era o F-724.
- Evidencia:
  - Claude Code 2.1.287 (bundle do binário): `StopFailure` "fires instead of Stop when an API error (rate limit, auth failure, etc.) ended the turn", e a saída do hook é ignorada. Payload: campos comuns, `hook_event_name: "StopFailure"`, `error` (enum), `error_details?`, `last_assistant_message?`. Enum `error`: authentication_failed, oauth_org_not_allowed, account_on_hold, verification_required, billing_error, rate_limit, overloaded, invalid_request, model_not_found, server_error, unknown, max_output_tokens, cloud_credential_error. Sem erro tipado a CLI manda `unknown`. O 401 de endpoint de terceiro sai como `authentication_failed` com "Please run /login · API Error: …".
  - `claudeHookSpecs` registrava UserPromptSubmit, PreToolUse, PostToolUse, PostToolUseFailure, Notification e Stop, mas não `StopFailure`. O turno recusado nunca chegava a `/hook/status` e o status semântico ficava `working`.
  - `hasPaneStartEvidence` dava a ficha por iniciada com `getAgentTurnStartSequence > 0` (o UserPromptSubmit do brief) e chamava `recordSuccess` no disjuntor.
  - A normalização compartilhada (`agent-hook-listener.ts`, Orca) não é o caminho do Main, que lê `/hook/status` pelo parser emdash. Ela tinha a mesma cegueira: `StopFailure` → `done` sem categoria.
  - Testes que reprovam o código antigo: `delegation-supervisor-start.test.ts` › "F-734: … credencial recusada sem trabalho: fecha o pane, abre o disjuntor da chave, reroteia e avisa o Maestro" (no código antigo a ficha sai na 1ª varredura) e `flavors.test.ts` › "covers the documented event surface per flavor" (sem `StopFailure`).
- Causa: o Main não recebia o fim de turno com erro de API da família Claude, e o watchdog do F-723 tratava "turno aberto" como "começou".
- (resolvedor) Correcao:
  - `59f1453a` — `shared/agent-stop-failure.ts` (novo) é a allowlist `error` → categoria: `auth` (authentication_failed, oauth_org_not_allowed), `billing` (billing_error, account_on_hold, verification_required), `invalid_request` (invalid_request, model_not_found) e `other` (o resto e qualquer valor fora do enum). A família Claude registra `StopFailure` → `stop-failure`. O parser devolve um `stop` só com `stopFailure: <categoria>`, sem texto. O endpoint não dispara o fechamento mecânico `[auto]` para ele. O reducer (`agent-status.ts`) marca tool events com o bit `toolActivity` e guarda, sem conteúdo, como cada turno acabou (`getAgentLastTurnEnd`, `tapAgentTurnEnd`: categoria e se rodou ferramenta). O status continua `completed`, porque o pane está parado no prompt. O `turn_ended` do observer sai em `error`. A normalização Orca leva a mesma categoria no `done`.
  - `dd15c2a8` — `circuit-breaker.ts`: `trip(key, openMs)` abre na hora por uma janela própria. Contar 1 de 3 falhas em 60 s nunca abria para chave recusada, porque cada recusa leva minutos de retry da CLI.
  - `9e23a8b1` — `pane-start-watchdog.ts` e `delegation-supervisor.ts`. Na família Claude (prova de turno) a ficha espera o desfecho do turno do brief, e só ele é julgado. Ferramenta, handoff ou Stop normal provam o início. StopFailure `auth`/`billing`/`invalid_request` sem trabalho é falha provada (`provider-auth`/`provider-billing`/`provider-request`) e segue o passo 2 do F-723: fecha o pane (nunca `operatorOpened`), disjuntor, no máximo um reenvio com a autoridade atual de quem pediu e a CLI em `excludeAdapterIds`. CLI pedida pelo operador, retomada, segunda tentativa ou nenhuma alternativa → só avisa. O aviso diz, por exemplo, `[nao-iniciou:<paneId>] … credencial recusada pelo provedor (o turno do brief acabou antes de qualquer trabalho)`. `rate_limit` e transitórios (`other`) liberam a ficha sem veredito: são do failover (F-249/F-718). Disjuntor: credencial recusada sem conta gerenciada é a chave de todo pane da CLI e abre o adapter por 15 min (`CREDENTIAL_REJECTED_OPEN_MS`). Com conta gerenciada a pausa é por conta (F-676, failover) e o adapter só conta a falha. Pedido recusado só conta. Traces: `pane-start-rejected` (novo) e `breaker` no `pane-not-started`.

- Fora do escopo:
  - Kimi e Grok continuam mandando `StopFailure` como `stop` (payload deles não conferido). Esse caminho segue alimentando o fechamento mecânico com o texto que a CLI enviar.
  - `worker-handoff-enforcement` anexa o tail do pane ao handoff sintético quando um worker sem handoff fecha. O tail pode conter a linha de erro da CLI (sufixo de chave já mascarado por ela). É anterior a este fix e vale para todo pane fechado sem handoff.
  - `tool-util.ts` chama `recordSuccess` quando um spawn não pendente fica com o PTY gravável, o que pode fechar um `trip` antes da janela. Spawn não pendente não tem ficha.
  - Pausa da conta gerenciada: fica com o failover, que a aplica ao ver o 401 na tela. O watchdog não toca na conta.
  - Não validado em pane real: o payload foi conferido no bundle do Claude Code 2.1.287 e o fluxo coberto por testes. Também não foi conferido o que uma versão antiga do Claude Code, sem `StopFailure`, faz com a chave no settings. O 2.1.287 ignora evento de hook desconhecido com um aviso.
