# F-581 — `nexus_git_sync` recusado à mão do operador (vibe): "routine local operation requires renderer user authority"

## F-581 | categoria: usabilidade | severidade: media | status: corrigido

- Tela/fluxo: pane do operador (`role user`, sem missão) chamando
  `nexus_git_sync` via `http-mcp` — a ferramenta era negada embora o mesmo
  pane já possa chamar `nexus_git_pull`/`nexus_git_push`.
- Arquivo:linha: `src/main/orch/mcp-dispatch.ts` `bindEffectAuthority`
  (~L383: o early-return do modo vibe excluía `routine-local-operation`
  junto de `renderer-authorized-effect`).
- Passos: 1) dentro de um pane do operador, chamar `nexus_git_sync`;
  2) receber a recusa "routine local operation requires renderer user
  authority".
- Esperado: o pane da própria mão do operador sincroniza — `git_sync` é um
  fast-forward verificado, subconjunto estrito do `git_pull` que o mesmo
  pane já executa em vibe.
- Observado: recusa de autoridade — o vibe early-return só valia para
  policies que não fossem `renderer-authorized-effect` NEM
  `routine-local-operation`, então `git_sync` caía no gate de origem
  renderer mesmo sendo menos privilegiado que tools já permitidas.
- Causa: exclusão ampla demais no early-return vibe — `routine-local-operation`
  foi agrupado com `renderer-authorized-effect` (`ui_action`) embora sua
  autoridade não seja de origem renderer, só de conveniência do fluxo da UI.
- Correção (`mcp-dispatch.ts`): o early-return vibe agora exclui apenas
  `renderer-authorized-effect` — um agente MCP nunca dirige a UI.
  `git_sync` passa pelo caminho normal de vibe (handler como fronteira,
  auditoria mantida). Workers de missão e orquestradores não mudam (não são
  vibe) e seguem exigindo autoridade de usuário renderer para a lane
  routine-local.
- Limites deliberados: `ui_action`/`renderer-authorized-effect` continua
  fora do alcance de qualquer agente MCP; a recusa do worker de missão está
  coberta por teste.
- Evidência: teste "permits repository sync from the renderer or the
  operator's own pane" em `mcp-dispatch-security.test.ts` — `ipc-renderer`
  ok, `http-mcp` com contexto de usuário ok, `http-mcp` com contexto de
  missão negado; handler chamado 2×. 92/92 no arquivo.
