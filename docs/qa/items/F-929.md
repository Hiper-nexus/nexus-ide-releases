# F-929 — `lint:main-sync` reprova todo build do Windows em checkout CRLF

## F-929 | categoria: build | severidade: alta | status: corrigido
- Tela/fluxo: `npm run make` no Windows (`premake` → `lint:main-sync`, F-764).
- Arquivo:linha: `scripts/check-main-sync.mjs` (`normalizedTokens`).
- Passos: num checkout com `core.autocrlf=true`, `node scripts/check-main-sync.mjs`.
- Esperado: `main sync audit: no new synchronous processes`.
- Observado (05/10, main 9b3a0cb3b, 0.76.194): 4 violações — `subscription-auth.ts:617 execFileSync` e `shell-catalog.ts:29 spawnSync` como "new", e as exceções dos mesmos dois usos como "stale". O build local do Windows para antes de empacotar.
- Causa: a impressão digital vem dos tokens do scanner do TypeScript, que não reescaneia templates. Depois de um `${…}` o fechamento do template e o resto do trecho viram um token só, com as quebras de linha dentro. Com CRLF o token difere do gravado na allowlist (gerada em LF). Só os dois usos com template de substituição dentro da chamada eram afetados.
- (resolvedor) Correcao: `normalizedTokens` normaliza `\r\n`/`\r` para `\n` antes de escanear; as impressões digitais em LF não mudam. Teste novo em `scripts/check-main-sync.test.mjs` (falha no código antigo).
- Como foi achado: primeiro build local do Windows da 0.76.194 (o Actions estava sem créditos e o run do GitHub não chegou a rodar).
