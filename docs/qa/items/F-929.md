# F-929 — "Atualizar CLI" do Codex falha em instalação standalone/cask: canal não reconhecido

## F-929 | categoria: funcional | severidade: alta | status: corrigido
- Tela/fluxo: botão/ação "atualizar CLI" do Codex no MCP/UI do pane (`installOrUpdateProviderCli`).
- Arquivo:linha: `src/main/adapters/cli-install-recipes.ts:225` (recipe de instalação) e o novo ramo do updater logo antes de `minimax-code`; erro em `src/main/persistence/provider-config-store.ts` ("Não reconheci o canal da CLI usada pelo pane").
- Passos: num Mac com o Codex instalado pelo **instalador standalone** (`curl -fsSL https://chatgpt.com/codex/install.sh | sh`) — binário em `~/.codex/packages/standalone/releases/<versão>/bin/codex`, com `~/.local/bin/codex` só como symlink — clicar em "atualizar CLI" do Codex.
- Esperado: a atualização roda pelo canal correto da instalação.
- Observado: erro "Não reconheci o canal da CLI usada pelo pane; atualize essa instalação pelo canal original." `selectCliUpdateRecipe` só reconhecia npm (`/lib/node_modules/@openai/codex/`) e um suposto brew de fórmula; a instalação standalone não casava nenhum candidato e caía no `return null`.
- Causa: (1) o Codex não tem subcomando de auto-update (o próprio wrapper npm `bin/codex.js` v0.160.0 orienta reinstalar pelo gerenciador: `npm/pnpm/bun install -g @openai/codex@latest`), então não existia ramo para o instalador standalone; (2) o Codex no Homebrew é **cask** (`brew install --cask codex` → `/Caskroom/codex/`), mas a recipe usava `brewRecipe('codex')` (fórmula → `/Cellar/`), que nunca casa um cask instalado.
- (resolvedor) Correção:
  1. Novo ramo no `selectCliUpdateRecipe`: realPath sob `~/.codex/packages/standalone/` → `scriptRecipe('https://chatgpt.com/codex/install.sh', { automaticUpdate: true })`. O instalador oficial é idempotente e atualiza in-place. A detecção usa o **realPath** (não `~/.local/bin/codex`, que symlinks de instalações npm também usam — vide testes de "external launcher").
  2. `RECIPES.codex.darwin`: `brewRecipe('codex')` → `brewCaskRecipe('codex')`, que o loop de candidatos resolve por `/Caskroom/codex/` com `brew upgrade --cask codex`.
- Teste: `cli-install-recipes.test.ts` — "reruns the official installer for a standalone Codex (F-929)" e "updates a Homebrew-cask Codex with brew upgrade --cask (F-929)". Os casos npm (prefixo próprio, symlink externo, Windows shim, F-688) seguem verdes — sem regressão.
- Como foi achado: suporte ao vivo — update do Codex falhando no Mac de um usuário. Diagnóstico: leitura de `cli-install-recipes.ts` + do wrapper instalado `@openai/codex/bin/codex.js` (v0.160.0) e do `install.sh` oficial (layout `BIN_DIR=~/.local/bin`, `STANDALONE_ROOT=~/.codex/packages/standalone`, `RELEASES_DIR=$STANDALONE_ROOT/releases`). Falta confirmar num app assinado com uma instalação standalone real (o `realpath` do binário do usuário fecha a prova de ponta a ponta).
