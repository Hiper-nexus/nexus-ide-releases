# F-1417 — Revisão de segurança só leitura rebaixada para "verificação visual pendente"

## F-1417 | categoria: funcional | severidade: media | status: corrigido
- Fluxo: worker `readOnly:true` com a task "Revisão de segurança, só leitura, do
  auto-update de CLI (F-1397 × F-1395 com C5/C6/C7) e do F-1411 Kimi bracketed
  paste" entregou `success`.
- Observado: o handoff virou `partial`, com o artefato
  `nexus.visualVerification {required:true, verified:false}` e o prefixo
  "[verificação visual pendente]". A tarefa não tem UI.
- Causa confirmada (RED): `visualTaskRequirement`
  (`src/main/orch/visual-handoff-gate.ts`) classifica o texto do prompt, e esse
  texto pode carregar o rodapé do Nexus "Regra de design do projeto (sempre que
  o trabalho envolver UI): … Leia DESIGN.md antes de editar a interface … como
  verificou a interface renderizada …". Isso acontece no `ruleText`, ou quando
  o brief do orquestrador cita esse rodapé, como fez a evidência do F-1411.
  `withoutMountedPromptContextBlocks` só remove os blocos `<tag>` do início; o
  rodapé passava e acionava `requiresDesignAuthority`. A task sozinha nunca foi
  visual, e "paste" e "Kimi" não são o gatilho.
- Correção: antes de classificar, o bloco da regra de design sai do texto, do
  cabeçalho até a frase fixa que o fecha ("…ainda não aplicada como regra
  vigente.") ou até a próxima linha em branco. A decisão passa a olhar só a
  task. Um pedido visual direto com o rodapé continua exigindo a captura.
- `readOnly` não entrou na regra: uma auditoria visual só leitura ("audite a
  tela de checkout") precisa da captura. O que decide é o sinal de UI na task.
- Validação: `npx vitest run src/main/orch/visual-handoff-gate.test.ts`
  (21/21). RED: com o fonte da base, "o rodapé de design injetado pelo Nexus
  não torna a task visual" falha. `npx tsc --noEmit -p tsconfig.json` limpo.
