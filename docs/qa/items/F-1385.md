# F-1385 — Worker não usa o Node fixado pelo projeto (npx/tsc rodam no Node errado, better-sqlite3 quebra)

## F-1385 | categoria: funcional | severidade: media | status: corrigido
- Tela/fluxo: spawn de worker (CLI agent) → `spawnAgentSession` → montagem do `env.PATH` do PTY. O worker herdava o PATH do processo main (Node default do operador, v26) e ignorava o Node que o projeto fixa.
- Arquivo:linha (antes):
  - `src/main/pty/pty-manager.ts:2063`: `identityEnv`/`env` copiam `PATH` de `process.env` (allowlist) sem considerar `.nvmrc`/`.node-version`/`package.json`.
- Passos:
  1. Projeto declara Node 22 (`package.json#nexusRelease.node = 22.23.2`, `engines.node = ">=22.12.0 <23"`).
  2. A máquina tem outro Node como default no PATH (v26, ABI 147).
  3. Um worker roda `npx vitest`/`tsc` com o PATH herdado.
- Esperado: o worker usa o Node que o projeto fixa, sem reinstalar nada.
- Observado: `npx`/`node` resolvem o Node do default do operador; o `better-sqlite3` nativo do projeto (compilado para o ABI 127 do Node 22) falha com `ERR_DLOPEN_FAILED`.
- Evidencia (RED): `src/main/pty/node-version-path.test.ts` — `.nvmrc = 22` + um `node@22/bin` falso não prefixava o PATH (o módulo nem existia). Teste "sem `.nvmrc`" passava por acidente porque nada era aplicado.
- (resolvedor) Correcao:
  - Novo `src/main/pty/node-version-path.ts`: `detectPinnedNodeMajor` (precedência `.nvmrc` → `.node-version` → `package.json#nexusRelease.node` → `package.json#engines.node`), `candidateNodeBinDirs` (Homebrew arm64/intel/linuxbrew + nvm `~/.nvm/versions/node/v<major>.*/bin`; vazio no win32) e `resolveInstalledNodeBin`. Tudo puro e injetável.
  - `applyProjectNodeToWorkerPath` prefixa o `bin` do Node fixado ao `env.PATH`. Sem pin, ou sem Node compatível instalado, nada muda (nunca instala). Receipt em `[worker-node] <adapter>: PATH → <binDir> (<motivo>)`.
  - `src/main/pty/pty-manager.ts:2064`: aplica o prefixo no `env` do spawn (e espelha em `identityEnv` quando separado).
  - **Exceção `minimax-code`**: o addon nativo dele (better-sqlite3, ABI 147) é compilado para o Node que o F-789 sonda no PATH, não para o Node do projeto; prefixar o Node 22 quebraria a TUI e dessincronizaria a decisão do permit (`process.env.PATH`) do PATH real do spawn.
- Validacao:
  - `src/main/pty/node-version-path.test.ts`: 10/10 (prefixa com pin + bin compatível; inalterado sem pin; inalterado sem bin compatível com `reason`; PATH vazio; `majorFromVersion`; precedência; fallback `nexusRelease`/`engines`; candidatos homebrew/win32; resolução).
  - `src/main/pty/pty-manager.test.ts`: 194 passed / 8 skipped (inclui o F-789, que exigiu a exceção acima).
  - `npx tsc --noEmit -p tsconfig.json`: 0.
