# F-1214 — o timeout do gate de comando da meta (/goal) matava só o shell e deixava o processo travado órfão

## F-1214 | categoria: funcional | severidade: media | status: corrigido
- Tela/fluxo: Goal Governor (`nexus_goal_register` → `advanceWave` / reconcile) com gate `type: 'command'`.
- Arquivo:linha (antes): `src/main/orch/goal-governor.ts:465-477` — `spawn(command, { shell: true })` e, no timeout (padrão 120 s), `proc.kill('SIGKILL')`.
- Passos: 1) o gate roda um comando que trava num neto, como `npm test`, que sobe um node de teste preso; 2) o timeout dispara.
- Esperado: o timeout derruba o comando travado, que é justamente o motivo de ele existir.
- Observado: o SIGKILL acerta só o `/bin/sh` (ou o `npm`). O neto travado é reaproveitado pelo launchd/init (ppid 1) e roda sem dono. Também não morre no quit, porque `shutdownGoalGovernor` não mexe em gates em voo. Cada nova tentativa do gate empilha mais um.
- Evidencia (`ps` antes e depois, macOS). Mesmo spawn e mesmo kill do gate, gate `sleep 30 & echo $! > hung.pid; wait`:
  ```
  before: shell=79179
    ps hung grandchild before timeout: 79187 79179 00:00 sleep 30
    ps 1s after the timeout kill: 79187     1 00:01 sleep 30      <- órfão
  after: shell=79390
    ps hung grandchild before timeout: 79400 79390 00:01 sleep 30
    ps 1s after the timeout kill: (gone)
  ```
- (resolvedor) Correcao: em POSIX o gate roda no próprio grupo de processos (`detached: true`) e o timeout manda SIGKILL para o grupo (`process.kill(-pid)`). É o mesmo padrão de `sensor-broker.ts:killTree`. No Windows segue `proc.kill`, sem mudança.
- Validacao:
  - Teste novo em `src/main/orch/goal-governor.test.ts` ("F-1214: a timed-out command gate takes its whole process tree down…"): falha antes (neto vivo 2 s depois do timeout, `expected true to be false`) e passa depois.
  - `goal-governor` e `tools-goal` verdes (12/12).
  - `tsc --noEmit` verde.
- Limite: no Windows o timeout continua matando só o filho direto (precisaria de `taskkill /T`, como em `acp-client.ts:killHarnessProcessTree`). Ficou fora porque não há como validar em Windows nesta rodada. Um gate em voo também não é cancelado no quit; ele termina sozinho ou no timeout.
