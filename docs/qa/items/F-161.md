# F-161 — Claude atribui ao próprio comando Bash edições de outro pane

## F-161 | categoria: funcional | severidade: media | status: corrigido
- Tela/fluxo: panes Claude em abas diferentes usando o mesmo checkout.
- Arquivo:linha: `src/main/orch/hooks-gen.ts:473`.
- Passos: 1) Abrir Claude e outro agente no mesmo checkout. 2) No Claude, executar um comando de leitura demorado. 3) No outro pane, editar arquivos enquanto o comando roda.
- Esperado: o resultado do comando de leitura não apresenta as alterações do outro agente como edições suas.
- Observado: Claude Code 2.1.283 anexa `toolUseResult.bashEditDiff` ao resultado do Bash e imprime `Updated` com os arquivos alterados por outra sessão. As abas organizam terminais; não criam worktrees automaticamente.
- Evidencia: no incidente de 26/09, o Codex alterou `.tnp-statement-state > p` e o teste de NavalhaPay às 11:40:09. O Claude/Jarvis anexou o mesmo diff ao resultado de `gh pr checks` às 11:40:25. O `message.content` desse resultado contém apenas os checks do CI; o diff está no metadado `bashEditDiff`. O PR 1763 tem nove arquivos exclusivos do Jarvis (sete de feature e dois de documentação). O reflog confirma a troca do checkout compartilhado às 10:41. Identidades de conversa distintas; sem evidência de mistura do transporte PTY.
- Fonte do provedor: [Claude Code 2.1.269](https://github.com/anthropics/claude-code/releases/tag/v2.1.269) introduziu `bashEditDiffEnabled`. O schema do binário local 2.1.283 confirma que `false` desativa a coleta/exibição do diff de Bash.
- (resolvedor) Correcao: configuração privada por pane com `bashEditDiffEnabled: false`, nos caminhos de HOME governado e `--settings` dos panes diretos. Hooks e diffs das ferramentas Edit/Write preservados. Nenhuma alteração no perfil global do usuário. Não promete isolamento dos arquivos: trabalhos independentes precisam de worktrees/pastas distintas; o histórico já exibido não é apagado.
- Validação: regressão nos dois caminhos falha antes da mudança (`undefined` em vez de `false`). GREEN: 39 testes em quatro suites de hooks/configuração passaram; `npm run typecheck` passou. Commit: o commit deste finding.
