# F-745 — Hook global do Codex/Claude no Windows falhava (exit 255) fora do Nexus

## F-745 | categoria: funcional | severidade: baixa | status: corrigido
- Tela/fluxo: Codex (ou Claude) rodando FORA de um pane do Nexus, no Windows. Ele usa os hooks globais que o Nexus instala em `~/.codex/hooks.json` (`~/.nexus/agent-hooks/codex-hook.cmd`).
- Arquivo:linha: `src/main/agent-hooks/installer-utils.ts` (`windowsHookEndpointLoadLines`).
- Passos:
  1. Abrir o Codex num terminal comum (sem `NEXUS_AGENT_HOOK_ENDPOINT` no ambiente).
  2. Qualquer evento de hook (SessionStart, PreToolUse…).
- Esperado: o script sai 0 sem fazer nada (não é pane do Nexus).
- Observado (02/10, `cmd /d /c codex-hook.cmd` sem a variável): "A sintaxe do comando está incorreta." e exit 255 a cada evento.
- Causa: com a variável indefinida, `%NEXUS_AGENT_HOOK_ENDPOINT:~-4%` não se expande. O bloco `if … ( for /f … )` multilinha não parseia, e o `cmd.exe` aborta o script. Dentro do pane a variável existe e o defeito não aparecia.
- (resolvedor) Correcao:
  - `if not defined NEXUS_AGENT_HOOK_ENDPOINT goto nexus_hook_post` antes do bloco e o rótulo depois dele. O `goto` pula as linhas sem parseá-las.
  - Com a variável (endpoint `.cmd` ou arquivo `export`), o script posta igual ao anterior: verificado com servidor local, mesmo token e mesmo corpo.
  - Teste que reprova o código antigo: `installer-utils.test.ts`, que roda o script gerado no `cmd.exe` sem a variável (só no win32).
