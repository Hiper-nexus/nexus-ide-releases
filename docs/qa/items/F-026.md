# F-026 — Quota ignora upstream explícito de uma conta

## F-026 | categoria: funcional | severidade: media | status: corrigido
- Fluxo: provider roteável, como Claude com conta API key apontada explicitamente para GLM.
- Arquivos: `src/main/quota/quota-service.ts`, `src/main/quota/provider-live-usage.ts`, `src/shared/quota-types.ts`.
- Esperado: consultar o fornecedor declarado com a chave da entrada exata, mantendo sua identidade de adapter/conta.
- Observado: a linha Claude seguia apenas a sonda Claude OAuth, apesar de a conta utilizar outro fornecedor.
- Evidência: RED com adapter Claude, upstream explícito GLM e chave fictícia do próprio adapter; nenhuma consulta externa real.
- Correção: campo opcional `usageProviderId` separado do adapter dono. Upstream não-default explícito mantém a precedência do spawn; conta de assinatura pinada não herda esse destino. Origem API key usa o provider declarado, sem recorrer a OAuth quando não existe quota API compatível. O resolver canônico valida novamente owner/conta/modo/upstream e usa a mesma precedência de configuração do spawn, sem lista multi-origem. Conta pinada e cofre frio não recorrem a fallback. Alteração do destino ou do modo de autenticação separa a identidade do cache.
- Limites: sem chave acessível do proprietário a quota continua desconhecida; o sistema não tenta chaves de outra conta. Defaults genéricos e contas de assinatura não implicam associação de upstream.
- Validação: 144 testes de quota/native auth em 17 arquivos com HOME temporário e resolvers simulados; typecheck, renderer sinks e diff check.
