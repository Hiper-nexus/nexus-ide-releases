# F-579 — Pane da família Claude não consegue `git push`: HOME efêmero nasce sem identidade git/SSH/gh do operador

## F-579 | categoria: funcional | severidade: alta | status: corrigido

- Tela/fluxo: qualquer pane gravável da família Claude (direto/operator-choice
  ou worker gated) — o agente consegue commitar localmente mas todo
  `git push`, `git pull` de remote privado e `gh` falham dentro do pane.
- Arquivo:linha: `src/main/orch/hooks-gen.ts` `prepareEphemeralHome` (~L700:
  o overlay nascia só com `.claude/`, `.claude.json`, `nexus-gate.mjs`,
  `nexus-mcp.json` e os links de keychain do F-575); flags ligadas em
  `src/main/orch/mcp-server.ts` `prepareAgentSpawnDecoration` (~L1096).
- Passos: 1) abrir um pane Claude; 2) pedir ao agente para dar push num
  remote HTTPS do GitHub; 3) o agente tenta `git push`, `gh auth status`,
  procura `~/.ssh` e a keychain — e desiste.
- Esperado: o pane escreve como o operador — commit com `user.name/email`
  reais e push autenticado pelo helper/credencial que o operador já tem.
- Observado (campo): agente dentro de um pane com
  `HOME=/Users/<user>/.nexus/ephemeral/e54fe39c226a` reportou nenhuma
  entrada de keychain para github.com, `~/.ssh` inexistente, `gh` "not
  logged in" e desistiu do push. O overlay carrega `.claude/`,
  `.claude.json`, `nexus-gate.mjs`, `nexus-mcp.json` e nada mais —
  `~/.gitconfig` (que nesta máquina guarda
  `credential.https://github.com.helper = !/Users/cleofasrocha/.local/bin/gh
  auth git-credential`), `~/.ssh`, `~/.config/gh/hosts.yml`,
  `~/.netrc`/`~/.git-credentials`/`~/.gnupg` e os rc files ficam todos de
  fora. Não é fronteira de segurança: panes Claude graváveis nunca são
  confinados pelo kernel (Seatbelt só vale para lanes readOnly e Codex), e
  o processo lê o HOME real por caminho absoluto de qualquer jeito — a
  omissão só quebrava push/commit/gh.
- Causa: o overlay efêmero foi desenhado (F-567) para isolar conversa e
  auth Claude; ninguém projetou a identidade de desenvolvedor junto, então
  o `$HOME` do pane é uma casa vazia para git/ssh/gh.
- Correção: dois tiers opt-in em `prepareEphemeralHome`, ambos fail-closed
  por default, best-effort por entrada e idempotentes:
  - **Tier 1 (`carryDeveloperIdentity`)** — linka só
    `DEVELOPER_IDENTITY_HOME_ENTRIES` (`.gitconfig`, `.git-credentials`,
    `.netrc`, `_netrc`, `.ssh`, `.gnupg`, `.config/git`, `.config/gh`). Os
    `.config/*` exigem `<overlay>/.config` como diretório REAL 0700 criado
    só quando ainda não existe — um `.config` linkado pelo tier 2 nunca é
    substituído. Vai para TODA lane gravável Claude-family (direta e
    gated): workers também precisam commitar e dar push como o operador.
  - **Tier 2 (`carryNativeHome`, POSIX only)** — linka TODA entrada do topo
    do HOME real exceto `NATIVE_HOME_EXCLUDED_ENTRIES` (`.claude`,
    `.nexus`, `Library`, `.Trash`) e qualquer nome começando com
    `.claude.json` (cobre `.claude.json`, `.claude.json.backup`,
    `.claude.json.backup.<ts>`). `.claude-mem`, `.claude-server-commander`
    etc. NÃO são excluídos (match exato de `.claude` + prefixo
    `.claude.json`). É a lane da escolha do operador: "o pane é o próprio
    HOME menos o estado de conversa Claude". `Library` fica fora para a
    política keychain arquivo-a-arquivo do F-575 continuar sendo o único
    caminho.
  - Ligação em `mcp-server.ts`: `carryDeveloperIdentity: meta?.readOnly !==
    true` e `carryNativeHome: meta?.readOnly !== true && !gateHome`.
- Limites deliberados: lanes read-only não recebem nada (nunca commitam e
  podem estar confinadas); no win32 o tier 2 é no-op e o `.gitconfig` do
  tier 1 vira hardlink — `git config --global` escrito dentro do pane não
  persiste um arquivo novo; o teardown (`fs.rmSync` no overlay) remove os
  links sem segui-los — provado por teste que confere conteúdo do HOME
  real após `cleanupSessionArtifacts`.
- Evidência: `hooks-gen.developer-identity.test.ts` novo (7 testes: tier 1
  completo com asserts de symlink+realpath, entradas ausentes, fail-closed
  default, tier 2 com conjunto de exclusão, variante darwin com keychain
  per-file, teardown sem seguir links, e prova física `git config --global
  --get user.email` com `HOME=<overlay>`); +6 testes em
  `mcp-server-governed-profile.test.ts` (direto/gated/read-only ×
  claude/glm). Prova física nesta máquina (`/tmp/nexus-f579-proof.log`):
  com `HOME=<overlay>` o `git config --global --get
  credential.https://github.com.helper` mostra o helper do `gh`, `gh auth
  status` reporta logged in e `git push --dry-run` imprime
  "Everything up-to-date". Relacionados: F-567, F-575, F-578.
