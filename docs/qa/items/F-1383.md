# F-1383 — Segredo em `args` de servidor MCP atravessa o hub em claro

## F-1383 | categoria: seguranca | severidade: alta | status: corrigido
- Tela/fluxo: MCP Hub — selo de segredos, sync fill-gaps (import/export) e materialização de servidores no spawn dos panes.
- Arquivo:linha (antes): `sealMcpHubSecrets` (`src/main/mcp-hub/mcp-hub-secrets.ts`) só varria `env` e `headers`; `applyMcpSync` (`mcp-hub-sync.ts:~529`) gravava o hub sem selar; `loadMcpHubServersForSpawn` (`mcp-hub-spawn.ts`) repassava args sem tratar refs de cofre.
- Passos: 1) Config de terceiro (ex.: Cursor/Claude Code) com servidor stdio cuja `args` traz flag de credencial (`--figma-api-key=figd_…`, 61 chars no caso real da máquina do operador). 2) Sync importa para o hub. 3) Hub é gravado, sofre backup `.bak` e é exportado/materializado nos panes.
- Esperado: nenhum segredo em claro no `mcp-hub.json`, nos backups nem nas projeções de UI; spawn e export recebem o valor real pelo mesmo mecanismo de cofre do env.
- Observado: o arg com a chave atravessava em claro o hub, os `.bak` timestamped e os exports para as CLIs; a UI de Settings recebia o valor sem máscara.
- Evidencia (RED, antes do fix): 13 testes novos falhando —
  - `mcp-hub-secrets.test.ts` › "F-1383": `sealMcpHubSecrets` com `args: ['-y','figma-mcp','--figma-api-key=figd_X…']` devolvia o arg em claro (`figd_` presente no JSON selado, 0 refs no cofre); idem para `--token VALOR` e prefixos `sk-`/`ghp_`/`xox`/`figd_`.
  - `mcp-hub-spawn.test.ts` › "F-1383": spawn não resolvia ref de cofre em arg (sem a opção `secretGet`) nem descartava refs órfãs.
  - `mcp-hub-sync.test.ts` › "F-1383": `applyMcpSync` gravava o hub importado com o arg em claro (sem `sealHub`).
  - `mcp-hub-core.test.ts` › "F-1383": `maskServerForUi` não mascarava args e `restoreMaskedSecrets` não restaurava arg mascarado.
- (resolvedor) Correcao:
  - `mcp-hub-secrets.ts`: selo e hidratação passam a varrer `args`. Detecção reusa os padrões existentes de `src/shared/secret-redaction.ts` (`redactCommandLine`/`SECRET_VALUE_RE`/`FLAG_SECRET_RE`): `--flag=VALOR`, valor após flag de credencial (`CREDENTIAL_FLAG_RE`, nova exportação que compartilha a mesma lista de nomes de flag), e token com prefixo conhecido (incluído `figd_` no `SECRET_VALUE_RE` — chave Figma do caso real). O arg inteiro vai para o cofre sob a chave `mcphub:<scope>:<serverId>:args:<index>` e vira ref `__nexus_vault__:` no disco; hidratação valida a chave exata da posição (ref plantada em índice errado é recusada, fail-closed, igual ao env).
  - `mcp-hub-sync.ts` + `product-wave-ipc.ts`: `applyMcpSync` aceita `sealHub` e sela o hub ANTES de gravar (o handler IPC passa `sealMcpHubForDisk`); dryRun não escreve no cofre. Exports para as tools continuam recebendo o valor real (o hub entra hidratado no sync).
  - `mcp-hub-spawn.ts` + `orch/mcp-server.ts`: `loadMcpHubServersForSpawn` aceita `{ secretGet }` e resolve refs de `args` para o valor real no spawn (env/headers secretos continuam fora do config gerado, invariante mantida). Sem resolvedor ou com falha na hidratação, o arg-ref é descartado; se o valor descartado era o argumento de uma flag de credencial, a flag órfã vai junto (não sobra `--token` sem valor).
  - `mcp-hub-core.ts`: `maskServerForUi` mascara args com ref ou resolvidos de ref (`args.<index>` em `vaultRefFieldKeys`), sempre como `[REDACTED]` integral; `restoreMaskedSecrets` restaura arg mascarado pelo índice e recusa (fail-closed) quando não há valor guardado.
- Nao feito (registro): segredos em `env`/`headers` do hub continuam NÃO resolvidos no spawn (sanitizeRecord os descarta) — postura pré-existente e fora do escopo; o sync (export) é o caminho que leva esses valores às tools. Credenciais em args no spawn do Codex seguem pelo argv `-c` (visível em `ps`), como já ocorria com o valor em claro — mudar esse transporte é decisão de produto separada.
- Validacao: `npx vitest run` dos 4 arquivos do hub + vizinhos (`secret-redaction`, `command-redaction*`, `command-block-store`, `cli-mcp-inject`, `product-wave-mcp-secrets`, `product-wave-mcp-rollback`, `pty-analysis-main-load`, `arms-endpoint`) — 139+ testes verdes; `tsc --noEmit` 0 erros.
