# F-1366 — Servidor MCP com cwd perde o diretório de trabalho no spawn do hub

## F-1366 | categoria: funcional | severidade: media | status: corrigido
- Tela/fluxo: materialização de servidores do hub no spawn dos panes (família Claude, Codex, OpenCode, Grok) e hub bridge.
- Arquivo:linha (antes): o schema aceita `cwd` (`mcp-hub-core.ts:31`) e `hubFromStdioLike` copia (`mcp-hub-sync.ts:130`), mas `McpHubSpawnServer` (`mcp-hub-spawn.ts:46-55`) não tinha o campo, `toSpawnServer` (`:98-113`) não repassava e `claudeFamilyHubMcpServers` (`:271-277`) não emitia. O hub bridge (`mcp-stdio-bridge.ts`) também descartava o `cwd` da entrada e não o passava ao `spawn`.
- Passos: 1) hub com server stdio `command: "./SkyComputerUseClient"`, `cwd: "~/.codex/computer-use/…"`. 2) Spawn do pane/bridge.
- Esperado: o processo nasce com o cwd declarado; command relativo resolve.
- Observado: sem cwd, `./` resolvia contra o cwd do pane/workspace — binário inexistente, ENOENT (falha inferida de código+config pela sonda; sem linha de log da sessão).
- Evidencia (RED, fonte anterior): `mcp-hub-spawn.test.ts` › "F-1366: servidor com cwd chega ao spawn com o mesmo cwd" e › "família Claude resolve command relativo contra o cwd (formato sem cwd)" falhavam (`cwd` undefined; command `./SkyComputerUseClient` sem resolução).
- (resolvedor) Correcao:
  - `McpHubSpawnServer.cwd` + repasse no `toSpawnServer`.
  - Família Claude (`claudeFamilyHubMcpServers`): `cwd` NÃO é emitido — docs oficiais do Claude Code (2026-10) não têm esse campo e entrada com campo desconhecido pode ser pulada no boot. Em vez disso, command explicitamente relativo (`./`/`../`) é resolvido contra o cwd para caminho absoluto.
  - Codex (`codexHubMcpArgs`), OpenCode e Grok (projeções do spawn): emitem `cwd`, formato que suporta.
  - Hub bridge: `McpStdioServerDescriptor.cwd` lido da entrada e passado ao `spawn` (F-1366 + guarda do F-1365 no mesmo descritor).
  - Export do sync para cursor/cline/opencode/codex JÁ emitia cwd (`toCursorEntry`/`toOpenCodeEntry`/`mergeCodexToml`) — sem mudança.
- Nao feito (registro): resolução de command relativo na IMPORTAÇÃO contra `~/.codex/computer-use` (sugestão da sonda para o caso computer-use) — exigiria conhecimento de layout específico do Codex; o cwd carregado cobre o spawn. `env` `CLAUDE_PROJECT_DIR` não é sinônimo de cwd (docs), não usado.
- Validacao: `mcp-hub-spawn.test.ts`, `mcp-stdio-bridge.test.ts` verdes; `tsc --noEmit` 0 erros.
