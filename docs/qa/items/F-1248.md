# F-1248 — `content_sha256` sem migração: banco de build intermediário perdia a proveniência de edição em silêncio

## F-1248 | categoria: funcional | severidade: media | status: corrigido
- Tela/fluxo: boot do `nexus.db` e proveniência de edição (F-1237/F-1242).
- Arquivo:linha (antes):
  - `src/main/persistence/db.ts:182`: a coluna `content_sha256` (F-1242) só existia no `CREATE TABLE IF NOT EXISTS provider_conversation_edits`;
  - `src/main/persistence/schema-migrations.ts:16-50`: `ADD_COLUMN_MIGRATIONS` sem entrada para ela.
- Relacionado a F-1237 e F-1242. Achado da revisão sênior antes da tag.
- Passos:
  1. Rodar um build entre `f11f3c746` (F-1237, cria a tabela) e `0d2afccdd` (antes do F-1242): a tabela nasce sem `content_sha256`.
  2. Atualizar para um build com o F-1242 e abrir o app.
- Esperado: o boot acrescenta a coluna; a proveniência volta a gravar e ler.
- Observado: o `CREATE TABLE IF NOT EXISTS` não faz nada numa tabela que já existe. O `INSERT ... content_sha256` falha, `recordConversationEdits` devolve 0 e `listConversationEdits` devolve vazio, sempre e sem log (as duas engolem o erro por contrato).
- Evidencia (RED, launchd, fonte anterior):
  - `db-migration-snapshot.test.ts` › "a tabela antiga ganha a coluna no boot e volta a gravar e ler": `expected +0 to be 1`;
  - `schema-migrations.test.ts` › "adds only missing columns…": `expected [ 'rel_path', 'edited_at' ] to include 'content_sha256'`.
- (resolvedor) Correcao:
  - Causa: coluna nova numa tabela que já tinha saído em build local, declarada só no `CREATE`.
  - `schema-migrations.ts`: entrada `{ table: 'provider_conversation_edits', column: 'content_sha256', definition: "content_sha256 TEXT NOT NULL DEFAULT ''" }`; o union de `table` ganhou a tabela. O boot migra na mesma transação verificada das outras colunas, com o snapshot de antes da migração (DSK-05). Linhas antigas ficam com `''`, que a leitura já ignora (não é sha256).
  - Testes: banco real com a tabela do build intermediário e uma linha antiga. Depois do boot, grava e lê a edição nova, e a linha antiga sem hash não aparece. Os fixtures de `schema-migrations.test.ts` passam a ter a tabela.
- Validacao (launchd): suíte focada GREEN; `tsc --noEmit` 0; `check-main-sync` 0; `src/main/persistence`, `src/main/orch/hook-*.test.ts`, `src/main/orch/mcp-server*.test.ts`, `src/main/regression-gate`, `src/main/pty/pty-manager.test.ts` e `heavy-shell-strict-mode.test.ts`: 79 arquivos, 1414 passaram e 8 foram pulados.
