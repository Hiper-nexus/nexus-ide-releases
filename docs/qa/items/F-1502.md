# F-1502 — Importar o arquivo exportado pelo próprio app falhava (squads internos no arquivo)

## F-1502 | categoria: funcional | severidade: alta | status: corrigido
- Renumerado na integração com a origin (0.76.252): este achado era o F-1448 da frente de squads (nunca publicado) e virou F-1502 para não colidir com a numeração que a origin publicou (F-1436..F-1451).
- Tela/fluxo: Configurações › Squads › Exportar (num PC) → Importar (no outro). Main: `exportSquadsJson` / `prepareSquadsImport` (`src/main/orch/squad-store.ts`) e o handler `squadImport` (`src/main/orch/orch-ipc.ts`).
- Arquivo:linha: `src/main/orch/squad-store.ts:802-815` (export) e `:835-841` (import), antes da correção.
- Passos: 1) Ter um squad próprio salvo. 2) Exportar. 3) Importar esse mesmo arquivo (no mesmo PC ou em outro).
- Esperado: os squads do usuário entram; os internos do Nexus (que já vêm com o app) não atrapalham.
- Observado: a importação recusava o arquivo inteiro com `managed built-in squad id is reserved and cannot be imported: nexus-pet-studio`. Ninguém conseguia levar os próprios squads para outro PC pelo arquivo que o app gera.
- Causa raiz: o export só tirava as cópias de missão (`mission-runtime-*`) e levava os 15 squads internos junto. A importação recusa qualquer id gerenciado — corretamente, para não deixar arquivo sobrescrever o app —, mas fazia isso recusando o arquivo todo.
- Correcao:
  - `exportSquadsJson` exporta só os squads do usuário (fora `builtin`, ids gerenciados e cópias de missão; helper `isAppOwnedSquadId`).
  - `prepareSquadsImport` ignora com aviso os ids do próprio Nexus (internos e cópias seladas de missão de exportações antigas) em vez de recusar o arquivo; eles continuam sem poder sobrescrever nada. O candidato ganhou `skippedIds`, e a checagem de integridade recusa id do app entre os alvos.
  - IPC `squadImport`: o modal nativo lista os ignorados; arquivo só com squads do Nexus volta `{ ok: true, count: 0, skipped }` sem modal e sem gravação; o resultado leva `skipped`.
  - Configurações › Squads (`ModuleSections.tsx`) diz quantos foram ignorados ("Importados 2 squads. Ignorados 1 squad do próprio Nexus…" / "Nenhum squad seu no arquivo: só havia 2 squads do próprio Nexus, que o app já tem.").
  - Teste antigo "rejects every managed builtin id…" virou "never imports a managed builtin id…": continua provando que o Pet Studio não é sobrescrito.
- Evidencia:
  - RED (código antigo): `npx vitest run src/main/orch/squad-store.test.ts -t "F-1502"` → 2 falhas: `Error: managed built-in squad id is reserved and cannot be imported: nexus-pet-studio` (round-trip do arquivo exportado) e `…: outcome-landing-page` (arquivo de versão antiga).
  - GREEN: `npx vitest run src/main/orch/squad-store.test.ts src/main/orch/orch-ipc-authority.test.ts src/renderer/components/settings/SettingsSquads.capabilities.test.tsx` → 177 passaram, 1 falhou: `orch-ipc-authority` "escapa o path selecionado…" com `ENOENT` ao renomear para um nome com `\n` (o NTFS não aceita); falha igual na base com `git stash` — ambiente Windows, não regressão.
  - Integração 0.76.252: o mock de `prepareSquadsImport` em `orch-ipc-authority.test.ts` devolvia `skippedIds: []` (inferido `never[]`) e os dois testes F-1502 que o sobrescrevem com ids quebravam o `npm run typecheck` (TS2345 em `:3795` e `:3822`); o mock passou a tipar `[] as string[]`. Só o teste muda.
