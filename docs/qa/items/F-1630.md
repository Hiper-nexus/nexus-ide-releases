# F-1630 — Conta automática do Claude virava pin permanente no pane salvo

## F-1630 | categoria: funcional | severidade: alta | status: corrigido
- Tela/fluxo: pane Claude solto, escolha automática de conta, salvar/restaurar layout e iniciar conversa nova.
- Arquivo:linha: `src/renderer/terminal/terminal-host.ts:1548`, `src/renderer/terminal/spawn-request.ts:64`.
- Passos: deixar o Main escolher a conta A; persistir o pane; A chega a 99% semanal enquanto B tem 7%; iniciar conversa nova no pane.
- Esperado: uma escolha automática volta à regra de folga para trabalho novo, que já drena a partir de 89% com leitura recente do provedor.
- Observado: o renderer persistia apenas `accountId`; todo spawn seguinte impunha esse id como pin, pulando a comparação de cotas no Main.
- Evidencia: teste `reavalia a conta automática persistida` falhou antes do patch com `acc-1` em vez de `acc-2`. Teste do store falhou porque a origem automática desaparecia. Remover a gravação da origem no terminal reproduziu duas falhas nos testes de integração do host.
- Evidencia de campo (22/10/2026, Windows 0.76.409): snapshot local às 14h41 com Claude A em 79%/99% e B em 18%/7%. O Maestro das 14h34 estava registrado em B. Não há recibo durável da escolha anterior, portanto o caminho reproduzido não foi atribuído conclusivamente ao episódio relatado.
- Correcao: o layout preserva `accountSelection`. Pane Claude automático e solto devolve a escolha ao Main ao iniciar conversa nova. Retomada exata/última sessão, missão, grant de orquestração, papel de missão e destino explícito permanecem vinculados. A resposta do Main mantém a origem; trocar explicitamente de conta ou de CLI limpa a origem automática.
- Compatibilidade: layouts antigos sem origem continuam vinculados, pois não permitem distinguir uma escolha explícita de uma automática. A nova marca nasce nos spawns automáticos desta versão. Nenhuma sessão em andamento é interrompida.
- Relacionado: F-995 (pin automático antes do primeiro spawn); aqui o pin surgia depois, ao persistir a escolha do Main.
- Revisao: a revisão independente encontrou perda da origem no failover. Três regressões do controller e uma do host reproduziram o caso. A recuperação preserva a política automática no layout e mantém o destino obrigatório só naquele spawn, inclusive com continuidade/retomada compartilhada. Conversas futuras continuam automáticas.
- Validacao final: `npm run typecheck`, `npm run security:renderer-sinks` (zero sinks) e `git diff --check` aprovados. 551 testes em 12 arquivos passaram, incluindo os modos de recuperação e a redação de segredos do failover; metadados de release coerentes. Revisão independente final: zero achados críticos/importantes, correção aprovada.
