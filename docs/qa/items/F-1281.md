# F-1281 — Updater do macOS tentava primeiro um browser_download_url de qualquer host https

## F-1281 | categoria: seguranca | severidade: baixa | status: corrigido
- Tela/fluxo: instalação de update no macOS pelo modo `gh`, no download do ZIP do Squirrel.
- Arquivo:linha (antes):
  - `src/main/update-source.ts:95-99` aceitava o `browser_download_url` do asset vindo do JSON da API, desde que começasse com `https://`.
  - `src/main/updater.ts:912-913` punha esse endereço em PRIMEIRO na lista de download, à frente dos endereços montados pela etiqueta nos repositórios conhecidos.
  - O caminho do Linux já recusa endereços vindos da API (`src/main/linux-self-update.ts:8-9`), e `isTrustedGithubReleasePath` já existia em `src/main/update-repos.ts`.
- Achado da revisão sênior do updater.
- Passos:
  1. Uma resposta de release (gh, espelho ou redirect) traz um asset `NexusIDE-darwin-arm64-X.zip` com `browser_download_url` apontando para outro host, como `https://evil.example/…zip`.
  2. O app oferece a versão e o operador (ou a instalação de fundo) instala.
- Esperado: o ZIP só vem do `github.com`, de um dos repositórios de release conhecidos. Qualquer outro endereço é ignorado, e o download usa os endereços montados pela etiqueta.
- Observado: o primeiro `fetch` do download ia ao host arbitrário. O Squirrel ainda confere a assinatura Developer ID antes de trocar o app, por isso a severidade é baixa. Mesmo assim, um terceiro escolhia de onde vinham 240 MB e via o IP do operador.
- Evidencia (RED, fonte anterior): `update-source.test.ts` › "F-1281: só aceita browser_download_url do github.com…" falha com `expected 'https://evil.example/NexusIDE-darwin-…' to be undefined`.
- (resolvedor) Correcao:
  - Causa: a validação do `browser_download_url` olhava só o esquema, não o host nem o caminho.
  - `update-source.ts`: `trustedZipDownloadUrl` aceita o endereço só se ele tiver `https:`, host exatamente `github.com` (o que também recusa porta) e `isTrustedGithubReleasePath(pathname)`. Fora disso, devolve `undefined`. A oferta continua: só o atalho do download some.
  - Teste novo em `update-source.test.ts`:
    - aceita o endereço do espelho canônico;
    - recusa `evil.example`, `github.com.evil.example`, `github.com@evil.example`, um repositório alheio no `github.com` e uma travessia `../` para fora do repositório;
    - com o endereço recusado, a versão continua oferecida com o mesmo `zipAsset`.
- Validacao: `vitest run` dos 7 arquivos do updater (`updater`, `update-source`, `updater-download`, `updater-feed`, `updater-mixed-platform-releases`, `linux-self-update`, `update-repos`): 115 testes passaram. `tsc --noEmit` terminou com 0, e `check-main-sync` também.
