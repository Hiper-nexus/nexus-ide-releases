# F-512 — Erro críptico de assinatura no auto-update e ausência de fallback manual

## F-512 | categoria: usabilidade | severidade: media | status: corrigido
- Tela/fluxo: Modal de Atualização do NexusIDE (`UpdateModal` / `updater.ts`)
- Arquivo:linha: `src/main/updater.ts:727`, `src/renderer/components/UpdateModal.tsx:306`
- Passos:
  1) Abrir o NexusIDE a partir de um build empacotado local sem Developer ID ou fora de `/Applications`.
  2) Detectar versão nova disponível (ex.: 0.76.19) e clicar em "Baixar e instalar".
  3) O ShipIt / Squirrel.Mac do macOS tenta validar a assinatura do binário em execução via `SecCodeCopySelf`.
- Esperado:
  - Orientação amigável em português explicando a necessidade de assinatura Developer ID / execução a partir de `/Applications`.
  - Botão de fallback direto para "Baixar instalador (.dmg)" e botão "Tentar novamente" na interface do modal, sem deixar o operador preso apenas em "Verificar agora".
- Observado:
  - Exibição de erro cru do macOS: `Could not get code signature for running application`.
  - A interface travava no estado `erro` exibindo unicamente o botão "Verificar agora", sem nenhuma forma de baixar o `.dmg` ou tentar novamente.
- Evidencia:
  - Interceptado o erro `Could not get code signature` em `wireSquirrel()` (`updater.ts`), gerando mensagem amigável: *"O app atual foi aberto fora de /Applications ou a partir de build sem assinatura Developer ID. Instale o .dmg oficial para atualizar."*
  - Adicionado botão primário "Baixar instalador (.dmg)" que abre diretamente a página do release no GitHub (`window.nexus.app.openExternal`) e botão secundário "Tentar novamente".
  - Testes unitários dedicados em `UpdateModal.test.tsx` e `updater.test.ts` passando com 100% de sucesso.
- (resolvedor) Correcao:
  - `src/main/updater.ts`: mapeamento de erro do Squirrel.
  - `src/renderer/components/UpdateModal.tsx`: adição dos botões de ação e fallback em fase de erro.
  - `src/renderer/components/UpdateModal.test.tsx`: suite de testes com act/createRoot/OverlayLayer.
