# F-431 — Kits de UI não iniciam no Windows por spawn de npx.cmd

## F-431 | categoria: funcional | severidade: alta | status: corrigido
- Tela/fluxo: Kits de UI, CLI shadcn/BoardUI e servidor MCP BoardUI.
- Arquivo:linha: `src/main/ui-kit/ui-kit-cli.ts:583`, `src/main/ui-kit/ui-kit-mcp-call.ts:194` (fonte v0.76.409).
- Passos: executar uma consulta/instalação de kit ou chamada MCP no Windows com Node/npm padrão no PATH.
- Esperado: processo inicia sem shell e preserva argumentos literais.
- Observado: Node 22.23.2 recusa `spawn(npx.cmd, ..., {shell:false})` com EINVAL; ambas as superfícies falham antes de iniciar o fornecedor.
- Evidencia: dois testes com processos Windows reais falham com `spawn EINVAL` antes da correção; log `runs/20261022-124617-0.76.409/windows-spawn-red.log` do monitor local.
- (resolvedor) Correcao: resolver node.exe e o entrypoint fixo npm/bin/npx-cli.js, mantendo shell:false, allowlist de ambiente e argv separado. Testes focados 74/74, suíte Windows relevante 1092 aprovados/8 específicos de plataforma pulados, typecheck aprovado. Revisão independente somente leitura sem achados restantes no patch.
