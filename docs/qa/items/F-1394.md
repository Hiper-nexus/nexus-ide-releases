# F-1394 — reescrita do ditado CODE recusa JSON válido com texto em volta e cai na tradução literal

## F-1394 | categoria: funcional | severidade: media | status: corrigido
- Tela/fluxo: ditado CODE com reescrita (`polish: 'code-prompt'`), head do cérebro `gemini-3.5-flash` com `jsonMode: false` (config do operador em `~/.nexus/plugins/voice/nexus-voice.json`).
- Arquivo:linha: `src/main/voice/code-prompt-polish.ts` (`parsePolishedPrompt`); consequência em `src/main/voice/code-dictation.ts` (falha de reescrita leva a uma nova STT com `translate: true`).
- Passos: 1) ditar 30 s ou mais no modo CODE; 2) o modelo responde `Here is the prompt: ```json {"prompt": …} ``` ` ou JSON seguido de texto.
- Esperado: a reescrita é aceita.
- Observado (voice.log): 3 de 14 ditados CODE (27/09, 29,5 s, 53,9 s e 32,6 s de fala, os mais longos) terminaram em `stt.codePolishSkipped reason=unparseable` após 5,9 a 6,7 s. Nenhum foi timeout (o limite é 8 s). Cada um pagou uma segunda STT de tradução, ou seja, a tradução literal do Whisper que o modo CODE existe para evitar. O parser só aceitava o corpo inteiro como JSON ou como bloco cercado.
- Evidência: o log guarda só o motivo (`unparseable`), não a resposta do modelo. O formato exato da resposta em campo é **provável, não provado**. Outra causa possível é resposta truncada por `MAX_POLISH_TOKENS = 1200` com o raciocínio do modelo. O F-1392 passa a registrar `polished` e `rawChars` por sessão para medir isso.
- (resolvedor) Correção: `parsePolishedPrompt` tenta o corpo inteiro e, depois, o trecho do primeiro `{` ao último `}`. Resposta sem `prompt` continua recusada.
- RED (contra 72cac12f2): `code-prompt-polish.test.ts` › "F-1394: aceita o objeto JSON com texto em volta" falha.
