# F-1213 — o reset de teste do agent-runtime-bridge largava o AgentAwakeService vivo, e o caffeinate real dos testes ficava rodando

## F-1213 | categoria: funcional | severidade: media | status: corrigido
- Tela/fluxo: suíte de testes. É a origem dos órfãos do F-1186: `hook-http-server.test.ts` → `ingestAgentHookStatus` → `publishAgentHookActivity` → `getAgentAwakeService()` real.
- Arquivo:linha (antes): `src/main/agent-runtime/agent-runtime-bridge.ts:152` — `__resetAgentRuntimeBridgeForTests()` fazia `awakeService = null` sem `dispose()`.
- Passos: 1) `node node_modules/vitest/vitest.mjs run src/main/agent-hooks/hook-http-server.test.ts` (o POST com `state: 'working'` liga o serviço real); 2) o `afterEach` chama `__resetAgentRuntimeBridgeForTests()`.
- Esperado: o cleanup do teste derruba a asserção de sono que o teste criou.
- Observado: o `caffeinate` real continua vivo depois do cleanup. No Linux (o CI roda lá) o mesmo caminho sobe o `systemd-inhibit` (F-1212).
- Evidencia (`ps` antes e depois, macOS):
  - Sonda com o mesmo fluxo e o mesmo `afterEach`, listando os caffeinate filhos do worker:
    `during: 50123 50048 /usr/bin/caffeinate -i -s -w 50048` / `afterCleanup: 50123 50048 /usr/bin/caffeinate -i -s -w 50048` (vivo depois do cleanup). Hoje só o `-w` do F-1186 o mata, e só quando o worker sai.
  - Com o `-w` removido temporariamente (reproduz o F-1186), `orphan-probe` no `hook-http-server.test.ts`:
    `pid=52179 ... STILL ALIVE after vitest exit (ppid=1)` / `ORPHANS LEFT: 1`.
    O job heavy que embrulhava o comando ficou preso (`job-launch` 50869 / supervisor 50896, mais de 5 min). Matar o 52179 liberou o job na hora: é o sintoma exato do F-1186.
  - Com esta correção, a mesma sonda mostra `afterCleanup: []`. Ainda sem `-w`, `ORPHANS LEFT: 0`.
- (resolvedor) Correcao: `__resetAgentRuntimeBridgeForTests` chama `dispose()` no serviço que está descartando, a menos que seja o mesmo injetado. Fica uma segunda trava independente do `-w` (F-1186) e do `cat` (F-1212).
