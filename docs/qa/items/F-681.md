# F-681 — Pane parado em diálogo de início: "Trust this folder?" do Codex e aviso de Bypass sem números do Claude

## F-681 | categoria: funcional | severidade: alta | status: corrigido
- Tela/fluxo: pane do operador pelo "+ Pane" (YOLO/Autopilot) no projeto hipergo; panes Claude-família em bypass.
- Arquivo:linha: `src/main/orch/cli-prompt-autoresponder.ts` (`BUILTIN_PROMPT_SIGNATURES`, `forceAcceptResponseMatch`), `src/main/orch/mcp-server.ts` (`cliPromptAutoResponder.bind`).
- Passos: 1) Abrir um pane Codex num projeto sem decisão de confiança. 2) Abrir um pane Claude em bypass com a versão atual do Claude Code.
- Esperado: o pane chega ao composer sem pedir Enter ao operador.
- Observado (29/09): o operador — "resolve isto, não pedir isto, pular" — com o Codex parado em "Trust this folder? › 1. Trust and continue / 2. Quit"; e "mesma coisa" com o Claude parado em "WARNING: Claude Code running in Bypass Permissions mode … No, exit / ❯ Yes, I accept".
- Evidencia: prints do operador. O Codex só tinha a assinatura do "Folder access" (F-666, restrito); o aviso de bypass só casava na forma numerada ("1. No, exit" / "2. Yes, I accept") e o Claude Code novo desenha sem números e com o cursor já em "Yes, I accept". O aceite forçado escolhia a PRIMEIRA assinatura cujo banner aparecesse — a numerada — e mandaria Seta+Enter a partir de "Yes", voltando a "No, exit".
- (resolvedor) Correcao:
  - Assinatura `codex-folder-trust` (`codexFolderTrustResponse`: setas até "Trust and continue" lidas da tela; `null` se o diálogo oferece "Open restricted"). Marcada `ungovernedOnly`: `bind` recebe `governed` do hook de spawn e, sem a informação, trata como governado — pane de missão governado nunca confia sozinho numa pasta (a postura restrita do F-666 fica intacta).
  - Assinatura `claude-bypass-acknowledgement-unnumbered` com `focusedMenuResponse`: lê onde o cursor `❯`/`›` está desenhado e calcula as setas; sem cursor visível não responde.
  - `forceAcceptResponseMatch` prefere a assinatura que casa inteira antes da que só viu o banner.
  - Testes: `cli-prompt-autoresponder.test.ts` (F-681: trust do Codex no pane do operador; governado e sem informação não respondem; "Folder access" continua restrito; bypass sem números com cursor em Yes → Enter, em No → Seta+Enter, sem cursor → nada; só a assinatura sem números casa a tela nova).
- Cobertura de diálogos de início por CLI (29/09): Claude/GLM/GLM Flash/LongCat (trust ×2, bypass ×2), Codex (Folder access, Trust this folder), Kimi, Grok, Devin, AGY (trust), MiMo (bypass), MiniMax TUI (sem diálogo — capturas reais), Muse (`--trust-workspace`). Termos de uso do AGY continuam com o operador (consentimento legal, uma vez).
