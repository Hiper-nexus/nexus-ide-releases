# F-151 — AGY não abre quando aliases de skills mudam no perfil privado

## F-151 | categoria: funcional | severidade: alta | status: corrigido
- Tela/fluxo: abrir AGY pela ferramenta de panes, com ou sem prompt inicial.
- Arquivo:linha: `src/main/adapters/managed-credentials.ts` (`prepareCheckoutProviderHome`).
- Passos: preparar perfil AGY; fazer `config/skills` apontar para `antigravity-cli/skills` nativo e o alias privado `antigravity-cli/skills` apontar para `config/skills`; abrir outro pane do mesmo checkout.
- Esperado: aliases de skills do mesmo perfil são reconciliados e a CLI inicia; auth e conversas permanecem preservadas.
- Observado: preparação aborta antes do PTY com `AGY skill link points outside its profile source`. Os dois aliases foram encontrados no perfil local; reprodução isolada com a função de produção devolveu o mesmo erro. A CLI nativa respondeu `AGY_OK` sem ferramentas.
- Evidencia: testes sintéticos reproduzem o bloqueio, preservação de credencial/conversa e recusa de link para outra conta. Não foram lidos nem gravados tokens reais para reproduzir o erro de links.
- (resolvedor) Correcao: reconciliar somente destinos da allowlist dos quatro aliases de skills da mesma origem/checkout, substituindo o link em si, sem seguir nem apagar o destino. Diretórios reais e links para outra conta continuam recusados.
- Outras CLIs: esse conjunto de aliases é exclusivo do AGY. Devin usa o mesmo helper para auth/conversas, mas não entra no ramo de skills; os testes de isolamento de ambos seguem necessários.
- Validacao: `npx vitest run src/main/adapters/managed-credentials.test.ts` passou (23 testes atuais; 44 contando cópia descoberta). Regressão falhou antes com o erro exato. Typecheck e renderer-sinks passaram. Reconciliados os dois aliases locais após conferir que todos os links de auth/config já apontavam para suas origens corretas; credenciais não foram substituídas.
- Prova no Nexus em execução: pane de teste `pane-mua7fwsl-k` abriu a TUI autenticada do AGY/Gemini 3.8 Flash e respondeu `AGY_OK`. O wrapper `pane_ask` marcou timeout enquanto a saída já continha a resposta; a validação é a resposta real e o composer visível, não o estado do wrapper. Pane de teste fechado ao fim. O código durável será incorporado ao próximo build do Nexus; os aliases locais já foram reparados.
