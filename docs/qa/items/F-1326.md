# F-1326 — Captura responsiva cortada ao tamanho do pane voltava como completa

## F-1326 | categoria: funcional | severidade: media | status: corrigido
- Tela/fluxo: `nexus_browser_responsive` (e `nexus_browser_screenshot` com device emulado) num pane de browser menor que o device.
- Arquivo:linha: `src/main/browser/browser-manager.ts` (`captureBrowserScreenshot`, clip do viewport emulado); `src/main/orch/tools-browser.ts` (registro de evidência visual).
- Passos: 1) Pane do browser em ~309×136 CSS. 2) `nexus_browser_responsive` numa fixture local.
- Esperado: captura do viewport emulado inteiro (390/800) ou aviso explícito de corte; captura cortada não conta como prova visual.
- Observado: mobile 390 e tablet 800 saíram 618×272 físicos (~309×136 CSS, DPR 2), título e texto cortados à direita e embaixo, devolvidos como sucesso sem aviso e registrados como evidência visual da tarefa.
- Evidencia: RED em `browser-manager-actions.test.ts` (view 309×136, tablet 800): a captura voltou com `width: 309` e sem `truncated`/`capturedCss`/`viewport`.
- (resolvedor) Correcao: a view só pinta os próprios bounds, então a captura de um device maior que o pane é marcada `truncated: true` com `capturedCss` e `viewport` (CSS px) em `BrowserScreenshotResult`. `nexus_browser_screenshot` e `nexus_browser_responsive` não registram captura marcada como evidência de `nexus.visualVerification`; a descrição da ferramenta manda alargar o pane e repetir. Capturar o device inteiro foi descartado: exigiria crescer uma view visível sobre o workspace (caminho de upgrade: captura offscreen no tamanho emulado).
- Validação: `npx vitest run src/main/browser/ src/main/orch/tools-browser-workspace.test.ts` 323/323 (27 arquivos); `npx tsc --noEmit -p tsconfig.json` limpo.
- Relacionado: prova visual exigida pelo operador para correção de UI.
