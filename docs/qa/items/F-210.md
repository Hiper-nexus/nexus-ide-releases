# F-210 — Claude nativo não descoberto e instalação npm colide com launcher existente

## F-210 | categoria: funcional | severidade: alta | status: corrigido
- Tela/fluxo: Providers → Claude → Instalar automaticamente no macOS.
- Arquivo:linha: `src/main/path-resolver.ts`, `src/main/adapters/cli-install-recipes.ts`, `src/main/persistence/provider-config-store.ts`.
- Relato: no Mac vizinho, Nexus mostra CLI não instalada e conta conectada; npm global falha EEXIST em `~/.local/bin/claude`. O operador depois confirmou `command not found` ao tentar consultar o Claude no Terminal. Conta salva não comprova CLI utilizável. Não houve acesso remoto à máquina nem inspeção do arquivo real; não se afirma que seu tipo foi identificado.
- Reprodução concreta: fixture com `~/.local/bin/claude` apontando para versão ausente e outro executável válido em `~/.local/share/claude/versions/`. O resolver real devolvia null: colocar a pasta de versões no PATH não descobre arquivos cujo nome é a versão, em vez de `claude`. npm era escolhido antes da receita nativa e colidia com o launcher ocupado. Instalação com exit 0 anunciava sucesso sem exigir redescoberta.
- Esperado: reconhecer uma instalação válida em pastas suportadas, preservar precedência explícita/PATH e não sobrescrever um launcher desconhecido. Após instalar, comprovar a CLI que o pane usará.
- Correcao: fallback somente para Claude POSIX, na pasta nativa conhecida, com seleção semver do executável regular mais novo e sem alterar links. PATH/launcher utilizável continuam prioritários. Receita oficial nativa passa a ser primeira no macOS; Windows e Linux preservam sua ordem de receitas. Clique de instalação reexamina e reaproveita Claude existente com versão comprovada. Instalação que não produz CLI verificável retorna erro, nunca sucesso silencioso. Nenhuma remoção de arquivo pessoal, mudança de credencial, HOME ou uso de `--force`.
- Fonte oficial consultada em 28/09: https://code.claude.com/docs/en/setup — instalação nativa recomendada; launcher em `~/.local/bin/claude` ligado à pasta de versões. A documentação também registra que launchers personalizados são preservados pelo instalador/atualizador.
- Validação: `path-resolver.test.ts`, `cli-install-recipes.test.ts`, `provider-config-spawn.test.ts`: 127 passed/4 skipped (plataformas não presentes); typecheck passou. Fixtures cobrem versões distintas/prerelease, link quebrado preservado, launcher ausente, prioridade de launcher válido, arquivo sem execução, recuperação sem PATH e verificação pós-instalação. Testes de IPC usam download/exec simulados; não instalaram software real.
