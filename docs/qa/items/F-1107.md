# F-1107 — URL malformada escapava do callback HTTP do preview

## F-1107 | categoria: seguranca | severidade: alta | status: corrigido
- Tela/fluxo: preview estático local iniciado por `nexus_preview_start`.
- Arquivo:linha: `src/main/orch/preview-server.ts:98`, `:138` e `:206` na base `dd71fb7096b864839b209d442acf5c0d6323c236`.
- Passos: 1) Iniciar um preview de diretório temporário com `index.html`. 2) Enviar GET com o caminho cru `/%` ou `/%C3%28` por `node:http`, sem normalização de URL.
- Esperado: recusa HTTP limitada à requisição inválida; o mesmo preview continua servindo arquivos válidos.
- Observado: `decodeURIComponent` lançava `URIError` antes do `try` de `serve`; a exceção saía do callback HTTP do Main e nenhuma resposta era concluída.
- Evidencia: RED real em `runtime217-preview-red.log`: duas falhas por timeout de 1 s e dois `URIError`, com a pilha `resolveSafe:98` → `serve:138` → callback HTTP `:206`. A fonte de produção ainda era a base durante esse RED.
- (resolvedor) Correcao: `resolveSafe` captura somente a decodificação e devolve `null` quando ela falha, seguindo a recusa 403 existente. O teste co-localizado emite os dois caminhos crus, exige `403/forbidden` e depois exige `200/<h1>preview ok</h1>` no mesmo listener para `/%69ndex.html?ignored=%`. Cada caso aguarda a prova física de fechamento do próprio preview.
- Validação: Node 22.23.2 e npm 12.0.0 fixados; `npx vitest run src/main/orch/preview-server.test.ts` passou 15/15; `npm run typecheck`, `npm run security:renderer-sinks`, `npm run lint:main-sync`, Oxlint dos dois arquivos e `git diff --check` passaram. Main-sync conservou os 91 usos legados exatos; renderer sinks encontrou zero sinks executáveis.
- Licença/proveniência: os dois caminhos alterados não constam nos manifests de `third_party/provenance`; nenhuma dependência, atribuição, pin original ou hash de proveniência precisou mudar.
- Limite: evidência de fonte e HTTP loopback real em Vitest, sem execução do Electron empacotado. A revisão independente e os gates finais do candidato continuam separados. O endpoint CDP bruto permanece fechado; versão, tag, build e publicação não foram alterados nesta correção.
