# F-639 — Pane Claude recusado com "A sessão expirou" quando só o access token venceu

## F-639 | categoria: funcional | severidade: alta | status: corrigido
- Tela/fluxo: abrir pane Claude com conta de assinatura gerenciada ("+ Pane", failover).
- Arquivo:linha: `src/main/persistence/account-store.ts:439` (`verifyManagedClaudeAccountForSpawn`), `src/main/quota/claude-native-account.ts:90` (`expiresAt <= now` → `auth-expired`).
- Passos: 1) Conta Claude gerenciada sem pane aberto por mais de 8 h (o access token dura ~8 h). 2) Abrir um pane nessa conta.
- Esperado: o pane abre — o escopo tem refresh token, e a CLI é dona da renovação (`.oauth_refresh.lock`).
- Observado: `[nexus] failed to start: A sessão de "admin@volarehost.com.br" expirou — entre novamente antes de abrir um pane.` A prova de identidade do spawn tratava access token vencido como sessão morta e recusava antes de a CLI ter chance de renovar. No Mac a sonda de cota roda a CLI no escopo de tempos em tempos e esconde o defeito; no Windows ela nunca rodava (F-640).
- Evidencia: print do operador (24/09, 0.76.96). Os dois escopos gerenciados deste PC tinham `expiresAt` vencido havia ~19 h com `refreshToken` presente.
- (resolvedor) Correcao: com escopo gerenciado, `auth-expired` e refresh token presente, o spawn roda a CLI UMA vez no escopo da conta (`probeClaudeCliUsage` + `managedClaudeCliEnv` — a mesma renovação da sonda de cota, nunca refresh HTTP do Nexus), relê o escopo sem cache (`readManagedClaudeAuthAsync(id, { fresh: true })`) e prova a identidade de novo no token novo. "Entre novamente" só quando nem a CLI renovou; token renovado de outra conta continua `mismatch`. Sem refresh token, ou conta só no vault, nada roda. Testes: `account-store.test.ts` › "F-639" (renova e prova; CLI não renova; renovação de outra conta; sem refresh token).
- Nota: a conta `retornoja@gmail.com` deste PC tinha o refresh token realmente consumido — o escopo gerenciado era cópia da linhagem do login nativo, e a CLI nativa renovou antes (ver F-645). Para ela, "entre novamente" é a resposta correta.
